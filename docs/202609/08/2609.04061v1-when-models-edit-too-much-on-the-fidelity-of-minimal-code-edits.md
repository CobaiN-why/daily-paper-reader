## 摘要
大语言模型（LLMs）越来越多地用于编辑现有代码，但仅正确性是不够的：有用的修复还应当是最小化、可审查且忠实于原实现的。我们研究了过度编辑，即模型在修复缺陷之外重写代码的倾向。我们通过将受控的AST级损坏注入参考解决方案，构建了一个基于400个BigCodeBench问题的评估框架，使每个修复任务都有一个已知的最小补丁。在各大前沿LLM中，过度编辑现象普遍存在，即便如GPT-5.5这样的强模型：高Pass@1可能与不必要的巨大编辑以及增加的认知复杂度并存。保留指令能显著减少此行为，将平均多余Levenshtein距离从0.195降至0.131，使增加的认知复杂度降低26.6%，并使Pass@1提高2.3个百分点。然而，这些收益并非仅仅来自更大的推理预算或更大的模型。接下来我们探讨是否能在后训练阶段直接学习最小化编辑。我们观察到，监督微调会过拟合观察到的损坏模式，而强化学习则在域外编辑保真度和性能保持之间取得了最佳权衡。这些结果将编辑保真度定位为代码修复质量的一个独立维度，并表明它可以被测量和学习。

## Abstract
Large language models (LLMs) are increasingly used to edit existing code, but correctness alone is not enough: useful repairs should also be minimal, reviewable, and faithful to the original implementation. We study over-editing, the tendency of a model to rewrite code beyond what is required to fix a bug. We construct an evaluation framework from 400 BigCodeBench problems by injecting controlled AST-level corruptions into reference solutions, giving each repair task a known minimal patch. Across frontier LLMs, over-editing is widespread even among strong models like GPT-5.5: high Pass@1 can coexist with unnecessarily large edits and added cognitive complexity. A preservation instruction substantially reduces this behavior, lowering average excess Levenshtein distance from 0.195 to 0.131, reducing added cognitive complexity by 26.6%, and increasing Pass@1 by 2.3 points. However, these gains do not simply follow from a larger reasoning budget or larger models. We next ask whether minimal editing can be learned directly during post-training. We observe that supervised fine-tuning overfits to seen corruption patterns, whereas reinforcement learning gives the best out-of-domain edit-fidelity and performance-retention trade-off. These results position edit fidelity as a distinct axis of code-repair quality and show that it can be measured and learned.

# 论文总结

## 1. 核心问题与整体含义

- **核心问题**：大型语言模型在代码修复（bug fix）中存在系统性“过度编辑”（over-editing）问题——即模型修复缺陷时，会重写超出必要范围的代码。这种行为即使在功能正确（通过测试）的情况下依然存在。
- **研究动机**：真实维护场景中（brownfield），开发者不仅需要补丁能通过测试，更要求补丁易审查、忠实于原意、尽量小、不引入额外复杂度。现有基准过度关注功能正确性（如 Pass@k），忽略了“编辑保真度”这个质量维度。
- **整体含义**：本文证明“高 Pass@1 并不等于好的修复”，首次将编辑保真度定位为代码修复质量的一个**独立、可测量、可学习**的轴，并系统研究了其诱因、干预手段与训练方法。

## 2. 方法论

论文方法可概括为以下流程：

### 2.1 基准构建：受控损坏注入
- 从 BigCodeBench 中采样 400 个问题，对参考正确解注入 **1~2 个 AST 级结构化损坏**，仅保留损坏后无法通过原始测试的样本。
- 损坏类别涵盖 14 种（如比较运算替换、range 边界偏一、排序反转、累积器初始化等），按语义归为 4 类：谓词/控制流、计算/数值、边界/迭代、API/数据语义。
- 每个任务因“损坏是注入的”，天然存在**已知最小补丁（即注入损坏的逆操作）**，首次为修复任务提供了真实可靠的极小补丁参考。

### 2.2 评估指标
三个互补指标，核心是“相对已知最小修复的派生指标”：
- **Pass@1**：修复通过全部隐藏测试的比例；
- **额外编辑距离 ELev（Excess Levenshtein distance）**：`D_model − D_gold`，即模型输出与损坏代码的归一化 token 级编辑距离减去金标修复的该项距离，用于度量与极小的额外改动；
- **新增认知复杂度（Added Cognitive Complexity）**：模型输出与金标修复间认知复杂度之差，捕捉“补丁虽短但结构变乱”的过度编辑。
- 指标经人工验证：ELev 与人对“可审查性/忠实性”判断的 Cohen's κ 分别达 0.897/0.939。

### 2.3 提示干预
在通用修复指令基础上增加**保留指令（preservation clause）**：“...but keep as much of the original code as possible”，比较两种条件下的行为差异。

### 2.4 后训练学习
在 Qwen3-4B 模型上对比四种后训练策略，全部以奖励修复正确性与编辑最小性为训练信号：
- **SFT**：直接监督学习（金标修复）；
- **rSFT**：拒绝采样，筛选最小编辑且通过测试的补丁训练；
- **DPO**：偏好优化，小的成功编辑 vs 大的成功编辑；
- **RL**（GRPO 目标）：奖励 `r(M) = λ_exec − λ_edit·e(M)`，综合考虑通过率和相对编辑距离。

### 2.5 数据来源与场景
- **训练数据**：DeepCoder 的 4,141 个样本，注入 1~10 个损坏；
- **域内测试**：上述 400 BigCodeBench 任务；
- **域外测试**：20 种未见过的损坏类型；
- **跨域转移**：Defects4J 真实 Java 单方法 bug；
- **通用能力保留测试**：LiveCodeBench v6。

## 6. 主要结论与发现

1. **过度编辑在边界模型中普遍存在**，且独立于正确性：强模型如 GPT-5.5 High 在 Pass@1=0.823 时，其额外编辑距离是 Opus 4.7 的 4 倍以上。
2. **保留指令显著有效**：平均 ELev 从 0.195 降至 0.131，新增认知复杂度下降 26.6%，Pass@1 提升 2.3 个百分点（40/50 个设置中提高）。最强的过度编辑器改进最明显，原本较忠实的模型（如 Opus 4.7）变化小。
3. **推理增强与模型扩大不是通用解药**：推理影响因模型而异（有的提升保真度，有的反之）；模型规模扩大对忠实度无单调改善。
4. **最小编辑可以学习，RL 是较优路径**：RL 在 OOD 场景达到 ELev=0.050、Pass@1=0.782（几乎追上 SFT 的域内水平），不损失 LiveCodeBench 能力（+0.6 点）；SFT 域外崩塌（Pass@1 0.458，LCB −14.9），rSFT、DPO 亦明显退步。
5. **RL 的策略**：在资源效率（低秩 LoRA 少量参数即可捕获风格偏好）与跨语言迁移（Java Defects4J 上原样转移且不损修复率）上均表现稳健。
6. **过度编辑的实质**是修复粒度错位 + 任务框架错配，主要模式为：防御性泛化（64.2%）、数据流重写（63.2%）、契约漂移（34.7%）、功能增强（23.6%）等。

## 7. 优点

- **基准设计巧妙**：不是用 LLM 产 bug 再“估测”最小修复，而是**手动注入 AST 变换获得理论已知的极小补丁**，为“最小修复”提供了天然真值，使得对“多改了多少”的度量有绝对可信的参照；这对于该领域后续研究具有可用价值。
- **指标体系完整且经人工验证**：Pass@1 + 相对编辑距离 + 认知复杂度三维视角，并做了大规模专家验证，不只是盲目追求模型内部统计指标；对 CodeBLEU 的批评理由充分、可复现。
- **结论链条完整**：发现问题（RQ1）→提示干预（RQ2）→机制排除（RQ3，推理/规模非主因）→行为分类（RQ4）→后训练习得（第 4 节），推理层层递进。
- **多维度实验设计**：覆盖模型族、提示、推理设置、模型尺度、后训练方法、奖励设计、LoRA 秩、rollout 预算、跨语言迁移等，且全部做了统计显著性与鲁棒性验证，广度与深度俱佳。
- **发现具有实践价值和可操作性**：关于保留指令的提示结构可以立刻在相关工具中落地，是很实用的收获。

## 8. 不足与局限

- **评估场景受控性限制**：注入的是人为设计、函数级局部 bug，非真实仓库的跨文件/复杂逻辑缺陷。论文自己也承认，真实场景往往更复杂，模型在这些简单局部任务上过度编辑，不能完全代表真实行为；相反，对局部任务的保真也不必然意味着复杂场景下的忠实。
- **单语言主导**：评价与训练以 Python 为主，跨语言验证只限于 Defects4J 的少量 Java 单方法，其他语言（如 JS、TS）并没有得到太多体现。
- **模型覆盖范围有限**：后训练实验只覆盖 Qwen 家族，对闭源前沿模型无法做训练级对比。
- **人类研究规模偏小**：验证指标仅 3 位注记者 × 100 对样本；单注记者审计仅 100 个高 ELev 样本；虽然结论有统计学支持，但规模化依然不够。
- **绝对修复率偏低**：Defects4J 实验中模型绝对修复率极低（4B 仅 ~7%、14B 约 ~15%），虽然看出“保真度偏好可迁移”，但样本量过大可能造成迁移机制不明。
- **“保留指令”效应的产品级可操作空间**：论文没有探讨在长提示（复杂任务）下保留指令是否依然有效，也没有解释模型内部为何发生这种模式切换，理解深度有限。
- **未揭露全部算力开销**：虽给出单次 RL 运行成本，但没有给总训练资源需求，复现成本高。
- **用 ELev 的 0 边界判“比最小还小”的样本被归作坏样本**：SFT 出现负 ELev（修得比金标还少），论文将这类“欠编辑”解释为不安全/无效修复，但没有深入讨论这种欠修复与过修复的边界或同等有害性。
