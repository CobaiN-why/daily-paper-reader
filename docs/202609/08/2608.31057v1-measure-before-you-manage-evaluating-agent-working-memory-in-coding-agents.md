## 摘要
智能体工作记忆是异构的。诸如指令、工件、工具输出和智能体生成状态等对象扮演着不同的语义角色，并展现出不同的大小、保留和表示特征。近期研究已开始探索能够解释这种异构性的记忆管理机制。本研究聚焦于语义异构性，并探讨其应如何塑造编码智能体工作记忆的管理与评估。通过对55个存档的编码智能体轨迹的分析，我们发现语义上不同的工作记忆对象表现出不同的保留和压缩行为。这种异构性促使我们采用语义感知的记忆管理策略。我们研究了两种语义感知策略：一种面向对象的压缩策略和一种基于检索的策略。评估结果显示，校准增益可能无法迁移至保留任务，且相等的token预算并不意味着相等的传递上下文或管理成本。一次真实系统的重放进一步揭示了仅凭名义预算无法捕捉的服务器限制。这些结果共同说明了语义结构为何对智能体工作记忆至关重要，以及为何评估记忆管理策略不能仅依赖于名义token预算。我们将这些经验归纳为四个层级：存储状态、传递上下文、管理工作和任务或过程结果。

## Abstract
Agent working memory is heterogeneous. Objects such as instructions, artifacts, tool outputs, and agent-generated state play different semantic roles and exhibit different size, retention, and representation profiles. Recent work has begun to explore memory-management mechanisms that account for such heterogeneity. This work focuses on semantic heterogeneity and studies how it should shape the management and evaluation of working memory in coding agents. Across 55 archived coding-agent trajectories, we find that semantically different working-memory objects exhibit distinct retention and compression behavior. This heterogeneity motivates semantically informed memory management. We study two semantically informed strategies: an object-aware compression policy and a retrieval-based policy. Their evaluation shows that calibration gains may not transfer to held-out tasks, and that equal token budgets do not imply equal delivered context or management cost. A real-system replay further exposes serving limits that nominal budgets alone do not capture. Together, these results show why semantic structure matters for agent working memory and why evaluating memory-management strategies requires more than a nominal token budget. We organize these lessons into four levels: stored state, delivered context, management work, and task or process outcome.

- **研究动机**：主流记忆管理机制（保留、压缩、驱逐、检索策略）往往将异构状态一视同仁；然而不同语义对象在大小、持久性、表示方式、生命周期上存在明显差异。忽略了这一异质性，可能导致评估结论失真。
- **核心主张**：语义结构应当塑造记忆管理的设计与评估，评估不能只看名义token预算，必须区分**存储状态、交付上下文（delivered context）、管理工作（management work）、任务/过程结果**四个不同层级分别测量。

## 2. 方法论

### 2.1 工作记忆模型
- 主系统维护一个有序的"消息计划"（message plan），引用带类型的对象。
- 对象类型：**指令**（Instructions）、**工件**（Artifacts，如源码视图）、**工具输出**（Tool outputs）、**智能体状态**（Agent state）。
- 每条记录含对象ID、大小、创建步骤、表示形式（raw/compressed/summary/pointer）及路径/版本/依赖等元数据。
- 指针（pointer）保留对象ID，可通过 recall_object 工具恢复，驱除不等于永久删除。

### 2.2 内容度量公式
对对象 $o$，令：
- $s_o$ = 代理token大小，$c_o$ = 创建步骤，$e_o$ = 首次驱逐步骤，$T$ = 轨迹终点；
- 保真间隔 $r_o = \max(0, \min(e_o, T) - c_o)$
- 内容体积 $V_c = \sum_{o\in c} s_o$（每条保留记录计一次）
- 保真加权成本 $R_c = \sum_{o\in c} s_o r_o$

这两者皆为会计量，不是供应商账单、KV-cache占用或语义因果效用。

### 2.3 对象感知压缩策略（OA）
- 启发式非学习评分，综合类型/子类型权重、记录年龄、访问次数、过期/取代惩罚与渲染大小。
- 评分公式（C.1、C.2）：
  - $u_o = \max(10^{-6},\ b_t e^{-d_t a_o} m_o[1+0.35\min(k_o,5)](1-p_t z_o)q_o)$
  - $S_o = u_o / \max(s_o^{\text{rendered}}, 1)^{0.5}$
- 类型默认参数：指令（基分1.0，无衰减）、智能体状态（基分0.8，衰减0.04）、工件（基分0.6，衰减0.06）、工具输出（基分0.5，衰减0.18）。
- 最多四轮按分数降级候选人（raw→compressed→summary→pointer）；指令和新建对象受保护。

### 2.4 检索式策略（GA）
- 借鉴记忆检索的三组件评分（D.1）：
  $$S_o^{GA} = 0.5 \cdot \tilde{g}_{0.99}^{s-\ell_o} + 3.0 \cdot \tilde{\cos}(e_o, e_q) + 2.0 \cdot \tilde{I}_o$$
  - 其中 $\tilde{\cdot}$ 表示 min-max 归一化，$\ell_o$ 为按“准入”步（非自动提示包含）更新的时钟
  - 相关性：局部 BAAI/bge-small-en-v1.5 嵌入，比较候选内容与 issue 文本和最近智能体状态
  - 重要性：独立模型请求生成1-10评分，运行内缓存
- 与基因型（Generative Agents）的对齐是**改编而非复现**。不含反思、规划等组件。

### 2.5 对比基线
- **FIFO**：按创建时间驱逐。
- **LRU**：基于主系统自动提示包含（INCLUDE_IN_PROMPT）更新的访问时钟（存在信号污染缺陷）。
- **LRU-D**（需求驱动变体）：观测 READ/RETRIEVE/UPDATE 需求事件。
- **UC（统一压缩）**：决策规则统一（年龄阈值3步+FIFO），但共享类型相关结构压缩器；目的是区分“决策规则”与“编解码算法”。
- **OA**：对象感知压缩策略。

## 6. 主要结论与发现

1. **语义异质性真实存在且稳定**：工具输出占55.5%总体体积份额但仅40.2%保留加权成本；工件中位数大小624 vs 工具输出73代理token，工件保留时间更长（平均10.71 vs 8.61步）。体积份额和保留成本份额分布显著不同。
2. **同等预算不等于等效预算**：名义15%标签下，实际预算/参考峰值在15%–76.7%（宽扫描可达165%）间浮动；预算地板可能让不同分数产生完全相同绝对预算。
3. **同一上限亦不保证相等的传输上下文**：八个完整配对臂之间，没有一个受限臂对能在全部八个任务上实现10%以内的交付状态匹配；FIFO–UC配对在8个任务中最多8个任务全部失配（最大差距88.8%）。
4. **管理工作也是比较的一环**：同上限下，GA额外285次重要性调用、OA额外169次摘要调用。GA–FIFO墙上时间差正偏（8任务均+67.45秒），消除了同算力对比的等价性。
5. **校准收益未必迁移**：OA在保持集上未复现校准集中显著的重复调用减少。存储量不够——需要一个4级评估方案来区分存储状态、交付上下文、管理工作和结果。
6. **探索性服务重放**：在32,768 token冻结限位下，未约束臂在一个任务上超限（达到37,883 tokens），而所有约束臂低于上限（16,643 tokens）——交付上下文是一项硬可行性约束。
7. **生命周期信号可能被破坏**：一次保存轨迹中，读取不变内容仍生成新版本，触发5次工具输出失效（版本信号不等于语义陈旧/过期）；自动提示包含更新访问时钟加剧LRU退化。缺陷信号需检测并修正。

## 7. 优点

- **诚实、严格的方法论**：明确区分校准 vs 保持集、过程 vs 结果、名义 vs 绝对 vs 交付预算；主动披露校准-保持集不一致。
- **多程序设计与透明度**：分层样本、任务内平均、配对检验、精确检验（枚举符号分配，处理零差集）、Bootstrap置信区间（任务级变化而非独立再运行）；同时准确指出各类统计方法的适用范围。
- **统一实验空间**：同一轨迹存档上顺序进行4级评估，允许比较不同方案的报告粒度。
- **提出“先测量再管理”框架**：从一维token预算扩展到四维报告（存储状态、交付上下文、管理工作、结果），对记忆管理策略的评估有普适推广价值。
- **区分决策规则与压缩codec**：UC与OA的对比强调“决策规则统一”不是“编解码统一”；分离了机制与效果。
- **诚实否定自身**：论文多处承认模型版本未固定、生命周期信号缺陷、无有效修复评估、备份存档不完整。这种自我批判弥补了数据不足。

## 8. 不足与局限

- **样本规模小且非随性**：核心结论建立在8–15个任务的少量轨迹上，依赖单个任务高影响数据点（如单任务LRU-D重复调用=7）。对象表征覆盖55条轨迹但统计依赖对象采样非任务独立复制。
- **任务覆盖窄**：集中在SWE-bench类issue上，Terminal-Bench探针仅描述边界，无跨工作负载的任务-策略可迁移性验证。
- **无有效任务修复结果**：检索研究缺正式修复评估；本地评估器只检查部分测试；步天花板碰顶常发生于多数臂，修复成败统计失效。
- **预算与资源测量的单位/口径不一**：预算测量早期用 cl100k_base、后期用 Qwen2.5-Coder-32B-Instruct 冻结分词器，口径不同不可互换；混合口径将致误导性比较。
- **明确的机制实现缺陷**：访问时钟因自动提示包含而退化，版本检测失真；OA 的年龄/复用输入无效数据；未生成校正系统版本轨迹，无法验证“如果修正……会怎样”。
- **模型/服务不可复现**：服务端模型 revision 未锁定；历史请求、重试和干预记录不完整；模型提供商远端更新导致跨重放差异。
- **结构压缩探针的语义信息无质量验证**：压缩比率是类型特定实现属性，非内在可压缩性；事实保留度（literal-string retention）非人工验证的语义保留。
- **伦理与合规声明缺项**：资产许可证/使用条款未列全标；未讨论社会影响（尽管不涉及新模型发布或高风险数据集）。
- **整体计算资源汇总缺失**：除探索性GB10重放外，主实验未披露具体GPU类型/数量、开发运行和失败实验的总算力。

## 结尾
该文提供了一次高度自我审计、方法论上严谨的工作记忆研究挑战：从单维token预算评估转向四维分层评估。其样本规模限制和模型/数据可复现性问题使其结论需谨慎外推，但“测量先于管理”的框架及对名义预算的谨慎态度在多数智能体记忆管理研究中都具有普适参考价值。
