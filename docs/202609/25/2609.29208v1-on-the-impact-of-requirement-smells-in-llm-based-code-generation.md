## 摘要
软件需求通常被纳入LLM辅助软件开发所使用的提示中。近期工作表明，需求异味会影响需求与代码之间的自动化可追踪性，但关于其在代码生成中影响的实证证据仍然有限。为弥补这一空白，我们在先前关于自动化可追踪性的研究基础上，复用其数据集和需求异味分类体系，同时对其进行扩展，以评估LLM生成代码的功能正确性。我们使用一个包含四个应用的需求及相应系统测试的基准，逐步向原本清晰的需求中引入语义、句法和词汇层面的异味，并分析其对生成实现的影响。我们的结果表明，增加异味密度通常与基于测试套件的功能正确性降低相关，尽管无异味的需求仍可能产生有缺陷的代码。我们还发现，不同异味类别具有相似的影响。这些发现提供了额外的实证证据，表明需求质量在LLM辅助代码生成中的重要性，同时表明高质量需求本身并不能保证正确性，因为这取决于若干因素，包括LLM。与先前工作相比，我们的结果表明，需求异味的影响取决于软件工程任务：尽管它们对可追踪性的影响较为温和，但代码生成似乎更为敏感。总体而言，这项工作推动了对LLM辅助软件工程中任务依赖的质量效应的进一步研究。

## Abstract
Software requirements are typically incorporated into prompts used in LLM-assisted software development. Recent work has shown that requirement smells can affect automated traceability between requirements and code, but empirical evidence on their effects in code generation remains limited. To address this gap, we build upon a prior study on automated traceability by reusing its dataset and requirement smell taxonomy, while extending it to evaluate the functional correctness of LLM-generated code. Using a benchmark consisting of requirements and corresponding system tests for four applications, we progressively introduced semantic, syntactic, and lexical smells into otherwise clear requirements and analyzed their influence on generated implementations. Our results suggest that increasing \textit{smell density} was generally associated with lower test-suite-based functional correctness, although non-smelly requirements could still produce faulty code. We also found that different smell categories had similar effects. These findings provide additional empirical evidence of the importance of requirement quality in LLM-assisted code generation, while showing that high-quality requirements alone do not guarantee correctness, as these depends on several factors, including the LLM. Compared with previous work, our results suggest that the impact of requirement smells depends on the software engineering task: whereas their effects on traceability were modest, code generation appears more sensitive. Overall, this work motivates further investigation into task-dependent quality effects in LLM-assisted software engineering.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 已被广泛用于软件开发生命周期各环节，需求文档常被直接作为提示（prompt）输入 LLM 以生成代码。LLM 输出质量高度依赖提示质量，而需求工程（RE）中传统关注的缺陷（如歧义、不一致、需求异味）可能直接影响生成代码的质量。
- **核心问题**：已有研究（Vogelsang et al., 2025）表明需求异味会影响需求到代码的自动化追溯，但关于需求异味如何影响 **LLM 代码生成的功能正确性**，实证证据仍然有限。
- **整体含义**：本文通过受控实验，系统考察需求异味的**存在性、密度和类别**如何影响 LLM 生成代码的测试套件层面的功能正确性，旨在为"需求质量在 LLM 辅助软件工程中的作用"提供实证依据，并揭示质量效应可能具有**任务依赖性**。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：以 Vogelsang et al. 的自动化追溯研究为基础，**复用其数据集、需求异味分类法和异味注入策略**，将评估目标从"追溯准确率"扩展为"生成代码的功能正确性"。
- **异味分类（三层次）**：
  - **语义异味（semantic）**：影响需求含义或解释，如引入歧义、上下文依赖解释。
  - **句法异味（syntactic）**：涉及语法或结构表述，如被动语态、否定结构。
  - **词汇异味（lexical）**：个别词语或表达导致精确性/清晰度下降，如弱动词、模糊阈值。
- **异味注入流程**：
  - 基于 Frattini et al. 的需求异味分类法手工设计变体；
  - 每个修改后的需求**保留原始意图**，仅引入目标异味；
  - 由另一位作者独立评审，验证：①异味类别正确、②无意外缺陷、③需求仍具现实性；分歧通过讨论达成共识。
- **骨架与提示构造**：
  - 每个游戏预定义 Java 骨架（类、属性、方法签名），每个需求映射到唯一方法，支持需求级单元测试；
  - 提示结构固定为四部分：①任务描述、②实现约束、③Java 骨架、④功能需求（仅此部分随实验条件变化）。
- **LLM 配置**：GPT-4o 与 DeepSeek-V3，temperature=0，未设最大 token 限制，每个配置生成 5 次输出以捕捉残余变异。
- **评估方法**：采用**需求级单元测试**（JUnit + Mockito），每个需求映射到一个或多个测试；整个测试套件对每次生成实现执行，通过率作为功能正确性指标。
- **统计方法**：
  - RQ1：通过率、方差、标准差；
  - RQ2：Spearman 秩相关（ρ），双侧检验 α=0.05，Bonferroni 校正（K=15，α*=0.0033），边界值采用精确置换检验；
  - RQ3：卡方独立性检验 + Cramér's V 效应量，Bonferroni 分别对聚合层（6 次比较，α*=0.0083）和应用层（24 次比较，α*≈0.0021）校正。

## 3. 实验设计：数据集、Benchmark 与对比

- **数据集 / 场景**：复用原研究的四个游戏应用（共 74 条功能需求）：
  - **Dice**（25 条需求）：回合制骰子游戏；
  - **Arkanoid**（19 条）：打砖块街机游戏；
  - **Snake**（14 条）：贪吃蛇；
  - **Scopa**（16 条）：意大利传统纸牌游戏。
- **Benchmark 配置**：
  - **RQ1**：非异味基线需求；
  - **RQ2**：5 个递增异味密度等级（Set 1–5），如 Dice 为 0、5、9、13、17 个异味，Arkanoid 为 0、4、7、10、13，Snake 为 0、3、5、7、9，Scopa 为 0、3、6、9、12；
  - **RQ3**：三个类别专属集合，各游戏内语义/句法/词汇异味数量相等（Dice/Arkanoid 各 4 个，Snake 各 2 个，Scopa 各 3 个，受最少类别限制）。
- **对比对象**：
  - 两个 LLM：**GPT-4o**（闭源）与 **DeepSeek-V3**（开放权重）；
  - 对比维度：异味有无、异味密度等级、异味类别、不同应用；
  - 与 Vogelsang et al. 的追溯研究结果进行**探索性对比**。
- **评估指标**：平均通过率（5 次运行均值）、最佳通过率（单次最高）、方差/标准差（稳定性）。

## 6. 主要结论与发现

- **RQ1（无味基线）**：
  - 两个 LLM 在无味需求下均能通过大多数需求级测试，Arkanoid 表现最佳（DeepSeek-V3 五次运行中三次全部 19 条通过，GPT-4o 最高 18 条）；
  - 但**无味需求并不保证完全正确**，Dice、Snake、Scopa 均出现持续失败，尤其是涉及共享函数、顺序依赖和动态游戏状态的场景；
  - DeepSeek-V3 在 4 个应用中的 3 个平均通过率更高。
- **RQ2（异味密度）**：
  - 总体上，**异味密度增加与平均功能正确性下降相关**（如 DeepSeek-V3 在 Dice 和 Snake 上 ρ=-1.00，GPT-4o 在 Snake 上 ρ=-0.97、Scopa 上 ρ=-0.90）；
  - 但幅度、单调性和方向因应用和 LLM 而异；Arkanoid 对异味最不敏感；
  - **所有相关性经 Bonferroni 校正后均不显著**。
- **RQ3（异味类别）**：
  - 不同类别影响因应用和 LLM 而异，**没有任何类别持续产生更大降幅**；
  - 例如 Snake 上 GPT-4o 对语义异味最敏感，DeepSeek-V3 对词汇异味最敏感；Scopa 上 GPT-4o 对句法异味降幅最大；
  - 聚合层和应用层卡方检验经校正后**均不显著**（最小未校正 p=0.0098，V=0.577，为 Snake 上 DeepSeek-V3 的词汇异味）。
- **与追溯研究对比**：
  - 追溯研究中异味效应较小且不显著；本研究表明代码生成任务**描述性上更敏感**，但同样未达统计显著，故对比仅为探索性。
- **总体结论**：需求异味的影响可能源于**需求质量、任务特性与 LLM 行为之间的交互**，而非单一异味类别；高质量需求是必要非充分条件。
