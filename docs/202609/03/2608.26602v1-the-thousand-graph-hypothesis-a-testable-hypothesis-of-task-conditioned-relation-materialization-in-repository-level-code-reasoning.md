## 摘要
大型软件仓库往往超出模型上下文限制。将仓库知识训练进模型成本高昂且很快过时，而本地检索可能遗漏分散的需求，显式关系图则带来持续的维护负担。我们提出一种仅实体的外部接口，在推理期间进行任务条件化关系物化。两层索引将全局路由与局部实体聚焦分离，并在DeepSeek-V4-Flash和SWE-bench Verified上进行了评估。在零预构建实体-关系边的条件下，基础、单层和两层条件的成功率分别为92.1%、94.2%和95.6%。

## Abstract
Large software repositories are often beyond model context limits. Training repository knowledge into models is costly and quickly stale, while local retrieval can miss scattered requirements, and explicit relation graphs add ongoing maintenance burden. We propose an entity-only external interface with task-conditioned relation materialization during inference. A two-layer index separates global routing from local entity focus and is evaluated on DeepSeek-V4-Flash and SWE-bench Verified. The base, one-layer, and two-layer conditions achieve 92.1%, 94.2%, and 95.6% success, respectively, under zero pre-built entity-relation edges.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景问题**：大型软件仓库的规模远超语言模型单次上下文窗口的处理能力，而仓库又是持续演化的（提交、重构、迁移不断改变状态）。仓库级代码推理由此面临“最新知识如何进入推理”的难题。
- **三条现有技术路线的不足**：
  - **训练注入**：将仓库知识训练进模型参数，代价高昂且快速过时，难以持续更新；
  - **按需检索**：灵活但受步数限制，容易遗漏跨文件的、分布零散的关键实体；
  - **显式外部代码图**：精确可查询，但仓库变更带来关系抽取、图同步与一致性维护的长期生命周期成本。
- **核心研究问题**：如何在不重复全量训练、也不维护长期外部关系图的前提下，让模型在推理阶段对跨文件的实体进行任务特定的组织？
- **论文提出的立场**：外部系统可能**只需要持久化实体，不需要持久化实体间关系边**；当相关实体进入上下文后，自注意力机制可以在推理时**短暂地（transiently）物化任务特定关系**——这就是贯穿全文的核心命题。
- **深层含义**：这是一个“机制假说”而非具体工程模块。它试图重新划分外部存储与模型内部计算的边界：外部只负责“把正确的实体送进上下文”，模型内在的注意力机制自动完成“实体间关系构建”，避免了显式关系图全生命周期的维护负担。

## 2. 论文提出的方法论

### 2.1 核心思想

- **“千图假说”（The Thousand-Graph Hypothesis）**：同一个仓库针对不同任务 q₁、q₂，会（在模型内部）产生不同的潜在任务图 Gq₁ ≠ Gq₂；同一个实体集合可以因任务上下文不同，被自注意力组织成完全不同的关系结构。
- **“隐式关系物化假说”（Implicit Relation Materialization Hypothesis）**：只要任务相关实体能够全部进入有限的上下文窗口，模型就能自发组织出完成任务所需的连接，无需外部预构建边（E_rel_input = ∅ 成为设计原则）。
- **关键定义**：
  - 实体 $${v_i = (id_i, x_i, m_i)}$$，包含内容/摘要 $$x_i$$ 与元数据 $$m_i$$（类型、路径、签名、责任标签等）；
  - 注意力公式：$$A_q^{(\ell,h)} = \text{softmax}(Q_q^{(\ell,h)} K_q^{(\ell,h)\top} / \sqrt{d})$$；
  - 实体间强度权重由聚合函数 Φ 作用于各层各头的注意力分数得出：$$w_{ij}(q) = \Phi(\{A_q^{(\ell,h)}[a,b]\})$$；
  - 任务图 $$G_q = (V_q, W_q)$$。这些潜在量**不输出、不持久化**，仅是假说层面的可检验构造。

### 2.2 两层仓库实体索引（Two-Layer Repository Entity Interface）

为在有限上下文预算 B 内放下实体集合，论文提出分离关注点的两层索引机制：

| 层级 | 功能 | 操作 |
|------|------|------|
| 第一层：全局索引 | 从仓库级模块与责任标签中快速定位“候选领域” | $$D_q = \text{Locate}(q, I^{(1)}(R))$$ |
| 第二层：实体索引 | 在候选领域内精筛局部任务所需实体 | $$V_q = \text{Select}(q, D_q, I^{(2)}(R)) \subseteq V(R)$$ |
| 最终组装 | 将这些实体序列化为任务输入 | $$C_q = \text{Serialize}(q, V_q)$$ |
- **工作流程**：持久化实体抽取 → 全局路由 → 局部实体选择 → 提示组装 → 推理生成 → 补丁测试验证 → 仅回写更新实体与索引（不涉及任何边更新）。

### 2.3 可证伪预测

1. **任务敏感性**：相关实体及其交互随任务不同而不同；
2. **零边可行性**：无预构建边的条件下，仓库级修复仍然可行；
3. **覆盖效应**：缺少实体覆盖会损害成功率，更高覆盖则提升成功率。
- 实验直接检验第 2 点，并通过层级消融间接检验第 3 点。

## 6. 论文的主要结论与发现

1. **两层索引优于一层索引和基线**：在零预建边条件下，基线 / 一层 / 两层的成功率分别为 **92.1% / 94.2% / 95.6%**；两层比基线绝对提升 3.5 个百分点，比一层提升 1.4 个百分点。对应错误率从 7.9% 降至 4.4%（相对降低约 44%），从一层 5.8% 降至 4.4%。
2. **零预建边可行性得到支持**：整个系统无需任何预构建实体关系边即可完成仓库级修复，且提升覆盖率（两层索引相对一层）能进一步提升成功率——与前文“覆盖效应”预测一致。
3. **与假说的关系**：结果“与假说相容”（compatible），但不能直接证实模型内部确实发生了“潜在图物化”——内部机制仍是一个黑箱。

## 7. 优点

- **问题定位精准且有新意**：将仓库级代码推理重新定义为“长尾、演化状态”问题，指出关系边维护是独立于检索硬问题的第二重负担，提出了“谁该负责边构建”的尖锐反问。
- **假说驱动、可证伪的框架**：明确提出三条可检验预测（任务敏感性、零边可行性、覆盖效应），把讨论从“工程效果”提升到“机制命题”层面，研究范式具有示范意义。
- **架构设计简约**：两层索引将“全局路由”与“局部实体聚焦”分离，只维护实体与索引，概念上干净，工程落地成本低。
- **诚实的边界声明**：区分了“接受/拒绝假说”的强验证与“与假说相容”的弱证据，明确承认未直接验证模型内部潜在图；区分作者报告的大规模部署与当前可审计子集，方法论态度严谨。
- **统一视角的解释力**：将输入差异与任务差异在公式上剥离（设想 Vq1=Vq2=Vq3 只改变任务内容），为设计“同实体集合、不同任务”的受控心理物理实验提供了清晰的公式化基础。

## 8. 不足与局限

- **缺乏内部机制的直接证据**：“潜在图”是用注意力分数定义的构念，但论文从未从模型内部提取这些图来验证 Gq₁ ≠ Gq₂ 是否在事实上成立，核心假说仍属间接推断。
- **实验覆盖过于狭窄**：
  - 仅一个基准（SWE-bench Verified）、仅一个模型（DeepSeek-V4-Flash）；
  - 未与显式图系统进行同基准、同模型的公平对比，无法量化“省略关系图”相对“保留关系图”的真实代价与收益；
  - 缺少对失败模式的深入分析（两层索引未能修复的 4.4% 案例中，问题是实体遗漏，还是实体覆盖到位但关系组织失败？）。

- **长期部署证据的审计缺口**：作者报告的“200+ 仓库、半年以上”规模远大于透明公开的可审计子集（6 个仓库），中间的巨大落差削弱了大规模部署结论的外部可信度。
- **资源与成本数据缺失**：没有索引构建时间、更新能耗、存储开销等关键数据，无法评估相对显式图方案的实际成本节省量（论文只是以引用的方式提到他人系统的全量与增量 token 消耗作为参照）。
- **跨模型通用性未知**：对上下文窗口较短或注意力模式不同的模型，上述方法是否依然成立尚未验证；论文也未讨论需要多大上下文窗口才能支撑“实体全数入窗”的前提假设。
