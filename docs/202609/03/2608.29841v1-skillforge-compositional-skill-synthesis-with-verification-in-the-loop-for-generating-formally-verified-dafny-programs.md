## 摘要
从自然语言生成经过形式验证的程序仍具挑战性：现有方法要么在验证失败时无法补救地单次生成代码，要么依赖非确定且不透明的开放式智能体推理。我们提出SkillForge框架，将形式化代码合成分解为一系列原子、可复用的技能库，每个技能针对特定子任务，如规范推断、主体合成、不变量生成、错误诊断或定向修复，并由提示模板、工具绑定和可判定的成功标准定义。一个由验证驱动的编排器协调这些技能：它将候选程序提交给Dafny验证器，将失败诊断归类为结构化类别，确定性地路由到相应修复技能，并迭代直到形式正确性得到证明或预算耗尽。在一个从自然语言到Dafny规范配对的精选基准上，SkillForge显著优于最先进的智能体方法（包括ReAct式智能体、基于MCTS的修复和RL引导的验证）以及传统迭代基线，同时所需令牌更少、延迟更低。消融研究证实，每项技能都有可度量的贡献，且该编排器能快速收敛，大多数程序在首次尝试时即通过验证。

## Abstract
Generating formally verified programs from natural language remains challenging: existing approaches either produce code in a single pass without recourse when verification fails, or rely on open-ended agentic reasoning that is non-deterministic and opaque. We introduce SKILLFORGE, a framework that decomposes formal code synthesis into a library of atomic, reusable skills, each targeting a specific subtask such as specification inference, body synthesis, invariant generation, error diagnosis, or targeted repair, and defined by a prompt template, tool binding, and decidable success criterion. A verification-driven harness orchestrates these skills: it submits candidates to the Dafny verifier, diagnoses failures into structured categories, deterministically routes to the appropriate repair skill, and iterates until formal correctness is proved or a budget is exhausted. On a curated benchmark of natural language to Dafny specification pairs, SKILLFORGE substantially outperforms both state-of-the-art agentic approaches (including ReAct-style agents, MCTS-based repair, and RL-guided verification) and traditional iterative baselines, while requiring fewer tokens and lower latency. Ablation studies confirm that every skill contributes measurably, and the harness converges rapidly with the majority of programs verified on the first attempt.

### 1. 核心问题与研究动机

- **问题定位**：从自然语言（NL）指令直接生成可通过 **Dafny 形式化验证**的程序，是当前 LLM 代码生成任务中的重要挑战。形式化验证要求程序不仅语法正确、算法正确，还必须携带充分的规范（前置/后置条件）、循环不变量与终止度量，以供 SMT 求解器自动证明。
- **现有方法的核心缺陷**：
  - **One-shot/Naive 生成**：一次性推理生成代码，验证失败后缺乏系统性诊断与修复机制。
  - **Naive iterative repair**：反复将错误信息原样回馈给模型，不加结构化分类，导致“规范缺失、不变量缺失、逻辑错误”混为一谈，修复过程振荡、浪费预算。
  - **Agent-based 方法**（ReAct、CodeAct、SWE-Agent 等）：将下一步行动的选择交给模型自由推理，非确定、不透明、计算开销不可控，在“错误空间有限且可分类”的验证场景中并非最优。
  - **Tree-search / RL 方法**（MCTS、CEGIS 等）：同时探索大量候选修复路径，容易产生组合爆炸，且缺乏针对验证错误的结构化利用。
- **核心主张**：在拥有“完美 oracle”（Dafny 验证器提供结构化、可分类的错误输出）的领域，**结构化的技能分解 + 确定性路由** 要优于开放式的智能体推理。本文据此提出 **SkillForge**，将验证失败从“下一步该做什么”的开放式问题转换为“封闭、可审计的路由决策”。

### 2. 方法论

#### 2.1 核心思想：技能库 + 验证驱动编排器

将“自然语言 → 已验证 Dafny 程序”任务分解为六个**原子技能**的序列编排，每个技能是一个三元组 s = (P, T, C)，即提示模板、工具绑定与**可判定成功标准**。**关键洞察**在于：Dafny 验证器输出的结构化错误可以被解析并映射到特定技能，从而将开放式推理替换为零推理开销的确定性路由。

#### 2.2 技能库（六种原子技能）

| 技能 | 功能 | 输入→输出 | 成功标准 |
|---|---|---|---|
| **InferSpec** | 从自然语言提取规范 | NL → (类型、前置/后置条件等) | Dafny 类型检查通过 |
| **SynthBody** | 基于规范生成可执行函数体（严格禁止改动规范） | NL + 规范骨架 → 函数体 | 程序编译通过 |
| **GenInvariant** | 生成满足初始化、保持性、充分性的循环不变量 | 程序 + 验证错误 → 含不变量的完整程序 | 验证通过 |
| **DiagnoseError** | 对验证失败分类（type_error / body_error / spec_gap / invariant_missing），正则匹配优先、LLM 兜底 | 程序 + 错误 →(类别, 行号, 建议) | 输出有效的类别与位置 |
| **RepairCode** | 对故障点做**最小编辑**修复，保持整体算法不变 | 程序 + 诊断 → 修复后程序 | 编译通过且与输入有差异 |
| **StrengthenSpec** | 从 NL 推断隐式约束，加强前置/后置条件而不改函数体 | 程序 + 诊断 + NL → 加强后的规范 | 验证通过 |

#### 2.3 验证驱动编排器（Verification-Driven Harness）

**核心流程（Algorithm 1）**：

```
spec ← InferSpec(x)
d ← SynthBody(x, spec)
for i = 1 to N:
    (ok, errors) ← DafnyVerify(d)
    if ok: return d
    记录最佳程序 dbest（按错误数最少）
    diag ← DiagnoseError(d, errors)
    skill ← Route(diag.category)
    d' ← skill(d, diag)
    if 无改进: d ← SynthBody(x, spec) with temperature=0.3  # 停滞重试
    else: d ← d'
return ∅
```

**确定性路由规则**：

- `invariant_missing` → **GenInvariant**
- `spec_gap` → **StrengthenSpec**
- `body_error` → **RepairCode**
- `type_error` → **SynthBody**

**四个关键机制**：

1. **初始合成**：InferSpec + SynthBody 组合生成首个候选，若一次通过则直接返回（无需修复）。
2. **错误条件路由**：验证失败→DiagnoseError 分类→确定性映射到唯一修复技能，路由决策不需要模型自由推理。
3. **迭代合成**：维护状态 (d, errors, diag, history)，支持进度跟踪与回滚。
4. **终止与可靠性保证**：硬迭代预算 Nmax、停滞检测（dᵢ = dᵢ₋₁）、单调性检查（错误数连续两轮增加则回滚到 dbest）。**形式可靠性无条件成立**：编排器返回的程序必已通过验证，不会返回未经验证的结果。

### 3. 实验设计

#### 3.1 基准数据集

- 自建基准，共 **178 对 NL–Dafny 样本**，按难度分层：
  - **Simple**（62 个）：单子句谓词、无循环的纯函数；
  - **Medium**（71 个）：非平凡前置条件、多子句后置条件或递归定义；
  - **Hard**（45 个）：需要循环不变量与终止度量的 while 循环方法，或需要辅助证明的引理。
- 样本来源：Dafny 标准库（42）、DafnyBench（86）、GitHub 上的开源验证项目（50）。

#### 3.2 对比方法

- **传统基线**：One-shot、Structured one-shot、Naive repair (N=5)、CoT + Repair (N=5)。
- **Agentic 基线**（核心对比，同以 GPT-5.5 为后端、N=5 预算）：ReAct-Verify、CodeAct-Dafny、MCTS-Repair（50 rollouts）、Laurel（50 nodes）、Clover（N=5）、Proof2Silicon（N=5，RL 引导验证修复）。

#### 3.3 指标

**Verification Rate (VR，最终通过率)、Equivalence Rate (ER，语义等价率)、Average Iterations (AI，平均迭代轮数)、First-Pass Rate (FPR，首次通过率)**。

#### 3.4 实验结果摘要

- **主结果**：SkillForge 达到 **VR 91.6%**，超过最强基线 Proof2Silicon（85.4%）6.2 个百分点，超过传统最强基线 CoT+Repair（77.5%）14.1 个百分点；ER 86.5% 同样领先；**平均迭代 1.8 轮，为所有迭代方法中最低**；FPR 71.3% 最高。
- **分难度结果**：优势随难度增长而扩大——Simple 98.4% vs. 96.8%（余量小）；Medium 93.0% vs. 84.5%（+8.5pp）；Hard 77.8% vs. 66.7%（**+11.1pp**）。Hard 任务优势主要来自 GenInvariant 技能。
- **成本指标**：平均 4.6K tokens、2.8 次验证调用、14.2s 延迟；相比 ReAct-Verify 节省 48% tokens，相比 MCTS-Repair 节省 68% tokens。

### 6. 主要结论与发现

1. **结构化技能分解 + 验证驱动编排**显著优于智能体方法与树搜索/RL 方法：VR +6.2pp（相比最强基线），同时 token 消耗与延迟大幅降低。

3. **首次通过率（71.3%）最高**，说明“先精确推断规范、再锚定该规范生成函数体”的分解方式优于端到端生成。
4. **优势随任务难度增大而扩大**：Hard 子集比最强基线高 11.1pp，瓶颈集中于循环不变量生成。
5. **迭代回路是最大增益来源**（+20.3pp），验证在环是各类迭代方法性能提升的主要驱动力。
6. **VR–ER 差距（5.1pp）**表明存在“验证通过但语义偏离参考实现”的情况，语义对齐与验证成功是两条相对独立的挑战。

### 7. 方法优点

- **范式创新**：提出“技能库 + 验证在环”替代“开放式智能体”的合成范式，将有界验证错误空间转化为确定性路由问题，消除了智能体方法中非必要的推理开销。
- **可判定成功标准**：每个技能均有明确、机械可检查的成功判据，使技能可独立测试、组合，并支撑严格终止与可靠性保证。
- **形式可靠性保证**：无论内部技能质量如何，编排器从不返回未验证的程序，可靠性保证是无条件的。
- **高效透明**：确定性路由和局部最小编辑，使整个修复过程可审计、可复现，且 token 与延迟显著低于所有迭代方法。
- **良好的成本-性能平衡**：比树搜索和 RL 方法大幅节省验证器调用次数，且对模型能力的依赖较低（Claude Sonnet-4.5 + SkillForge 即可匹配 GPT-5.5 + Proof2Silicon 的水平）。
- **消融严谨完整**：逐技能消融、错误类别归因、收敛性分析俱全，结论的证据链扎实。

### 8. 不足与局限

- **基准规模有限**：178 个样本虽与既有基准相当，但覆盖范围仍较窄，难以充分代表真实世界验证任务的多样性。
- **领域绑定**：技能库与错误分类体系（spec_gap、invariant_missing 等）为 Dafny 专用，迁移到 Lean 4、Coq 等语言需重新设计全部技能与路由表，框架通用性仅停留在原则层面。
- **模型结论的可靠性存疑**：文中使用的“GPT-5.5”“Claude Opus-4.7”在当前公开模型列表与常见版本命名规范中基本不可见，实验结论的可复现性与可信度有待证实。若模型不可公开获取，则整个数值对比缺乏独立验证基础。
- **GenInvariant 是明显短板**：成功率仅 64.7%，复杂量词与归纳不变量的合成仍是主要失败模式。
- **VR–ER 差距（5.1pp）未完全弥合**：部分验证通过的程序与参考实现语义不一致，现有方法对语义对齐的约束相对较弱。
- **诊断错误可能存在级联放大**：DiagnoseError 一旦误分类（11.8% 失败率），后续路由将执行错误修复并浪费迭代预算，论文对此仅做少量案例分析，缺少系统性的鲁棒性评估。
- **手工设计的技能模板与提示词**：模板工程量大且未经自动优化，实际应用时需要为每个新语言或新任务重新设计提示，扩展性与维护成本较高。
- **开放式探索仍有价值**：论文坦承对某些复杂归纳证明等问题，开放式的 ReAct 式推理偶尔能解决而 SkillForge 结构化流程却失败，说明“结构压倒灵活性”的边界有待进一步刻画。
