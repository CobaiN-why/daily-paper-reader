## 摘要
大型语言模型（LLM）生成的源代码中经常包含漏洞，然而少有工作研究其内部机制如何区分安全生成与易受攻击的生成。在本工作中，我们系统地对LLM进行机制解读，旨在理解代码安全性-漏洞性如何由LM中的组件表示或驱动，并将这些见解转化为可操作的引导策略，以鼓励更安全的代码生成。为此，我们引入了CodeSec-Pairs数据集，该数据集包含从Llama-3.1-8B-Instruct中采样的9,342对Python安全与易受攻击的对比代码对。利用该数据集，我们探索了定位与代码安全性相关的层和注意力头的方法，并进一步尝试了不同的推理时引导策略以减少漏洞。特别地，我们提出了DuoSteer，一种双重引导方法，同时将安全性和代码正确性引导应用于注意力头。在五种漏洞类型的实验中，DuoSteer平均使漏洞率降低26.9%，功能正确性提高7.5%，不仅优于其他引导变体，也优于提示和监督微调基线。该优势同样在Qwen-2.5-Coder-7B-Instruct上得到复制，使用了从该模型采样的另外2,500个对比对。

## Abstract
Large language models (LLMs) frequently generate source code containing vulnerabilities, yet little work studies the internal mechanisms that distinguish safe from vulnerable generation in them. In this work, we systematically perform a mechanistic interpretation of LLMs, aiming at both understanding how code safety-vs-vulnerability is represented or driven by components in an LM and turning the insights into actionable steering strategies to encourage safer code generation. To this end, we introduce CodeSec-Pairs, a dataset of 9,342 Python safe-and-vulnerable contrastive code pairs, sampled from Llama-3.1-8B-Instruct. Utilizing the dataset, we explore approaches to localize layers and attention heads that relate to code safety, and further experiment with different steering strategies for inference-time vulnerability reduction. In particular, we propose DuoSteer, a double-steering approach that simultaneously applies safety and code-correctness steering to attention heads. In experiments over five vulnerability types, DuoSteer leads to an average of -26.9% vulnerability rate reduction and +7.5% functional correctness improvement, which outperforms not only other steering variants but also prompting and supervised fine-tuning baselines. The advantage also replicates on Qwen-2.5-Coder-7B-Instruct with another 2,500 contrastive pairs sampled from that model.

### 2. 提出的方法论

#### 2.1 数据集构建：CodeSec-Pairs
- **数据来源**：从 Emergent Misalignment、SecurityEval、CodeLMSec、CyberSecEval-Instruct 等基准中选取编码任务；从 Llama-3.1-8B-Instruct 中以 t=1.0、top-p=0.95 采样生成（每任务 N=10 次）。
- **配对方式**两类：
  - **intra-prompt pairs**（共4,260对）：在**同一良性提示**下采到安全代码与漏洞代码，配对后用于训练探针与构建引导向量，隔离了提示风格混杂因素；
  - **cross-prompt pairs**（共5,082对）：将良性提示下的安全样本与"漏洞诱导提示"（如附加"跳过输入验证"指令）下的漏洞样本配对，仅用于因果敲除实验，以扩充低漏洞率CWE的样本量。
- **标签体系**：使用 CodeQL 做漏洞检测标注；使用 GPT-4.1 按两个维度为每对样本自动标注结构距离（Minimal/Refactor/Divergent）与修复机制（Substitution/Guard-Addition/Deletion/Unclear），并经人工验证（Cohen's κ=0.73~0.81）。
- **覆盖范围**：5个CWE（CWE-022/079/094/295/502），共9,342对（Llama版）；在 Qwen-2.5-Coder-7B-Instruct 上额外收集2,500对用于泛化验证。

#### 2.2 机制定位（Localization）
- **线性探针（Linear probing）**：对每层残差流或每个注意力头的均池化输出训练逻辑回归二分类探针（safe vs vulnerable），衡量安全/漏洞差异在何处**线性可解码**。
- **因果头敲除（Causal head knockout）**：在教师强制（teacher forcing）下将每个头（限于 probe 排名前256的头）的输出置零，计算安全/漏洞边际似然差的因果效应：
  - δ = log-likelihood(safe) − log-likelihood(vulnerable)，在敲除后与基线相比的变化 Δ 即为该头的因果贡献；
  - Δ<0 表示该头是"安全促进"头，敲除后模型减少对安全续写的偏好。
- **关键发现**：线性探针定位与因果定位结果**高度分歧**（Spearman |ρ|=0.072，p>0.25）；每CWE最重要的因果头在探针排名中仅列第64~249位——探针只能定位"编码处"，无法定位"驱动处"。

#### 2.3 引导策略（Steering）
- **引导向量**：以均值差（MD）向量 v = x̄_safe − x̄_vulnerable 为对比方向（探针权重方向 PD 被证明在所有CWE上劣于 MD）；采用 σ-归一化确保跨尺度可比：x ← x + α·(v/σ)。
- **三种单引导变体**：
  - **Layer MD**：在最优探针层对整个残差流注入方向；
  - **Probe MD**：按探针准确率排名选 top-k 头注入；
  - **Causal MD**：按因果效应排名选 top-k 头注入。
- **DuoSteer（核心创新）**：双引导方法，在**安全因果头集合**注入安全方向、在**正确性因果头集合**注入正确性方向，二者按各自系数叠加：
  - z = z + α_s·(v_safe/σ_s)·1[(ℓ,j)∈H_s] + α_c·(v_correct/σ_c)·1[(ℓ,j)∈H_c]
  - 正确性方向收集自"安全且正确 vs 安全但不正确"的对比对，从而在隔离正确性信号的同时不引入安全性混杂；
  - 由于安全-因果与正确性-因果头集合高度不重合（重叠头很少；两方向余弦≈−0.16，近似正交），单独联合对比（safe∧correct vs vulnerable∧incorrect）的单一向量在中等强度下会在3/5个CWE上崩溃。

### 6. 主要结论与发现

1. **探针信号与因果驱动分量高度脱节**：线性探针描述"信息在哪里可读"，因果敲除揭示"哪里在驱动行为"，二者在注意力头级别几乎不相关（|ρ|≤0.072），按探针排名选取干预目标会错失真正驱动漏洞生成的头。
2. **因果定位比探针定位更能有效降低漏洞率**：对相同MD向量，注入因果排名头（Causal MD）在CWE-079、CWE-502等上显著优于注入探针排名头（Probe MD），V降幅差距可达14.6个百分点。
3. **单向量安全引导存在安全-正确性权衡**：大幅V下降常伴随C明显下降（如CWE-022上C下跌18.6%、CWE-094下跌15.7%）；安全方向在安全因果头附近也扰动了与正确性相关的分量。
4. **DuoSteer是化解权衡的关键**：将正确性方向部署于独立的正确性因果头上，以正确性作为一种"正则器"（correctness-as-regularizer）恢复功能正确性。在5个CWE上联合得分 C(1−V) 全面超越所有单引导变体——尤其CWE-502上由20.8升至94.1（V=0%、C=94.1%）、CWE-079上由40.7升至79.1。
5. **DuoSteer的增益可以跨模型泛化**：在Qwen-2.5-Coder-7B-Instruct上，在全部5个CWE上联合得分均为正增益，且CWE-079增益最大（+20.1）。
6. **DuoSteer优于提示基线，且SFT易脆弱**：Hint Prompting虽可降V但普遍严重牺牲C（4/5个CWE上C跌破基线）；SFT在CWE-079/295上反而抬高V；DuoSteer在V与C两个维度上均更为稳健。
7. **提示与引导作用空间近正交**：成功翻案（vulnerable→safe）的提示词引起的激活位移与学习到的安全引导向量夹角近乎90°（|cos|<0.02），二者作用方向互补，叠加可在边界CWE（CWE-022/094）上获得额外增益。
8. **可引导性差异可事后解释**：安全/正确性两方向在因果头上的余弦几何（反/对齐）以及训练对比对的修复模式集中度（Refactor占比、Substitution/Guard-Addition主导程度）共同预测各CWE上DuoSteer相对单引导的提升大小。

### 7. 方法或实验设计的亮点

- **"编码 vs 驱动"严格二分的方法论自觉**：同时使用线性探针与因果敲除并系统报告二者在头级别的脱节，避免了许多机制解释工作"以相关替因果"的方法陷阱。
- **因果定位与干预目标的闭环**：不只是"看见了"内部机制，而是将定位结果直接转为干预配置，使解释具备可验证的行为效力。
- **双方向解耦（DuoSteer）的设计精妙**：安全方向（safe vs vulnerable）与正确性方向（safe∧correct vs safe∧incorrect）采用严格正交化对比，从构造上隔离混杂；引入"正确性作为正则器"的思路，有效缓解了单方向引导的副作用。
- **实验严谨性**：
  - 以 CodeQL 静态分析 + 人工校准的 GPT-4.1 judge（κ≈0.87）+ 执行级单元测试三路交叉验证，大幅降低指标偏差风险；
  - 配以显著性检验、Wilson置信区间、采样解码鲁棒性、held-out配置选择协议等，增强了结论可信度；
  - 跨模型（Llama/Qwen）与多CWE覆盖提升了结论的普适性。
- **数据配套贡献**：CodeSec-Pairs 数据集含结构距离与修复机制的细粒度标注，可作为后续安全代码生成研究的公共资产。

### 8. 不足与局限

- **模型规模与可访问性受限**：仅验证了7B/8B开源模型；更大规模（70B/405B）及闭源API模型因需要白盒逐头激活访问，无法适用或尚未验证。
- **覆盖范围有限**：仅Python语言、仅5个CWE（022/079/094/295/502），且评估任务多为孤立函数存根（如SecCodePLT），未覆盖真实生产代码中常见的仓库级上下文、检索增强、多轮编辑等复杂场景；扩展需重新采集数据并重新做因果头定位。
- **因果定位不等于完整机制解释**：单头独立敲除无法揭示头间交互；零值替换也非最自然的反事实干预；未完成路径修补/完整电路追踪，严格来说仍属"局部因果归因"而非全电路机制解释。
- **正确性度量的残余风险**：GPT-4.1判断对CWE-022/295是唯一正确性工具（这两个CWE不提供单元测试）；已有的执行测试覆盖也偏窄（少量固定用例），存在漏判风险。
- **调节参数与配置选择成本**：各方法效果高度依赖对k（头数）、α（强度）的扫描；测试集上扫描的配置刻画的是容量上限，部署时需依赖held-out选择协议，跨分布表现仍有不确定空间。
- **边界CWE方法失效**：CWE-022中安全方向本身因果牵引力弱，所有引导变体都无法在不损失C的情况下降低V——DuoSteer并非普适解，其可靠性受限于目标CWE的"可引导性"。
- **潜在双刃剑风险（作者已在伦理声明中明确）**：引导方向是可反号的，反向操作可诱导更不安全的代码；作者建议仅做防御性发布。
