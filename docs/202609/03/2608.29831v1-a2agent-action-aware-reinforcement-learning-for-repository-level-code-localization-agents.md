## 摘要
定位与问题相关的代码区域是自动化软件工程中的关键步骤。然而，由于依赖于稀疏的轨迹级信号，现有方法无法识别哪些每轮动作是有效的，并且经常在探索过程中发现正确的代码区域，但未能将其提交。为解决这些局限性，我们提出了一种动作感知的强化学习方法，该方法结合了每轮奖励序列（奖励黄金代码区域的发现和提交）与动作级优势估计方案（通过将共享相同探索上下文的轮次分组来隔离每个动作的贡献）。大量评估表明，我们的方法在SWE-Bench Verified上比最新技术（SOTA）的平均F1提高了1.58%，在SWE-Bench Pro上提高了8.55%，我们的4B模型优于比它大8倍的基线。我们的代码可在 https://github.com/donian00/A2Agent 获取。

## Abstract
Localizing issue-relevant code regions is a critical step in automated software engineering. However, due to their reliance on sparse trajectory-level signals, existing methods cannot identify which per-turn actions are effective and often discover correct code regions during exploration but fail to commit them. To address these limitations, we propose an action-aware reinforcement learning method that combines a per-turn reward sequence rewarding both the discovery and commitment of gold code regions with an action-level advantage estimation scheme that isolates each action's credit by grouping turns sharing the same exploration context. Extensive evaluations show that our method improves the average F1 over the state-of-the-art (SOTA) by 1.58% on SWE-Bench Verified and 8.55% on SWE-Bench Pro, with our 4B model outperforming baselines up to 8x larger. Our code is available at https://github.com/donian00/A2Agent.

- **现有缺陷**：论文指出已有方法存在两大系统性问题：

- **一句话概括**：作者提出动作感知的强化学习方法，在每轮动作级别分解信用，同时激励对正确区域的“发现”与“提交”，以解决现有方法在细粒度信用分配上的结构性缺陷。

## 2. 论文提出的方法论

**核心思想：** 将仓库级代码定位视为有限步长的多轮决策过程，在已有分组相对策略优化（GRPO 类轨迹级优势估计）基础上，引入每轮奖励与动作级优势估计，使策略优化从“轨迹级”细化到“动作/回合级”。

### 2.1 奖励序列设计（Reward Design）

每个回合既有逐轮奖励，也有终止奖励，形成折扣回报，用于动作级优势计算：

- **终止奖励 r_T**：位于最终回合 T，包含两部分：
  - F1 奖励：r_F1 = F1文件 + F1模块 + F1函数，衡量预测与 gold 的多粒度重合度。
  - 发现-提交奖励 r_DC：衡量已探索到的 gold 位置中，有多大比例被提交至最终预测（对文件/模块/函数三种粒度取平均；若某粒度未探索到任何 gold 元素则该粒度不计入分母）。
- **逐轮奖励 r_t**：当某轮 action 返回的 observation 中新出现 gold 文件/模块/函数时，给予 δ_f + δ_m + δ_u 的即时奖励（各分量是该粒度下本轮新发现的 gold 数量占比）。这使得部分成功轨迹（探索到 gold 但未提交）仍能保留学习信号，并缓解折扣回报对早期动作的“信用低估”。
- 于是，从回合 t 开始的折扣回报为 G_t = Σ_{k=t}^{T} γ^{k-t} * r_k。

### 2.2 动作级优势估计（Action-Level Advantage Estimation）

- **状态代理与上下文分组**：代码库在整个轨迹中固定，不存在博弈/网页环境中原生状态相等概念。作者用当前回合的前 K 个动作序列 ϕ_K(t) = ⟨a_{t−K},…,a_{t−1}⟩ 作为“探索历史上下文”的状态代理，将同一 issue 的多条 rollout 中具有相同 ϕ_K(t) 的回合归入同一分组 G_t^{(K)}。当前动作不作为分组键值（保证组内动作可比较性）。由于所有工具均为确定性只读函数（对固定仓库、同参数返回同一 observation），组内探索上下文真实一致。

## 6. 论文的主要结论与发现

- **动作级监督胜于轨迹级信号**：A2Agent（Qwen3-4B）在 SWE-Bench Verified 的平均 F1 上超过 CodeScout-14B 1.58 个百分点；在 SWE-Bench Pro 上对全部开源基线全面大幅领先（相对最高高出约 8.55 个百分点），而且 4B/8B 模型性能超过比其大 8 倍的 Qwen2.5/3-32B 级基线。
- **逐轮奖励+上下文匹配分组是关键**：消融表明，消去逐轮奖励（退化到 GRPO）性能降幅最大；History Grouping 与 r_DC 各自独立贡献且互补，分别在“探索质量”与“提交一致性”两条轴上提升效果；二者的增益在函数级粒度上仍不衰减。r_DC 尤其将 Discovery-Commit gap 从各基线 40%+ 的失败占比显著压低。
- **探索行为已从“盲目广搜”变为“定向检索”**：在推理时间、平均输出 token 与轨迹模式层面（案例研究展示 SFT 无法到达 gold 文件而 RL 精确到达）均观察到这一转变。
- **定位增益准确传导至下游修复**：在保持修复后端一致的实验中，A2Agent 的最终 resolve rate 为 38.07%，显著高于其他基线约 7～11 个百分点，离 Oracle（45.93%）更近。
- **方法高度实用**：不需要外部 API 或 Docker 环境，支持全本地部署，适用于对代码隐私敏感的工程环境。H=2 是最佳历史深度，兼顾分组精确度与覆盖率的分界点。

## 7. 优点

- **问题定位精准**：识别出“动作级信用缺失”与“发现但未提交”两大真实痛点，用数据量化了 Discovery-Commit gap 的普遍性（占各基线失败 40%+），问题指向非常有说服力。
- **方法轻量优雅**：无需价值网络、无需重新执行环境、无需外部重采样（与 VinePPO/REEX 类方法相比在代码环境中不具备足够的锚点可比性），仅利用既有的静态索引与 rollout 组合就实现了动作级信用分解，具备很强的落地可行性。
- **奖励设计细致**：termination reward 同时包含最终准确率与“提交所探索到的 gold 的比率”，从行为层面直接惩罚浪费探索成果的失败模式；turn-level 奖励让部分成功不再零梯度。
- **消融与边际条件分析完整**：对每个组件做了独立变量拆解，并讨论了组大小不足如何处理（置零）、多层深度如何加权，消除了读者对“组大小有限、噪声大”的疑虑。
- **训练效率与推理效率透明化**：不是只报分数，同时提供了 token 消耗、推理时间、GDPR 型隐私场景下部署等实际考量。
- **实验生态链闭环**：从定位指标延伸到端到端 issue 解决率，说服力较强。

- **计算资源与模型覆盖有限**（作者自述）：只在 4B/8B 小模型上做实验，未在 14B/32B 以上或 MoE 模型上验证方法与规模扩展性；表 1/2 中的基线结果来自不同文献、不同训练/评估日期，虽然整体可靠，但也存在 benchmark 版本与库范围不一致等横向误差。
- **消融实验的局限**：2×2 消融与 H 敏感度实验只在单一数据集（SWE-Bench Verified）与单一骨干（Qwen3-8B）下完成，未提供 SWE-Bench Pro 上的消融、未跨多模型验证拆解结论的稳健性。
- **适用框架局限**：动作级分组依赖如下前提——仓库静态索引不变、同工具同名参数返回确定性结果、按 issue 够分组；在动态修改文件（patch 编写）、跨库引入外部依赖或非确定性工具（如 shell 命令执行有副作用）的一般性 agent 场景中并不能直接套用其分组技术。
- **学习信号定义依赖稀疏真值粒度的可用性**：文件/模块/函数级偏好是否与最终修复成功完全对齐，仍是一种启发式假设，更细的代码行级或 blame 级信号不在范围之内；对“issue 要求改大量文件时探索-提交的比例该如何表示”这类边界也有待处理。
- **Advantage-weighted 目标与标准化问题**：使用非策略迭代 roll-out 无重要性校正，作者承认可能会出现轻微 off-policy 漂移（引用了 AWR/REST 类研究解释了其鲁棒性），但未给出训练曲线或漂移度量的定量证据。
- **“低 token 消耗”主张与“广博探索”的另一面向**：A2Agent 因趋向于更短的观察与前缀而实现了更省时，但这种行为的成本可能是漏调较远但更软的依赖关系；表 6 外缺乏对“有效探索多样性与信息量”的单独详细分析。
