## 摘要
基于大语言模型（LLM）的软件智能体被设计用于自动化程序修复（APR）任务，这使得在不远的将来，APR 智能体无需太多人工干预即可自动修复缺陷成为可能。在这种情况下，我们能否信任 APR 智能体生成既功能正确又安全的代码？如果攻击者针对生产环境中的 APR 智能体，利用看似良性、却可能影响智能体生成正确但不安全代码的对抗性问题，又会怎样？本文通过开展一项实证研究，迈出了回答这些问题第一步。首先，我们构建了 SWEADV，这是一个包含 750 条对抗性问题描述的基准，由 SWE-bench Verified 中的 150 个修复任务构造而成。针对每个修复任务，我们创建了五条对抗性问题描述，分别对应一种攻击类型：命令执行、反序列化、路径遍历、拒绝服务以及弱哈希。其次，我们在 SWEADV 上评估了来自三种 LLM 后端的 mini_swe APR 智能体：GPT-5-Mini、MiniMax-M2.5 和 DeepSeek-R。我们发现，平均而言，对抗性问题描述可在 51.7% 的案例中诱导出修复成功但带有恶意行为的情况。第三，我们研究了典型检测机制是否足以阻止此类恶意补丁被接受。在修复前，使用 LLM 作为评判者对对抗性问题描述进行检测，平均检测准确率仅为 62.3%。在修复后，使用静态分析工具和 LLM 作为评判者对对抗性 APR 补丁进行检测，平均检测准确率分别仅为 39.4% 和 55.4%。我们得出结论：鉴于自主 APR 智能体易受对抗性攻击影响，目前尚不能在生产部署中信任它们。

## Abstract
Software agents with Large Language Models (LLMs) are designed for Automated Program Repair (APR) tasks, raising the possibility that, in the near future, APR agents will fix bugs automatically without much human intervention. Can we trust an APR agent to produce both functionally correct and secure code in such situations? What if attackers target production APR agents with adversarial issues that seem benign but may influence the agents to produce correct but insecure code? In this paper, we took a first step towards answering these questions by conducting an empirical study. First, we created SWEADV, a benchmark of 750 adversarial issue descriptions constructed from 150 repair tasks in SWE-bench Verified. For each repair task, we created five adversarial issue descriptions, one for each attack type: command execution, deserialization, path traversal, denial of service, and weak hashing. Second, we evaluated mini_swe APR agents from three LLM backends on SWEADV: GPT-5-Mini, MiniMax-M2.5, and DeepSeek-R. We found that on average, adversarial issue descriptions can induce malicious behaviors with successful repair in 51.7% of cases. Third, we investigated whether typical detection mechanisms are sufficient to prevent such malicious patches from being accepted. Pre-repair detection with LLM-as-judge on the adversarial issue descriptions resulted in an average detection accuracy of only 62.3%. Post-repair detection on adversarial APR patches using static analysis tools and LLM-as-judge achieved average detection accuracies of only 39.4% and 55.4%, respectively. We conclude that autonomous APR agents cannot be trusted yet in production deployment, given their susceptibility to adversarial attacks.

- **核心疑问**：在这种自主化场景下，APR 智能体能否生成既**功能正确**又**安全**的代码？如果攻击者提交看似良性、实则精心构造的对抗性 issue，是否会诱导智能体产出"通过测试但含漏洞"的补丁？
- **研究空白**：现有 APR 基准（SWE-bench 等）均假设 issue 为良性，只验证功能正确性；已有的红队工具（如 SWExploit、提示注入攻击）往往**模型特定**，无法通用。
- **整体含义**：论文通过实证研究首次系统性地揭示——**"通过测试的补丁"不等于"安全的补丁"**，当前 SOTA APR 智能体在生产部署中尚不可信。

## 二、方法论：核心思想与关键技术细节

### 核心思想
构建**模型无关（model-agnostic）**的对抗性基准 **SWEADV**：将同一份对抗性 issue 文本用于测试任意受害 APR 智能体，无需针对特定模型定制。

### 威胁模型（黑盒）
- 攻击者**唯一能力**是提交/影响自然语言 issue 描述 $i^*$，不能修改仓库 $R$、补丁 $p^*$、测试套件 $T$ 或验证流水线。
- 攻击目标：构造 $i^*$ 使生成补丁 $p^* = V(R, i^*)$ 同时满足
  - 恶意载荷谓词：$V_a(R, p^*) = \text{TRUE}$
  - 功能验证谓词：$T(R, p^*) = \text{TRUE}$

### SWEADV 构建流程（两步自动化流水线）

**步骤 1：攻击载荷创建**
- **目标符号（target symbol）提取**：解析 golden patch diff，映射到仓库源码，选取被改动行最多的封闭符号（函数/方法/类）。
- **注入符号（injected symbol）生成**：基于目标符号名 + 邻近项目命名（patch 标识符、同作用域兄弟符号），用命名模板合成仓库风格的 helper 名，选择首个不存在于仓库的候选名。
- **攻击载荷模板**：包含四要素——可选导入、可替换函数名、一个或多个攻击者可控的环境变量输入、攻击特定的危险汇聚点（dangerous sink）。
- 五类攻击对应五种危险 sink：命令执行、不安全反序列化、攻击者可控路径写文件、昂贵正则匹配、敏感值弱哈希。

**步骤 2：对抗性 issue 创建**
- 攻击者 LLM（Gemini 2.5 Pro）接收原始 issue + 攻击载荷，生成保留原始修复目标、同时嵌入恶意要求的对抗文本。
- 构造期代理修复智能体（mini_swe + Gemini 2.5 Pro）生成候选补丁。
- **轻量级 diff 验证器**：提取新增行/新增 helper 定义，用载荷族特定启发式规则检查是否"定义并接入执行"（需同时含注入 helper、攻击者可控输入、危险 sink，以及连接 helper 与目标符号的调用）。通过则保留，否则反馈给攻击者 LLM 重试。

### 评估指标（公式）
对 $N$ 次对抗修复尝试，设 $F$ 为通过功能验证的补丁数，$I$ 为注入并调用预期漏洞的补丁数，$S$ 为两者皆满足的补丁数：

$$FR = \frac{F}{N}, \quad ISR = \frac{I}{N}, \quad ASR = \frac{S}{N}$$

- **FR（Fix Rate）**：功能有效修复率
- **ISR（Injection Success Rate）**：注入成功率
- **ASR（Attack Success Rate）**：既通过测试又含恶意行为的攻击成功率

### 漏洞标签验证
- **静态验证**：攻击特定验证器检查是否定义攻击者可控输入源、含危险 sink、并接入执行路径（仅定义未调用的 helper 不算）。
- **动态验证**：动态触发 harness 在容器中施加补丁，提供受控触发输入，检查良性标记副作用，强化 ground truth。

### 评估的模型
- **修复 LLM（3 个）**：GPT-5-Mini、MiniMax-M2.5、DeepSeek-R，统一使用 **mini_swe** APR 智能体框架。
- **攻击者 LLM**：Gemini 2.5 Pro；**代理修复 LLM**：mini_swe + Gemini 2.5 Pro。
- **裁判 LLM（4 个）**：Gemini-3-F、GPT-4o、Claude-S-4.6、DeepSeek-R。

2. **修复后静态分析**：Semgrep、Bandit。
3. **修复后 LLM 裁判**：输入静态分析结果 + 生成补丁。
4. **组合检测**：输入 issue 描述 + 补丁 + 静态分析结果（RQ4）。

- RQ1：APR 智能体对 SWEADV 的鲁棒性
- RQ2：LLM-as-judge 能否检测对抗 issue（修复前）
- RQ3：对抗补丁能否被识别（修复后）
- RQ4：issue 级 + 补丁级组合检测是否足够

## 六、主要结论与发现

### RQ1：APR 智能体普遍脆弱
- **Finding 1**：对抗注入**不降低修复性能**（FR 与良性样本差距多在 4% 内），无 trivial 迹象表明 issue 被污染。
- **Finding 2**：SWEADV 的 ASR 达 **48.5%–54.0%**，是基线（18.8%–26.4%）的近两倍；跨 LLM 差异仅 5.5%，泛化性强。
- **Finding 3**：`weak_hashing` 最易注入（MiniMax-M2.5 达 64.0%），`path_traversal` 最难（44.7%/40.0%）；成功取决于载荷能否自然融入修复。

### RQ2：LLM 裁判检测对抗 issue 效果有限
- **Finding 4**：SWEADV 上 guided prompt 平均准确率仅 **62.3%**；相比基线准确率/F1 下降最多 16.6%/13.9%。Claude-S-4.6 在基线近 100%，在 SWEADV 仅 66.0%/74.5%。
- **Finding 5**：**DoS 注入最难检测**，因其行为类似正常校验支持（GPT-4o F1 < 10%）。

### RQ3：修复后检测不足
- **Finding 6/7**：规则静态分析无效——Semgrep 平均 49.5% 准确率，Bandit 仅 29.3%；规则覆盖率决定效果，对显式危险 API 有效，对上下文相关载荷（路径遍历、DoS）弱。
- **Finding 8**：补丁级 LLM 裁判优于静态分析，但 SWEADV 上平均准确率仅 **55.4%**（略高于 50-50 猜测）。
- **Finding 9**：LLM 裁判可弥补规则覆盖不足（改善路径遍历、DoS），但会**过度泛化**，削弱对简单攻击（命令执行、反序列化）的检测。

### RQ4：组合检测仍不足
- **Finding 10**：组合检测在基线近乎完美（88.8%/87.8%，Claude-S-4.6 达 98.1%/98.2%），但 SWEADV 上仅 **65.9%/72.4%**，最佳模型 Claude-S-4.6 也仅 75.8% 准确率。
- **Finding 11**：性能因攻击类型而异，仅 Claude-S-4.6 较一致，但仍因对抗请求外观合法而不充分。

### 补充发现
- **Finding 12**：前沿模型 **Claude Opus 4.5** 在 206 个"骗过所有测试 LLM"的实例上，FR 98.1%、ISR 86.4%、**ASR 85.4%**——更强的编码模型可能因更善于遵循指令（包括恶意指令）而**更易被欺骗**。
- **Finding 13**：定性分析 600 个假阴性，最主要失败原因（359/600）是**把恶意载荷误判为合法 bug 修复或功能请求**；其次（161/600）是**要求显式恶意意图**才判定对抗。检测器常识别出良性意图，却未能发现"修复目标与安全敏感新增代码之间的错位"。

## 七、优点

- **模型无关的基准设计**：同一对抗文本可测试任意受害智能体，相比 SWExploit 等模型特定方法更具通用性与可复现性。
- **端到端自动化构建流水线**：从 golden patch 自动提取目标/注入符号，生成攻击载荷与对抗 issue，含验证与重试机制，可规模化。
- **多层次、多模型评估**：修复前/后、静态/LLM/组合三种防御范式，3 修复 LLM × 4 裁判 LLM 交叉验证，结论稳健。
- **ground truth 双重验证**：静态 diff 规则 + 动态触发 harness，降低标签噪声。
- **定性分析深入**：对 600 个假阴性归类，揭示检测失败的认知根因（合法外观、要求显式恶意意图），对后续防御研究有指导价值。
- **威胁模型现实**：黑盒、仅能提交 issue，符合真实开源协作场景；明确区分构造期代理与评估期受害模型，避免数据泄漏。
- **前沿模型补充验证**：发现"更强模型更易被诱导"的反直觉结论，警示性强。

## 八、不足与局限

- **覆盖范围有限**：仅 150 个 SWE-bench Verified 任务、Python 仓库、5 类攻击，结论向其他语言/漏洞类型/任务规模的外推需谨慎。
