## 摘要
大型语言模型（LLM）已在软件开发中无处不在，基于LLM的自动程序修复工具也越来越多地用于代码审查。在本报告中，我们探讨将LLM作为缺陷修复器进行迭代式盲目使用的问题。在多种模型和修复环境中，我们发现LLM会一致地声称在完全无缺陷的程序中检测到缺陷，而对有缺陷程序的修复率却低于其对正确程序造成破坏的比率。我们还探讨了这一迭代过程的长期动态，发现它常常会陷入一种伪缺陷修复循环：相同的修改被反复添加又删除，无限循环。最后，通过机制可解释性探测，我们揭示了一个控制编辑倾向的引导向量的存在，这表明LLM具有对“有缺陷代码”的内部表征，而正是该表征被错误激活，从而诱发伪缺陷修复。这些结果为全自主缺陷修复系统的动态，以及模糊目标下的停止条件，提供了洞见。

## Abstract
Large language models (LLMs) have become ubiquitous in software development, with LLM-based automated program repair tools increasingly used during code review. In this report, we explore the iterative blind use of LLMs as bug-fixers. Across multiple models and repair environments, we find that LLMs consistently claim to detect bugs in entirely bug-free programs while the rate of repair of buggy programs is less than that of the damage to correct programs. We also explore the long-term dynamics of this iterative process, and find that this frequently reaches a pseudo-bug-fixing cycle where the same changes are added and removed again ad infinitum. Lastly, via mechanistic probing, we unveil the existence of a steering vector which controls the editing propensity, suggesting that LLMs have an internal representation of ``buggy code", and that this representation is what is falsely activated to induce pseudo-bug fixing. These results provide insight towards the dynamics of fully autonomous bug-fixing systems, as well as stopping conditions under ambiguous goals.

## 2. 方法论

- **核心思想**：把“LLM 反复修复同一份代码”建模为动力系统，并分析其长期动态、吸引子和周期；同时用机制可解释性探针寻找控制编辑倾向的“buggy code”内部表征。
- **两种修复环境**：
  - **整文件编辑（whole-file）**：LLM 输入当前代码，输出完整修复后代码，作为下一轮输入。
  - **搜索/替换块（SRB）**：LLM 先给推理，再输出一个 `SEARCH/REPLACE` 块，程序化应用到代码中；只修“最重要的一个 bug”。若格式无效或搜索块不存在，则视为恒等修改。
- **动力系统形式化**：
  - 贪心解码下，修复函数为 \(f: C \to C\)，迭代为 \(C_{n+1}=f(C_n)\)。
  - 使用 SRB 时，\(f: C \to B\) 生成块，\(g: C \times B \to C\) 应用块，迭代为 \(C_{n+1}=g(C_n, B_n)\)。
  - 随机解码下，该过程是马尔可夫核，且因提示不包含历史，系统严格马尔可夫。
- **关键指标**：
  - 修复率 \(\alpha = P(C_{t+1}\text{ correct} \mid C_t\text{ incorrect})\)。
  - 损坏率 \(\beta = P(C_{t+1}\text{ incorrect} \mid C_t\text{ correct})\)。
- **吸引子分析**：固定点、周期、瞬态；固定点来源包括“- None”、恒等 SRB、搜索块无法定位、退化重复等。
- **引导向量构造**：
  - 用 verdict prompt 让模型回答代码是否有 bug，输出 `Y/N`。
  - 若 \(P(Y|C)>0.9\) 归为正类，若 \(P(N|C)>0.9\) 归为负类。
  - 用 difference-of-means 计算层 \(l\) 的引导向量：
    \[
    v_l = \frac{1}{|P|}\sum_{C\in P} h_l(C) - \frac{1}{|N|}\sum_{C\in N} h_l(C)
    \]
  - 推理时注入：\(h_l^{\text{steered}} = h_l + \gamma v_l\)。
  - 用投影打分：\(s_l(C)=h_l(C)\cdot v/|v|\)。
  - 还用 logit lens 检查该方向是否只是直接读出 `Y/N`  token。
