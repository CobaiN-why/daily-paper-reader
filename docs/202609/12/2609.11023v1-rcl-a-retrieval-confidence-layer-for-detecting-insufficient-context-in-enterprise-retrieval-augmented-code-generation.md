## 摘要
面向代码生成的检索增强生成（RAG）已在公共代码仓库上得到广泛研究，在这些场景中，模型的参数化知识通常能够弥补不完美的检索。但在企业代码库中，这一假设会失效，因为私有API、内部框架和未文档化的团队约定完全处于任何模型预训练分布之外。近期关于私有库代码生成的研究表明，即使采用oracle（完美）检索，也不能消除错误，而是将失败定位到下游的API使用环节；另外，置信度门控检索已在开放域问答中利用模型内部置信度得到研究。二者都没有解决以下问题：在生成开始之前，检索本身对于私有代码查询是否在结构上足够。我们提出RCL（检索置信层），一种插入在检索与生成之间的轻量级模块，它结合由调用图导出的结构覆盖分数与一个新颖度分数，后者用于估计查询对模型先验之外知识的依赖程度，从而在生成发生之前检测检索不足。当置信度低于校准阈值时，RCL会触发有针对性的后续检索，或标记输出以供人工审查，而不是在不完整上下文下静默生成。我们描述RCL的架构，形式化其评分函数，并提出一种评估方法：使用通过向开源Java仓库注入合成内部API而构建的私有代码基准，在无需专有代码的情况下模拟企业场景。我们报告结果（第7节），在生成正确性上比较RCL与仅基于相似度的检索。我们的观点是，检索充分性——以结构化方式而非模型内部置信度来评估——是构建更安全的私有企业环境中代码生成系统的一个独特且当前尚未充分处理的信号。

## Abstract
Retrieval-Augmented Generation (RAG) for code generation has been studied extensively on public repositories, where a model's parametric knowledge often compensates for imperfect retrieval. This breaks down in enterprise codebases, where private APIs, internal frameworks, and undocumented team conventions fall entirely outside any model's pretraining distribution. Recent work on private-library code generation shows that even oracle (perfect) retrieval does not eliminate errors, but locates failures downstream in API usage; separately, confidence-gated retrieval has been studied for open-domain question answering using model-internal confidence. Neither addresses whether retrieval itself was structurally sufficient for a private-code query before generation begins. We introduce RCL (Retrieval-Confidence Layer), a lightweight module inserted between retrieval and generation that combines a call-graph-derived structural coverage score with a novelty score estimating a query's dependence on knowledge outside the model's prior, to detect insufficient retrieval before generation occurs. When confidence falls below a calibrated threshold, RCL triggers a targeted follow-up retrieval or labels the output for human review, rather than generating silently against incomplete context. We describe RCL's architecture, formalize its scoring functions, and propose an evaluation methodology using a private-code benchmark built by injecting synthetic internal APIs into open-source Java repositories, simulating the enterprise condition without proprietary code. We report results (Section 7) comparing RCL against similarity-only retrieval on generation correctness. Our position is that retrieval sufficiency, assessed structurally rather than from model-internal confidence, is a distinct and currently underaddressed signal for building safer code-generation systems in private, enterprise settings.

## 1. 核心问题与整体含义

- **背景**：RAG 代码生成在公开仓库上已被广泛研究，模型在预训练中见过大量相似代码，因此即使检索不完美，参数化知识也能部分补偿。
- **企业场景失效**：私有 API、内部框架、遗留模式、未文档化团队约定完全处于任何模型预训练分布之外。一旦检索不完整，模型没有参数回退，只能幻觉出看似合理的内部 API，或静默误用从未见过的约定，生成“流畅、自信但错误”的代码。
- **现有工作缺口**：
  - RepoCoder、GraphCoder、RLCoder 等改进“检索什么”，但不判断检索到的集合是否足够。
  - MEMCoder 研究私有库代码生成，但假设 oracle 检索，失败定位在下游 API 使用。
  - 置信门控检索在开放域 QA 中用模型内部置信度，但模型无法可靠地对自己从未见过的私有 API 表达置信。
- **核心主张**：需要区分“检索相关性”与“检索充分性”。检索充分性应结构化评估，并在生成前检测；RCL 正是插入检索与生成之间的轻量置信层，用于发现上下文不足并触发补检索或人工复核，而非静默生成。

## 2. 方法论

- **核心思想**：在标准 RAG-for-code 流水线的检索器与生成器之间插入 RCL，不替换检索器，只评估检索结果是否覆盖查询真实依赖面，并据此决定生成、补检索或标记复核。
- **问题形式化**：
  - 查询 q，企业代码库 C，检索结果 R(q)，真实依赖面 D(q)。
  - 检索充分性 = R(q) 覆盖 D(q) 的程度。
  - 两类风险：
    - **可覆盖风险**：缺失依赖存在于代码库中，可通过更好查询或第二轮检索补回。
    - **先验缺口风险**：缺失依赖属于模型预训练中几乎没有暴露的知识，无法安全依赖参数知识。
- **结构覆盖分**：
  - 离线预计算代码库的静态调用图索引，识别目标插入点可达的 callee 函数、父类/接口成员、导入的内部符号，得到 D̂(q)，作为 D(q) 的静态近似。
  - 结构覆盖分 S_cov(q) = |D̂(q) ∩ symbols(R(q))| / |D̂(q)|。
  - 接近 1 表示检索器找到了正确生成实际会调用的代码；低分表示主题相关但结构不完整。
- **新颖度分**：
  - 对每个未覆盖符号 s ∈ U = D̂(q) \ symbols(R(q))，估计其新颖度，综合：
    - 标识符模式在公共代码参考分布中的低频率；
    - 内部代码特有的命名/结构特征；
    - LLM 对该形状符号熟悉度的自评。
  - 查询级新颖度分 S_nov(q) = (1/|U|) Σ_{s∈U} novelty(s)。
- **组合置信分**：
  - C(q) = S_cov(q) · (1 − S_nov(q))。
  - 采用乘法形式，体现覆盖与新颖度是复合风险：完整覆盖可抵消新颖度风险；覆盖缺口若只是通用低新颖度符号，则风险较小。
- **决策策略**：
  - C(q) ≥ τ：正常生成。
  - C(q) < τ：从 U 中未覆盖、高新颖度符号发起定向后续检索，限定固定轮数。
  - 补检索预算耗尽后仍低于 τ：仍生成，但标记为低置信度，供人工复核。
  - τ 在留出验证集上校准，权衡误复核开销与漏检风险。

## 3. 实验设计

## 6. 主要结论与发现

- **整体 pilot 结果**：
  - Similarity-only：覆盖 0.782，召回 0.798，幻觉 10。
  - Fixed-k expanded：覆盖 0.940，召回 0.825，幻觉 10。
  - RCL：覆盖 0.925，召回 0.841，幻觉 7。
  - RCL 获得最高召回和最低幻觉数，同时平均检索上下文少于 fixed-k expanded。
- **触发子集结果**：
  - Similarity-only：召回 0.393，幻觉 7。
  - RCL：召回 0.524，幻觉 3。
  - RCL 平均召回提升 13.3 个百分点，幻觉调用从 7 降到 3，且使用更小的定向检索扩展。
- **核心发现**：
  - 检测检索不足并响应以定向补检索，比盲目扩大 k 更有效。
  - 覆盖与新颖度作为复合风险的方向性结果与假设一致。
  - 检索充分性——基于结构而非模型内部置信度——是私有企业代码生成中一个独立且当前未充分处理的信号。
  - 注入合成内部 API 的基准构造方法可作为无需专有代码的可复用评估模式。
