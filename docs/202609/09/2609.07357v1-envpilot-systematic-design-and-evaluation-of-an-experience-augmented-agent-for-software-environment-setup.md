## 摘要
环境设置是软件工程中一项关键但复杂的任务，严重依赖专家知识。现有的自动化环境设置方法缺乏从过去执行轨迹中积累经验并随时间演进的能力。因此，它们的性能受到限制，因为它们经常进行冗余探索，忽略有用的历史解决方案，并且难以跨不同软件生态系统进行泛化。我们提出了EnvPilot的系统设计与实证验证，这是一种经验增强型代理，将轨迹衍生经验重用操作化应用于软件环境设置。EnvPilot维护了一个可扩展的轨迹衍生记忆（TDM），初始包含667条高质量经验。它系统地将历史执行轨迹中的隐式知识转化为结构化经验，并通过上下文感知检索机制在任务执行期间检索最相关的指导。这使得EnvPilot能够结合多种经过验证的设置策略，提供比仅依赖静态项目文件或网络检索的方法更精确、更详细的指导。为了评估EnvPilot，我们构建了AES-Bench，一个覆盖9种编程语言、包含112个真实世界GitHub实例的多语言基准。实验表明，EnvPilot在降低推理成本的同时，实现了75.00%的Pass@1成功率，达到了新的最先进（SOTA）水平。我们的实证研究表明，结构化经验表示和上下文感知检索机制都是必不可少的。

## Abstract
Environment Setup is a critical yet complex task in software engineering that relies heavily on expert knowledge. Existing automated environment setup methods lack the ability to accumulate experience from past execution trajectories and to evolve over time. As a result, their performance is limited because they often perform redundant exploration, ignore useful past solutions, and fail to generalize across diverse software ecosystems. We present the systematic design and empirical validation of EnvPilot, an experience-augmented agent that operationalizes trajectory-derived experience reuse for software environment setup. EnvPilot maintains an expandable Trajectory-Derived Memory (TDM), initialized with 667 high-quality experiences. It systematically transforms implicit knowledge from historical execution trajectories into structured experience and retrieves the most relevant guidance during task execution through the Context-aware Retrieval mechanism. This enables EnvPilot to combine multiple validated setup strategies, providing more precise and detailed guidance than methods that rely solely on static project files or web retrieval. To evaluate EnvPilot, we construct AES-Bench, a multilingual benchmark of 112 real-world GitHub instances across 9 programming languages. Experiments show that EnvPilot achieves a new state-of-the-art (SOTA) with a 75.00% Pass@1 success rate while reducing reasoning costs. Our empirical study shows that both the structured experience representation and the Context-aware Retrieval mechanism are essential.

软件环境设置（Software Environment Setup）是软件工程中的关键基础任务，广泛支撑着代码执行、测试、部署等环节，也是构建高质量训练数据集与训练强化学习（RL）智能体的前提。然而，环境设置高度依赖专家经验，真正实现自动化面临巨大挑战。

**现有方法的主要不足：**
- 依赖静态信息（README、CI配置等）或网页检索，把每个任务当作孤立问题处理，缺少跨任务经验积累能力；

**论文核心主张**：将从历史执行轨迹中提取的结构化经验进行系统性复用，能显著提升智能体在环境设置任务上的效果与效率。

## 2. 提出的方法：EnvPilot

### 2.1 核心思想
EnvPilot 是一种**经验增强型（Experience-Augmented）代理**，核心思路是将"组织学习"的经验复用理念引入自动化环境设置，遵循 **LRAE 循环**（Learn–Retrieve–Act–Evaluate）：
- 从历史执行轨迹中学习
- 检索相关上下文经验
- 在容器内执行
- 评估结果并补充记忆

### 2.2 Trajectory-Derived Memory（TDM，轨迹派生记忆）

- **经验表示**：每条经验采用 `<problem, solution, action>` 结构化三元组——Problem 为错误的现象描述，Solution 为策略性根因分析，Action 为可直接执行的命令。
- **记忆构建**：
  - 初始用 781 条来自 Multi-SWE-Bench 执行轨迹，经 LLM 蒸馏得到 **667 条高质量经验**（保留率 85.4%）；
  - 构建过程自动化，采用 DeepSeek-R1 进行链式推理，三步流水线：数据收集聚合 → 基于"通用性/完整性/准确性"三标准定义高质量条目（含少量人工种子示例）→ LLM 蒸馏为 JSON；
  - 采用 5% 人工审计确认质量，并且存储的是抽象模式，非粗原始冗余轨迹。

### 2.3 Context-aware Retrieval（上下文感知检索机制）
区别于传统"失败后再检索"的做法，EnvPilot 在执行前主动预判可能的设置障碍，包含三步：
1. **代码库相关信息提取**：分析 README、CI/CD 配置文件、构建配置等，生成结构化 codebase profile（语言版本、包管理器、构建/测试命令、系统级依赖等）；
2. **上下文感知查询生成**：基于 profile 由 LLM 生成 3–5 个假设性、意图对齐的问题，模拟潜在故障点；
3. **多查询检索与重排**：将多个查询向量化（Qwen3-Embedding-8B），检索 TDM 中问题的向量相似度，采用 **Reciprocal Rank Fusion (RRF)** 综合排序，最终选出 top-k（默认 k=10）条经验注入 agent 上下文。

### 2.4 容器化执行与自动评估
- 任务在隔离的容器环境中执行，全程记录执行轨迹和测试日志，保证安全性和可复现性；
- **LLM-as-a-Judge** 自动评估框架：以 DeepSeek-V3 为裁判，核心原则是判断**环境的完整性**而非**代码逻辑的正确性**，三类判据：区分断言失败与环境错误、测试生命周期完整性（须有完整 summary）、编译与执行必须实际触发测试命令（E）——即技术上以 ECSR 作为衡量指标。

## 6. 主要结论与发现

- **SOTA 性能**：在 AES-Bench（112）上 EnvPilot。用 DeepSeek-V3-0324 实现了 **75.00% Pass@1 成功率**（而 SWE-Agent 为 62.50%，RepoLaunch 为 55.36%，ExecutionAgent 为 43.75%），同时在较低 token 损耗与 API 调用方面刷新了 SOTA，相比现有方法提升了 **12.5%+**；
- **跨模型可迁移**：使用 GPT-4o-mini时（46.43%）仍显著领先所有基线，尤其在小模型能力不足的前提下，TDM能作为外部知识脚手架弥补能力差距；
- **消融结论**：TDM 是最关键（去掉后下降 12.50 pp），完整三元组 + 上下文感知检索的协同才是收益最大化路径；所有不完整变体（B–E）的总成功率都收敛在 66.96%，说明单有记忆但不完整/不精确地接入并不能稳定生效；
- **评估工具高度可靠**：LLM-as-a-Judge 与人工标注的一致性达到 Accuracy 98.04%、Precision 99.26%、Recall 97.45%、F1 98.34%；
- **检索量并非越大越好**：k=10 是最优点；k=15 和 k=20 引入信息过载，成绩回落（74.11%→71.43%），说明上下文中的信息密度和精确度比数量更重要；
- **稳定性**：EnvPilot 三轮运行的平均成功率为 74.11%±4.09，而无 TDM 的基线仅为 62.20%±2.25，最低一轮的 69.64% 仍高于无记忆基线最高之一轮的 64.29%，记录提升是系统性而非巧合；
- **主要失败类型**（以最优一轮的记录失败总数 25 例计）在安装前已知失败占比最大的是**工具链和运行时问题（60%）**，后面跟随原生依赖错误、平台限制（合计分布在 16%/16%）和仓库配置错误（8%）。

## 7. 优点与亮点

1. **问题选择有价值**：环境设置是 LLM+软件工程落地的重要"最后一公里"基础设施问题，此前少有系统性的经验复用研究；
2. **记忆精度高**：颠覆了"存完整轨迹"或"存自然语言总结"的记忆做法，设计了可执行的 `<problem, solution, action>` 三元组，兼顾解释性和可直接行动性；
3. **前瞻式检索创新**：以往检索多为反应式（出错后查找），EnvPilot 采用基于 codebase profile"假设性问题生成 + 多查询 RRF 融合"的主动式检索，把故障预防提前到执行之前；
4. **一体化闭环设计**：LRAE 循环让智能体天然具备增量学习和自我更新能力；同时评估期冻结内存，保证评估公平；
5. **构造了新基准 AES-Bench**：版本锁定 + 完整执行测试 + 9 种语言 + 112 个任务，同时兼顾规模与多样性，免除了 EnvBench 局限性（仅 Python/Java 且无真实测试执行）；
6. **严格验证自动化评估**：不盲目信任自动评估，而是用 460 条轨迹的大样本人工标注做裁决器校准；
7. **成本分析维度丰富**：论文同时公布成功率、API 次数、Token 量和美元成本，使比较全面且务实。

## 8. 不足与局限

- **算力信息缺失**：无法复现实际部署/推理所需的硬件与能耗成本，论文作为实验的“黑盒”服务器部署状况（如 API 费用与延迟）未被记录，影响学术复现便利度；
- **外部有效性的边界**：①只选择开源、可公开获取依赖的网络项目，未涉及工业级私服/内部包镜像/严格安全策略场景；②集中在 Linux 容器（Ubuntu 22.04）与 x86 平台，未覆盖移动/嵌入式/高性能计算平台；③AES-Bench 整体上偏向库/服务端中等规模项目，不含超大型 monorepos 与数据管线复杂系统；
- **基线适应性受限**：Repo2Run 只能评估 Python 子集、Bash-based Agent 在 DeepSeek-V3-0324 上因工具调用框架不兼容而完全不可用，跨语言的完整对比公平性受到一定制约；此外大多数基线只跑一次而主方法跑三次，降低了对比的对称性；
- **C/C++ 等异质生态存在负迁移**：消融结果显示 C/C++ 在没有记忆时反而最高（68.00%），而加上记忆后稳定性下降（48.00%~60.00%），说明记忆在某种不易迁移的环境中可能会分散 agent 的判断，论文尚未提出经验过滤或负经验抑制方案；
- **评估粒度较粗**：ECSR 是一个二元 Success/Failure 指标，论文自己不承认没有界定中等成功级别（如关键命令通过但测试 report 不完整），未来需更细粒度的分级评价；
- **潜在的过拟合风险**：作者承认底层 LLM 预训练数据可能已包含相关代码片段，"弱泄漏"无法完全排除；虽然 TDM 层面做了仓库名过滤，基线模型在同一基座下与 EnvPilot 的比较相对公平，但绝对数值仍可能受预训练影响；
- **记忆初建的来源单一**：初始 667 条经验只来自 Multi-SWE-Bench 的执行轨迹，虽然语言多样但很可能未均衡覆盖所有生态的极端边界（如 C/C++ 工具链的组合爆炸），对记忆初始多样性的进一步扩展是有空间但未论述的成本问题；
- **无显著性检验**：多次运行只在 TDM 组和 w/o TDM 组上做了，且差异报告仅有均值±标准误，未给出配对检验/置信区间；消融各变体的小差异更缺乏统计验证支撑。
