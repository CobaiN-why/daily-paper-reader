## 摘要
从以人为中心的辅助向自主软件工程（ASE）代理的转变，使得解决现实世界中复杂的软件工程任务成为可能。然而，这些代理的试错本质会产生冗长的交互轨迹，在上下文窗口限制和成本方面造成严重瓶颈。虽然上下文压缩提供了一种潜在的补救措施，但先前的方法遭受静态剪枝策略和粒度不匹配的困扰，常常无法保留对软件工程任务至关重要的语义依赖和语法细节。为了在减少上下文长度的同时严格保留关键任务证据，我们引入了AttnCompress，一种动态注意力引导的轨迹压缩框架。与现有方法不同，AttnCompress通过三个关键机制弥合了语义完整性与动态适应性之间的差距：（1）通过困惑度（PPL）尖峰进行结构感知分段，以保留代码和日志的语法结构；（2）使用代理注意力权重进行相关性估计，以量化历史块与代理当前推理的精确相关性；以及（3）一个动态滚动窗口，随着任务的发展重新评估和召回历史上下文。在SWE-Bench-Verified和Multi-SWE-Bench上的广泛评估表明，AttnCompress实现了53.17%的通过率，超越了先前最先进的基线，同时将令牌消耗减少了21.6%，总成本降低了33.6%。该框架被证明是与模型无关的，并能有效地推广到多种编程语言。

## Abstract
The transition from human-centric assistance to Autonomous Software Engineering (ASE) agents has enabled the resolution of complex real-world SE tasks. However, the trial-and-error nature of these agents generates lengthy interaction trajectories, creating severe bottlenecks in terms of context window limits and cost. While context compression offers a potential remedy, prior approaches suffer from static pruning strategies and granularity mismatches, often failing to preserve the semantic dependencies and syntactic details crucial for SE tasks. To strictly preserve critical task evidence while reducing context length, we introduce AttnCompress, a dynamic attention-guided trajectory compression framework. Unlike existing approaches, AttnCompress bridges the gap between semantic integrity and dynamic adaptability through three key mechanisms: (1) structure-aware segmentation via perplexity (PPL) spikes to preserve the syntactic structure of code and logs; (2) relevance estimation using proxy attention weights to quantify the precise relevance of historical blocks to the agent's current reasoning; and (3) a dynamic rolling window to re-evaluate and recall historical context as the task evolves. Extensive evaluation on SWE-Bench-Verified and Multi-SWE-Bench demonstrates that AttnCompress achieves a pass rate of 53.17%, outperforming prior state-of-the-art baselines while reducing token consumption by 21.6% and total costs by 33.6%. The framework proves to be model-agnostic and generalizes effectively across diverse programming languages.

## 1. 核心问题与整体含义（研究动机与背景）

大型语言模型推动了软件工程从“人类辅助”向“自主软件工程”（Autonomous Software Engineering, ASE）范式转变。ASE代理通过迭代式 ReAct（Reasoning + Acting）循环，在代码库分析、文件编辑、测试执行和调试之间进行长跨度交互，可解决真实世界的 GitHub issue。然而，这种试错型工作流会产生非常冗长的交互轨迹，造成三类严重问题：

- **上下文窗口瓶颈**：观测内容（Observation）平均占总 token 的 62.6%，长轨迹极易超出 LLM 上下文窗口硬限制。
- **成本与延迟膨胀**：token 消耗快速累积导致 API 费用与推理延迟显著上升。
- **“Lost-in-the-Middle” 效应**：过量噪声会降低模型的推理质量。

论文将现有上下文压缩方法归纳为三类，认为其均有根本局限：

- **启发式剪枝**（如 ObsMask）：按规则丢弃旧消息，属静态、不可逆的一次性压缩，忽略了调试过程的非线性特征（focus shifting）。
- **总结式压缩**（如 AgentDiet）：用额外 LLM 重写历史，存在幻觉风险，且容易丢失精确的代码细节（行号、变量名、文件路径等），并引入大量附加推理开销。
- **token 级选择**（如 Lingua/Lingua-2）：忽略代码语法结构，可能破坏 JSON 对象、函数定义等，使上下文无法理解。

论文进一步归纳出 SE 轨迹压缩的两大核心挑战：
1. **粒度不匹配**：粗粒度消息级压缩保留过多噪声；细粒度 token 级压缩破坏语法结构。真实场景中一个 700+ 行文件输出往往只有 15 行有效，需要语义块的粒度。
2. **动态相关性**：调试过程中代理的关注点会漂移，静态压缩一旦删除旧上下文就无法恢复，导致冗余重检索并可能引发幻觉。作者通过人工审计发现约 40% 的轨迹存在此种 focus shifting 问题。

## 2. 方法论：AttnCompress 框架

AttnCompress 是一个插拔式中间件（middleware），位于 SE Agent 轨迹管理器与后端 LLM 之间，目标是将原始轨迹压缩为尽可能短但仍保留任务关键证据的轨迹。框架包含三个连续阶段：

### 阶段一：基于 PPL 尖峰的结构感知分段（Structure-Aware Segmentation）

- 利用小型代理模型（Proxy Model, 默认 Qwen3-4B-Instruct）计算工具输出文本各行的平均困惑度 PPL，公式为：
  - PPL(lᵢ) = exp(−(1/|lᵢ|) Σ log P(x | x<context>))
- 通过相邻行 PPL 差分序列检测局部尖峰：计算差分序列的均值 μ 与标准差 σ，定义自适应阈值 τ = μ + h·σ；差分超过阈值的局部极大值点即为语义边界。
- 将原始输出划分为语义连贯的块集合 B = {b₁, b₂, …, bₘ}，避免 token 级裁剪破坏 JSON、函数体和日志结构；过小的单行块与前块合并。

### 阶段二：基于代理注意力的相关性估计（Attention-based Scoring）

- 构造输入序列：压缩的历史轨迹 + 新观测 + 追加一个特殊 Query Token（即后端 LLM 的生成起始 token，如 `<|im_start|>`），代表代理的“当前推理状态”。
- 用代理模型执行单次前向传播，提取指定层（默认最后一层）的注意力权重。块 bᵢ 的重要性得分为 query token 到块内各 token 的平均注意力：
  - Score(bᵢ) = (1/|bᵢ|) Σ_{t∈bᵢ} A(q_gen, t)
- 根据得分降序排序，在给定压缩比 ρ 下设置 token 预算，贪心选取 Top 块进入保留集，其余丢弃。
- 计算上的关键优化：阶段一的 PPL logits 与阶段二的注意力图在**同一次前向传播**中提取，效率高。

### 阶段三：动态滚动窗口的三层上下文维护（Dynamic Rolling Maintenance）

将轨迹划分为三个区域：
- **Immediate Memory（原始保留）**：最近 k 轮（默认 k=2）不压缩，保留即时行动细节。
- **Short-term Memory（滚动缓冲）**：中间区域，每轮重新进行分段、评分与压缩，适应快速焦点变化。
- **Long-term Memory（固定归档）**：更早的历史，静态存储以利用前缀缓存（prefix caching），仅在“全局刷新”时重构。

两种运行模式（对应 Algorithm 1）：
- **增量更新（标准模式）**：长时边界不变，只对短期区域进行重压缩，与静态长期记忆拼接输出，最大化前缀缓存命中率。
- **全局刷新（触发模式）**：当短期缓冲累计超过阈值 M（默认 10 轮）时，将长期归档与短期缓冲合并进行全局重新选择，使先前被抑制的信息可被“复活”，并将归档指针推进至当前原始边界。

## 3. 实验设计

### 数据集 / Benchmark
- **SWE-Bench-Verified**：主评估数据集，500 个真实 GitHub issue。实验采用 AgentDiet 划分：100 个实例用于验证集（消融/调参），200 个实例作为测试集（主对比评估）。
- **Multi-SWE-Bench-Flash**：跨语言泛化评估，300 个实例，覆盖 7 种编程语言（Rust、TypeScript、JavaScript、Java、Go、C、C++），任务复杂度更高。

### 基线方法与统一框架
- 所有方法（含基线）集成在同一 Trae-Agent 框架中，统一 tail size k=2；总结类方法使用与代理相同的强 LLM 做总结，保证最优能力，对比公平。
- 基线共 7 个：Original（完整上下文上界）、Random（随机丢弃 75%）、SlidingWindow（8k token 窗口）、ObsMask（启发式规则）、Lingua（token 级分类选择）、LLMSummary（LLM 总结）、AgentDiet（近期 SOTA 轨迹改写）。

### 后端 Agent LLM
主实验使用三种后端：Gemini-3-Flash、Qwen3-235B-A22B-Instruct、Qwen3-Coder-30B-A3B-Instruct。

## 6. 主要结论与发现

- **主结果（RQ1）**：AttnCompress 在 SWE-Bench-Verified 上达到压缩方法中最高的平均 Pass 率 **53.17%**，比 SOTA AgentDiet（51.17%）相对提升 3.9%；比全文上下文基线低约 2 个百分点（55.17%），但 token 降低 42.3%。Token 消耗比 AgentDiet 减少 **21.6%**，总成本降至 0.0949 美元（比 AgentDiet 0.1429 美元降低 **33.6%**，比 Original 0.1189 美元降 20.2%），端到端延迟比 AgentDiet 少 26.4%。
- **重复运行**：Qwen3-Coder-30B 上 5 次运行的均值通过率（43.70%）高于 LLMSummary（42.70%）与 AgentDiet（41.80%）。
- **消融（RQ2）**：代理注意力贡献最大（+7.0% Pass 率），滚动窗口次之（+5.0%），PPL 分段贡献+3.0%；三组件均不可缺失。按注意力导出的代理注意力取向与后端 LLM 高度对齐（Spearman 0.60~0.64，Top-20% 重叠 0.62~0.66，表 5），即使全局排名存在差异，压缩在注意力预算内保留的显著块仍能覆盖后端 Agent 所需信号。
- **跨语言（RQ3）**：Multi-SWE-Bench-Flash 上 AttnCompress Pass 率 19.67%，大幅超过其他压缩方法，达到 Original（20.33%）的 **96.7% 相对性能**，token 成本降约 20%；Java、C 等静态类型语言表现与完整上下文相当。

## 7. 优点

- **训练免费（training-free）**：不需要训练任何额外模块，直接利用代理模型的注意力/PPL 信号，即插即用于不同 ReAct 风格代理，通用性好。
- **粒度适配性好**：PPL 尖峰从语义边界切割，既避免信息碎片化，也避免保留整段噪声；针对代码/日志结构化内容尤其有效。贪心选择在注意力排序基础上做整块保留，保留了如函数定义、引用路径等的完整性。
- **动态过滤能适配调试的非线性性**：三层滚动缓冲与全局刷新在保留前缀缓存收益的同时实现历史信息召回，缓解 focus shifting 问题。
- **不同模型家族的注意力分布一致性被系统验证**：通过注意力量化代理-后端对齐（小模型也保留关键显著块），证明框架与代理模型无关。
- **成本计量公平透明**：主实验中压缩开销以官方 API 价格计算，并考虑前缀缓存折扣，对 AgentDiet 等总结方法的成本未低估。
- **调参弹性**：主要超参（压缩比、tail size）平滑调节成本/性能，不构成脆弱的触发点（表格显示阈值、代理层等取宽泛范围稳定性较好），默认仅取压缩率 0.2 即能超越 SOTA。

## 8. 不足与局限

- **与完整上下文的差距仍然明显**：Pass 率从 55.17% 降至 53.17%（约 2 个百分点），说明压缩仍会删除某些后续重要证据（如早前文件路径/辅助函数）；因给定 token 预算与可能的错误删除，无法保证恢复。
- **未报告统计显著性**：主对比只报告均值；5 次重复运行的表 2 仅覆盖一个后端与一个验证子集，未提供配对检验或置信区间。

- **外部泛化尚未全面验证**：实验基于 Trae-Agent 一个代理框架；讨论虽声称可迁移至其他 ReAct 风格代理，但 SWE-agent、OpenHands 等其他流行的 SE 代理未验证。
- **压缩时上下文重构会带来额外推理时延**：虽整体低于 AgentDiet，但高于纯启发式方法（ObsMask/SlidingWindow 无分析开销）；延迟/性能之间的取舍依成本约束而定。
- **超参工程依赖**：PPL 阈值与 rolling window 等超参虽在验证集调优，但需在本地部署或上线前针对新任务再校准。
- **基准局限**：SWE-Bench 及 Multi-SWE-Bench 仍以测试通过率作为成功代理（plausible patch may not equal correct fix）；视觉等其它 SWE 领域未评估。
- **成本计量的隐含假设**：代理模型分析时间与 API 价格按线上推理计算，未讨论代理模型本地部署（GPU 占用、吞吐）对总拥有成本的影响；也缺乏对“上下文重构导致缓存失效次数”的定量测量报告。
