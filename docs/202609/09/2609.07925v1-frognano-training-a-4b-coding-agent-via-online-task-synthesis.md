## 摘要
我们提出了FrogNano，一个4B编程智能体，旨在即使在资源受限的环境下也能高效且有效地处理软件工程（SWE）任务。它仅通过在大约1500个SWE环境中的合成任务上进行强化学习（RL）进行后训练。提高性能的一个关键成分是一个在线任务合成管道，该管道创建的任务针对当前检查点可学习性的前沿进行校准。本报告提供了证据表明，仅使用合成任务就可以训练出具有竞争力的小型编程智能体，而无需传统地从大型模型中进行蒸馏，并且生成位于当前智能体可学习性前沿的任务非常重要。我们报告了训练方法、跨不同环境的评估以及深入分析的细节，为我们持续探索可以在最小硬件上运行的轻量级但功能强大的编程智能体奠定了基础。

## Abstract
We present FrogNano, a 4B coding agent designed to tackle software engineering (SWE) tasks efficiently and effectively, even under resource-constrained environments. It is post-trained exclusively via RL on around 1,500 SWE environments with synthetic tasks. A key ingredient for improving performance is an online task synthesis pipeline that creates tasks calibrated to the frontier of learnability for the current checkpoint. This report provides evidence that competitive small coding agents can be trained with synthetic tasks alone, without traditional distillation from larger models, and that generating tasks at the learnability frontier of the current agent is important. We report details on the training methodology, evaluations across diverse environments, and in-depth analyses, serving as a foundation for our ongoing exploration of lightweight yet capable coding agents that can run on minimal hardware.

## 1. 论文的核心问题与整体含义

- **研究动机**：当前软件工程（SWE）领域的高性能编码智能体大多依赖前沿大模型（数十亿到千亿参数）或专有API，服务成本高昂，难以在本地部署和重复实验。论文希望探索**是否能用参数规模小得多的模型（4B）训练出具备仓库级代码修复能力的编码智能体**。
- **整体含义**：论文证明了**仅依靠强化学习（RL）和合成任务，不依赖大模型蒸馏，也能训练出有竞争力的小型编码智能体**。其最终模型 FrogNano（4B参数）在 SWE-bench Verified 等基准上达到了通常需要 32B–100B+ 参数模型的性能水平，显著降低了编码智能体的训练与推理门槛。
- **核心命题**：在线任务合成的关键在于**将任务难度持续校准到当前策略的“可学习前沿”**，使任务分布与策略能力协同演化，这是超越静态数据或简单难度过滤的关键。

## 2. 论文提出的方法论

### 2.1 总体架构：TaskPilot 与 Leaf 构成的迭代 RL 闭环

- 训练流程从 Qwen3.5-4B 基础检查点 π(0) 出发，交替执行：
  1. **任务生成与校准阶段（TaskPilot）**：面向当前策略 π(t) 合成约 300 个任务；
  2. **RL 训练阶段（climb）**：在 Leaf 环境中用这批任务通过 DPPO 优化策略，得到 π(t+1)；
  3. 重复 5 轮，最终得到 FrogNano。

### 2.2 轻量级 Agent Harness：Leaf

- 研究发现 Qwen3.5-4B 在复杂 R2E-Gym/SWE-Agent 框架中难以可靠完成任务（约96%轨迹达到轮次上限），因此设计了更符合 Claude Code 风格工具约定的 Leaf。
- Leaf 仅暴露 5 个类型化工具：`read`、`write`、`edit`、`glob`、`bash`；无工具调用的回复视为最终答案并终止回合。
- **关键效果**：在相同设置下，Qwen3.5-4B 从 R2E-Gym 的 8.3% 提升到 Leaf 的 37.2% SWE-bench Verified 解决率；较大模型（MiniMax-M2.5）对 harness 变化不敏感（均为66.5%），说明该设计对**小模型尤为重要**。

### 2.3 在线任务合成：TaskPilot

- **任务来源**：以 SWE-rebench 的真实仓库快照为基底，使用任务生成模型联合生成问题陈述（issue）、黄金补丁（gold patch）和隐藏的 F2P（fail-to-pass）测试。
- **可执行验证**：任务必须满足：F2P 测试在原始快照上失败、应用黄金补丁后通过，且原有 P2P（pass-to-pass）测试保持稳定。
- **策略引导校准**：使用当前 4B Leaf 策略对候选任务进行 N 次 rollout，估算解决率：
  \[
  \hat{p}_{policy} = \frac{1}{N}\sum_{j=1}^{N} R_j, \quad R_j \in \{0,1\}
  \]
  - 迭代 1–4：目标为 \( \hat{p}_{policy} = 0.5 \) 附近；
  - 修订后的迭代 5：使用更强的任务生成模型，目标区间降为 \( 0 < \hat{p}_{policy} \le 0.5 \)。
- **“生成–评估–改进–再评估”循环**：任务过难或过易时，修改问题陈述等语义内容并重新评估，直到进入目标难度范围；解决率为 0（过难）或 1（过易）的任务会被改进或丢弃。
- **与纯过滤的区别**：TaskPilot 不只是筛掉不合难度任务，还会**主动修改任务（如补充行为契约、移除实现定位信息）以校准难度**，见文中 optbinning 示例。

### 2.4 RL 训练配方

- 算法采用 **DPPO**（带不对称轨迹重要性采样），并借鉴 DAPO 的零方差组过滤。
- 每个 RL climb 包含 200 个更新；每轮 32 个任务组 × 8 条轨迹/任务 = 256 轨迹；策略权重跨轮继承，优化器与 RNG 状态重置。
- 训练与 rollout 异步执行：2 张 GPU 训练（上下文并行度2），6 张 GPU 推理生成轨迹。
- **效率奖励**：仅在成功轨迹上施加对数长度惩罚：
  \[
  R(N) =
  \begin{cases}
  1, & n \le N,\\
  1 - \alpha \ln(n/N), & n > N
  \end{cases}
  \]
  用于抑制过长的推理链；并给达到预算上限但任务已解决的部分成功轨迹 0.5 的奖励。

## 6. 论文的主要结论与发现

1. **无需蒸馏，合成任务即可训练出强力小模型**：仅靠 Qwen3.5-4B + RL + TaskPilot 合成的任务，达到 61.5% SWE-bench Verified，接近/超过多款 32B–100B 级开源与专有模型。

5. **工具使用行为可迁移到不同环境**：在未见过的 mini-SWE-agent（仅 bash 工具）上仍获得显著提升。
6. **行为漂移问题可通过“合并”部分恢复**：整合早期多工具并行调用行为能够改善效率或小幅提升最终性能。

## 8. 不足与局限

- **规模与语言覆盖**：训练数据基于 Python 为主的 SWE-rebench 仓库，对非英语、非 Python 生态、无可靠测试的项目适用性未验证；
