## 摘要
随着上下文长度扩展，注意力日益成为大型语言模型的主要计算瓶颈。标准Transformer仍然强大但计算效率低下，因为它们将相同的注意力预算分配给每个令牌，而不考虑其上下文需求。现有的局部-全局混合模型通过混合受限上下文注意力和全上下文注意力提供了更高效的替代方案，但它们通常在层或头之间静态分配跨度。为解决这些局限，我们提出LoGo，一种令牌级动态局部-全局注意力机制，利用注意力跨度作为注意力预算分配的直接代理。每个LoGo层包含耦合的局部和全局分支：所有令牌在受限上下文窗口内获得高效的局部注意力，而学习到的门控仅对需要长距离信息的令牌激活具有全上下文访问的全局注意力。基于阈值的预算控制器在没有辅助损失的情况下维持目标全局比率，渐进掩蔽调度在稀疏路由生效前稳定训练。我们进一步实现了查询稀疏的Triton内核，将减少的全局注意力计算转化为实际加速。大量实验验证了LoGo的有效性，表明它保留了全注意力Transformer在不同模型规模下的扩展行为。在受控比较中，LoGo优于全注意力Transformer和匹配预算的静态局部-全局混合模型，在长距离检索方面表现突出。分析进一步表明，LoGo学习了可解释的跨度分配模式。这些结果表明，学习到的令牌级跨度分配是改善长上下文性能-计算权衡的有效且可扩展的方法。

## Abstract
As context lengths scale, attention increasingly becomes a primary computational bottleneck in large language models. Standard Transformers remain powerful but computationally inefficient, as they allocate the same attention budget to every token regardless of its contextual demand. Existing local-global hybrids provide a more efficient alternative by mixing restricted- and full-context attention, but they typically allocate span statically across layers or heads. To address these limitations, we propose LoGo, a token-level dynamic local-global attention mechanism that uses attention span as a direct proxy for attention budget allocation. Each LoGo layer contains coupled local and global branches: all tokens receive efficient local attention over a restricted context window, while a learned gate activates global attention with full-context access only for tokens requiring long-range information. A threshold-based budget controller maintains a target global ratio without auxiliary losses, and a progressive masking schedule stabilizes training before sparse routing takes effect. We further implement query-sparse Triton kernels that convert reduced global-attention computation into practical speedups. Extensive experiments validate LoGo's effectiveness, showing that it preserves the scaling behavior of full-attention Transformers across model sizes. In controlled comparisons, LoGo improves over the full-attention Transformer and matched-budget static local-global hybrids, with clear gains on long-range retrieval. Analysis further shows that LoGo learns interpretable span allocation patterns. These results suggest that learned token-level span allocation is an effective and scalable way to improve the long-context performance-compute trade-off.

## 1. 核心问题与整体含义（研究动机与背景）

**核心问题**：随着大语言模型（LLM）上下文长度不断扩展，注意力机制的计算成本迅速增长，成为主导瓶颈。标准Transformer将所有计算均分给每个token，完全没有考虑不同token在预测难度与上下文需求上的显著差异。现有局部-全局混合注意力虽然通过混合受限与全上下文注意提高了效率，但分配方式是**静态**的——要么按层（inter-layer）固定交替，要么按头（intra-layer）固定分配，所有token在相同层/头中走完全相同的注意路径，无法根据单个token的实际需要动态调整访问跨度。

**LoGo的核心主张**：注意力跨度（attention span）可以作为注意力预算的直接代理——既决定可访问的上下文范围，又决定计算成本，且其需求往往可从上下文线索中预判（例如固定短语中的词只需局部线索，而跨长距离检索的词需要全局信息）。LoGo试图让模型在**训练过程中端到端学习**"哪类token需要全局注意"的分配策略，而非依靠手工规则或静态混合结构。

**研究意图**：该研究回答三个核心问题（RQ1-RQ3）：
- 模型能否学会token级别的局部/全局跨度分配，将稀缺的全局注意力花在最有需要的token上？
- 作为预训练骨干，LoGo能否保持标准Transformer的扩展行为（scaling behavior）？
- 在相同参数和FLOPs条件下，token级跨度分配能否相比静态局部-全局混合模型改善性能-计算权衡？

**整体含义**：这项工作探索了注意力条件计算的新方向——把"跨度"本身作为动态分配的决策单元，展示了在受控预算下通过端到端学习即可实现有效、可扩展的长上下文优化，而非依赖结构硬编码。

## 2. 方法论：LoGo的注意力机制

### 2.1 总体架构

LoGo每个注意力层包含**耦合的局部与全局双分支**，两分支使用相同的注意力形式（softmax attention），但可访问的跨度不同：

- **局部分支**：在短滑动窗口（w=128）内计算注意力，覆盖所有token；
- **全局分支**：在全因果前缀上计算注意力，仅对**被选中的query位置**激活；
- 未选中token的输出退化为纯局部结果；被选中token的输出为局部与全局的加权融合。

### 2.2 三个核心组件

**组件一：耦合的局部/全局分支**

- 局部与全局分支的QKV表示通过**共享主投影**获得局部特征（公式4），再通过**轻量变换**从局部表示派生全局表示（公式5）：LP变换（线性投影AU,h∈R^{dh×dh}）或SO变换（逐元素缩放+偏移）。
- 变换初始化为恒等映射，两分支共享起点后随训练逐渐特化，参数增量约为~1%。
- 分支输出通过ContextNorm（逐头RMSNorm）规范化，防止门控因分支幅度差异而被"污染"。

**组件二：Token级跨度偏好门控**

- 通过标量门向量w_g将每个token的隐藏状态映射为局部-全局偏好分数：
  p_t^(ℓ) = sigmoid(x_t^(ℓ)ᵀ w_g^(ℓ))
- 用**层特定自适应阈值**b_th将连续偏好转为硬路由决策：
  z_t^(ℓ) = I[p_t^(ℓ) > b_th^(ℓ)]
- 融合权重采用竞争式配对（weighted fusion）：被选中token的输出为 (1−p_t)·局部输出 + p_t·全局输出，使门控在两种跨度间显式竞争。

**组件三：基于阈值的预算控制器 + 渐进掩码（P-mask）**

- 预算控制无需辅助损失，通过批量路由统计量调整阈值：
  b_th^(ℓ) ← b_th^(ℓ) + γ·sign(F^(ℓ) − ρ^(ℓ))
  其中F^(ℓ)为实际激活比例，ρ^(ℓ)为目标比例，γ为更新率。
- **渐进掩码**：初始阈值设为负值使所有token先激活全局注意，从而在稀疏路由生效前让门控与双分支先获得密集监督信号训练。阈值按设定步数逐步升至0.5（门控初始中心），从而渐进引入稀疏性。

### 2.3 高效实现（Query-Sparse Triton内核）

- 全局分支以**query行稀疏**的方式计算：选中的query被压缩到紧凑张量中，同时在KV侧保留原始的密集键值，不丢失全上下文语义。
- 前向计算通过紧凑cu_seqlens保存真实序列位置以施加正确的因果掩码。
- 反向传播镜像同一行稀疏结构：仅对选中行写入query梯度，KV梯度按因果有效的选中query块累积。
- 设计避免了头级负载不均（头间共享同一token级路由），并兼容张量并行和序列并行。
- **解码阶段**：未被选中的token跳过全局调用；批量解码采用保守策略，仅在整个微批次无选中行时才跳过全局调用。
- **复杂度**：单层总注意力复杂度为 O(TwHdh + ρ^(ℓ)T²Hdh)，与同比例静态混合的主导计算量一致，但实现了跨token动态分配。

## 6. 主要结论与发现

1. **扩展性保持**：在200M到3.3B范围内，LoGo一致地匹配或优于全注意力Transformer（训练损失更低、Wiki/Lambada PPL更低、常识推理精度相当或更高），证明token级跨度分配不损害骨干的可扩展性。

2. **受控对比优势**：在1.5B、100B token预训练后，LoGo取得了最高的语言建模性能（训练损失2.112，低于Transformer的2.119和静态混合的2.121/2.122）、最佳Lambada准确率（56.57 vs Transformer 53.97）、最低Lambada PPL（7.50 vs 8.36）。

3. **长距离记忆的显著提升**：RULER任务中LoGo的优势随序列长度扩大——32k CT平均83.0分（Transformer 78.9分），128k CT平均65.4分（Transformer 58.1分），整体比全注意力高出约7个百分点，多针任务提升尤为明显。

4. **短上下文表现持平**：在短上下文召回任务上LoGo与全注意力Transformer基本持平（57.65 vs 57.52），优于inter-layer但略低于intra-layer基线。

5. **实现效率**：query-sparse Triton核实现了接近理想比例的实际加速——在50%预算下64k序列长度加速1.99×；高稀疏度（10%-25%）下甚至优于CUDA密集FlashAttention。

6. **可解释性**：LoGo学习到了有意义且可解释的跨度分配模式：序列开头多用局部、句子开头倾向全局、固定短语趋于局部、长距重复触发强全局激活、上下文切换后快速降低全局使用。

7. **消融验证**：确认了轻量LP解耦、ContextNorm、加权竞争融合、无辅助损失阈值控制、渐进掩码的各自必要性。

- **实验方法论规范**：在匹配参数与FLOPs条件下与两代静态混合范式对比，控制了变量、验证了性能-计算权衡的真实改善，而非只报告质量提升。这是该领域中较稀缺的实验严谨性。

- **附带可解释性分析**：从mask级统计到词级可视化，证明分配模式语义上与语言学的直觉一致（长程重复/上下文切换等），增强了方法的可信度和未来改进空间。

## 8. 不足与局限

- **缺乏更大规模的验证**：3.3B是最大的参数量训练，这限制了"scaling behavior保持"这一核心结论的普遍性——LLM实际应用动辄7B及以上，更大幅度下路由学习是否仍然稳定尚不明确。

- **无与直接相关动态注意力方法的实验对比**：论文只在Related Work中文字性地与其他动态注意力方法（CoLT5、SMA等）区分，却没有在受控同等条件下与它们做实验对比，这削弱了其声称"更优"的证据强度。

- **算力资源披露不足**：全文未交代GPU型号数量、训练墙钟时间、能源开销等关键信息，不利于社区对其成本效益作客观判断，也阻碍复现。

- **预训练语料不公开**：使用了非公开的in-house语料，意味着第三方即便获得代码也难以独立复现论文的主要结论。

- **实现效率存在争议空间**：Triton实现仅在高稀疏度(≤25%)下快于CUDA密集FlashAttention，50%预算下落后CUDA密集内核（约1.99×是相对同语言Triton的加速）；论文承认了该差距，意味着还需CUDA级工程优化才能实际达到部署效益。

- **内存节省有限**：LoGo保留密集KV缓存O(T)，与全注意力相同，本身不带来KV缓存内存节省——对推理内存瓶颈改善有限，需要与其他记忆优化方案组合才能全面受益。

- **受控实验仅1.5B规模下进行**：大规模（如33B+）语境下的"静态混合 vs LoGo"结论仍有待检验；不同预算比例下LoGo与静态混合的短上下文记忆差异也有部分波动（如FDA的代价）。

- **动态路由的收敛稳定性风险**：阈值控制器依赖手工设定的γ和渐进掩码时长，对不同数据分布/不同模型大小的灵敏度未做系统扫描，存在工程调参的不确定性。

- **缺乏多语言与代码专项评测**：虽然分析中提到了对代码域的可视化，但性能层面对代码、多语言等任务没有定量评测。
