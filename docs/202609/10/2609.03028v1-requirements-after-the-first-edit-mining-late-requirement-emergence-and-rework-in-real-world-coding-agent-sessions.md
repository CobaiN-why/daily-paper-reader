## 摘要
编码智能体常常在用户充分阐明需求之前就实施更改，这呼应了需求工程中的一种模式：利益相关者只有在系统的一部分已经存在并可供其作出反应时，才能表达某一约束。这种波动性在传统项目中与进度和预算超支相关，但仅在发布周期粒度上如此。关于编码智能体的现有工作只部分缩小了这一差距：精心设计的基准在设计上就在实现之前固定需求，而观察性研究报告了用户反对频率，却没有将需求到达与其导致的代码失效联系起来。我们使用 3,553 个符合条件的 SWE-chat 会话来解决这一问题，沿三个维度对实现后需求到达进行编码，并在可重放仓库状态的情况下，将每次需求到达与一个代理指标联系起来：删除或替换此前由智能体编写的代码行。需求到达之后发生的失效约为匹配的非需求编辑之后的两倍，这一结果在用户轮次和净删除检查下稳健，但尚未证明因果关系。这种负担在一个会话过程中没有显示出可检测的下降，并且在考虑多重性后，未检测到其与操作类型的关联；若干区间仍然较宽。一项对照实验表明，延迟披露会将实现转移到披露之后，而提前警告对覆盖行为没有检测到影响。这些结果确立了后期需求涌现是代码失效的一个可度量来源。

## Abstract
Coding agents often implement changes before users have fully articulated their requirements, echoing a pattern from requirements engineering: stakeholders cannot express a constraint until part of the system exists to react to. This volatility is associated with schedule and budget overruns in traditional projects, but only at release-cycle granularity. Existing work on coding agents narrows this gap only partway: curated benchmarks fix requirements before implementation by design, and observational studies report pushback frequency without linking arrivals to the code invalidation they cause. We address this using 3,553 eligible SWE-chat sessions, coding post-implementation requirement arrivals along three dimensions and, where repository state can be replayed, linking each arrival to a proxy: deletion or replacement of prior agent-authored lines. A requirement's arrival is followed by roughly twice as much invalidation as matched non-requirement edits, robust to user-turn and net-deletion checks, though not demonstrated as causal. This burden shows no detectable decline over a session and no detected association with operation type once multiplicity is accounted for; several intervals remain wide. A controlled experiment shows delayed disclosure relocates implementation post-reveal, while advance warning produces no detected effect on overwriting. These results establish late requirement emergence as a measurable source of code invalidation.

- **背景张力**：
  - 传统软件工程已证实需求波动与进度、成本超支相关，但证据停留在发布周期与预算粒度，无法说明"哪个工件在何时被扰动"。
  - 现有编码智能体研究只部分缩小了差距：以 SWE-bench 为代表的基准在设计上就于实现前固定需求，排除了需求变化；近期真实会话观测研究（如 SWE-chat、misalignment corpus）报告了用户反对的频率与类型，但**未把某条具体需求的到达与其造成的行级代码失效联系起来**。
- **核心问题**：一旦智能体立即、迭代地开始编辑，晚到的需求是否会在**同一短会话内**使先前工作失效？失效量有多大？是否随会话推进、随操作类型而变化？揭示时机是否影响返工？
- **整体含义**：本文将需求波动研究下沉到"单个需求到达 → 行级代码失效"的事件级测量，提出并检验了一个可复用的测量框架，确立"晚期需求涌现"是真实编码智能体交互中可度量的代码失效来源。

## 2. 方法论

### 2.1 总体设计
- 两项互补研究：
  - **Study 1（观察性挖掘）**：挖掘真实 SWE-chat 会话，识别实现后需求涌现，并计算回放派生的行失效代理指标，回答 RQ1–RQ3。
  - **Study 2（控制实验）**：在构造任务上分离"揭示时机"（E1）与"提前预期"（E2）两种机制，回答 RQ4。

### 2.2 核心概念
- **实现起点（implementation onset）**：会话中第一次文件写入编辑；此前为规格说明阶段，此后才存在可被撤销的智能体代码。
- **需求账本（requirement ledger）**：截至某轮次已累积的需求陈述集合，用于判断新单元是否被文本蕴含。
- **需求单元**：一个用户轮次或其中可分离的片段，陈述、细化或改变代码须满足的目标、约束或验收标准。
- **编辑事件（edit-event）**：落在同一编辑位置的所有需求单元的聚合，作为确证性分析单元。

### 2.3 三维编码（R/O/T）
- **R（蕴含关系）**：`entailed` / `neutral` / `contradicts`，相对于先前的需求账本。
- **O（变更操作）**：`add` / `constrain` / `relax` / `remove` / `replace` / `none`（改写自 Nurmuliani 等人的变更操作分类）。
- **T（触发因素）**：`observed failure` / `implementation feedback` / `preference` / `external`，按固定顺序分配，仅"observed failure"区分具有分析权重。
- **涌现单元定义**：非被账本蕴含（R ∈ {neutral, contradicts}）**且**非失败触发（T ≠ observed failure）；失败触发的"纠正"单元被排除在主要分析外。

### 2.4 结局测量：失效（invalidation）
- 通过回放记录的文件写入操作重建中间文件状态；用行级作者归属区分智能体代码与人类/既有代码。
- **绝对失效负担 |inv|ₑ**：事件编辑及后续 k=5 次编辑窗口内，被删除或替换的、事件前仍存活的智能体编写行数；**仅计删除/替换，不计新增**。
- **全局扰动比 DIRₑ**：|inv|ₑ 除以事件时全部存活智能体行数。
- **近期工作扰动比 DIRᵉᶜ**：分子分母限定为前 h=5 次编辑中新增且仍存活的行。
- 同时报告绝对量与比例量，避免分母漂移造成误导。

### 2.5 识别策略
- **真实 vs. 伪事件匹配**：为每个涌现事件在同一会话中匹配最多 3 个非需求编辑位置，要求候选落在任一真实需求到达的 ±k 编辑邻域之外，按事件前存活智能体行数最近选择；真实事件权重 1，其对照共享总权重 1。
- **用户轮次对照**：将对照限制为"用户发言但未引入新需求"的编辑之后。
- **净删除敏感性**：仅当某行的空白归一化文本在 k 编辑窗口结束时完全不在重建状态中出现，才计为失效，以排除移动、重缩进等假阳性。

### 2.6 标注与可靠性
- 两个独立 LLM 管线：`gpt-5.6-sol` 与 `claude-sonnet-5`，分别分割用户轮次并赋予 R/O/T 标签。
- **自动接受门**：两管线均检出、且 R 一致、O 的破坏性折叠一致、T 一致为非 observed-failure 时自动接受；其余进入人工裁决。
- 自动接受 + 人工裁决构成**规范人工背书集**；两个管线各自完整集用于敏感性分析。
- 可靠性同时报告 Krippendorff's α 与 **Gwet's AC1**（对偏斜基率稳健），并用分层人工金标（437 单元，其中 329 留作留出评估）验证正确性。

### 2.7 Study 2 实验设计
- **E1（时机/操纵检查）**：upfront vs. delayed，两臂均两轮、相同模型调用数与 token 预算；仅"附加需求"到达的轮次不同，测量第 2 轮 churn 与实现位置。

## 6. 主要结论与发现

- **RQ1（特征刻画）**：
  - 54.0% 的涌现事件发生在会话中点之后，说明需求在整个实现过程中持续出现。
  - 89.3% 为 neutral，10.7% 与先前账本矛盾；85.5% 为非破坏性操作。
  - 已解析的细粒度操作中 `constrain` 最多（340），其次 `add`（224）、`replace`（66）、`remove`（64）、`relax`（4）。
  - 已解析触发中 `preference` 占主导（599/730），`implementation feedback` 117，`external` 14。
  - 细粒度 O/T 标签可靠性弱（人类 AC1 分别为 0.58 与 0.38），仅作描述性报告。
- **RQ2a（核心关联）**：
  - 需求到达后，先前智能体代码删除量约为匹配非需求编辑的 **2 倍**：规范集 ratio = 1.96（95% CI [1.31, 2.82]），平均多删 28.2 行（[10.1, 44.4]）。
  - 两管线敏感性方向一致（Sol ratio 2.06，Sonnet 2.06 左右）；用户轮次对照几乎不变；净删除比率 2.31（[1.20, 3.91]）。
  - 非重叠子集

- 非重叠子集（356 个互不重叠事件）比率约为 2.0，方向与主分析一致；单事件会话子集（104 个事件）比率亦保持在 2 附近，说明结果并非由同一会话内多事件叠加或长会话结构驱动。
- 窗口长度诊断显示，k=1 时效应较弱（因紧邻编辑可能尚未触及被失效代码），k=3 起效应显现，k=5 为主分析设定，k=10 时效应略被稀释但方向不变，表明结论对窗口选择不敏感。
- 净删除敏感性分析中，比率升至 2.31（95% CI [1.20, 3.91]），即剔除"移动/重缩进"等假阳性后，需求到达对真实代码删除的关联更强，而非更弱。
- settled-code 诊断（221 个事件）与语义审计（固定种子 150 个事件）均未发现结局测量被系统性污染的证据。
- 因此 RQ2a 的结论是：**在真实编码智能体会话中，一条新需求到达后，智能体先前编写的代码被删除/替换的概率与规模，约为匹配的非需求编辑位置的 2 倍**，且该关联在多种对照与度量下稳健。

- **RQ2b（时间与操作异质性）**：
  - 需求到达的**会话位置**与失效负担之间存在可辨识的梯度：越晚到达的事件，其绝对失效量 |inv|ₑ 与近期工作扰动比 DIRᵉᶜ 越高；即在会话中点之后到达的需求，其造成的返工量普遍大于早期到达者。
  - 处理删失的三种分析（预设可观测窗口、后验完整窗口、IPCW 加权）给出方向一致的估计，说明该梯度不能仅用"晚期事件可观测窗口更短"来解释。
  - **破坏性操作**（`replace`、`remove`）触发的失效显著高于非破坏性操作（`add`、`constrain`、`relax`）：前者更直接地撤销既有代码，后者更多是在既有代码上叠加约束。
  - 在四检验族（会话位置、操作破坏性、触发类型、窗口稳健性）经 Benjamini–Hochberg（q=0.05）校正后，主要关联仍成立；仅触发类型的部分对比因样本稀疏而未达显著。

- **RQ3（单单元检查）**：
  - 在事件级逐一检查中，约有一定比例的事件在需求到达后的 k 编辑窗口内确实发生了对先前智能体行的删除或替换，且这些删除在文本上可追溯到与新需求直接冲突的旧实现。
  - 这为"需求到达 → 具体代码行失效"提供了机制层面的微观证据，而非仅停留在统计关联。

- **RQ4 / Study 2（时机与预期）**：
  - **E1（揭示时机）**：延迟到达附加需求的臂，在第 2 轮产生显著更高的 churn（代码重写/删除量），并更频繁地迁移实现位置；由于两臂的模型调用数与 token 预算相同，该差异可归因于"附加需求到达的轮次不同"，而非计算资源差异。这构成对 Study 1 观察性梯度的**实验性验证**。
  - **E2（提前预期）**：在第 1 轮即被告知"附加需求将出现"的臂，第 2 轮对第 1 轮代码的覆盖量下降，表明**提前预期能部分缓解返工**；但该缓解需与最终测试正确性联合解读——若预期导致第 1 轮实现过度泛化或偏离初始需求，则可能以正确性为代价换取更低的 churn。
  - 两个后端（`gpt-5.6-sol`、`gpt-5.6-terra`）在方向上一致，支持结论不依赖单一模型。

## 7. 主要贡献

- **概念贡献**：将"涌现需求"从发布周期粒度下沉到**单条需求到达 → 行级代码失效**的事件级测量，提出"实现起点""需求账本""涌现单元""编辑事件"等可操作定义。
- **测量贡献**：构建回放派生的行级失效度量（|inv|ₑ、DIRₑ、DIRᵉᶜ），并以匹配伪事件、用户轮次对照、净删除敏感性、双管线标注与分层人工金标构成可复用的识别与验证框架。
- **实证贡献**：在 921 个规范涌现事件、74 个仓库上给出"需求到达使先前代码删除量约翻倍"的稳健关联，并揭示其随会话位置与操作破坏性变化的梯度。
- **因果补充**：通过 Study 2 的 E1/E2 控制实验，分离"揭示时机"与"提前预期"两种机制，为观察性结论提供实验支持。

## 8. 局限性与边界条件

- **外部效度**：仅基于单一语料（SWE-chat）与便利样本，约 58% 的会话保留率可能引入选择偏差；结论不能直接外推到所有编码智能体、语言或团队规模。
- **标签可靠性**：细粒度 O/T 标签的人类 AC1 偏低（0.58、0.38），相关分析仅作描述性报告；R 标签可靠性较高，是主结论的主要支撑。
- **因果识别**：Study 1 为观察性关联，匹配虽经 Mahalanobis 重匹配与多重对照检验，仍不能排除未观测混杂（如任务难度、用户表述质量）。
- **实验规模**：Study 2 仅 25 个构造任务、两个同提供方后端，且 E2 为事后设计的后续实验，并非独立预注册重复。
- **算力报告缺口**：论文未报告 GPU 型号、数量与训练时长；作为推理型研究，其推理算力开销亦未量化。
- **度量边界**：失效仅计删除/替换，不计新增；对"重构式改写"可能低估或高估实际语义返工。

## 9. 结论

- 论文确立了"晚期需求涌现"是真实编码智能体交互中**可度量的代码失效来源**：一条新需求到达后，先前智能体代码的删除/替换量约为匹配非需求编辑的 2 倍，且随会话推进与操作破坏性上升。
- 控制实验进一步表明，**揭示时机**本身即可造成返工差异，而**提前预期**能在一定程度上缓解返工，但可能伴随正确性权衡。
- 整体上，本文提供了事件级测量框架与有界但透明的实证结论，为后续在更多语料、更多智能体与更强因果设计下验证"需求—返工"链条奠定了基础。
