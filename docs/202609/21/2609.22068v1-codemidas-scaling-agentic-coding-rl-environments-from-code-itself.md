## 摘要
通过强化学习（RL）训练能力强的编码智能体，需要有多样化任务以及可靠的验证器。开源代码库为此类任务提供了丰富来源，但现有方法通常依赖 issues 和 commits 等开发工件，限制了可提取任务的范围。为了更好地扩展 RL 环境，我们提出 CodeMidas，一种智能体流水线，仅以源代码作为其唯一的任务特定输入，将现有代码库中已实现的功能转化为可执行的 RL 环境。CodeMidas 将智能体计算分配到环境构建的每个阶段：智能体探索已实现的功能以形成行为规范，基于原始代码的执行构建测试，并通过执行检查和重复求解 rollout 来验证和过滤候选任务。最终数据集包含来自 3,185 个开源代码库的 5,545 个训练任务，涵盖 23 种编程语言和 15 个技术领域。使用 GRPO 在这些任务上训练 MiMo-V2.5，在五个多样化基准上均提升了性能，涵盖 issue 修复（DeepSWE +11.7%）、完整程序构建（ProgramBench +17%）和终端任务（Terminal-Bench v2.1 +8.5%）。消融实验表明，增加高质量训练任务的数量可以提升性能。轨迹分析显示，经 RL 训练的智能体表现出更好的行为，例如增加代码库探索和更多样化的自我验证。这些结果确立了源代码作为构建 RL 环境的可扩展基础，从而提升编码智能体在多样化软件任务上的表现。

## Abstract
Training capable coding agents via reinforcement learning (RL) requires diverse tasks with reliable verifiers. Open-source codebases offer a rich source of such tasks, while existing methods typically rely on development artifacts such as issues and commits, limiting the range of tasks that can be extracted. To better scale RL environments, we present CodeMidas, an agentic pipeline that turns implemented functionality in existing codebases into executable RL environments using source code as its only task-specific input. CodeMidas allocates agentic compute to every stage of environment construction: agents explore implemented functionality to formulate behavioral specifications, construct tests grounded in execution of the original code, and validate and filter candidate tasks through execution checks and repeated solution rollouts. The resulting dataset has 5,545 training tasks from 3,185 open-source codebases spanning 23 programming languages and 15 technical domains. Training MiMo-V2.5 on these tasks with GRPO improves performance on all five diverse benchmarks, covering issue repair (DeepSWE + 11.7%), whole-program construction (ProgramBench +17%), and terminal work (Terminal-Bench v2.1 +8.5%). Ablations show that increasing the number of high-quality training tasks improves performance. Trajectory analysis shows the RL-trained agent demonstrates better behaviors like increasing codebase exploration and more diverse self-verification. These results establish source code as a scalable foundation for constructing RL environments that improve coding agents across diverse software tasks.

- **背景**：用强化学习（RL）训练编码智能体，需要同时满足两个条件——**任务足够多样**（支撑泛化）与**奖励足够可靠**（可靠验证器）。

- **论文主张**：**源代码本身**即可作为唯一的任务特定输入。已实现的功能天然同时提供"任务定义"和"参考答案"：公共接口与可观测行为定义"要实现什么"，执行原始代码提供测试期望，周边代码库提供真实项目起点。论文用 Table 1 论证 CodeMidas 是唯一不需要 issue/PR/commit/已有测试/书面描述的方法，且覆盖 23 种语言。

## 2. 方法论

### 2.1 总体思想
CodeMidas 是一条**智能体流水线**，把每个阶段的计算都交给 agent，产出"任务陈述 + 容器化开发环境 + 隐藏可执行验证器"三元组。验证器全程置于求解环境之外，仅在判分时注入，返回 0/1 二值执行奖励。

### 2.2 四个核心模块

- **模块 1：任务设计与代码库适配**
  - agent 检查代码库结构与构建元数据，识别具备**公共入口点**与**可观测结果**的功能；
  - 支持三类接口：命令行工具（看进程输出）、纯库函数（看返回值）、有状态库 API（看跨调用状态变化）；
  - 追踪公共入口与共享依赖来划定任务范围，随后**删除选定的核心实现**，调整剩余代码形成连贯的开发起点；
  - 原始实现单独保留为**参考解**；
  - 任务陈述只规定输入、可观测行为、必需公共接口，**内部实现细节保持开放**。

- **模块 2：基于执行的测试构造**
  - agent 把陈述中的行为需求映射为测试输入与边界用例，在参考副本上调用公共入口并记录结果；
  - 测试形态匹配接口类型：CLI 用命令执行、纯函数用输入-输出、有状态 API 用调用序列（含顺序与清理行为）；
  - **每个测试记录它覆盖的具体需求**；陈述固定的输出用参考执行确定期望值，未规定的方面只检查已声明约束（如"必须抛某类异常"但不锁定异常消息措辞）；
  - agent 逐条审查断言中**陈述不支持的约束**（精确措辞、偶然顺序、内部结构），替换为行为检查；若断言依赖私有符号且无行为替代，则任务被拒；
  - 修改后的测试在参考解上重跑以确认兼容性；最终测试输入与断言冻结用于判分。

- **模块 3：环境准备与执行一致性**
  - 从统一基础镜像出发安装依赖、准备构建/运行资源；
  - **清理会泄露被删实现的产物**：编译输出、缓存副本、构造 agent 留下的文件；同时移除与目标功能相关的原始测试；
  - **执行一致性检查**：在训练运行时设置下用 6 个全新容器验证——2 个放起始代码库（必须失败）、4 个放参考解（必须通过），既检查 fail-to-pass 转移，也筛查执行不稳定。

- **模块 4：基于 rollout 的事后过滤**
  - **泄露过滤**：对抗性 rollout 主动搜索求解者可见环境（编译产物、缓存、构造残留、已安装的目标项目副本）以"白拿"答案，记录支撑证据的命令与输出，由独立审查对照参考解与验证器裁定，确认可绕过即拒。
  - **解法一致性审查**：每任务让编码 agent 尝试 4 次，审查 agent 结合轨迹、提交代码、测试输出、陈述、验证器与参考解，判断实现是否满足陈述，并标记**假阳性**（错解通过测试）与**假阴性**（正解未通过），存在验证器缺陷即拒。
  - **rollout 结果过滤**：前沿模型每任务多次尝试，**只保留既有成功也有失败的任务**（全通过或全失败无法区分"太难"与"任务缺陷"）。

## 6. 消融实验

- **质量 vs 数量的核心对照**：过滤后的高质量子集（1k / 3k / 5k）与未过滤的 8k"vanilla"任务池对比。

- 各过滤阶段的边际贡献：环境清理消除泄露捷径、执行一致性检查剔除不稳定任务、三步事后过滤（泄露过滤 / 解法一致性 / rollout 结果）排除假阳性与假阴性——消融显示这些环节对最终效果均有正向作用。
