## 摘要
尽管有效，编程智能体常常产生可观的经济成本。其反复出现的成本低效行为仍未得到充分探索。我们开展了首个针对编程智能体行为性成本低效的研究，分析了 SWE-bench Verified 上四种配置下 Claude Code 和 Mini-SWE-Agent 的 1,200 条轨迹。我们识别出三种成本低效行为：被包含的检索、相似脚本生成和测试重复执行。随后，我们在留出的 SWE-bench Verified 和 Pro 任务上，对超过 1 万条轨迹评估了三种缓解策略：结构感知检索、智能体合成技能和开发者设计技能。我们的主要发现是：(1) 这三种行为影响 79.00%–98.00% 的编程任务，并最高占任务成本的 22.75%。(2) 结构感知检索可能引入检索开销并改变智能体委派，导致检索效率提升不一致，成本增加最高达 28.14%。(3) 智能体合成技能倾向于产生低层次、特定于轨迹的指导，限制其有效性和通用性。(4) 相比之下，开发者设计技能提供高层次、与轨迹无关的指导，将成本降低最高达 41.73%，约为智能体合成技能最大收益的两倍。

## Abstract
Although effective, coding agents often incur substantial monetary costs. Their recurring cost-inefficient behaviors remain underexplored. We conduct the first study of behavioral cost inefficiencies in coding agents, analyzing 1,200 trajectories from Claude Code and Mini-SWE-Agent across four configurations on SWE-bench Verified. We identify three cost-inefficient behaviors: subsumed retrieval, similar script generation, and test re-execution. We then evaluate three mitigation strategies: structure-aware retrieval, agent-synthesized skills, and developer-designed skills, over 10k trajectories on held-out SWE-bench Verified and Pro tasks. Our main findings are: (1) The three behaviors affect 79.00\%--98.00\% of coding tasks and account for up to 22.75\% of task cost. (2) Structure-aware retrieval can introduce retrieval overhead and alter agent delegation, causing inconsistent improvements in retrieval efficiency and cost increases of up to 28.14\%. (3) Agent-synthesized skills tend to produce low-level, trace-specific guidance, limiting their effectiveness and generality. (4) In contrast, developer-designed skills provide high-level, trace-agnostic guidance, reducing cost by up to 41.73\%, roughly twice the maximum gain from agent-synthesized skills.

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想

- 先用**作者定义的 18 类动作标签体系**（五类：检索、修改、验证、Git、其他）将不同框架的轨迹统一投影到共享词汇，再针对三类行为设计检测器，量化其流行度、频率与货币成本贡献。
- 然后评估三种缓解策略：结构感知检索、智能体合成技能、开发者设计技能。

### 2.2 三类成本低效行为的定义与检测

- **子集检索（SubRetrv）**：检索完全被先前检索覆盖的代码。
  - 检测：对每个返回 ≥5 行非空内容的检索 b，向后扫描，找到第一个返回上下文完全覆盖 b 的动作 a，标记 (a,b) 为一对 SubRetrv。
- **相似脚本生成（SimScrpt）**：用微小变化重新生成高度相似的脚本，而非编辑现有脚本。
  - 检测：提取临时脚本（`python -c`、heredoc）与文件脚本（`.py`），去除空行与注释行，保留 ≥5 行；对每个生成动作 b，找最近的前序动作 a，其脚本行级 Jaccard 相似度 ≥0.60，标记为一对。
- **测试重执行（ReTest）**：在未更新补丁的情况下重复执行相同测试。
  - 检测：按补丁间窗口划分轨迹；窗口内按执行的测试分组，保留最后一次执行，前面标记为 ReTest。

### 2.3 成本归因

- 使用 tiktoken 的 o200k base 分词器统计被标记动作的推理、命令与工具输出 token 数。
- 生成内容按输出 token 价格计费；生成内容与工具输出在后续 LLM 请求中按输入/缓存 token 计费，汇总得到该动作的归因成本。

### 2.4 三种缓解策略

- **结构感知检索（CodeGraph）**：基于 AST 的代码符号与关系索引，CC 通过 MCP 服务器（7 个功能）访问，MSA 通过 `cgsrc`/`cg` 命令行访问；索引每任务预建，编辑后自动刷新。
- **智能体合成技能（SynSkills）**：
  - 构建轻量分析代理（ReAct 循环，温度 0，每次调用 ≤8192 token，每轨迹 ≤50 步），配备四个只读工具（`get_skeleton`、`get_step`、`get_gt_patch`、`get_agent_submission`）。
  - 按行为成本占比排序，前 25% 轨迹用代理分析，其余受影响轨迹用单次 LLM 调用处理；最后用 Trace2Skill 层次化合并为每配置一套技能。
  - 每配置生成 23–41 条操作规则，具体、场景化。
- **开发者设计技能（DevSkills）**：从 RQ1 发现中人工提炼的 7 条通用行为原则，所有配置共享，要求高层次、与轨迹无关。七条原则为：读取前先假设、复用上下文、仅做定向补丁、先理解测试框架、捕获测试输出而非重跑、持久化制品并有意图地版本化、打破循环。

## 6. 主要结论与发现

### 6.1 RQ1：三类行为普遍且昂贵

- 三种行为合计影响 **79.00%–98.00%** 的任务，占任务货币成本的 **6.86%–22.75%**；CC 整体低效水平最低。
- **SubRetrv 最普遍**：影响 64.33%–92.33% 任务，每任务 2.15–6.37 次，占成本 5.01%–11.41%。CC 中主要源于重读子代理已检索代码（跨代理 SubRetrv 占 50.15%）；MSA 主要源于放大定位、低反馈编辑与长调试循环。检索量本身不决定严重程度，架构如何管理上下文更关键。
- **SimScrpt**：影响最高 68.00% 任务，占成本最高 9.57%；在 MSA 中发生频率是 CC 的 **5.91–9.98 倍**。CC 的内置指令将 SimScrpt 主要限制为临时脚本，MSA 还会重复生成文件式测试与编辑脚本。
- **ReTest**：影响 49.67%–83.00% 任务，占成本最高 5.39%；MSA MM3 最严重（平均 5.29 次/任务）。主要成因：仓库特定测试知识缺口、测试信号恢复、进度停滞。
- 时间分布：SubRetrv 集中在前半段，ReTest 偏向中后段，SimScrpt 分布较广。

### 6.2 RQ2：结构感知检索不必然成本高效

- CodeGraph 不能一致降低 SubRetrv，也不能改善任务成本效率。
- CC 下 SubRetrv 降幅超 75%，但成本在 Verified-200 上升 8.30%、Pro-100 稳健上升 12.19%。原因：CodeGraph 反馈冗长（每查询 token 是其他检索的 8.2–16.6 倍），且 H45 子代理调用降至零，约相同 token 量转移到价格贵 3 倍的 S46 主代理。
- MSA 下六个设置中四个 SubRetrv 增加；智能体将 CodeGraph 叠加在普通检索之上，而非替代，总 token 增加 9.11%–29.29%，成本稳健增加 8.39%–28.14%。
- 结论：**大幅降低 SubRetrv 不保证端到端成本下降**；结构感知检索应关注反馈量、工具集成与模型编排。

### 6.3 RQ3：开发者设计技能显著优于智能体合成技能

- **SynSkills**：在 8 个设置中 3 个稳健降本 8.86%–22.32%，无稳健成本增加或 Pass@1 退化；但摊销合成成本后优势基本消失，仅 MSA MM3 在 Pro-100 保持稳健降本（-9.65%），MSA Q35+ 反而稳健增加。
- **DevSkills**：8 个设置中 6 个稳健降本 **7.88%–41.73%**，约为 SynSkills 最大收益的两倍；仅 CC 在 Verified-200 有 1.50 pp 的 Pass@1 小降。行为层面同样更优，例如 MSA S46 在 SubRetrv 上降 51.52%/43.57%，而 SynSkills 仅 11.38% 与 +2.50%。
- **机制解释**：SynSkills 倾向产生低层次、轨迹特定指导（如处理特定 shell 引号

），而 DevSkills 提供高层次、可迁移的原则（如"读取前先假设"），因此在不同任务与配置间泛化更好。此外，DevSkills 直接作用于行为根因，而 SynSkills 往往只是复制已有轨迹中的表层模式，难以改变智能体的默认执行策略。

### 6.4 跨 RQ 的综合发现

- **行为级降本 ≠ 任务级降本**：CodeGraph 在 CC 下将 SubRetrv 削减超 75%，但端到端成本反而上升，说明成本效率由检索反馈量、模型定价层级与工具编排共同决定，而非单一行为频次。
- **技能来源比技能数量更重要**：DevSkills 仅 7 条原则即可在 6/8 设置中稳健降本 7.88%–41.73%，而 SynSkills 每配置生成 23–41 条规则，摊销后优势大多消失。这提示"少而通用"的人工先验在成本效率上优于"多而具体"的自动合成。
- **框架与模型的交互**：CC 的低效水平整体最低，得益于内置指令与子代理委派；MSA 的低效更依赖所选模型，MM3 在 ReTest 上最严重，Q35+ 在 CodeGraph 下成本增幅最大，说明缓解策略需与模型能力匹配。

## 7. 讨论与实践启示

- **对智能体框架设计者**：
  - 应显式管理跨代理上下文，避免子代理检索结果被主代理重复读取（跨代理 SubRetrv 在 CC 中占 50.15%）。
  - 结构感知检索工具应控制单次返回的 token 量，并考虑将其集成到主代理而非高价主代理层，否则可能把成本从子代理转移到更贵的模型上。
  - 内置行为约束（如限制脚本重复生成）可显著抑制 SimScrpt，CC 的经验表明框架级指令比事后技能注入更有效。
- **对智能体使用者/团队**：
  - 关注执行过程中的行为模式，而非仅看总 token 或通过率；本文检测器可复用于自有轨迹的成本审计。
  - 优先采用少量、高层次的行为原则（如 DevSkills 的七条），而非依赖自动合成的细粒度技能，后者摊销合成成本后收益有限。
  - 在引入新工具（如 CodeGraph）时，应同时监测任务级成本与 CoP，避免"行为改善但账单上升"。
- **对研究者**：
  - 行为性成本低效是一个可系统化、可量化的研究维度，本文的 18 类动作标签与三类检测器可作为后续工作的基础。
  - 需要更多工作探索如何在降低行为频次的同时不引入额外 token 开销，以及如何设计跨模型、跨框架通用的成本效率技能。

## 8. 局限与未来工作

- **执行随机性**：受预算限制，仅 9 个方法单元进行三重复，其余 15 个单次运行，依赖等方差假设转移噪声地板；行为级指标噪声大，未给出稳健性判定。虽然压力测试显示主要成本结论稳健，但单次运行的方法单元仍可能存在未被捕获的方差。
- **基准覆盖**：RQ1 在 SWE-bench Verified 的 300 个早期任务上分析，RQ2–RQ3 使用 Verified-200 与 Pro-100，虽覆盖多仓库，但仍限于 SWE-bench 系列，结论对其他编程任务（如前端、数据科学、长周期项目）的泛化性有待验证。
- **行为检测的完备性**：三类行为由人工定义与校准，可能遗漏其他成本低效模式（如过度规划、无效 Git 操作、冗余工具调用），18 类标签体系也依赖框架动作的可映射性。
- **成本归因假设**：成本按标准分词器与模型定价估算，生成内容与工具输出的后续输入/缓存计费采用简化模型，实际账单可能因缓存命中率、批处理折扣等而偏离。
- **技能合成成本**：SynSkills 的合成成本占 RQ1 求解成本的 5.35%–22.64%，摊销后优势消失，说明自动技能合成在当前规模下经济性有限；未来可探索更低成本的合成方式或跨任务复用。
- **未来方向**：
  - 将行为检测器扩展到更多框架与任务域，并开放为可复用工具。
  - 研究行为级干预与端到端成本的因果机制，尤其是检索反馈量与模型定价层级的交互。
  - 设计能同时降低行为频次与 token 开销的工具集成方案。
  - 探索在训练或微调阶段注入成本效率原则，而非仅在推理时通过提示或技能注入。

## 9. 总体评价

本文是首个针对编程智能体行为性成本低效的系统研究，贡献在于：（1）提出统一的动作标签体系与三类可量化检测器（SubRetrv、SimScrpt、ReTest）；（2）在四种配置、两个基准、超万条轨迹上量化其流行度与成本贡献（合计影响 79.00%–98.00% 任务，占成本 6.86%–22.75%）；（3）评估三种缓解策略，揭示"行为改善不等于成本下降"（CodeGraph）以及"开发者设计技能显著优于智能体合成技能"（DevSkills 6/8 设置稳健降本 7.88%–41.73%，约为 SynSkills 两倍）。研究设计严谨，引入噪声地板与稳健判定阈值，成本归因透明。主要不足在于部分方法单元单次运行、基准限于 SWE-bench 系列、行为检测可能不完备。总体而言，本文为编程智能体的成本效率研究提供了可复用的分析框架与明确的实践启示，是该方向的重要基础性工作。
