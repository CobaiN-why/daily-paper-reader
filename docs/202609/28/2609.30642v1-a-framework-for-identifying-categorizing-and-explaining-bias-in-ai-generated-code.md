## 摘要
随着大型语言模型（LLM）被整合到软件开发工作流中，人们开始担忧 AI 生成代码中存在的无意识偏见。尽管有证据表明这些偏见确实存在，但系统性地识别、分类和解释它们的研究仍然有限。本研究调查 AI 生成代码中的偏见，并评估 LLM 能否通过一个由分类体系驱动的框架可靠地识别和解释这些偏见。我们扩展了一个现有的包含偏见的 AI 生成 Python 代码数据集，并手动为代码片段标注偏见类别和人工撰写的理由，以建立一个真值数据集。利用该数据集，我们通过上下文学习（ICL）将专有和开源 LLM 评估为自动化的偏见检测与理由说明系统。最后，我们使用结构化的理由说明和代码识别指标，分析了 LLM 生成的解释与人工撰写的理由之间的相似性。我们的发现表明，LLM 能够有效支持代码偏见的识别与解释。Gemini 达到了 80.14% 的分类准确率，精确率为 84.0%，召回率为 95.7%；而最佳开源替代模型 Qwen3-coder 达到了 82.45% 的准确率、68.64% 的精确率和 80.22% 的召回率。此外，相对于人工撰写的推理，这些模型的理由说明相似度得分分别为 80.4% 和 80.14%，代码识别相似度得分分别为 86.0% 和 87.82%。这些结果表明，LLM 能够检测生成的 Python 代码中带有偏见的逻辑，并生成与专家解释高度一致的说明。

## Abstract
As Large Language Models (LLMs) become integrated into software development workflows, concerns regarding unintentional biases in AI-generated code. Although evidence suggests these biases exist, limited research has systematically identified, categorized, and explained them. This study investigates bias in AI-generated code and evaluates whether LLMs can reliably identify and explain it through a taxonomy-driven framework. We extended an existing dataset of biased AI-generated Python code and manually annotated snippets with bias categories and human-authored justifications to establish a ground-truth dataset. Using this dataset, we evaluated proprietary and open-source LLMs as automated bias detection and justification systems through ICL. Finally, we analyzed similarity between LLM-generated explanations and human-authored justifications using structured justification and code identification metrics.   Our findings demonstrate that LLMs can effectively support code bias identification and explanation. Gemini achieved 80.14% classification accuracy, with 84.0% precision and 95.7% recall, while the best open-source alternative, Qwen3-coder, achieved 82.45% accuracy, 68.64% precision, and 80.22% recall. Additionally, the models achieved justification similarity scores of 80.4% and 80.14%, respectively, relative to human-authored reasoning, and code identification similarity scores of 86.0% and 87.82%. These results suggest that LLMs can detect biased logic in generated Python code and produce explanations that substantially align with expert interpretations.

## 2. 方法论：核心思想、关键技术细节与流程

- **总体思路**：
  - 扩展已有带偏见 AI 生成 Python 代码数据集。
  - 人工标注偏见类别与理由，构建真值数据集。
  - 设计细粒度偏见分类法与标准化解释框架。
  - 使用 ICL 提示 LLM 进行偏见类型识别、偏见代码定位和理由生成。
  - 将 LLM 输出与人工标注进行相似度对齐评估。

- **数据来源与准备**：
  - 基于 Huang et al. 的数据集，包含 7,840 个 Python 函数片段，原标签为二分类“有偏/无偏”。
  - 抽取其测试集 784 个片段进行人工多标签标注。
  - 最终用 LLM 对全量 7,840 个样本进行扩展标注。

- **偏见分类体系**：
  - 先通过文献综述构建高层偏见分类表。
  - 再细化为可操作标注 schema，包含三个维度：
    - Protected Attribute：是否涉及受保护属性。
    - Association Type：正关联或负关联。
    - Bias Type：具体偏见类型。
  - 操作化保留的偏见类型包括：
    - Naming/Documentation bias
    - Stereotype bias
    - Demographic bias
    - Representational bias
    - Threshold/Cutoff bias
    - Proxy bias
  - 规则约束：
    - Threshold/Cutoff 必须有阈值比较。
    - Proxy bias 仅在未显式引用受保护属性时适用。
    - Representational bias 仅适用于正关联，要求某群体被选择性纳入而其他群体被排除。

- **标准化解释框架**：
  - 每条理由由三部分组成：
    - Trigger：引入或暴露偏见的代码元素，对应字段 `biased_code`。
    - Mechanism：该元素如何造成偏见关联或决策行为，对应字段 `issue`。
    - Impact：更广泛的社会或结构性影响，对应字段 `impact_reasoning`。
  - 模板形式：“The [Trigger] [Mechanism], resulting in [Impact]。”

- **人工标注流程**：
  - 两名作者采用迭代共识编码。
  - 五轮校准，每轮约 30 个共享代码片段。
  - 当评分者间一致性超过 90% 后正式标注。
  - 最终在完整标注 schema 上达到约 98% 共识。
  - 剩余分歧通过讨论解决。

- **ICL 提示设计**：
  - 开发 ICL1–ICL5 五个提示配置。
  - 初始提示包含分类体系、决策规则、少样本示例、理由模板和 JSON 输出 schema。
  - 后续迭代针对误报、证据 grounding、字段一致性、边缘案例、Representational bias 规则等进行改进。
  - 每轮在 Gemini 2.5 Pro 上测试 600 个代码片段。
  - 停止标准：IRR 低于 90% 或分类性能提升超过 2% 时继续；否则停止。
  - 最终 ICL5 用于所有模型。

- **评估指标**：
  - Precision、Recall、Accuracy。
  - 偏见类型识别准确率（BT Accuracy）。
  - 偏见代码识别准确率（BCR）。
  - 理由相似度分数（JSS）。
  - 相似度使用 Python `difflib.SequenceMatcher`，实现 Ratcliff/Obershelp 算法：
    - \(S(A,B)=\frac{2M}{|A|+|B|}\)
    - \(M\) 为最长连续匹配子序列中的匹配元素数。
    - 分数范围 0 到 1，1 表示完全一致。
