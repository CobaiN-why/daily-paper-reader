## 摘要
工具观测主导了软件工程智能体的上下文，使得长交互历史难以低成本维护。现有上下文压缩方法可能丢弃后续动作所需的信息，而让智能体适应软词元表示又可能损害其原始行为。为了在减少上下文的同时保留动作关键信息和智能体行为，我们将潜在观测、硬动作（LOHA）与锚定上下文蒸馏（ACD）相结合。LOHA 是一种上下文布局，将压缩后的历史与需要精确引用的文本分开；ACD 是一种训练方法，能够在约束行为漂移的同时实现潜在读取。LOHA 将较早的工具观测压缩为软词元，同时以文本形式保留智能体自身的轮次和最近 K 个观测，从而提供对历史信息的紧凑访问以及对近期内容的精确访问。为使智能体能够使用这种表示，ACD 将基础模型的全文预测蒸馏到潜在视图中，同时将其在纯文本输入上的行为锚定到同一基础模型。在 SWE-bench Verified 上，K=3 使 Qwen3-4B 的每次调用上下文减少 43%，使 SWE-Master-4B-RL 减少 57%，解决率分别为 12.1% 和 21.8%，而未压缩基线分别为 14.5% 和 27.5%。单次运行的新近性扫描在 K=8 时达到 14.4% 和 23.0%，更大的窗口通常更有利于任务性能而非压缩。在 32K 词元限制下，K=3 的 Qwen3 解决了 199 个实例子集中的 21.1%，而同一适配智能体使用全文时仅为 11.1%。在并发单 GPU 服务中，其实例吞吐量达到该全文智能体的 1.9 倍。

## Abstract
Tool observations dominate the context of software-engineering agents, making long interaction histories costly to maintain. Existing context compression methods can discard information needed by later actions, while adapting agents to soft-token representations can compromise their original behavior. To reduce context while preserving action-critical information and agent behavior, we combine Latent Observations, Hard Actions (LOHA), a context layout that separates compressed history from text needed for exact reference, with Anchored Context Distillation (ACD), a training method that enables latent reading while constraining behavioral drift. LOHA compresses older tool observations into soft tokens while retaining the agent's own turns and the last K observations in text, providing compact access to historical information and exact access to recent content. To enable the agent to use this representation, ACD distills the base model's full-text predictions into the latent view while anchoring its behavior on plain-text inputs to the same base model. On SWE-bench Verified, K=3 reduces context per call by 43% for Qwen3-4B and 57% for SWE-Master-4B-RL, with resolve rates of 12.1% and 21.8% versus 14.5% and 27.5% for their uncompressed bases. A single-run recency sweep reaches 14.4% and 23.0% at K=8, with larger windows generally favoring task performance over compression. Under a 32K-token limit, Qwen3 with K=3 resolves 21.1% of a 199-instance subset versus 11.1% for the same adapted agent using full text. In concurrent single-GPU serving, it achieves 1.9 times that full-text agent's instance throughput.

## 1. 核心问题与整体含义

- **背景**：大语言模型被广泛用作软件工程智能体，通过工具检查仓库、修改代码、运行测试并依据结果迭代。工具观测（文件内容、搜索结果、堆栈跟踪、测试日志等）在交互历史中占据主导地位。论文指出，在 CoderForge 轨迹中，工具观测平均占轨迹 token 的 **69%**，导致长交互历史维护成本高昂。
- **现有方法的问题**：
  - 观测掩码、历史摘要、子任务折叠、选择性剪枝等上下文压缩方法虽然缩短历史，但**难以判断哪些细节会被后续动作依赖**。
  - 编码智能体不仅需要语义理解，还需要**精确字符串匹配**（如 `str_replace` 编辑必须逐字匹配源码），摘要式压缩可能丢失后续工具调用所需的确切文本。
  - 软 token 压缩虽能缩短序列，但让解码器适应新的连续嵌入表示可能**损害其原有工具调用与代码编辑行为**。
- **核心问题**：如何同时做到（1）压缩上下文、保留动作关键信息；（2）让智能体学会读取压缩历史，同时不破坏其原有行为？
- **整体含义**：论文提出 **LOHA + ACD** 框架，将“压缩你所见（工具观测）”与“不压缩你所说（智能体自身轮次与精确动作文本）”分离，并通过行为锚定蒸馏实现稳定适配。其目标是在性能与效率之间取得可控权衡，尤其适用于长程软件工程智能体。

## 2. 方法论

### 2.1 核心思想

- **LOHA（Latent Observations, Hard Actions）**：一种上下文布局。将较早的工具观测体压缩为软 token，但保留系统提示、任务描述、智能体自身轮次以及**最近 K 条观测的原始文本**，以支持需要精确引用的动作。
- **ACD（Anchored Context Distillation）**：一种训练方法。让智能体从潜在视图读取压缩观测，同时通过全文本视图的行为锚定，限制其相对基础模型的行为漂移。

### 2.2 LOHA：潜在观测 + 硬动作

- **渲染方式**：
  - 观测仍保留在原始位置和原生工具响应包裹中；被压缩的观测体用 memory 标记包裹，按 1,024 token 窗口编码，替换为约 1/16 数量的软 token。
  - 周围工具包裹仍为硬 token，保持与工具调用的关联。
- **新近策略（Hard-Last-K）**：
  - 给定 m 条观测，第 i 条观测体的表示为：若 `i > m - K`，保留原文；否则使用编码器 `E(oi)` 压缩为软 token。
  - 新观测先以文本进入，离开窗口后才可被压缩；旧观测仍可通过潜在表示访问，必要时可用工具重新检索精确内容。
  - K 可在推理时选择，无需重新训练；K=3 为主设置，K∈{0,1,2,3,4,8,∞} 用于扫描。
- **短观测规则**：少于 128 字符的观测体始终保留文本。

### 2.3 ACD：锚定上下文蒸馏

- **学生结构**：
  - 冻结的 LCLM 编码器 + 可训练 MLP 适配器 + 基础解码器 + 低秩“阅读补丁”（reading patch）。
  - 对每个投影矩阵 `W0`，定义 `ΔW = WLCLM - W0`，参数化为 `Wθ = W0 + AB`，其中 `rank(AB) ≤ ρ`；A、B 初始化为 ΔW 的秩-ρ 截断 SVD。
  - 默认 ρ=64，覆盖 252 个解码器投影，约 132M 参数；适配器约 9.2M；归一化增益也可训练，初始化自基础模型。总可训练参数约 141.5M。
- **两个视图**：
  - 全文本视图 `xH`：所有观测均为硬 token。
  - 潜在视图 `xL`：所有观测体压缩为软 token。
  - 预测按 assistant token 身份对齐；另在潜在示例中追加 read-back 问题，监督从压缩观测中恢复字面内容。
- **损失函数**：
  - 总损失：`L = Ldistill + λLanchor`，论文中 λ=1。
  - **蒸馏项 `Ldistill`**：在潜在视图上，让学生预测匹配教师（基础模型）在全文本上下文下的预测分布；同时加入 read-back 答案 token 的交叉熵。使用前向 KL 默认。
  - **锚定项 `Lanchor`**：在全文本视图上，约束学生预测接近同一基础模型的原始预测分布，防止适配后普通文本行为漂移。
  - 两项分别按各自监督 token 数归一化，使相对权重由 λ 显式控制。
- **教师选择**：
  - 两项均使用原始基础模型作为教师：为潜在读取提供全文本预测目标，为行为保持提供参考分布。
  - 使用外部模型作锚定会鼓励学生采用外部模型行为，因此采用**自锚定**。
- **KL 估计**：
  - 教师冻结且轨迹固定，可预先缓存教师 top-k（默认 64）token log 概率及剩余概率质量。
  - 训练时在缓存 token 加一个尾部桶上计算 KL，是完整词表 KL 的下界；附录报告 M=32 时前向 KL 估计误差在 0.1% 以内，反向 KL 低估约 3.5–4.2%。

### 2.4 训练与推理流程

- **训练数据**：从 CoderForge 中每个任务选取最短成功轨迹，共 **35,140 条轨迹**，1.29B 原始 token，0.31B 教师评分 assistant 位置；消融使用前 3,514 条。
- **训练设置**：双视图渲染并打包为 204,800 token 序列；AdamW，patch 与归一化增益学习率 `1e-4`，适配器 `5e-5`，余弦调度，10% warm-up；训练 1 个 epoch。离线训练，教师目标缓存，避免教师前向传播。
- **推理**：使用脚手架原生函数调用与工具；每次模型调用前按选定 K 渲染历史；旧观测被编码为软 token；全潜在历史为追加式，Hard-Last-K 下窗口推进会使前缀缓存从首个变更观测起失效。
- **成本核算**：区分表示长度与执行轨迹成本；编码观测体约 16× 压缩；上下文级压缩比因包裹、短观测、提示、assistant 轮次和近期窗口仍为文本而低于 16×。
