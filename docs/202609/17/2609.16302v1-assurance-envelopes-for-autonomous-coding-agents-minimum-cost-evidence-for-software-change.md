## 摘要
当编码智能体回到既有软件时，它会继承早期工程工作产生的证据：测试、类型检查、证明、静态分析和轨迹。重新加载全部证据是浪费的，但丢弃变更所依赖的某一部分证据，可能使某个必需性质得不到支持。给定变更必须保持的性质，即其义务，我们问可用证据的哪个最小成本子集能重新建立这些性质，并称这样的子集为任务条件下的保证包络。证据以及组合证据的规则构成一个带类型的推理图；当从所选证据进行前向链接到达某个义务时，该义务即被满足，我们通过该闭包来验证每个选择，而不是信任优化器。我们评估中由软件衍生的图来自先前 AI 编码智能体运行的保存结果；我们冻结这些产物，并问对于后续任务应恢复哪些累积证据。来自 Rust、IronBlocks 和 Pong 结果的小图表明，最小包络取决于任务；当当前证据无法重新建立某个必需性质时，可能不存在这样的包络；有些性质需要多个证据片段共同支持；扩展需求会增加证据，而非替换证据。一个预先设定的包含 249 个实例的合成基准刻画了计算表现：丢弃“多个证据片段共同支持”结构的基线必然无法重新推导它们；每个完成的精确交叉校验都与 CP-SAT 优化器一致；在 500 个证据的图上，求解时间中位数保持在 20 毫秒以下；但每个目标有许多替代推导的图在远更小的规模上就超时，因此难度由结构而非原始规模驱动。本文贡献是将已有优化方法有限地应用于为软件变更选择保证上下文；发现义务以及下游智能体收益仍是开放问题。

## Abstract
When a coding agent returns to existing software, it inherits evidence from earlier engineering work: tests, type checks, proofs, static analyses, and traces. Reloading all of it is wasteful, but dropping a piece the change depends on can leave a required property unsupported. Given the properties a change must preserve, its obligations, we ask which least-cost subset of the available evidence re-establishes them, and we call such a subset a task-conditioned assurance envelope. Evidence and the rules that combine it form a typed inference graph; an obligation is met when forward chaining from the selected evidence reaches it, and we validate every selection by that closure rather than by trusting the optimizer. The software-derived graphs in our evaluation come from preserved outcomes of prior AI coding-agent runs; we freeze those artifacts and ask which accumulated evidence should be restored for a later task. Small graphs from Rust, IronBlocks, and Pong outcomes show that the minimum envelope depends on the task, that none may exist when current evidence cannot re-establish a required property, that some properties need several pieces of evidence together, and that expanding the requirements adds evidence rather than replacing it. A prespecified synthetic benchmark of 249 instances characterizes computation: a baseline that discards the 'several pieces together' structure necessarily fails to re-derive them; every completed exact cross-check agreed with the CP-SAT optimizer; and median solve time stayed below 20 ms at 500-evidence graphs, except that graphs with many alternative derivations per target timed out at far smaller sizes, so structure, not raw size, drives difficulty. The contribution is a bounded application of established optimization to selecting assurance context for a software change; discovering the obligations and downstream agent benefit remain open.

# 论文总结：Assurance Envelopes for Autonomous Coding Agents

## 1. 核心问题与整体含义

- **背景**：自主编码智能体回到既有仓库时，会继承先前工程工作留下的证据——通过的测试、类型检查、已解除的契约义务、静态分析结论、监控轨迹、运行策略与需求历史。源代码本身无法重建这些结论。
- **两难**：把全部旧产物与工具结果都重新加载既浪费又未必有用；但丢弃变更所依赖的某一片证据，可能让某个必需性质失去支撑。选择过少比选择过多更严重。
- **核心问题（RQ）**：给定程序制品、软件变更任务与语义/验证上下文，可用带类型证据的哪个最小成本子集，能在显式组合规则下推导出全部给定任务义务（obligations，即 roots）？
- **概念定义**：这样的充分选择称为**任务条件保证包络**（task-conditioned assurance envelope）——为某一程序、任务与上下文选取的、足以重新建立变更必须保持性质的最小成本证据束。
- **为什么独立测试覆盖率不够**：有些结论需要多个前提同时成立（合取），有些存在替代推导路径（析取），还有共享支撑。问题因此不是"检索哪些仓库文本"，而是"恢复哪些机器产生的工程证据"。
- **理论定位**：独立固定覆盖下退化为加权集合覆盖；带合取规则、中间义务、替代推导与共享叶子时，是超图 / AND-OR 图上的最小证明（支撑）问题，与逻辑溯因相关。作者强调这是把**已有优化**有界地应用到软件变更的保证上下文选择，而非新的复杂度结果。
- **明确边界**：义务集合与推理规则是**输入**，不是从自然语言或代码中推断的；义务的自动发现与下游智能体的实际收益均为开放问题。

## 2. 方法论

- **核心思想**：把证据与组合规则建成一个带类型的推理图（有向超图），把"任务所需性质被满足"定义为从所选证据做前向链闭包能到达全部根义务，再在该语义下求最小成本证据子集，并用独立闭包校验（而非信任优化器）验证每个解。
- **问题对象**：
  - `P`：精确制品标识；`t`：请求的工程任务；`M`：语义/验证上下文（编译器与选项、语言配置、运行时与内存模型、依赖、实际跑过的分析）。
  - `O(P,M)`：可能被要求的义务全集；`R(P,t,M) ⊆ O(P,M)`：该任务实际要求的**根义务**（条件化决策，构造完整 R 属外部需求与变更影响问题）。
  - `E`：可用证据；`G`：有限带类型推理图。证据直接建立若干义务；边把一组必须同时成立的前件义务映射到一个后件义务（AND）；共享同一后件的多条边是替代推导（OR）。
- **闭包与充分性**：对 `S ⊆ E`，`Cn_G(S)` 由确定性前向链定义——初始含被选证据直接建立的义务，反复加入前件全部被支持的后件，直至不再增长。V1 中图有限、单调、无环。
  - 充分性判据：`R(P,t,M) ⊆ Cn_G(S)`（式 1），即操作上的接受准则，并要求独立闭包检查验证求解器报告的可行性。
- **最小支撑与不可行**：`S*(P,t,M) ∈ arg min_{S⊆E} Cost(S)`，约束为上式（式 2）。可能多解同成本；若无解则当前证据对任务不足。**包含最小性与最小成本是两回事**。
- **成本模型**：实验以单位成本度量支撑基数，另设小的确定性整数成本作为次要条件；涉及延迟、新鲜度、人工、风险的多目标选择需要策略甚至 Pareto 前沿，不属 V1。
- **形式关系**：独立固定覆盖 → 加权集合覆盖；含合取、中间义务、替代与共享叶 → 有向超图上的最小证明/支撑问题。
- **实现要点**：
  - 不可变 Python dataclass 表示证据、义务、规则与任务需求；证据携带语义类型、上下文标识、假设与整数成本。
  - NetworkX 存储推理图，校验节点/边类型、引用、上下文、规则元数、成本与无环性。
  - 闭包验证器做确定性前向链并记录推导溯源；穷举优化器对受限实例返回可行性、全部等成本最优与包含最小支撑。
  - CP-SAT（OR-Tools）适配器用二值变量编码证据、义务、规则，约束编码合取并要求每个被支持义务都有正当理由；每个 CP-SAT 返回的支撑都由独立闭包验证器复核。
  - 规模生成器用 SHA-256 计数器构造而非平台伪随机；规范清单绑定族、参数、种子、成本、节点、边、根与图哈希。
