## 摘要
由大语言模型（LLM）驱动的编码智能体在自动化软件工程任务方面已取得快速进展，但仓库级问题解决仍然具有挑战性。除了生成一个看似合理的补丁之外，智能体还必须在相互依赖的文件中定位相关代码，并维护既充分又聚焦的仓库上下文。代码图能够揭示非局部关系，但线性文本接口会掩盖其拓扑结构；渲染完整仓库图会得到过于稠密、难以可靠感知的可视化表示，而一次性局部视图会随着探索推进而变得过时。我们提出 RepoAtlas，一个免训练模块，它通过在仓库代码图上进行“选择—投影—刷新”循环来维护不断演化的多模态仓库视图。RepoAtlas 结合问题中的证据与智能体当前的探索状态，在固定预算下选择任务相关区域，将所选结构投影为互补的视觉与文本表示，并在探索状态的变化使视图过时时对其进行刷新。我们在 SWE-bench Verified 上评估 RepoAtlas，相对于最强的多模态图基线，它使解决率提高了 2.4 个百分点，同时将输入 token 数与模型调用次数平均减少了 5.8% 和 7.8%，并在不同家族与规模的三个模型上均取得一致增益。

## Abstract
Large language model (LLM)-powered coding agents have made rapid progress in automating software engineering tasks, yet repository-level issue resolution remains challenging. Beyond generating a plausible patch, an agent must localize relevant code across interdependent files and maintain repository context that is both sufficient and focused. Code graphs expose non-local relations, but linear text interfaces obscure their topology; rendering the full repository graph yields visual representations that are too dense to perceive reliably, whereas a one-shot local view becomes stale as exploration proceeds. We present \textbf{RepoAtlas}, a training-free module that maintains evolving multimodal repository views through a \emph{select--project--refresh} loop over a repository code graph. RepoAtlas combines evidence from the issue with the agent's current exploration state to select a task-relevant region under a fixed budget, projects the selected structure into complementary visual and textual representations, and refreshes the view when changes in the exploration state render it outdated. We evaluate RepoAtlas on SWE-bench Verified, where it improves the resolve rate by 2.4 points while reducing input tokens and model calls by 5.8\% and 7.8\% on average, relative to the strongest multimodal graph baseline, with consistent gains across three models of different families and scales.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 驱动的编码智能体在自动化软件工程任务上进展迅速，但**仓库级问题求解（repository-level issue resolution）**仍是难点。智能体不仅要生成看似合理的补丁，还必须在相互依赖的文件中**定位相关代码**，并维护**既充分又聚焦**的仓库上下文。
- **核心矛盾**：
  - 代码图能显式表达非局部关系（跨文件调用、导入、继承等），但**线性文本接口会掩盖拓扑结构**，智能体需通过多轮交互重建全局关系，带来额外推理与交互开销。
  - 渲染**完整仓库图**会得到过于稠密的可视化表示，VLM 难以可靠感知。
  - **一次性局部视图**会随着探索推进而变得过时，无法跟上智能体焦点迁移。
- **三个设计挑战**：
  1. **视图选择（view selection）**：在有限预算下保留最任务相关的证据。
  2. **多模态投影（multimodal projection）**：确定布局及视觉/文本信息分配方式。
  3. **视图刷新（view refresh）**：判断何时更新或替换当前视图。
- **整体含义**：论文将仓库上下文构建形式化为**演化视图维护（evolving view maintenance）**问题，提出免训练模块 RepoAtlas，让代码图作为"演化的多模态上下文"而非静态文本负载来服务智能体。

## 2. 方法论

### 核心思想
- RepoAtlas 是一个**免训练模块**，在仓库代码图上通过 **选择—投影—刷新（select–project–refresh）** 循环维护动态多模态仓库视图 $G_t = (V_t, E_t, M_t)$，其中 $(V_t, E_t)$ 为结构内容，$M_t$ 为呈现规格。

### 基础图与状态建模
- **静态图**：对固定仓库快照构建离线有向类型化代码图 $G = (V, E, \tau_V, \tau_E)$。节点包括模块、类、可调用对象、变量；边包括包含、继承等结构关系与调用、导入、重写、符号使用等语义依赖。每个节点存储限定名、签名（若有）和精确源码位置。
- **探索状态**：将智能体与仓库的交互建模为演化探索状态 $s_t(F_t, C_t, G_{t-1}, \phi_t)$，其中 $F_t$ 为近期检查文件集，$C_t$ 为已识别相关实体集，$G_{t-1}$ 为最近交付的视图，$\phi_t \in \{Localize, Edit, Test\}$ 为阶段变量。
- **视图约束**：$|V_t| \le B_V$，$|E_t| \le B_E$；节点可为具体实体或聚合超节点；视图不必是 $G$ 的字面子图。

### A. 预算化结构选择
- **任务条件相关性**：从三路证据估计节点直接相关性——词汇证据（issue 与代码标识符匹配）、语义证据（issue 与实体嵌入相似度）、轨迹证据（来自 $s_t$ 的当前焦点）。校准到统一尺度后，采用**节点级取最大值**融合以保持精度：
  $$a_t(v) = \max(a^{lex}_t(v), a^{sem}_t(v), a^{traj}_t(v))$$
- **相关性传播**：从 $G$ 构造行随机转移矩阵 $P$，边权由边类型决定并归一化；对归一化直接相关性分布 $\bar{a}_t$ 做**个性化 PageRank**，通过幂迭代求解唯一不动点：
  $$\tilde{e}_t = (1-d)\bar{a}_t + dP^\top \tilde{e}_t$$
  最终相关性取节点级最大值 $r_t(v) = \max(\bar{a}_t(v), \tilde{e}_t(v))$，保留强直接证据。
- **连通结构构建**：在视图预算约束下求解连通区域最大化总相关性（式 3）；必要时引入**超节点**，并通过**代表性暴露**让每个超节点以最高分成员作为具体节点暴露其精确源码位置。

### B. 自适应多模态投影
- **对齐多模态表示**：视觉表示暴露拓扑、分组、边方向、关系类型与跨文件连通性；文本表示保留标识符、实体类型、签名与源码位置。通过**稳定引用键**关联视觉元素与文本记录及源码位置。
- **自适应投影**：视图形式、空间布局、标签粒度与模态分配均以 $(V_t, E_t)$ 拓扑和 $s_t$ 为条件（如调用/符号使用主导的区域可用力导向布局）。投影可改变布局、标签粒度与模态分配，但**不改变所选实体与关系**，不同呈现规格内容等价。

### C. 状态感知视图刷新
- **通用复用/刷新决策**：在步骤 $t$ 评估当前视图 $G_{t-1}$ 是否仍覆盖当前阶段相关证据；覆盖则复用，否则重跑选择与投影。仅保留当前视觉表示，刷新时替换图像，但**在紧凑文本索引中保留代码位置**以约束视觉上下文开销。
- **阶段条件刷新**：
  - **Localize**：维护跟随探索范围的多模态视图；issue 描述始终作为选择证据，防止偶然观察挤占原始任务上下文；仅当结构覆盖不足时刷新。
  - **Edit**：首次实质性编辑后进入，视觉上下文在编辑阶段收益低甚至干扰，故**替换为聚焦的文本表示**（修改代码及其结构影响）；仅在实质改变补丁范围时刷新。
  - **Test**：与当前工作范围一致的反馈保留视图；改变推断影响范围的反馈触发刷新；之后若前阶段范围仍有效则恢复，否则回到 Localize。

## 6. 主要结论与发现

- **性能提升**：相对最强基线，解决率平均提升 **2.4 个百分点**；Qwen3.6 上 63.1%（+1.6 点）、MiMo-V2.5 上 68.0%（+1.1 点）、Kimi-K2.5 上 72.4%（+3.0 点）。
- **效率提升**：输入 token 平均减少 **5.8%**，模型调用减少 **7.8%**；API 成本分别降低 6.9%、2.9%、2.4%。平均每实例仅呈现 **2.43 个视图**。
- **一致性**：改进在三个不同模型家族与规模上均一致，说明收益非特定于单一模型。
- **消融发现**：
  - 移除节点预算 → 解决率 -3.3 点，token/调用几乎不变，说明预算主要控制视觉密度而非交互成本。
  - 移除视觉通道 → -1.9 点，输入 token +9.8%、调用 +8.1%；移除文本通道 → -3.9 点且全指标恶化，证明**两模态互补**。
  - 固定布局（即使是最强力导向布局）→ -2.7 点，说明不同区域受益于不同投影。
  - no refresh → -4.7 点（延迟结构上下文）；per-call refresh → 降至 51.0%（过早替换视图、打断连续性）。
- **选择分析发现**：相对 fixed k-hop，RepoAtlas 将 FA@3 从 0.256 提升至 0.336、FA@5 从 0.320 至 0.392、AC 从 0.412 至 0.494；PageRank 传播与代表性暴露贡献互补。
- **案例发现**：成功案例中 RepoAtlas 打开 gold 文件的中位步数为 2（对比 SeeRepo 的 7/11），平均调用 47.5 次（对比 66.3），3/3 解决（对比 0/3）。
- **失败模式**：静态图无法捕获**仅运行时建立的依赖**（sympy-17630），刷新会反复收窄同一错误区域。

## 7. 优点

- **问题形式化清晰**：将仓库上下文构建抽象为"演化视图维护"，并分解为选择/投影/刷新三个可独立设计的子问题，框架具有通用性。
- **免训练、即插即用**：不改动基座模型、不需微调，可适配不同 VLM 与智能体框架。
- **多模态互补设计合理**：视觉暴露拓扑、文本保留标识符与源码位置，并用稳定引用键对齐，兼顾结构感知与可执行性。
- **阶段自适应策略务实**：编辑阶段主动放弃视觉、回归文本，符合"视觉在定位阶段更有用"的实证观察。
- **刷新控制精细**：区分复用/刷新、显式请求/主动检查，并给出 Localize/Edit/Test 三阶段判据，避免视觉上下文累积。
- **预算化选择有算法支撑**：个性化 PageRank 传播 + 节点级最大值融合 + 超节点代表性暴露，兼顾精度保持与依赖覆盖。
- **实验维度较完整**：主结果 + 六组消融 + 独立选择分析 + 成功/失败案例，且跨三个模型家族验证一致性。

## 8. 不足与局限

- **静态图的结构性盲区**：无法表达运行时注册的依赖（如动态注册的 postprocessor），失败案例显示刷新可能反复收窄错误区域，反而强化错误假设。
- **仓库语言与任务覆盖有限**：评估集中于 SWE-bench Verified 与 LocBench，主要面向 Python 仓库；未验证多语言、多仓库规模的可扩展性。
- **计算资源未披露**：论文未报告 GPU 型号、数量与推理时长，自托管成本仅以"租赁等价参考"折算，实际部署成本难以精确复现。
- **基线数量与公平性**：仅对比 3 个基线，缺少与更多近期图智能体方法的比较；SeeRepo

仅在 40.5% 实例中触发视图，其对比结果可能低估该基线；未报告方差与置信区间。
- **刷新触发机制偏启发式**：阶段判据（如"是否实质改变补丁范围""是否改变推断影响范围"）依赖对轨迹的语义判断，论文未给出可复现的判定阈值或自动化实现细节，可能存在实现敏感性。
- **超节点可能掩盖关键细节**：聚合虽控制视图规模，但代表性暴露只保留最高分成员，若真正相关实体位于超节点内部而非代表节点，智能体仍可能漏检。
- **相关性融合策略的取舍未充分验证**：节点级最大值融合被用于"保持精度"，但论文未对比求和/加权等替代融合方式，无法判断该设计是否最优。
- **视图预算固定**：$B_V=15$、$B_E=20$ 为固定超参，未探讨预算随任务难度或阶段动态调整的可能性，也未给出预算敏感性分析。
- **跨仓库/跨快照迁移未验证**：静态图基于单一快照离线构建，未讨论仓库在多次提交间演化时图与视图的一致性维护。

## 9. 潜在改进方向

- **引入动态/运行时依赖线索**：结合执行轨迹、测试反馈或动态分析补充静态图盲区，缓解"仅运行时建立的依赖"导致的失败模式。
- **刷新判据形式化**：将阶段条件刷新中的语义判断转化为可度量的覆盖度或漂移指标，提升可复现性与调参透明度。
- **自适应预算**：让 $B_V$、$B_E$ 随阶段与不确定性动态变化，在 Localize 阶段放宽、Edit 阶段收紧。
- **扩展语言与规模**：在 Java、TypeScript、Go 等多语言仓库及更大规模代码库上验证可扩展性。
- **融合策略与超节点策略的消融细化**：对比 max/weighted-sum/attention 等融合方式，以及超节点内多代表暴露策略。
- **更强的基线对比**：纳入更多近期图引导智能体，并公开复现脚本以消除公平性疑虑。

## 10. 总体评价

RepoAtlas 的核心贡献在于**把"仓库上下文构建"重新表述为"演化视图维护"问题**，并用免训练的"选择—投影—刷新"循环给出可落地的实现：预算化结构选择（词汇/语义/轨迹三路证据 + 个性化 PageRank 传播 + 超节点代表性暴露）保证在有限预算下保留任务相关证据；自适应多模态投影在视觉拓扑与文本源码位置之间做互补分工；状态感知刷新则通过 Localize/Edit/Test 阶段条件复用或替换视图，避免视觉上下文累积。实验上，论文在三个不同家族与规模的 VLM 上报告了一致且幅度适中的改进（解决率 +2.4 点，输入 token −5.8%，调用 −7.8%），六组消融与独立选择分析进一步定位了各设计组件的贡献，成功/失败案例也提供了定性洞见。

其主要弱点在于：静态图无法覆盖运行时依赖这一根本性限制、部分机制（刷新判据、融合策略、预算设定）缺乏敏感性分析、以及计算资源与基线公平性的透明度不足。总体而言，这是一项**问题定义清晰、工程实现务实、实验覆盖较完整**的工作，为"如何让代码图以多模态、演化式上下文的形式服务编码智能体"提供了有价值的参考框架；其局限也指明了动态依赖建模与自适应视图控制是后续值得深入的方向。
