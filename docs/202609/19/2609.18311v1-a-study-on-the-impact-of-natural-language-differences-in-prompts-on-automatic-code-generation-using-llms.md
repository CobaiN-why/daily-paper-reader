## 摘要
大型语言模型（LLMs）在自动代码生成任务中表现出色，从而推动了该领域的新研究。尽管已有大量研究探索了基于LLM的代码生成，但输入提示中自然语言的影响仍未得到充分探索（语言偏差）。本研究旨在（1）量化输入提示的自然语言如何影响基于LLM的代码生成性能，并（2）评估一种减少代码生成中语言偏差的缓解策略。我们在AtCoder、LeetCode和BigCodeBench上评估代码生成的准确率（Accuracy）。为了量化代码生成中的语言偏差，每个问题分别以英语、日语和中文呈现。我们使用七个LLM（GPT-4o、o3-mini、DeepSeek-V3.2、Llama-3、Qwen2.5-Coder-14B、Qwen2.5-Coder-0.5B和GitHub Copilot），并以准确率（Accuracy，即生成的代码通过所有测试用例的问题数量）来评估它们的性能。我们比较翻译前后的准确率，以评估翻译作为一种缓解策略的有效性。我们观察到，问题陈述的自然语言会影响基于LLM的代码生成性能。具体而言，各数据集官方支持的语言取得了最高的准确率中位数。此外，翻译提高了准确率，但其有效性在不同数据集和模型类型之间并不一致。我们发现，AtCoder包含比例特别高的叙事风格问题陈述以及更长的问题陈述。自然语言显著影响LLM代码生成的准确率。在某些设置下，翻译可以缓解语言偏差，但其有效性取决于数据集和模型类型。此外，输入提示的叙事性方面和上下文长度是与语言偏差以及翻译作为缓解策略的有效性相关的重要因素。

## Abstract
Large Language Models (LLMs) have demonstrated remarkable performance in automatic code generation tasks, thereby encouraging new research in this area. Although numerous studies have explored LLM-based code generation, the impact of the natural language in input prompts remains unexplored (language bias). This study aims to (1) quantify how the natural language of input prompts influences LLM-based code generation performance and (2) evaluate a mitigation strategy to reduce language bias in code generation. We assess code generation Accuracy on AtCoder, LeetCode, and BigCodeBench. To quantify the language bias on code generation, each problem is presented in English, Japanese, and Chinese. We use seven LLMs (GPT-4o, o3-mini, DeepSeek-V3.2, Llama-3, Qwen2.5-Coder-14B, Qwen2.5-Coder-0.5B, and GitHub Copilot) and assess their performance in terms of Accuracy (the number of problems for which generated code passes all test cases). We compare Accuracy before and after translation to evaluate the effectiveness of translation as a mitigation strategy. We observed that the natural language of problem statements affects LLM-based code generation performance. Specifically, the languages officially supported by each dataset achieved the highest median Accuracy. Also, translation improved Accuracy, but its effectiveness was not consistent across datasets and model types. We found that AtCoder contained a particularly high proportion of narrative-style problem statements and longer problem statements. Natural language significantly affects LLM code generation accuracy. Translation can mitigate language bias in some settings, but its effectiveness depends on the dataset and model type. Furthermore, the narrative aspects and context length of input prompts are important factors related to language bias and the effectiveness of translation as a mitigation strategy.

- **背景**：LLM 在自动代码生成任务中表现突出，已有研究（如 GitHub Copilot 57% Java 准确率、GitHub 上约 29% 的 Python 函数由 AI 生成）表明其在实践中被广泛采用。
- **核心问题**：现有研究多关注编程语言差异，但**输入提示所使用自然语言（英语、日语、中文等）对代码生成性能的影响（语言偏差，language bias）尚未被系统探索**。
- **前期工作局限**：作者团队此前的工作（Koyanagi et al., MSR 2024）仅使用 GitHub Copilot 和 AtCoder 数据集，发现语言偏差存在（如 Copilot 在日语题上表现最好），但存在**基准局限**与**模型局限**。
- **本文定位**：作为前期工作的**概念性复现（conceptual replication）**，扩展至 3 个数据集和 7 个 LLM，并首次探索**缓解策略（翻译）**，同时首次研究提示的**叙事性（narrative）与长度**对代码生成的影响。
- **整体含义**：自然语言选择是影响 LLM 代码生成性能的一个被低估但重要的因素；翻译可以在某些场景缓解语言偏差，但效果依赖数据集与模型。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：将同一编程题目分别用英语、日语、中文表述，测量不同自然语言下 LLM 生成代码的准确率差异，并检验"翻译到表现最好的语言"能否作为缓解手段。
- **准确率定义**：Accuracy = 生成的代码通过**全部测试用例**的问题数占比（每个语言 × 难度组合重复 5 次取中位数，以缓解 LLM 随机性）。
- **目标自然语言选择标准**：
  - 必须是高资源语言（保证数据规模）；
  - 至少有一位作者为母语者或为学术通用语言（保证提示质量）；
  - 需包含前期工作所用语言（保证可复现性）。
- **翻译流程（用于构建真值数据集）**：
  - Step 1：用 DeepL 自动翻译（英→中、英→日）；
  - Step 2：由母语为日语/中文的作者人工校验修正；
  - 建立**编码手册（coding book）**，采用开放式编码 + 饱和准则（连续 50 个样本无新码即停止）来系统识别和纠正翻译错误。
  - 该流程生成的问题**不存在于 LLM 训练数据中**，可缓解数据泄漏问题。
- **翻译缓解策略（RQ2）**：将问题从准确率最低的语言翻译到准确率最高的语言，使用 DeepL、Google Translate、GPT-4o 三种工具，**不做人工校验**（模拟实际使用场景）。
- **叙事性问题的定义（三项标准，满足至少一项即为叙事型）**：
  - **具体主语（Subject）**：如"Bob"等具体名词；
  - **情境化目标（Contextualized Objective）**：如"求 Snuke 的最小悲伤值"而非抽象数值目标；
  - **无关句子（Unrelated Sentences）**：如背景铺垫/风味文本。
- **代码质量辅助分析**：使用 Pylint 统计每行警告数、计算圈复杂度（cyclomatic complexity）和生成代码行数（LOC）。
- **实验工作流（4 步）**：生成代码 → 运行测试判定通过/失败 → 重复 5 次取中位数 → 翻译提示并重新评估。

## 3. 实验设计

- **数据集 / 场景**：
  - **AtCoder**：756 题（难度 A、B、C、D 各 189 题），取自 ABC 第 99–287 场，官方支持日语和英语；
  - **LeetCode**：100 题（16 easy / 52 medium / 32 hard），官方支持英语和中文；每题由 ChatGPT 辅助生成 15 个不重复测试用例并在官网逐一验证；
  - **BigCodeBench**：288 题（按 95% 置信度、5% 误差边际估算样本量），规格说明型代码生成，主要提供英语。
- **基准（Benchmark）**：以"通过全部测试用例的问题比例"作为准确率指标；AtCoder/LeetCode 用平台测试用例，BigCodeBench 用官方评估框架。
- **对比的 LLM（7 个）**：
  - 闭源：GPT-4o、o3-mini、DeepSeek-V3.2、GitHub Copilot；
  - 开源：Llama-3.1-8B-Instruct、Qwen2.5-Coder-14B、Qwen2.5-Coder-0.5B。
  - 选择标准：编程社区广泛使用、覆盖商业与开源、来自不同国家。
- **对比方法 / 条件**：
  - 三种自然语言的横向对比（RQ1）；
  - 翻译前后的纵向对比（RQ2，含三种翻译工具）；
  - 补充实验：C++ 代码生成（仅 AtCoder）、低资源语言（泰语、斯洛伐克语、芬兰语、保加利亚语、挪威语）。
- **代码生成设置**：统一系统/用户提示模板，指定输出格式；Copilot 因无 API，通过 VSCode 以注释形式嵌入题目并取首个建议。

## 6. 主要结论与发现

- **RQ1（语言偏差影响）**：
  - 各数据集**官方支持的语言**（AtCoder：英/日；LeetCode：英/中；BigCodeBench：英）常取得最高的中位准确率；
  - **语言差距（最高与最低中位准确率之差）因数据集和模型类型而异**：开源模型为 3.6%–6.6%，闭源模型为 2.7%–15.6%；
  - DeepSeek-V3.2 整体表现最好（24 个组合中 17 个最高）；o3-mini + 日语、DeepSeek-V3.2 + 英语/中文常表现最佳；
  - 开源模型整体性能较低，但在英语上相对更好；
  - **代码质量（Pylint 警告/行、圈复杂度、LOC）在不同语言间基本一致**，说明语言主要影响功能正确性而非代码风格。
- **RQ2（翻译缓解策略）**：
  - 翻译效果**因数据集和模型类型而异**；
  - LeetCode、BigCodeBench 翻译后准确率提升（LeetCode 英译中位提升 +6.2%/+6.3%；BigCodeBench +2.4%/+0.2%）；
  - AtCoder 上结果混合：开源模型译成英语提升（中位 +3.2%），闭源模型下降（中位 -5.3%）；译成日语对两组均下降；
  - 翻译工具（Google/DeepL/GPT）之间差异不显著（BLEU 均值 0.501–0.564）。
- **补充分析**：
  - AtCoder 叙事型问题占比 74.0%，LeetCode 为 50.0%；AtCoder 句子数中位数是 LeetCode 的两倍多；
  - **叙事型 + 长上下文**的 AtCoder 问题准确率更低（中位差 -6.9%）；**叙事型 + 短上下文**的 LeetCode 问题反而更高（+3.4%）；
  - 失败案例分析：50 个失败样本中 20 个由叙事性因素导致，主要涉及**误解与不当抽象**而非逻辑错误；
  - C++ 结果与 Python 一致（DeepSeek-V3.2 最佳、官方语言更优）；
  - **低资源语言间也存在语言偏差**（如斯洛伐克语、芬兰语优于保加利亚语），且模型能力提升无法消除偏差。

## 7. 优点

- **系统性与广度**：首次在 3 个数据集、7 个 LLM、3 种高资源语言上系统量化代码生成的语言偏差，并扩展到 C++ 和 5 种低资源语言。
- **概念性复现 + 扩展**：在前期工作基础上增加模型、数据集和缓解策略，增强结论可推广性。
- **新颖的叙事性分析**：首次定义并量化"叙事型问题陈述"对代码生成的影响，揭示上下文长度是关键调节变量。
- **翻译质量可控**：区分"真值数据集翻译（人工校验）"与"缓解策略翻译（自动）"，避免混淆；建立编码手册并用 kappa 系数验证一致性。
- **多维度评估**：不仅看准确率，还分析 Pylint 警告、圈复杂度、LOC，排除代码风格干扰。
- **可复现性**：提供完整复现包（Zenodo DOI），包含提示模板、测试用例生成提示、编码手册。
- **实践指导价值**：明确指出用户应根据数据集选择提示语言、使用翻译前应先评估效果。

## 8. 不足与局限

- **构念效度**：
  - 低资源语言翻译**未经母语者校验**（作者团队无相应母语者），质量可能影响结论；
  - 仅以 Python 为主、C++ 仅限 AtCoder，编程语言覆盖有限。
- **内部效度**：
  - 闭源模型（GPT-4o、o3-mini、Copilot、DeepSeek）内部结构不公开，**无法保证实验期间模型未更新**；
  - **数据污染风险**：AtCoder/LeetCode 有大量公开题解与博客，训练数据可能包含，观察到的语言差异可能部分来自训练数据分布而非模型内在能力；
  - LeetCode 测试用例非官方隐藏测试集，可能未覆盖边界情况；
  - 翻译准确性依赖人工判断，缺乏量化评估；5 次重复次数为人为设定参数。
- **外部效度**：
  - 3 个数据集不代表全部代码生成场景；
  - 7 个 LLM 未覆盖所有可用模型（如未选日本开发的 LLM，因无符合标准者）；
  - Copilot 被排除后续分析，限制了对其语言偏差的深入结论。
- **应用限制**：翻译缓解策略并非普适，闭源模型在 AtCoder 上反而退化，说明直接套用翻译可能有害，需针对具体数据集与模型先行验证。
