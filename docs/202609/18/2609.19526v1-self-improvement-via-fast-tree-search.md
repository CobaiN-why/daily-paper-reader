## 摘要
编码智能体可以递归地修改自身实现，形成自我改进的循环。虽然先前工作表明这能提升编码基准上的性能，但现有方法成本高昂且计算密集。我们引入了一个简单、样本高效的自我改进框架，在严格预算约束下显著提升编码性能。我们将候选自我修改的评估确定为主要的运行时瓶颈，因为先前方法通过使用修改后的智能体重跑一部分基准任务来估计其有效性，这很耗时。我们提出了基于快速树搜索的递归自我改进（SIFT），它用 LLM-as-a-judge 信号来增强这些下游任务评估，该信号在候选补丁之间进行成对比较，其中胜负记录通过正则化 Bradley-Terry 模型聚合，得到的强度分数驱动轻量级解耦树搜索中的基于排名的父节点采样。昂贵的下游任务评估仅保留给最有希望的节点。使用完全解耦的树搜索流水线，评判者分数提供中间信号以指导对有希望的候选补丁的探索，而不会受慢速评估运行的瓶颈限制。SIFT 在完整 Polyglot 基准上优于现有的基于树搜索的自我进化框架，并在 CPU 小时、挂钟时间和 API 成本方面显著降低资源需求。

## Abstract
Coding agents can recursively modify their own implementations, forming a loop of self-improvement. While prior work shows this can boost performance on coding benchmarks, existing approaches are costly and compute-intensive. We introduce a simple, sample-efficient self-improvement framework that significantly improves coding performance under strict budget constraints. We identify evaluation of candidate self-modifications as the main runtime bottleneck since prior approaches estimate their effectiveness by re-running a subset of benchmark tasks with the modified agent, which is time-consuming. We introduce Recursive Self Improvement via Fast Tree-search (SIFT), which augments these downstream task evaluations with an LLM-as-a-judge signal that performs pairwise comparisons between candidate patches, where the win-loss record is aggregated with a regularized Bradley-Terry model, and the resulting strength scores drive rank-based parent sampling inside a lightweight disaggregated tree search. Expensive downstream task evaluations are reserved only for the most promising nodes. Using a fully disaggregated tree search pipeline, the judge scores provide intermediate signal to guide exploration on promising candidate patches without being bottlenecked by slow evaluation runs. SIFT outperforms existing tree-search based self-evolution frameworks on the full Polyglot benchmark with significantly lower resource requirements in terms of CPU hours, wall clock time, and API cost.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究领域**：编码智能体的递归自我改进（recursive self-improvement）——智能体修改自身源代码以提升未来任务表现，理论上可追溯到 Gödel Machine。
- **已有进展**：Gödel Agent、SICA、Darwin-Gödel Machine（DGM）、Huxley-Gödel Machine（HGM）等已验证该范式在编码基准上有效。
- **核心痛点**：现有方法的搜索过程**极其低效**。每个候选自我修改都必须跑完整/子集基准任务来估计其价值，形成昂贵的反馈回路；据文献，SWE-Bench 上评估成本可达约 22,000 美元、消耗数千 CPU 小时。
- **关键洞察**：作者将自我改进的主要瓶颈定位为**评估信号的"信号-成本"权衡差**——全量基准可靠但昂贵，小子集便宜但信号噪声大。
- **整体含义**：提出 SIFT，通过在候选生成与昂贵基准评估之间插入一层"廉价偏好排序层"，在严格预算下仍能发现有效的自我改进补丁，使自我改进研究更可及。

## 2. 方法论

### 2.1 核心思想
- 维护一个候选 agent harness 档案（archive），用**成对 LLM-as-a-judge 比较**提供中间信号，决定扩展与评估优先级；仅在最有希望的节点上执行昂贵下游评估。
- 自我改进循环包含两个角色：**coding model**（运行时主干，解任务）与 **self-improving model**（上层，诊断弱点并写补丁）。

### 2.2 关键技术细节

- **LLM-as-a-judge（成对比较）**
  - Judge 不接触任何基准任务或结果，仅看候选实现本身。
  - 每个新候选只与档案中少量（最多 K=10）强节点比较；比较目标按 judge rank 与 accuracy rank 从前 10 节点中选取，以控制成本。
  - 输入格式消融表明：**"Full files"**（完整源码）优于"仅 Diffs"；默认采用 full-file 且不做 swap-order。

- **正则化 Bradley-Terry（BT）聚合**
  - 每个节点 i 有潜在强度 θᵢ>0，偏好概率 P(i≻j)=θᵢ/(θᵢ+θⱼ)。
  - 累计胜场矩阵 W，用带伪计数 λ 的正则化 BT 对数似然拟合：
    ℓ_λ(θ)=Σ_{i≠j}(W_{ij}+λ)·log[θᵢ/(θᵢ+θⱼ)]。
  - 用 MM 定点迭代求解，迭代至归一化强度最大变化 <10⁻⁶ 或 100 次；归一化使 Σθᵢ=n。
  - 结果强度仅通过**排名** r_b(i) 使用，避免对绝对数值尺度敏感。

- **基于排名的父节点采样**
  - P(i) ∝ exp(−α·r_b(i) − β·r_a(i) − η·log(1+vᵢ))，其中 r_b 为 BT 强度排名、r_a 为准确率排名、vᵢ 为被选为父节点的次数。
  - 前两项偏向 judge/accuracy 表现强的节点，第三项（访问计数惩罚）鼓励探索、避免反复精修同一谱系。默认 α=β=η=1。
  - 尚未完成评估的节点临时继承父节点准确率。

- **解耦（Disaggregated）流水线**
  - 非阻塞主循环：采样父节点 → 异步自我改进 → 判官比较并重拟合 BT → 入评估优先队列（按 r_b+r_a 排序）；扩展与评估并行，避免被慢评估阻塞。
  - 新节点先过"easy subset"（4 任务）过滤损坏补丁；用固定子集保证节点间可比。

- **算法流程（Algorithm 1 概要）**：初始化 base agent 并评估 → 循环：收集完成的扩展、easy 评估、加入档案、选比较目标、查询 judge、重拟合 BT、入队 → 收集完整评估、更新准确率 → 采样新父节点发起异步扩展 → 启动评估 → 存档检查点 → 返回最高实测准确率节点。

## 6. 主要结论与发现

- **性能提升**：Polyglot-225 上，Qwen3-30B 配置达 31.1%（judge 为 Qwen3-480B）、32.0%（gpt-5.4 judge）；o3-mini + gpt-5.4 judge 达 **35.1%**，超过 DGM 的 30.7%（且 DGM 用了 80 节点搜索）。
- **效率大幅改善**：以约 1/10 的 CPU 小时达到更高准确率；Qwen3-30B 运行仅 224 CPU 小时、6.7 小时墙钟、$34.3；优于 HGM 的 30.5% @347 CPU 小时。
- **可迁移性**：SIFT 发现的 harness 在 gpt-5-mini、gpt-5.4-mini 上均一致提升，说明其优化的是通用能力而非过拟合特定 coding model。
- **Judge 的作用是排序而非精度替代**：BT 排名与真实准确率 Spearman ρ≈0.72；搜索期准确率本身不能可靠选出最佳 agent，而 judge 排序可以。强 judge（gpt-5.4-high）在 top-5 内 pairwise 一致度 1.00，弱 judge（gpt-5）降至 0.50。
- **输入格式影响显著**：Full files 的 Spearman ρ=0.68，明显优于 Diffs 的 0.40；swap-order 收益有限但成本翻倍。
- **解耦流水线贡献主要加速**，投机扩展进一步缩短达标时间。
- **定性发现**：judge 能识别下游评估无法察觉的失败模式（如 TerminalBench 中被默认关闭的 verifier、每次新建 shell 的 bash 重写），但也存在偏好保守改动而非额外机制的偏差。

## 7. 优点

- **方法简洁且样本高效**：用成对 judge + BT 聚合替代大量基准评估，将成本降低一个数量级，显著降低研究门槛。
- **设计合理**：仅使用排名而非原始分数，降低对 judge 校准的敏感性；正则化 BT 处理稀疏比较图，理论上有适定性与 top-K 恢复保证。
- **工程上高效**：完全解耦流水线允许扩展与评估并行，不被慢评估阻塞；优先级队列聚焦高潜力节点。
- **实验严谨**：多基准、多模型、留出全量评估、重复评估、无 judge 消融、跨模型迁移，并报告资源开销。
- **安全意识到位**：限制可写文件、拒绝修改 harness/基准代码的补丁、沙箱执行，明确讨论评估完整性风险。
- **理论支撑**：附录给出正则化 BT 的适定性定理、理想化 top-K 恢复定理、排名采样的概率质量放大命题及访问计数惩罚的无永久饥饿命题。

## 8. 不足与局限

- **仍依赖下游评估验证**：judge 只做中间信号，最终改进仍需基准评估确认，未完全摆脱昂贵评估。
- **judge 强于 coding backbone**：最强配置中 judge 模型（如 gpt-5.4）强于 coding model，非"纯自我评判"；小模型或开权重 judge 是否可行未验证。
- **BT 单标量假设**：假设每节点单一潜在强度，可能掩盖任务维度上的权衡（如长时程调试 vs 语法修复），无法表达多技能画像。
- **judge 存在偏差**：倾向保守改动、偏好更少机制，可能造成不完全正确的排序；弱 judge 在 top-5 内排序不可靠，影响最终选择。
- **实验覆盖有限**：judge 模型强度对比每条件仅一次搜索运行；未报告 GPU 型号/数量；TerminalBench 上 judge 选出的节点搜索期分数反而略低于 accuracy rank 1（18/50 vs 19/50），说明排序并非总是最优。
- **安全与评估完整性风险**：候选补丁可能利用 harness 弱点、放宽约束或迎合评估假象；论文观察到诊断 agent 曾提议放宽评测 harness，虽被拦截，但此类风险需持续防范。
- **应用限制**：正则化与采样超参数（α、β、η、λ）需调优；η=0 会明显降性能，跨任务/模型的泛化配置仍需验证。
