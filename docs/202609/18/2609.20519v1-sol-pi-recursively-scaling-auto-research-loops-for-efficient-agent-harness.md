## 摘要
随着编码智能体从有监督的代码补全转向无人值守、全天候的探索，其工作从孤立的预测扩展为推理、工具使用与反馈的长轨迹。因此，token 效率对于扩展递归自我改进变得重要。我们在执行框架层采用受 RSI 启发的方法，在越来越多且多样的环境中扩展自动研究循环，以进行执行框架的 rollout。在这种规模下，该过程产生了可复用的改进，这些改进可迁移到其开发环境之外，推动自动执行框架发现迈向生产级成果。四种机制经过筛选保留下来并构成 SoL-Pi，涵盖动作执行、上下文压缩、观察处理和委托阅读。在 51 项任务的 EdgeBench 评估中，SoL-Pi 在 GPT-5.6 Sol 和 Opus 5 上取得了与 Pi 相当的性能，同时将记录的 token 流量减少了 44.7–49.0%，并将 API 成本降低了约三分之一。换言之，相对于原生 Codex 和 Claude Code 执行框架，估计每小时可节省 8.75–13.50 美元；相对于 Pi，可节省 4.36–5.71 美元。

## Abstract
As coding agents move from supervised code completion to unattended, around-the-clock exploration, their work expands from isolated predictions into long trajectories of reasoning, tool use, and feedback. Token efficiency therefore becomes important for scaling recursive self-improvement. We take an RSI-inspired approach at the harness layer, scaling auto-research loops across increasingly numerous and diverse environments for harness rollouts. At this scale, the process yields reusable improvements that transfer beyond their development setting, moving automated harness discovery toward production-level outcomes. Four mechanisms survive selection and form SoL-Pi, spanning action execution, context compaction, observation handling, and delegated reading. On the 51-task EdgeBench evaluation, SoL-Pi achieves performance comparable to Pi across GPT-5.6 Sol and Opus 5 while reducing recorded token traffic by 44.7-49.0% and API cost by about one third. In other words, estimated hourly savings are \$8.75-\$13.50 relative to native Codex and Claude Code harnesses, and \$4.36-\$5.71 relative to Pi.

## 一、核心问题与整体含义（研究动机与背景）

- **背景转变**：编码智能体正从"有监督的代码补全"转向"无人值守、全天候自主探索"，其工作形态由孤立预测扩展为包含推理、工具调用、环境反馈的长轨迹。
- **核心瓶颈**：在长时程运行中，token 消耗与 API 成本急剧累积，**任务级 token 效率**成为递归自我改进（RSI）能否规模化的第一性系统问题。
- **现有路径的局限**：已有效率工作多聚焦于降低"每 token 成本"，如更快注意力核、服务基础设施、量化压缩、调用更便宜模型等；本文提出**正交方向**——通过**智能体执行框架（harness）**这一模型与环境之间的中介层来提升 token 使用效率，无需额外模型训练。
- **harness 优化的困难**：工具使用、上下文管理、验证、委托、恢复、终止等环节高度耦合，局部有利的改动可能引发下游失败或把成本转移到执行后期；人工排查长轨迹、归纳失败模式并转为代码改动代价高昂、难以跨任务扩展。
- **研究目标**：采用 RSI 启发的思路，让 AI 优化器自动、迭代地改进 harness，并保证所发现的改进**可迁移**到搜索环境之外，避免在搜索任务上过拟合（此前研究已指出演化 harness 在留出任务上增益边际的问题）。

## 二、方法论

### 核心思想
- 将 harness 改进建模为受 RSI 启发的、面向**可复用效率机制**的搜索，核心是"**从宽到深（broad-to-deep）漏斗**"：外层广撒网探索假设，内层对候选做反复实现、评审、加固。
- **三条设计原则**：
  - **广度与深度**：广度扩展假设覆盖，深度反复实现/评审/加固有前景的候选。
  - **独立验证**：留出证据仅在候选**冻结后**评估，且**永不回流**到搜索，防止把验证失败"打补丁"成任务特定解。
  - **可扩展编排**：隔离、一次性的搜索谱系，使漏斗可跨更多想法与环境扩展而不产生失败耦合。

### 关键技术细节与流程
- **搜索流水线**：研究 AI 分析基线 harness 的执行轨迹 → 识别可避免的开销 → 构建候选机制池 → 在开发环境中测试。接受标准为：需在**不止一个**开发环境中提升效率，同时保持任务完成能力。
- **双门筛选**：
  - **能力门**：所有能力指标必须落在**预先声明并固定**的容差范围内（指标与容差由优化智能体控制之外固定，防止"刷分"）。
  - **效率门**：候选必须至少改善一个已声明的效率指标。
  - 通过双门者按声明指标保留**非支配解**。
- **搜索规模**：外层初始提出 **152 个方向**，分属六个提议家族（context、progress、tools、delegation、prompt and policy、improvement and evaluation）；整体约 **150 个方向**、约 **500 个可执行环境**、超过 **3,000 次运行**、超过 **60,000 次 agent–environment 交互**。
- **实现循环**：在常规 autoresearch 循环（提议→实现→固定实验→检视→保留/修改/丢弃）之上，扩展基于 **Ralph Loop** 的迭代实现环：实现者按显式完成标准精炼候选，独立评审者检查后再评估，评审失败触发修改；每个独立搜索作为**一次性实例**运行共享技能模板，保留候选与证据、丢弃被修改的编排代码。
- **冻结与评估隔离**：在留出评估前冻结机制源码、配置、指标、能力容差与接受规则；EdgeBench 输出完全不进入搜索循环。

### 四个保留机制（SoL-Pi 的构成）
- **Action Fusion（动作融合）**：将"编辑/写入文件"与随后的"测试/构建/运行"命令合并为一次工具请求，结果在单个观察中返回，消除中间模型往返（示例：3 次 API 调用降至 2 次）；需检查变更结果的命令仍保持分离。
- **Online Context Compact（在线上下文压缩）**：以**计划步骤完成**为重新考虑压缩的边界。利用已完成步骤间的请求数与未完成步骤数估算剩余模型请求，并以当前上下文增长速率填满窗口的请求数封顶；**成本门**比较预计输入节省与重写提示缓存的额外成本，只有节省大于成本（且后续压缩需更大余量以覆盖未回收的重写成本）时才触发 Pi 原生压缩，或在接近窗口上限且压缩可缩短上下文时触发。
- **ObservationPack（观察打包）**：对超过阈值（**10 KiB**）的大工具输出本地归档，前两次 provider 请求仍全量发送；从第三次起替换为**稳定句柄 + 原始大小 + 完整首尾行的短摘录**，智能体可按句柄按需取回精确页；较小结果不变。
- **Evidence-Preserving Reducer（证据保留缩减器）**：对来自预定义命令集、至少 **4 KiB** 的构建/测试日志进行压缩；文件读取与搜索结果绕过。harness 归档精确输出，调用**低成本模型**抽取关键证据生成紧凑 receipt，再由**确定性验证器**校验 receipt 的 schema、源哈希、退出状态、精确引文与大小；验证失败、怀疑凭据泄露或 receipt 无体积缩减时**回退到原始日志**。该机制在 ObservationPack 之前处理工具结果，ObservationPack 识别其标记并跳过以保留已验证证据；辅助模型仅做证据抽取，诊断与行动选择仍由主智能体负责。

### 实现与后端设置
- 四机制均实现为 **Pi** 的扩展；Evidence-Preserving Reducer 使用 **GPT-5.6 Luna（high）** 抽取证据；成本门依据上下文大小与缓存写/读价格比估算缓存重写开销，不单独计价摘要调用。
- EdgeBench 的 51 个公开任务中，**11 个**用于冻结候选的单向验收，其余 **40 个**保留作最终泛化评估。

## 六、主要结论与发现

- **EdgeBench（GPT-5.6 Sol）**：SoL-Pi [Efficiency] 总 token 1.10 B，比 Pi 少 **49.0%**，保留 Pi 平均分的 **93.7%**（42.0 vs 44.8），token 成本低 **33.2%**；SoL-Pi [Performance] 平均分从 44.8 提升至 **47.2**（+5.3%），token 流量降 6.1%，token 效率提升 9.8%。
- **跨模型迁移（Opus 5）**：无额外搜索/适配下保留 Pi 平均分的 **94.3%**，token 流量降 **44.7%**，API 成本降 **33.5%**；SoL-Pi [Performance] 在 Opus 5 上达到 **50.482** 分。
- **成本节省**：相对原生 Codex（GPT-5.6 Sol）降 **50.0%**，相对 Claude Code（Opus 5）降 **54.3%**；估计每小时节省 8.75–13.50 美元（相对原生 harness）、4.36–5.71 美元（相对 Pi）。
- **Terminal-Bench 4**：SoL-Pi 解出 15/63（Codex、Pi 各 18），但总模型成本比 Pi 降 **26.3%**（$211.12 vs $286.45），每解出任务成本降 **11.6%**（$14.07 vs $15.91），说明效率增益可泛化。
- **IMO 2026**：SoL-Pi 通过 3/6，总成本 $62.69，**每通过题成本最低**（$20.90 vs Codex $22.89、Pi $25.32）。
- **Agent Swarm**：SoL-Pi worker 集群 2 小时达 1,127 cycles、成本 $60.11，比 Pi 基线集群（1,366 cycles、$82.12）**降本 26.8%**；SoL-Pi 集群与单智能体均通过全部 8 个速度阈值，Pi 基线集群通过 7 个。
- **机制行为**：四个机制在不同后端均降低总 token；GPT-5.6 Sol 下 ObservationPack 得分最高，Opus 5 下 Action Fusion 得分最高；Opus 5 上触发率与触发强度更低（可能因 harness 仅在 GPT-5.6 Sol 轨迹上优化），但被触发时仍提升效率；完整栈中 ObservationPack 更"挑剔"（可能与 Evidence-Preserving Reducer 在观察密集轨迹上重叠），且每个机制在完整栈中的效率增益均大于其单独配置。
- **缓存权衡**：压缩会牺牲部分前缀缓存复用，完整栈在 GPT-5.6 Sol 下将 cache-read 从 2.1326 B 降至 1.0605 B，cache-write 从 0.0141 B 升至 0.0316 B，但总成本仍从 $1,339 降至 $894，说明应看**全任务成本**而非仅缓存复用率。
- **总体判断**：RSI 式

式 harness 自优化在**不修改模型权重、不做额外训练**的前提下，能够产出可跨任务环境、跨模型后端迁移的 token 效率增益；其关键在于把"验证隔离 + 冻结评估 + 非支配保留"作为搜索的结构性约束，而非事后补丁，从而把效率优化从"局部调参"提升为"可复用机制的发现"。

## 七、局限与不足（作者自述与读者可辨识的问题）

### 作者明确承认的局限
- **搜索成本高昂，缺乏 scaling law**：完整自动研究循环代价大，难以在固定预算下对搜索的"广度 vs 深度"做受控对比；本文只报告了一个"宽→深"漏斗的实例，未给出可外推的规模—收益关系。
- **触发依赖训练分布**：机制在 GPT-5.6 Sol 轨迹上被搜索得到，迁移到 Opus 5 时**触发率与触发强度明显下降**——虽然被触发时仍有效，但说明机制的"激活条件"部分绑定于开发后端的交互风格。
- **消融为描述性而非因果**：单机制与完整栈的比较在各自触发任务子集上进行，**无法隔离机制间交互效应**；"完整栈中每个机制增益更大"这一观察更接近相关性而非已证明的因果。
- **评估集规模有限**：EdgeBench 仅使用 51 个公开任务（官方共 134 个），Terminal-Bench 4 排除了依赖 GPU 的任务，IMO 2026 仅 6 题；样本量限制了统计显著性声明。

### 读者可辨识的额外问题
- **价格口径的时效性**：全部成本以 2026 年 8 月 17 日的 API 价格计算，且压缩带来的节省高度依赖**缓存写/读价格比**；若定价结构变化，Online Context Compact 的成本门判据需要重新标定，结论的绝对数值可能不稳健。
- **辅助调用未单独计价**：Evidence-Preserving Reducer 的摘要调用（GPT-5.6 Luna high）未单独计入成本，尽管其规模相对主模型较小，但严格意义上成本比较并非完全同口径。
- **实现层耦合**：四个机制均作为 Pi 的扩展实现，其效果与 Pi 的工具调用协议、压缩原语、缓存策略强相关；迁移到结构差异较大的 harness（如 Codex、Claude Code）时，机制能否以同样形式生效未被验证。
- **"冻结"的边界**：冻结机制源码与接受规则可防止验证集回流，但开发环境本身仍是被选定的 535 个环境；对搜索环境分布的偏置是否影响机制普适性，缺乏独立检验。
- **失败模式报告不足**：文中对"被丢弃的方向"与"触发但无收益"的情形报告有限，难以判断效率增益的方差与尾部风险。

## 八、总体评价与启示

### 贡献定位
- **问题设定有价值**：把"任务级 token 效率"提升为长时程编码智能体的**第一性系统约束**，并明确指出其与"每 token 成本"优化的正交性，是一个清晰且少被系统处理的切入点。
- **方法论可复用**：以"宽→深漏斗 + 独立验证 + 一次性搜索谱系"组织的 RSI 式流程，其结构本身独立于具体机制，可迁移到其他 harness、其他模态（如浏览器智能体、数据分析智能体）。
- **机制设计有工程深度**：四个保留机制分别针对**往返次数**（Action Fusion）、**上下文增长**（Online Context Compact）、**大观察体积**（ObservationPack）、**日志噪声**（Evidence-Preserving Reducer），覆盖面互补，且都强调**确定性回退**（验证失败即回退原始日志、按句柄可取回精确页），这是可靠性设计的关键。
- **实证证据较扎实**：跨四个 benchmark、两个模型后端、单机制与组合、单智能体与 swarm 的矩阵式评估，加上跨模型零适配迁移测试，构成了较强的外部效度支持。

### 方法与结论的边界
- 该文证明了"**harness 层的效率机制可以被自动发现且可迁移**"，但尚未证明"**该流程在任意预算/任意后端下都能稳定产出机制**"。
- 效率与能力的权衡被表述为"保留 Pi 平均分的 93.7% / 94.3%"，属于**受控的近似无损**，而非严格无损；对能力要求极高的场景，该权衡是否可接受需按任务判定。
- 缓存复用率下降而总成本下降的现象，提示评估 agent 效率时必须使用**全任务成本**口径，这对后续 benchmark 设计具有方法论意义。

### 对后续研究的启示
1. **搜索规模的可控研究**：需要在固定预算下系统变化外层方向数与内层迭代数，建立 harness 优化的 scaling law。
2. **跨 harness 迁移**：验证机制在工具协议差异更大的框架间是否仍生效，以及需要何种"抽象层"来承载机制。
3. **机制交互的因果分析**：用因子设计（factorial design）或逐机制增量评估替代当前的"触发子集描述性比较"，以分离交互效应。
4. **触发条件的自适应**：降低机制对开发后端交互风格的依赖，例如以轨迹统计特征（而非后端身份）作为触发信号。
5. **成本模型的稳健性**：把定价结构、缓存策略、辅助模型调用纳入统一成本模型，并报告对价格扰动的敏感性。
6. **失败与尾部风险报告**：公开被丢弃方向与无收益触发的分布，有助于判断方法的可靠性与适用边界。

**一句话总结**：SoL-Pi 以"验证隔离 + 冻结评估 + 非支配保留"约束下的宽→深搜索，自动发现了四个可迁移的 harness 效率机制，在多个 benchmark 与两个模型后端上实现约 33%–54% 的 API 成本下降，同时保留约 94% 的基线能力；其最大价值在于提出并初步验证了"无需训练即可优化 agent 执行框架"这一研究范式，而其最大缺口在于搜索规模规律、机制交互因果与跨 harness 普适性尚待系统研究。
