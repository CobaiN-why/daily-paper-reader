## 摘要
使用可验证奖励强化学习（RLVR）训练的长时程软件工程（SWE）智能体通常仅接收终端结果监督，难以区分有成效的动作与冗余探索或功能回归。我们提出 SWE-MILE，一种异步势能诱导里程碑信用分配框架，它从工作流运行时中提取细粒度过程监督，无需辅助奖励模型或外部评估器。SWE-MILE 将任务相关文件暴露程度和测试状态对齐程度分别量化为导航势与验证势。这些势的差异将里程碑进展和回归归因到单个动作，而折扣反向信用将监督传播到先前步骤。为了高效获取中间验证状态，SWE-MILE 进一步引入异步影子探测，它在隔离沙箱中重放改变仓库的动作，并与智能体的主要交互并行运行验证，从而在很大程度上隐藏验证延迟。由此得到的过程信用增强了终端结果优势，并提供信息丰富的学习信号。在两个代表性长时程 SWE 任务上的实验表明，智能体性能获得显著提升，凸显了工作流运行时信号作为长时程 SWE 智能体过程监督的实用来源。

## Abstract
Long-horizon software engineering (SWE) agents trained with reinforcement learning with verifiable rewards (RLVR) typically receive only terminal outcome supervision, making it difficult to distinguish productive actions from redundant exploration or functional regressions. We propose SWE-MILE, an asynchronous potential-induced milestone credit assignment framework that derives fine-grained process supervision from workflow runtime, without auxiliary reward models or external evaluators. SWE-MILE quantifies task-relevant file exposure and test-state alignment as navigation and verification potentials, respectively. Differences in these potentials attribute milestone progress and regressions to individual actions, while discounted backward credit propagates supervision to preceding steps. To efficiently acquire intermediate verification states, SWE-MILE further introduces asynchronous shadow probing, which replays repository-changing actions in an isolated sandbox and runs verification in parallel with the agent's primary interaction, largely hiding verification latency. The resulting process credit augments terminal outcome advantages and provides informative learning signals. Experiments on two representative long-horizon SWE tasks demonstrate substantial improvements in agent performance, highlighting workflow runtime signals as a practical source of process supervision for long-horizon SWE agents.

## 1. 核心问题与整体含义

- **背景**：LLM 已从单轮代码生成走向长时程软件工程（SWE）智能体，在真实仓库中通过多轮交互完成代码库导航、检查、编辑与测试（SWE-bench、SWE-bench Pro、NL2Repo-Bench 等）。随着 SWE-Gym、R2E-Gym、SWE-rebench V2、DeNovoSWE 等可执行环境的出现，RLVR（带可验证奖励的强化学习）成为提升 SWE 智能体能力的重要范式。
- **核心痛点**：RLVR 的奖励几乎只作为**终端结果**被消费——单元测试只告诉 rollout 成功或失败，却不揭示哪些中间动作有贡献、哪些造成了损害。SWE 轨迹通常包含数十到上百个异质动作，成功轨迹中可能夹杂冗余探索或临时功能回归，失败轨迹中也可能已经正确完成问题定位或部分修复。把所有动作赋予同一结果奖励，造成严重的**时序信用分配（temporal credit assignment）**问题。
- **现有三条路线的不足**：
  - *规则法*（G-RA 等）：奖励合法工具调用/成功执行等，只反映协议合规或浅层工具行为，不等于实质任务进展，且易被 reward hacking。
  - *辅助模型法*（SWE-TRACE、SWE-Shepherd、Rubric-based GRM 等）：依赖奖励模型或外部 LLM 评判，信号是模型估计的代理量，不直接锚定仓库的可验证功能变化，并引入额外推理开销与延迟。
  - *状态聚合法*（GiGPO、GraphGPO）：按等价状态聚合多 rollout 估计步价值，但 SWE 状态丰富、高维、历史相关且部分可观测，状态匹配稀疏，价值仍间接来自下游结果。
- **论文的整体主张**：SWE 工作流的**运行时（runtime）本身就是被低估的过程监督来源**。最终验证器虽然只给出二元结果，但其底层证据（哪些 F2P 测试已通过、哪些 P2P 测试发生回归、关键文件是否被检索与查看）天然是结构化、细粒度的。关键挑战在于把这些里程碑进展**归因到具体动作**。SWE-MILE 即在**不使用辅助奖励模型或外部评估器**的前提下，从运行时信号构造动作级过程信用。

## 2. 方法论

### 2.1 核心思想与术语

- 三个定义：
  - **milestone（里程碑）**：轨迹中可观测的中间进展或回归；
  - **potential（势）**：量化该进展的标量状态函数；
  - **shadow probe（影子探测）**：在隔离影子沙箱中运行一次验证器，获得某一步的中间测试状态。
- 受 Ng et al. (1999) 的势函数奖励塑形（potential-based reward shaping）启发，用**相邻步势差**把里程碑变化归因到动作，并叠加**折扣反向信用**把监督传播到先前步骤。
- 总体框架（图 1）：主沙箱执行正常 agent–环境交互；影子沙箱按原序重放改变仓库的动作，异步探测中间验证状态。过程信用用于修正 RLOO 结果优势。

### 2.2 Codeflow 交互脚手架

- 五个结构化工具：`search`、`read_file`、`edit_file`、`execute_bash`、`submit`；另有 `search` 的 text/symbol/file/directory 模式、`read_file` 的 file/diff/status 模式、`edit_file` 的 replace/insert/create/delete/apply_patch/undo 模式。
- 支持 **Bash-only 模式**（仅 `execute_bash` + `submit`）以研究结构化动作空间 vs 灵活动作空间的影响。
- **检索/阅读归因**：对专用工具，依据成功执行后**模型实际可见的观察**归因；仅返回路径或状态的输出不算内容查看。对 Bash，用 `shlex` 词法切分 + 命令规则识别检索/阅读操作，对内联 Python 用 AST 分析，结合模型可见 stdout、解析出的目标路径与可信仓库文件清单做文件级归因，只用高置信证据更新。
- **编辑归因**：比较工具执行前后的仓库快照指纹，记录变更文件，从而识别 Bash 引起的文件改动。禁止修改受保护测试文件或改动 Git HEAD，违者回滚并受格式奖励惩罚。

### 2.3 导航势（Navigation Potential）

- 设任务相关文件集合为 $H$（来自数据集构造标注或 gold patch 涉及文件）。
- 每个文件 $f$ 的累计暴露度 $q_{f,t} \in [0,1]$ 取历史值与当前观测值的较大者：$q_{f,t} = \max(q_{f,t-1}, q^{\text{observed}}_{f,t})$。
  - 未出现：$0.0$；路径出现在搜索结果中：$0.2$；内容成功暴露给智能体：$1.0$。
- 导航势：$\Phi^{\text{navi}}_t = \frac{1}{|H|}\sum_{f\in H} q_{f,t}$。
- 取 max 的设计使**重复检索/查看同一文件不再增益**，抑制刷分；失败命令（如 `Error: file not found`）不给分。本文只用文件级监督，未使用行级标注。

### 2.4 验证势（Verification Potential）

- **问题修复任务**：设 $F$ 为初始未达目标的 F2P 测试集，$G$ 为初始正确且应保持的 P2P 测试集。
  - 已修复 F2P 比例：$p_t = \frac{1}{|F|}\sum_{i\in F} \mathbb{1}[y_{i,t}=y^*_i]$
  - 发生回归的 P2P 比例：$b_t = \frac{1}{|G|}\sum_{j\in G} \mathbb{1}[y_{j,t}\neq y^*_j]$
  - $\Phi^{\text{veri}}_t = p_t - \beta_{\text{any}}\mathbb{1}[b_t>0] - \beta_{\text{frac}} b_t$，其中 $\beta_{\text{any}}=0.1$、$\beta_{\text{frac}}=0.5$。
  - 初始 $\Phi^{\text{veri}}_0=0$，目标态为 1；严重回归时可变为负值。$\beta_{\text{any}}$ 防止 P2P 数量远多于 F2P 时单次回归被稀释。
- **整仓库生成任务**：仓库从空开始，验证器含成百上千验收测试，归一化通过率会稀释局部信用，故改用**未归一化的通过数差**：
  - $M_t = \sum_{i=1}^{N}\mathbb{1}[y_{i,t}=y^*_i]$，$M_0$ 由初始影子探测得到，$\Phi^{\text{veri}}_t = M_t - M_0$；目标态为 $N-M_0$。

### 2.5 过程奖励与信用

- 问题修复：$\Phi_t = \alpha_{\text{navi}}\Phi^{\text{navi}}_t + \alpha_{\text{veri}}\Phi^{\text{veri}}_t$（$\alpha_{\text{navi}}=0.05$，$\alpha_{\text{veri}}=0.2$）；$r^{\text{pot}}_t = \Phi_t - \Phi_{t-1}$。
- 整仓库生成：关闭导航势，且对势差做**非对称裁剪**：$r^{\text{pot}}_t = \alpha_{\text{veri}}\,\text{clip}(\Phi^{\text{veri}}_t-\Phi^{\text{veri}}_{t-1}, -c_-, c_+)$，$\alpha_{\text{veri}}=0.1$，$c_-=6$，$c_+=3$（对回归惩罚更强）。
- 过程信用：$C^{\text{process}}_t = r^{\text{pot}}_t + \lambda\sum_{u=t+1}^{|T|}\gamma^{u-t}r^{\text{pot}}_u + \eta r^{\text{fmt}}_t$，$\lambda=0.2$，$\gamma=0.9$，$\eta=0.25$；格式奖励 $r^{\text{fmt}}_t=0$（格式正确）或 $-1$（否则）。反向信用用于给"正确编辑所依赖的前置检索/定位动作"延迟反馈。
- **反 reward hacking 机制**：已完全暴露的文件重复查看不再增益；"故意破坏再修复"先被惩罚后才获得恢复奖励。

### 2.6 策略优化

- 不做步级跨轨迹归一化（避免长度偏差、结果与过程奖励耦合、跨语义步的上下文错位），而是把过程信用作为**结果优势的修正项**。
- 采用 RLOO 风格结果优势：$A^{\text{outcome}}_k = R_k - \frac{1}{K-1}\sum_{m\neq k}R_m \in [-1,1]$，轨迹内所有步共享。
- 最终优势：$A_{k,t} = A^{\text{outcome}}_{k,t} + C^{\text{process}}_{k,t}$；用步级 PPO 裁剪损失优化（$\epsilon_-=0.2,\epsilon_+=0.28$）。
- 该设计既保留轨迹级比较，又区分同轨迹内各步贡献。

### 2.7 异步影子探测

- 每个 rollout 创建初始状态相同的主沙箱与影子沙箱；主沙箱比较动作前后仓库哈希，检测到变化即把动作及其目标仓库状态异步入队。
- 影子沙箱按轨迹顺序重放这些动作，每次重放后运行验证器，获得中间测试状态。
- 影子 worker 与主 rollout 独立运行，探测与下一轮模型生成及后续交互**时间重叠**，仅在 rollout 结束时做一次同步；9600 次 rollout 统计显示验证势探测平均仅带来约 **2.07 s** 的墙钟尾延迟。
