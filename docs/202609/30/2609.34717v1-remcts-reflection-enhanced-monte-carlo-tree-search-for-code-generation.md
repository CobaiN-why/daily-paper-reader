## 摘要
开放权重的大语言模型（LLM）能够根据自然语言提示生成函数级程序，但看似合理的候选程序仍会在隐藏语义上失败，并在多次修复尝试中重复犯错。我们提出 ReMCTS，一个以执行为基础、记忆增强、由 LLM 引导的 MCTS 风格搜索框架。它将程序候选组织为树状态，保留分支局部的调试上下文，跨分支检索失败经验，并区分未通过的检查与不可用的证据。在 HumanEval 和 MBPP-Sanitized 上，在留出评估下，使用可见测试的 ReMCTS 在 10 个模型-数据集组合中的 8 个上优于直接生成，而仅代理搜索则较不稳定。受控的树搜索、采样、修复和记忆消融实验刻画了这些增益的来源与局限。一个包含 30 个任务的 HumanEval-X C++ 初步实验进一步表明其与编译器支持执行的兼容性，但并不构成广泛的多语言评估。

## Abstract
Open-weight large language models (LLMs) can generate function-level programs from natural-language prompts, but plausible candidates still fail on hidden semantics and repeat mistakes across repair attempts. We present ReMCTS, an execution-grounded, memory-augmented, LLM-guided MCTS-style search framework. It organizes program candidates as tree states, retains branch-local debugging context, retrieves failure experience across branches, and distinguishes failed checks from unavailable evidence. On HumanEval and MBPP-Sanitized, visible-test ReMCTS improves over direct generation in 8 of 10 model-dataset pairs under held-out evaluation, whereas proxy-only search is less stable. Controlled tree-search, sampling, repair, and memory ablations characterize the source and limits of these gains. A 30-task HumanEval-X C++ pilot further demonstrates compatibility with compiler-backed execution, but does not constitute a broad multilingual evaluation.

## 1. 核心问题与研究动机

- **问题定位**：代码生成不应被视为一次性的文本补全，而是一个**部分可观测反馈下的程序搜索问题**。即使模型生成语法正确的代码，程序仍可能在边界条件、接口约束、隐藏输入或复杂逻辑上失败。
- **现状缺口**：当前 LLM 代码生成普遍缺乏人类程序员的闭环工作流（写初稿 → 运行 → 观察错误 → 反思原因 → 修改 → 重试）。若首个方案落入错误的算法方向，后续局部修复往往只修补症状，底层算法仍然错误。
- **三个具体空白**：
  1. **单轨迹自修复陷阱**：后续修改基于同一条轨迹，容易反复修补局部症状，难以重新考虑替代算法。
  2. **树搜索奖励利用不足**：多数树搜索依赖数值奖励排序，未充分利用跨分支的自然语言错误诊断，兄弟分支无法从他人失败中学习。
  3. **无测试场景的证据混淆**：没有显式测试时，仅凭语义接受容易过度乐观，把"证据缺失"误当成"真实成功"，导致搜索过早终止。
- **整体含义**：论文主张在推理阶段构建一个"执行接地、记忆增强、LLM 引导"的搜索系统，探索多个候选程序、记录失败经验并跨尝试复用，从而突破单轨迹修复的局限。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体框架

- **ReMCTS** 是一个以执行为基础、记忆增强、由 LLM 引导的 **MCTS 风格**搜索框架，用于推理时程序搜索。
- 与标准 MCTS 的区别：**保留树策略、UCB 选择与反向传播结构，但使用 LLM 生成扩展，不进行经典随机 rollout**，因此称为"MCTS-style"。
- **五阶段闭环**：选择（Selection）→ 扩展（Expansion）→ 执行（Execution）→ 反思（Reflection）→ 反向传播（Backpropagation）。

### 2.2 记忆引导的树节点设计

- 每个节点定义为：`Node_i = [S_i, V_i, N_i, M^(k)_path,i, Φ_i]`
  - `S_i`：候选程序；`V_i`：累计价值；`N_i`：访问次数
  - `M^(k)_path,i`：k 跳路径反思记忆；`Φ_i`：执行反馈、奖励分解、风险信息、语义评审等元数据
- **路径记忆**：保留当前分支最近 k 条结构化反思（错误类型、失败症状、根因、修复提示、严重度），控制上下文长度并保持修复方向连贯。
- **全局记忆仓库 G**：跨分支存储错误经验，每个基准任务重新初始化；用 128 维确定性哈希 token 计数向量做嵌入，按余弦相似度检索 top-t=2 条记录，无硬相似度阈值。

### 2.3 记忆增强的 UCB 选择

- 标准 UCB 被扩展为 `UCB_M`：在利用项与探索项之外，加入**记忆启发式 H_i**：
  - `H_i = α·Conf(M^(k)_path,i) − β·Risk(M^(k)_path,i, G)`
  - `Conf` 奖励低严重度、正向奖励变化和存在修复提示；`Risk` 是与高严重度（≥0.7）全局记录的最大余弦相似度。
- 参数固定为 `C=1.4, α=0.4, β=0.6`，强调是设计选择而非理论最优。
- **软信号特性**：检索到的记忆进入扩展提示与语义启发式，但**从不删除分支**；后续执行证据可通过数值回报覆盖误导性检索。

### 2.4 证据驱动的奖励与接受机制

- **证据集**：`E_i = {E_unit, E_exec, E_contract, E_probe, E_meta, E_static, E_sem, E_risk}`，每项为 `(A_k, C_k, R_k)`——可用性、置信度、归一化分数。
- **关键设计：可用性感知**。不可用证据从奖励聚合中排除，`A_unit=0` 时缺失测试**不计为失败**。
- **无测试场景奖励**：
  - `R(S_i) = Σ_{g∈J} δ_g ω_g A_g C_g R_g(S_i) / (Σ ω_g A_g C_g + ε)`，`J={p,e,s,r}`
  - 权重 `(ω_p, ω_e, ω_s, ω_r)=(0.4,0.2,0.3,0.1)`，仅风险项 δ 取负号
- **已知测试场景**：`R_known = 0.6·R_obs_unit + 0.2·R_exec + 0.2·R_sem`，且必须全部可见测试通过才接受。
- **风险感知接受分数**：`Score_acc = R(S_i) − γ1·U_i − γ2·R_risk − γ3·D_i`
  - `U_i` 惩罚低置信度证据，`R_risk` 惩罚不安全行为，`D_i` 惩罚代码长度偏离
- **组件奖励细节**：
  - `R_exec = 0.3(I_c+I_r) + 0.2(I_t+I_o)`（编译、执行、可执行测试、非空输出）
  - `R_sem = C_sem · Q_sem · (1 − q_srisk)`（置信度与风险加权的 LLM 评审）
  - `R_risk = clip(0.2·n_danger + 0.15·I_{>200}, 0, 1)`；语法错误取 0.25
- **接受门控**：无测试场景需同时满足 Score_acc、proxy、execution、semantic 阈值并低于风险阈值；启用"完整分支后再接受"，且不早于最小迭代次数返回。
