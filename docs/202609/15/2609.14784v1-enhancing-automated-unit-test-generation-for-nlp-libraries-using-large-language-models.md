## 摘要
像 EvoSuite 这样的自动化单元测试生成工具在通用软件上表现良好，但在自然语言处理（NLP）库等领域特定软件上往往表现不佳，因为这类软件的输入必须遵循语义、句法和结构约束。大型语言模型（LLM）可以生成领域相关的测试代码，但仅由 LLM 生成的测试往往无法编译或达到足够的覆盖率。我们提出 LLMSuite，一种混合测试生成框架，将自精炼提示与类级别 LLM 推理集成到基于搜索的测试过程中。在该机制中，LLM 根据先前生成结果的反馈迭代改进其测试片段。这使模型能够生成日益精确、领域一致的代码片段，引导进化搜索去执行复杂且原本难以触及的行为。当底层进化算法在连续多代中没有任何目标得到改进时，这些精炼后的片段会被解析并注入 EvoSuite 的种群，以扩展搜索空间。为支持我们的评估，我们构建了一个新数据集，包含从五个广泛使用的 Java NLP 项目中抽取的 100 个类。我们还在 Java 中重新实现了 CodaMOSA——一种近期的 SBST-LLM 混合技术，以便进行直接比较。在该数据集上，LLMSuite 将分支覆盖率和行覆盖率分别提升约 10% 和 8%，并且相比 CodaMOSA-J 获得高 11% 的变异得分。与 EvoSuite 相比，LLMSuite 的分支覆盖率和行覆盖率约高 15%，变异得分高 5%。相较于仅使用 LLM 的基线，它将结构覆盖率提升 36%，变异得分提升约 24.7 个百分点。最后，LLMSuite 通过执行通常未被测试的领域特定行为，补充了手动编写的测试套件。

## Abstract
Automated unit test generation tools like EvoSuite perform well on general-purpose software but often struggle with domain-specific software such as Natural Language Processing (NLP) libraries, where inputs must follow semantic, syntactic, and structural constraints. Large Language Models (LLMs) can generate domain-relevant test code, but tests produced by LLMs alone often fail to compile or achieve sufficient coverage. We propose LLMSuite, a hybrid test generation framework that integrates self-refinement prompting with class-level LLM reasoning into the search-based testing process. In this mechanism, the LLM iteratively improves its test snippets based on feedback from previous generations. This enables the model to produce increasingly precise, domain-consistent code fragments that steer the evolutionary search toward exercising complex and otherwise hard-to-reach behaviors. When no objective improves over multiple generations in the underlying evolutionary algorithm, these refined snippets are parsed and injected into EvoSuite's population to expand the search space. To support our evaluation, we constructed a new dataset comprising 100 classes drawn from five widely used Java NLP projects. We also re-implemented CodaMOSA, a recent hybrid SBST-LLM technique, in Java to enable a direct comparison. Across this dataset, LLMSuite improves branch and line coverage by approximately 10% and 8%, respectively, and achieves an 11% higher mutation score than CodaMOSA-J. Compared to EvoSuite, LLMSuite yields roughly 15% higher branch and line coverage and 5% higher mutation score. Against an LLM-only baseline, it improves structural coverage by 36% and mutation score by about 24.7 percentage points. Finally, LLMSuite complements manually written test suites by exercising domain-specific behaviors that are often left untested.

## 1. 核心问题与研究动机

- **背景**：EvoSuite、Randoop 等自动化单元测试生成工具在通用软件上表现良好，其核心是搜索式软件测试（SBST），通过进化算法（如 DynaMOSA）最大化代码覆盖率。
- **问题**：这类工具在**领域特定软件**（尤其是 NLP 库）上效果显著下降。NLP 库的测试输入必须满足**语义、句法和结构约束**（如语法正确的句子、合法的解析树、连贯的标注流水线），而 SBST 缺乏领域语义理解，容易陷入局部最优。
- **具体证据**：论文以 Stanford CoreNLP 的 `MorphaAnnotator` 为例说明——EvoSuite 无法生成测试，原因是：(1) 难以构造必需对象；(2) 不了解领域特定输入格式；(3) 无法组合多个相关输入属性。
- **LLM 单独使用也不够**：LLM 能生成领域相关的测试代码，但纯 LLM 生成的测试常常无法编译、覆盖不足（LLMOnly 基线分支覆盖仅 32.64%）。
- **整体含义**：论文主张一种**互补的混合思路**——LLM 提供上下文洞察与语义有意义的输入，SBST 负责系统化的路径探索，从而在 NLP 这类领域特定库上实现更有效的测试生成。

## 2. 方法论：LLMSuite 框架

### 2.1 核心思想
LLMSuite 是扩展 EvoSuite 的混合测试生成框架，包含两个组件：**α 搜索过程**与 **β 基于 LLM 的测试生成**。关键设计是：**当搜索停滞时，调用 LLM 生成领域相关的测试片段，解析后注入 EvoSuite 的种群**，让进化搜索能够利用这些嵌入领域知识的测试继续演化。

### 2.2 搜索过程（α）
- 基于 EvoSuite 的 **DynaMOSA** 多目标优化算法。
- **停滞检测**：当种群适应度在连续 **S = 20 代**内对所有目标均无改进时，判定为停滞点，触发 LLM 测试生成。
- LLM 生成的测试与当前种群**合并（union）**，重新计算适应度并更新种群；这些测试可参与**交叉与变异**等遗传操作。
- 该 LLM 集成最多可触发 **L = 5 次**。
- 搜索结束后，所有测试统一编译，确保可编译且稳定（只应因断言违规而失败，而非幻觉代码导致的问题）。

### 2.3 LLM 测试生成（β）——三阶段提示流程
1. **初始测试生成**：以**类级别（class-level）**为上下文，生成初始测试类（默认使用类级提示以提供更丰富上下文）。
2. **格式重构（Reformat）**：将生成结果转换为 EvoSuite 要求的自包含格式（排除循环、外部方法调用、辅助工具等）。论文特意将"生成"与"重构"分离，因为在初始生成阶段强加格式约束会削弱 LLM 的创造力。
3. **自精炼（Self-Refine）**：迭代 **T = 5 轮**（默认）。每轮要求 LLM 分析尚未覆盖的场景、明确列出这些场景、并生成新的边界/极端/失败点测试用例。保留对话历史以支持反馈推理。所有测试进入共享池，按测试名去重。
   - 与 Madaan et al. 不同，本文把**反馈与精炼合并为单个提示**，以减少提示次数。

### 2.4 提示工程与后处理
- 提示模板遵循最佳实践：清晰开发者人设、可操作且精确的任务指令、Chain-of-Thought 式推理引导、标准化输入/输出格式（`[TEST]...[/TEST]`、`[CODE]...[/CODE]`）。
- 后处理：使用 **ANTLR 做语法校验**，并启发式修复常见问题（缺失逗号、括号）。
- 默认 LLM 为 **GPT-4o（ChatGPT-4o-latest-2025-07-12）**，框架为模型无关的模块化设计，也支持 `code-llama:13b-instruct`（经 Ollama）。

### 2.5 LLM2EvoSuiteParser（自定义解析器）
- 基于 **Spoon** 做静态分析，将 LLM 生成的文本代码转换为 EvoSuite 内部表示（如 `token.set(..., "VBD")` → `class1` 对象初始化 + `coreLabel0.set(...)` 调用）。
- 支持嵌套调用、varargs、多维数组、赋值语句、mock 语句。
- 对 EvoSuite 不支持的构造（循环、lambda、try-catch），**选择性提取有效子组件**（如 try 块中的语句、断言中的表达式）。
- 采用**宽松参数匹配**跳过幻觉行：若参数个数不匹配，保留前 N 个有效参数、丢弃多余部分。
- 在解析前设有**幻觉过滤阶段**：启发式修复不可行时，将幻觉行及其依赖行注释掉，保留其余有效语句。
