## 摘要
测试时扩展通过将额外的推理预算（例如调用次数或 token 数）用于直接采样、基于反馈的修复和推理引导的实现，从而改进代码生成。基于搜索的方法能够自适应地分配这一预算，但仍存在两个挑战。首先，树结构搜索将每条生成历史视为单独状态，即使不同轨迹收敛到同一程序，这会导致重复评估，并阻碍统计信息共享。其次，采样、修复和推理具有互补且依赖状态的收益，使得在有限预算下难以在它们之间进行在线分配。为解决这些挑战，我们提出了一种具有异构动作的自适应图搜索方法（GraphAHA）。GraphAHA 将测试时代码生成组织在一个带类型的有向无环图中。等价程序被合并为单个代码节点，使其下游搜索统计信息能够在所有发现路径中复用。分层 Thompson 采样随后选择是生成新状态还是沿现有后继状态继续，并在生成时从类型有效的采样、推理、实现和修复操作中进行选择。在 LiveCodeBench 和 CodeContests 上使用 Qwen2.5-Coder 和 DeepSeek-Coder 进行评估，GraphAHA 在 20 个案例中的 18 个取得了最佳分数。对于使用可见测试测得的 Pass@1，它在两个基准上对两个模型均优于最强基线，平均高出 4.1 个百分点，表明更有效地利用了固定推理预算。

## Abstract
Test-time scaling improves code generation by spending additional inference budget (e.g., calls or tokens) on direct sampling, feedback-conditioned repair, and reasoning-guided implementation. Search-based methods can allocate this budget adaptively, but two challenges remain. First, tree-structured search treats each generation history as a separate state even when trajectories converge to the same program, duplicating evaluation and preventing statistics from being shared. Second, sampling, repair, and reasoning have complementary and state-dependent payoffs, making online allocation among them difficult under a finite budget. To address these challenges, we propose an adaptive graph search method with heterogeneous actions (GraphAHA). GraphAHA organizes the test-time code generation in a typed directed acyclic graph. Equivalent programs are merged into a single code node, allowing their downstream search statistics to be reused across all discovery paths. Hierarchical Thompson sampling then selects whether to generate a new state or follow an existing successor and, for generation, chooses among the type-valid sampling, reasoning, implementation, and repair operations. Evaluated on LiveCodeBench and CodeContests with Qwen2.5-Coder and DeepSeek-Coder, GraphAHA achieves the best score in 18 of 20 cases. For Pass@1 measured using visible tests, it outperforms the strongest baseline for both models on both benchmarks by 4.1 percentage points on average, demonstrating more effective use of a fixed inference budget.

## 1. 核心问题与研究动机

- **背景**：测试时扩展（test-time scaling）通过在推理阶段投入更多算力（LLM 调用次数或 token）来提升代码生成质量。代码任务的特殊性在于候选程序可通过编译与执行验证，但真实开发场景下候选生成与验证会迅速增加延迟与成本，因此**有限预算下的算力分配**成为核心问题。
- **三类互补操作**：直接采样（Sample，提供广度但失败样本信息量低）、反馈驱动的修复（Repair，利用执行信号但易陷入局部实现、继承算法缺陷）、推理引导的实现（Reason→Implement，可开辟新算法路线，但草图不可执行、价值延后显现）。固定流水线会继承各操作的局限。
- **挑战一：程序状态重复**。MCTS 类树搜索把每条生成历史视为独立分支，即使不同历史收敛到同一规范化程序，也会重复评估、无法共享执行反馈与下游统计。
- **挑战二：采样/修复/推理的在线分配**。三者收益依赖状态，且推理草图为不可执行状态，其价值只能通过后续实现的程序体现，使 AB-MCTS 式自适应动作分配难以直接纳入推理。
- **整体含义**：论文提出 GraphAHA，将测试时代码生成建模为**带类型有向无环图上的可复用搜索**，并用分层 Thompson 采样联合分配异构动作预算，目标是最大化固定预算内最终程序通过公开测试的期望收益。

## 2. 方法论

### 2.1 核心思想
- 用**带类型 DAG** 表示搜索：问题节点 P、推理草图节点 S、可执行代码节点 C（附公开测试反馈）；边记录一次生成转移。
- 对每个生成程序做 **AST 规范化**，等价程序合并为同一代码节点（C\*），使评估分数与下游统计在所有发现路径间共享。
- 用**分层 Thompson 采样**决定“是否扩展新状态（Gen）”还是“沿已有后继继续（Cont）”，并在 Gen 条件下选择类型合法的生成动作。

### 2.2 异构动作空间（类型约束）
- 四类语义动作：**Sample**（P→C）、**Reason**（P→S）、**Implement**（S→C）、**Repair**（C→C）。
- 由于三者共享同一“生成代码”原语，仅源状态类型与上下文不同，作者把动作**因子化**为“源节点类型 + 待生成状态类型”：Gen_s 生成草图，Gen_c 生成代码。
- 类型约束动作集：A(Np) = {Gen_s, Gen_c, Cont}，A(Ns) = {Gen_c, Cont}，A(Nc) = {Gen_c, Cont}；Gen 条件下只用生成子集 AGen(v) = A(v) \ {Cont}。

### 2.3 分层选择与延迟反馈
- 每个节点维护**顶层 Beta 后验**（Gen vs Cont）；选 Gen 后由**第二层 Beta 后验**在合法生成动作间选择；选 Cont 后由**子节点专属 Beta 后验**选择后继。
- 采样 q_{v,c} ~ Beta(α_{v,c}, β_{v,c})，取 c\* = argmax q_{v,c}。
- **草图的延迟备份**：新草图不可执行，先分配 q 次强制 Gen_c 实现配额；草图本身不立即得分，待其实现被评估后，分数再回传给产生该草图的 Gen_s 决策。

### 2.4 规范化与图合并规则
- 用语法感知解析器去除注释与文档字符串，解析为 AST，对结构表示做哈希得到**规范化状态键**，从而忽略空白、换行、缩进等表层差异，降低精确字符串匹配造成的漏判。
- 重复状态分三类：**同提示重复**（同一提示重复采样出同一程序）、**自等同修复**（修复返回原程序）、**跨上下文收敛**（不同草图/提示/修复历史到达同一实现）。
- 为保证备份计算稳定，合并需**保持无环**：若 v = u（自环）则丢弃；若 v 已可达 u，则新增 u→v 会成环，同样抑制该边。

### 2.5 分数更新与备份
- 备份到**所有反向可达状态**（而非单条采样路径）。设 P 为 u 及其反向可达祖先上的边权连通矩阵，s 为仅含 s_u = r(c) 的稀疏源向量：
  - **ĝ = (I − dP)⁻¹ s，g = clip[0,1](ĝ)**；d 为阻尼因子（实验中 d = 1），裁剪为逐元素操作。
  - 直观含义：ĝ_i 聚合了从状态 i 到 u 的所有有向路径得分；多路径汇聚可能使值 >1，故裁剪回 [0,1] 以适配 Beta 更新。
- **难度感知分数塑形**：用根节点顶层 Gen 后验均值 μ_root 作为在线难度估计（越小越难）：
  - γ(μ_root) = μ_root + γ_hard(1 − μ_root)
  - g̃^{(k)}_{v,a} = (g^{(k)}_{v,a})^{γ(μ_root)}
  - α_{v,a} = α⁰_{v,a} + Σ_k g̃^{(k)}，β_{v,a} = β⁰_{v,a} + Σ_k (1 − g̃^{(k)})，即以分数成败计数做 Beta 更新。
- **算法流程（Algorithm 1）**：按“选择—扩展—备份”循环 B 次——若有待实现草图则弹出并执行 Gen_c，否则从根沿 Thompson 采样的 Cont 边走到 Gen 被选中；生成 y 后规范化并合并/新建节点，若无环则加边；新草图入队等待 q 次强制实现；代码节点执行评测得 r(c)，计算备份分数，更新所选 Gen 决策与各反向 Cont 决策，若来自草图则再回传至父 Gen 决策；最终返回图中最佳已评估代码节点。
- 附录给出**可逆性证明**：子图是 DAG，可按拓扑序使 P 严格上三角、Pⁿ = 0（幂零），故 (I − dP)⁻¹ = Σ_{ℓ=0}^{n−1} d^ℓ P^ℓ，且**无需 d < 1**；并给出路径和解释与有界归一化说明。
