## 摘要
测试用例合成对于评估和排序由大型语言模型（LLMs）生成的程序至关重要。然而，构建高质量测试用例仍然具有挑战性，因为可靠的预期输出往往难以获得。我们提出置信度门控直推式测试生成（CoTT），它首先使用高效的归纳过程，并且仅在归纳置信度较低时才调用直推式生成。这种自适应设计提高了输出可靠性，同时仅在需要时分配额外计算。在代码重排序基准上，CoTT 在所报告的指标上优于先前基线，同时相对于对每个输入都应用直推式生成降低了成本。这些结果表明，基于置信度的测试时计算分配，配合单个高效 LLM，提供了有利的效率-效果权衡。

## Abstract
Test case synthesis is crucial for evaluating and ranking programs generated by large language models (LLMs). However, constructing high-quality test cases remains challenging because reliable expected outputs are often difficult to obtain. We propose Confidence-Gated Transductive Test Generation (CoTT), which first uses an efficient inductive procedure and invokes transductive generation only when inductive confidence is low. This adaptive design improves output reliability while allocating extra computation only when needed. On code reranking benchmarks, CoTT outperforms prior baselines across the reported metrics while reducing cost relative to applying transductive generation to every input. These results show that confidence-based allocation of test-time computation provides a favorable efficiency-effectiveness trade-off with a single efficient LLM.

## 1. 核心问题与整体含义

- **研究背景**：测试用例是评估、打分和排序 LLM 生成代码的基础工具。随着 LLM 代码生成能力提升，基于执行的测试信号对识别更优程序候选愈发重要，尤其是在高质量人工测试稀缺或不可用时。
- **核心瓶颈**：测试合成中的“**oracle 问题**”——生成测试输入相对容易，但获得**可靠的期望输出**很困难。
- **现有路线及不足**：
  - 一类方法通过多次执行通用解程序，用多数投票/一致性估计期望输出，但当生成程序本身不可靠时，该信号可能失效。
  - 另一类方法使用输入条件生成、验证器引导执行或更强外部模型，但通常需要额外训练、搜索或辅助模型计算。
- **论文目标**：在**单个高效 LLM** 设定下，构造具有可靠期望输出的合成测试，用于代码重排序，并避免对所有输入无差别地投入昂贵计算。
- **整体含义**：论文将“测试输出生成”视为代码重排序的关键瓶颈，提出基于置信度的测试时计算分配机制，在效率与效果之间取得更优权衡。

## 2. 方法论：CoTT

- **核心思想**：先用高效的**归纳式（inductive）**过程预测期望输出；仅当归纳置信度低时，才调用更昂贵的**直推式（transductive）**过程，针对具体测试输入生成实例专用程序。
- **关键设计**：不是融合归纳与直推两个分布，而是通过置信度门控**选择信任哪一个分布**。
- **归纳输出分布**：
  - 针对原问题，用提示“Write a clean, efficient Python function ...”采样一池通用解程序。
  - 在测试输入 \(x\) 上执行这些程序，统计各输出 \(y\) 的出现次数 \(n_{\text{ind}}(y;x)\)，得到经验分布 \(p_{\text{ind}}(y|x)\)。
  - 归纳置信度为 \(c(x)=\max_y p_{\text{ind}}(y|x)\)，即最高频输出的占比/多数比率。
- **置信度门控**：
  - 给定阈值 \(\tau\)。
  - 若 \(c(x)\ge\tau\)，直接采用归纳预测 \(\arg\max_y p_{\text{ind}}(y|x)\)。
  - 若 \(c(x)<\tau\)，触发直推过程。
- **直推输出分布**：
  - 使用修改后的提示：“Write a Python function for the exact input \(x\) ...”，让模型生成**针对目标调用特化**的程序，允许忽略其他输入和一般化。
  - 执行这些程序，统计输出频率 \(n_{\text{trans}}(y;x)\)，形成 \(p_{\text{trans}}(y|x)\)。
  - 采用 \(\arg\max_y p_{\text{trans}}(y|x)\) 作为最终期望输出。
- **算法流程（文字版）**：
  1. 对问题采样 \(N_{\text{ind}}\) 个归纳程序。
  2. 对每个合成测试输入 \(x\)，执行归纳程序并形成 \(p_{\text{ind}}\)。
  3. 计算 \(c(x)\)。
  4. 若 \(c(x)\ge\tau\)，取归纳 argmax；否则采样 \(N_{\text{trans}}\) 个直推程序，执行后取直推 argmax。
  5. 将 \((x,\hat y(x))\) 作为测试用例，用于执行候选程序并按通过率重排序。
- **默认超参数**：每个问题 10 个测试用例，归纳采样 20，直推采样 10，超时 3 秒，阈值 \(\tau=0.8\)，温度 0.5，最大上下文 18,000 token，单轮最大生成 1,500 token。

## 3. 实验设计

- **数据集 / Benchmark**：

  - 每个任务配 5 个不同正确性的候选解，目标是恢复由参考测试套件诱导的真实排名。
- **评测任务**：给定共享的合成测试输入，各方法只负责预测对应期望输出，形成测试用例后执行所有候选解，并按通过率排序。
- **指标**：
  - **Top-1 准确率**：最高排名候选是否与参考一致。
  - **Bottom-1 准确率**：最低排名候选是否与参考一致。

  - **平均每题成本（美元）**：统计测试构造中所有输入/输出 LLM token 成本。

  - **SOL-VER**：输入条件生成 + 多 CoT 样本的直推式基线。
  - **SYNTRA**：直推式基线，输入条件输出生成与候选选择。
  - **rStar-Coder**：归纳式基线，多次采样通用程序并多数投票。
  - **TT w/o Gating**：始终直推的消融变体，隔离门控效果。
  - **CoTT**：本文方法。
- **公平性控制**：所有方法使用相同的合成测试输入，以隔离“测试输出生成”的差异。对于含训练或下游优化组件的基线，只应用其测试输出生成组件。

## 6. 主要结论与发现

- CoTT 在两个代码重排序基准上总体优于既有基线，并在效果与成本之间取得更好权衡。
- 在 HumanEval-R+ 上：
  - **TT w/o Gating** 的 Top-1 和 Spearman 最高（63.1、0.676）。
  - **CoTT** 的 Bottom-1 最高（66.7）。
  - CoTT 成本 $0.065，低于始终直推的 $0.077。
- 在 MBPP-R+ 上：
  - **CoTT** 在 Top-1、Bottom-1、Spearman 三项指标上均最佳（61.6、58.7、0.580）。
  - 成本同样低于始终直推。
- **置信度门控有效性的分析**：
  - 当仅归纳预测正确时，归纳置信度 \(c(x)\) 通常较高，说明归纳分布已可靠，无需直推。
  - 当仅直推预测正确时，\(c(x)\) 明显较低，说明归纳不可靠，切换到直推有益。
- **案例发现**：
  - Eulerian number 案例中，直推程序虽非通用正确，但补充了 \(n=0\) 的边界条件，修正了归纳错误。
  - `find(10, -2)` 案例中，归纳程序正确，直推程序反而引入负号错误；此时高置信度门控保留了归纳路径。
- **阈值与置信度分数**：
  - \(\tau\) 越大，直推率和成本单调增加。
  - HumanEval-R+ 上性能约在 \(\tau=0.8\text{–}0.9\) 后趋于平台；MBPP-R+ 上 \(\tau=0.8\) 是较好平衡点。
  - 最大概率、Top-2 margin、负熵表现相近；子集一致性成本更低但效果略弱。

## 7. 优点
