## 摘要
尽管测试时扩展增强了大型语言模型（LLM）智能体在长时程软件工程（SWE）中的能力，但稀疏的二值奖励（通过/失败）造成了严重的信用分配危机，并浪费了失败的探索轨迹。当前的轨迹优化与扩展方法成本高昂且受结构限制，依赖于无因果诊断的启发式状态复用，或缺乏可操作在线指导的延迟标量评分。我们提出 FLARE（全生命周期对齐与奖励引擎），一种由轻量级生成式奖励模型（GRM）驱动的新型密集监督范式。首先，RADAR——一种离线因果感知诊断框架——通过因果链回溯提取高保真、无后见信息的监督，以蒸馏出一个能够提供实时、步骤级风险反馈的 GRM。其次，FLARE 利用该 GRM 在整个生命周期中持续优化智能体。在推理阶段，FLARE 充当主动脚手架，自主拦截高风险生成步骤以进行局部断点重执行，从而大幅降低计算开销。在后训练阶段，GRM 的结构化信号可作为监督微调（SFT）的过程监督重排序分数，以及强化学习（RL）的步骤级密集奖励，从而缓解稀疏环境中的策略崩溃。大量评估表明，FLARE 在智能体生命周期中建立了新的帕累托前沿：FLARE（N=1）以 token 消耗降低为原来 1/5 的代价优于 Global Rollout（N=5）。将 FLARE 扩展到训练中，克服了长时程交互任务中的稀疏奖励问题，通过过程感知的数据整理在 SFT 中带来 19.13% 的相对性能提升，并在 RL 中实现一致的 9.19% 改进。

## Abstract
While test-time scaling enhances Large Language Model (LLM) agents in long-horizon software engineering (SWE), sparse binary rewards (Pass/Fail) create a severe credit assignment crisis and waste failed exploratory trajectories. Current trajectory optimization and scaling methods are costly and structurally limited, relying on heuristic state reuse without causal diagnosis or delayed scalar scoring without actionable online guidance. We propose FLARE (Full-Lifecycle Alignment and Reward Engine), a novel dense supervision paradigm driven by a lightweight Generative Reward Model (GRM). First, RADAR, an offline causal-aware diagnostic framework, extracts high-fidelity, hindsight-free supervision through causal-chain backtracking to distill a GRM providing real-time, step-level risk feedback. Second, FLARE uses this GRM to continuously optimize the agent across its entire lifecycle. During inference, FLARE acts as an Active Scaffold, autonomously intercepting high-risk generation steps for localized breakpoint re-execution, drastically reducing compute overhead. During post-training, the GRM's structured signals serve as process-supervised reranking scores for Supervised Fine-Tuning (SFT) and step-level dense rewards for Reinforcement Learning (RL), mitigating policy collapse in sparse environments. Extensive evaluations show that FLARE establishes a new Pareto frontier across the agent lifecycle: FLARE (N=1) outperforms Global Rollout (N=5) with a 5x reduction in token consumption. Extending FLARE to training overcomes the sparse reward problem in long-horizon interactive tasks, delivering relative performance gains of 19.13% in SFT through process-aware data curation and a consistent 9.19% improvement in RL.

  - 离线演化搜索（如 Satori-SWE）与多智能体辩论（如 SWE-Search）依赖延迟的标量奖励模型或重量级协商，无法在轨迹首次偏离时动态干预。

## 2. 方法论

### 核心思想
- 以轻量级 GRM 为中心，将"离线因果诊断 → 在线步骤级反馈 → 训练信号复用"统一为闭环。

### 关键技术细节

#### （1）RADAR：离线因果感知诊断框架
作为数据合成引擎，从轨迹 τ=(s₁,…,s_T) 中提取步骤级监督信号。

- **Step 1：轨迹语义压缩**
  - 每步压缩为结构化语义表示：`s̃_t = (I_t, A_t, O_t) = φ(s_t)`，分别表示意图、动作、观察。

- **Step 2：双轨诊断蒸馏**
  - **Track 1：逆向因果错误链分析**（针对失败轨迹）
    - 通过反向追踪识别根因优先的因果相关步骤集：`C = B(τ; G) = (s̃_{t1},…,s̃_{tk})`，其中 G 为全局信号（patch 差异、失败测试用例）。
    - 优先定位最早的可支持根源（root cause）用于重放；无关探索被排除；独立缺陷保留各自根因。
    - 每步赋予结构化标签：`y_{ti} = (z_{ti}, c_{ti}, d_{ti}) = A(s̃_{ti}; C, G)`，其中 z 为风险等级、c 为错误类型、d 为离线诊断分析。
  - **Track 2：主动错误注入**（针对成功轨迹）
    - 向预定义高影响步骤（Plan Creation、Critical Observation、Critical Action、Self-Correction）注入错误，扩充长尾错误样本。
    - 关键步骤选择：`K = {s̃_t | s_t ∈ τ⁺, κ(s̃_t) ∈ H}`。
    - 通过断点 rollout 得到经验恢复率：`p̂_t = (1/N) Σ I(T^{(n)}_t solves task)`。
    - 按恢复阈值 θ 分类严重度：`z_t = critical if p̂_t ≤ θ, else trivial`。

- **因果前缀蒸馏（Causal-prefix Distillation）**
  - 将离线分析 d_t 重写为仅依赖任务、当前步骤与前缀历史的在线分析：`d̃_t = M(d_t; q, s_t, H_t)`，`H_t = (s₁,…,s_{t-1})`。
  - 通过语义合规门检查：分类一致性、无支持锚点、patch/未来/测试预言泄漏；违规者重新生成。
  - 定义"无后见信息（hindsight-free）"监督的信息边界（但作者声明不构成形式化零泄漏保证）。

#### （2）GRM 优化
- 作为条件生成模型训练：`p_ψ(ỹ_t | q, s_t, H_t)`。
- 在 **Qwen3.5-4B** 上做监督微调，输出结构化风险等级、错误类型与因果一致的诊断解释。
- 输出格式为结构化 XML（含 `<analysis>`、`<issue rubric=... label=.../>`、`<severity>critical/trivial</severity>`），而非不可解释的标量分数。

#### （3）测试时干预：主动脚手架（Active Scaffold）
- 智能体提出下一步动作 `ŝ_t` 时，GRM 异步诊断已完成的步骤 s_{t-1}，产生诊断三元组 `y_{t-1} = (z_{t-1}, c_{t-1}, d^{diag}_{t-1})`。
- 干预发生在**下一个动作被提交之前**，不回滚已执行的工具操作：
  - 若 z_{t-1} ∈ {safe, trivial}：执行 ŝ_t；
  - 若 z_{t-1} = critical：基于诊断反馈重新生成下一步：`s_t = π(d^{diag}_{t-1}; H_t)`。

#### （4）训练时对齐：步骤级风险校准奖励
- **风险严重度因子**：`ω^risk_t = max(0, (P_succ(z_t) − P̄_succ)/P̄_succ)`（安全步）或 `max(0, (P_fail(z_t) − P̄_fail)/P̄_fail)`（非安全步）。
- **错误重要性因子**：`ω^err_t = max(0, (P̄_succ − P_succ(c_t))/P̄_succ)`。
- **步骤级风险校准奖励**：
  - 安全步：`r^step_t = ω^risk_t · η^pos_t · η^act_t`
  - 非安全步：`r^step_t = −ω^risk_t · ω^err_t · η^pos_t · η^act_t · η^rec_t`
- **三个动态调节系数**：
  - 位置感知权重：`η^pos_t = (1+log t)/(1+log T)`，终端权重归一为 1；
  - 动作稀有度权重：`η^act_t = 1 − N(a_t)/T`，降低高频动作贡献；
  - 重复惩罚：`η^rec_t = 1 + n(c)_t / (n(c)_{t-1})²`，针对错误类型重复出现。
- **轨迹级奖励**：`R(τ) = (1/T) Σ r^step_t`。
- **SFT 数据选择**：按 R(τ) 排序，保留 top-ranked 子集。
- **密集奖励集成**：`r^{(i)} = R(τ^{(i)}) + R_out(τ^{(i)})`，组内 z-score 归一化得到优势 `Â_i`，所有 token 共享该轨迹级优势，采用 GRPO 优化。

## 6. 主要结论与发现

- **测试时修复（RQ1）**：
  - GRM-DBKR 在 N=1 时达到 **14.10% F2P**，接近翻倍于 GR N=1（7.80%），并超过 GR N=5（13.72%）；
  - agent 输出比约 **66,711/12,517 ≈ 5.33**，支持约 5× token 缩减；
  - N=5 时 GRM-DBKR 达 **19.59%**，超 GR 5.87 个百分点；
  - P2P 保持率 **88.43%**，为所有方法最高；
  - 在 TypeScript（+7.91）、Python（+6.39）等语言切片均有正增益；最难任务桶中成功率从 1.0% 提升至 10.6%。

- **SFT 数据整理（RQ2）**：
  - 训练无关评分 ROC-AUC **75.74%**，优于随机（50.00%）与启发式 Critical Model（69.34%）；
  - FLARE 数据选择平均通过率相对随机采样提升 **19.13%**，优于 Rubric-Supervised Critic（+4.61%）；
  - 消融显示 ω^risk 与 ω^err 是最关键组件（平均 SFT 分别下降 8.52% 与 7.18%）。

- **RL 密集奖励（RQ3）**：
  - FLARE-RL 在四个基准全面提升：Verified +2.80、Pro +3.97、Multilingual +2.67、Compass +4.45；
  - 平均相对提升 **9.19%**，验证 GRM 信号可从离线排序迁移到在线策略优化。

- **案例分析**（alibaba/fescar#644）：GRM 成功识别"仅实现 Serializable 未保持 Null.get() 单例语义"的浅层修补风险，引导加入 `readResolve()` 方法，展示从步骤级诊断到具体实现约束的转化机制。

## 7. 优点

### 方法层面
- **全生命周期统一**：同一 GRM 诊断表示同时服务于推理干预、SFT 选择

与 RL 奖励塑形，避免了"推理一套信号、训练一套信号"的割裂，也为诊断能力在三个阶段之间的一致性提供了结构保证。
- **从标量评分转向结构化生成式诊断**：输出风险等级、错误类型与自然语言因果解释，使奖励/反馈具备可解释性与可归因性，而非黑箱分数。
- **干预时机精准**：Active Scaffold 在"下一步动作提交前"而非轨迹结束后介入，且不回滚已执行工具，兼顾了实时性与执行代价；异步诊断也避免了对主推理链路的阻塞。
- **对失败轨迹的再利用**：RADAR 将原本被丢弃的 11,621 条失败轨迹转化为步骤级监督信号，把稀疏二值奖励的"沉没成本"变为训练资产。
- **前缀化重写与合规门**：因果前缀蒸馏把离线分析改写为仅依赖前缀历史的在线可用形式，并设置分类一致性、无支持锚点、patch/未来/测试预言泄漏四类检查，方法论上对"后见信息泄漏"这一常见隐患有明确防范意识。
- **奖励设计有据可依**：ω^risk 由经验恢复率/失败率驱动，η^pos、η^act、η^rec 分别对应位置、稀有度、重复惩罚，每个系数都有直觉与经验依据，而非随意加权。

### 实验层面
- **跨模型、跨脚手架、跨语言、跨难度**的多维泛化验证，使结论不易被单一配置的偶然性所解释。
- **控制变量的 RL 对比**：在相同初始化、数据、rollout 预算、优化器与评测框架下仅替换奖励信号，因果归因清晰。
- **双重验证消融**：ROC-AUC（训练无关）与下游 SFT 通过率（训练相关）两条路径相互印证组件贡献。
- **人类+模型独立审计**：3 位 SWE 专家与 GPT-5 独立评审 608 条诊断，κ=0.887 表明标注可靠性高，且报告了细粒度错误类型，透明度较好。

### 工程与实用层面
- GRM 仅 4B 规模，属于轻量级，具备实际部署可行性；推理端约 5× token 缩减对长时程 SWE 的成本控制有直接价值。

## 8. 局限与不足

### 方法与理论层面
- **无形式化零泄漏保证**：作者明确声明"无后见信息"仅由语义合规门近似保障，不构成形式化的零泄漏证明；对于 SWE 场景中"测试用例即答案"的高风险设定，这一点尤为关键。
- **离线标注依赖强模型与全局信号**：RADAR 的 Track 1 依赖 patch 差异、失败测试用例等全局信号进行逆向因果链分析，其质量上限受标注模型能力制约，且论文未给出该离线阶段的完整成本。
- **错误注入的人为性**：Track 2 主动注入错误以扩充长尾样本，注入点选择（Plan Creation、Critical Observation 等）由人工预定义，可能与真实失败分布存在偏移，影响 GRM 的风险等级校准。
- **根因唯一性假设**：逆向因果链优先定位"最早可支持根源"，但在多缺陷耦合的真实 issue 中，早期步骤的"根因"可能只是表象，根因优先策略可能低估后置的独立缺陷。

### 评估与公平性层面
- **条件评估协议削弱绝对结论**：RQ1 中 GRM-DBKR 仅计在线引导 rollout，而基线计入初始 baseline rollout，"匹配 N"控制的是分支数而非完整轨迹数或模型调用数。因此"N=1 优于 N=5"需在协议口径下解读，不能直接外推为等算力下的绝对优势。
- **P2P 指标的归因模糊**：失败续跑未必由 GRM 造成，P2P 更多反映续跑策略的随机性，作为"保持率"证据的强度有限。
- **算力与成本披露不足**：论文未说明 GPU 型号/数量/训练时长，token 统计也不含 agent 输入、GRM 输入输出与延迟；离线标注与 GRM 训练的一次性成本未纳入核算，复现预算不可知。
- **在线开销未量化**：GRM 异步诊断的延迟、吞吐与对端到端 wall-clock 的影响未见报告，而这正是"实时干预"主张能否落地的关键。

### 覆盖范围层面
- 训练数据池集中在 multi-swe-rl、rebench 及补充 GitHub 实例，仓库与语言分布的代表性未充分讨论；Multilingual 虽含 9 种语言切片，但增益集中在 TypeScript/Python，对小语种的证据较弱。
- RL 实验仅在 Qwen3-30B-A3B 上开展，GRM 仅基于 Qwen3.5-4B，跨基座的可迁移性缺少多模型验证。

## 9. 启示与可迁移性

- **"诊断即奖励"的范式**：将同一生成式诊断表示贯通推理、SFT、RL，是把过程奖励从"设计问题"转为"复用问题"的一种可行路径，可迁移到数学推理、Web 导航、多轮工具调用等同样存在稀疏奖励的长时程任务。
- **前缀化监督重写**：把离线分析改写成仅依赖前缀历史的在线可用形式，并配套合规门，是缓解"训练时偷看答案"的通用工程手法。
- **奖励系数的经验标定思路**：用恢复率/失败率标定风险权重、用位置与稀有度调节步级贡献，为过程奖励设计提供了可复用的构造模板。
- **轻量 GRM 的性价比定位**：4B 规模即可支撑在线干预与数据筛选，提示"诊断模型不必与主智能体同规模"，对成本敏感的实际部署有参考意义。

---

## 10. 总体评价

FLARE 在问题选择上有明确的现实痛点指向（稀疏二值奖励下的信用分配），在方法上有清晰的统一主线（单一 GRM 贯通三阶段），在实验上有较广的覆盖与较严的消融。其最实质的贡献是把"过程诊断"从离线评分工具提升为贯穿推理与训练的一等公民，并用约 5× token 缩减、19.13% 的相对数据效率提升与 9.19% 的 RL 平均相对增益给出量化证据。

同时，其结论强度受限于条件评估协议、缺乏形式化泄漏保证、以及算力/在线开销披露不足。若后续工作能补齐等算力对比、多基座验证与端到端延迟核算，该范式的说服力会显著增强。
