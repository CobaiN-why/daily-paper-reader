## 摘要
自主软件工程智能体（SWE 智能体）可自动完成编码任务。每次智能体更新都可能需要重新运行完整基准，以检测回归和改进，而每次运行需消耗数亿个 LLM token，这使评估成为瓶颈。一种解决方案是仅评估基准实例的一个子集。然而，简单方法（如随机采样，或基于过去通过/失败结果的分层随机采样）可能产生高方差且不具代表性的子集。我们转向智能体轨迹，即智能体所采取动作的逐步记录。我们提出一种轨迹感知子集选择方法，用基于轨迹嵌入的确定性选择替代随机采样。我们首先根据测试集实例在最近一次完整测试运行中的测试结果对其进行分组，以保持历史通过/失败率，然后利用轨迹的嵌入空间选择子集。我们在三种回归场景下评估了 76 种子集选择配置，包括随机采样、基于嵌入的选择、基于聚类的选择，以及混合的“先筛选候选再子采样”策略。这三种场景是：相同配置重跑、模型和配置变更，以及智能体框架变更。我们最佳的轨迹感知方法是在嵌入空间中选择距离每个结果组质心最近的基准实例。它在我们评估的所有方法中取得了最低的估计误差。例如，当在选定的 5% 或 10% 测试实例子集上评估给定智能体版本时，与典型抽样相比，我们的方法将平均估计误差降低 3--11%，将最坏情况误差降低 4--11%；与最强基线的第 95 百分位抽样相比，降低 38--46%。结果表明，10% 的轨迹感知子集可将中位估计误差保持在 5% 以下，同时将 token 成本削减约 90%。

## Abstract
Autonomous software engineering agents (SWE-agents) automate coding tasks. Each agent update may require re-running the full benchmark to detect regressions and improvements, at a cost of hundreds of millions of LLM tokens per run, which makes evaluation a bottleneck. One solution is to evaluate only a subset of benchmark instances. Yet, simple approaches, such as random sampling or stratified random sampling based on past pass/fail outcomes, risk producing high variance and unrepresentative subsets. We turn to agent trajectories, the step-by-step record of the actions an agent took. We propose a trajectory-aware subset selection approach that replaces random sampling with deterministic selection based on trajectory embeddings. We first group test set instances by their test outcome in a recent full test run to preserve the historical pass/fail rate, then select the subset using the trajectory's embedding space.   We evaluate 76 subset selection configurations, including random sampling, embedding-based selection, clustering-based selection, and hybrid shortlist-then-subsample strategies, across three regression scenarios: same-configuration reruns, model and configuration changes, and agent framework changes. Our best trajectory-aware method is the one selecting benchmark instances closest to the centroid of each outcome group in the embedding space. It achieves the lowest estimation error among all methods we evaluate. For instance, when evaluating a given agent version on a selected subset of 5% or 10% of the test instances, our approach reduces the average estimation error by 3--11% and the worst-case error by 4--11% relative to the typical draw and 38--46% relative to the 95th-percentile draw of the strongest baseline. Our results show that a 10% trajectory-aware subset keeps the median estimation error below 5% while cutting token cost by roughly 90%.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：自主软件工程智能体（SWE-agents）已能修复程序、调试系统、生成并执行测试，主流评测基准如 SWE-Bench（500 个真实 GitHub issue 实例）、SWE-Bench Verified、SWE-Rebench、SWE-Bench Pro 等被广泛使用。
- **痛点**：评测一个智能体需要跑完整基准，每个实例都要经历完整的 agent loop（多轮 LLM 调用、工具调用、代码测试执行）。单次全量运行消耗数亿 token——论文实测 6 次运行合计 **34.4 亿 token**（3,442M），单次运行 3.35–9.45 亿 token。
- **现实需求**：开发者在 CI 或日常迭代中频繁修改模型、prompt、架构，每次改动都需要回归测试来发现提升或性能退化，但全量重跑不现实，**评估成为开发瓶颈**。
- **现有做法及其缺陷**：
  - OpenHands 等框架已支持限制实例数（如 500 中取 50 或 200），但子集采用**固定种子的随机采样**，无任何选择准则。
  - 简单分层（按历史通过/失败、按仓库）虽能降低方差，但**组内仍是随机抽样**，在小子集规模下方差大、可能过拟合稀有边界案例，且忽略执行过程中的行为信息。
  - 已有轨迹研究（如 Bouzenia & Pradel、Ceka 等）仅用于行为刻画与失败模式解释，**无人将轨迹用于"选择哪些实例来评测"**。
- **核心洞察**：相同结果的实例可能对应完全不同的智能体行为与失败模式（如重复命令循环、未运行测试套件），因此仅靠静态属性或最终 pass/fail 标签不足以选出代表性评测子集，需要从**逐步轨迹**中提取行为信息。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体流程（四阶段流水线）

**Parse → Sanitize → Vectorize → Select**，最终在后续运行中只评测所选子集，用其 resolve rate 估计全量基准的 resolve rate。

### 2.2 阶段一：轨迹解析（Parse Trajectories）

- 不同框架记录格式不兼容：OpenHands 是扁平动作列表，Moatless 是嵌套搜索树。
- 设计**统一 JSON Schema**：`trajectory_id / repo_name / agent_name / final_outcome / steps[]`，每步记录 `step_index / action_command / files_touched / tests_run / edit_size / error_message / observation`。
- 解析全自动、确定性：规则化 shell 命令归一化、模式匹配检测测试运行、用 exit code 提取错误（exit code ≠ 0 则记录 Python traceback 为 error_message）。
- **验证**：自动逐条比对解析结果与原始日志（动作、观察逐字匹配，exit code 一致），全部通过；另人工核验 20 条轨迹，全部匹配。

### 2.3 阶段二：轨迹净化（Sanitize Trajectories）——四相流水线

核心挑战是**数据泄漏**：outcome token（"passed"、"exit code 0"）会让嵌入按结果聚类；仓库名与测试框架痕迹会泄漏任务身份。

| 相 | 名称 | 关键做法 |
|---|---|---|
| Phase 1 | Discover Corpus | 用**字符模式化**（字母→c，数字→d）识别随机标识符（UUID、commit hash、临时路径），同模式 token 多者判为自动生成，掩码为 `[PATH]`、`[RANDOM_SEED]`；用 **Zipf 定律**按词频排序识别重复样板（`[Command`、`interpreter:`、`/workspace` 等）并建停用词表 |
| Phase 2 | Detect Outcome Leakage | 将语料分为通过/失败两组，用 **log-likelihood keyness 分析（G²）** 检测在某组中显著偏多的词，阈值 **G² > 10.83（p < 0.001）**；人工复核后**移除**结果指示词（passed、exit code 0）与仓库专用工具（pylint、dvc），**保留**任务相关术语（asyncio、hypothesis） |
| Phase 3 | Sanitize & Mask | 删除泄漏词，仓库身份替换为 `[REPO_VAR]`，结构化错误类型抽象化（`AssertionError → [ERR_ASSERT]`） |
| Phase 4 | Validate | 用 **TF-IDF + 逻辑回归（SGD 优化）** 训练 pass/fail 分类器，比较原始与净化语料的准确率与最大系数词 |

- **净化效果验证**：准确率保持相近区间（Single-setup 68.9% → 65.7%；Multi-model 72.8% → 76.2%；Multi-agent 78.3% → 80.3%），但最大系数词从 "passed"、`scrapy__scrapy`、`pylint` 变为 "scope"、"hypothesis" 等工程术语；另对每数据集随机抽 200 条净化轨迹扫描，未发现残留被删词。

### 2.4 阶段三：轨迹向量化（Vectorize Trajectories）

- 嵌入模型：**Nomic Embed v1.5**，8,192 token 上下文（可容纳长 traceback 不截断），通过 **Matryoshka Representation Learning** 固定维度 **d = 768**；输入为每步净化后的 action + observation 拼接串。
- **Pooled Embeddings（池化嵌入）**：借用说话人识别中的 statistics pooling，对 T×768 的步嵌入矩阵计算 **均值（语义中心）+ 标准差（步间行为变化）**，再拼接 **首步（step 0）、中间步（⌊T/2⌋）、末步（T−1）** 三个时序锚点，共 **5 × 768 = 3,840 维**固定向量。
- **Time-Series Embeddings（时序嵌入）**：保留完整 T×768 矩阵，保留动作顺序。

### 2.5 阶段四：子集选择（Select Subset）

**基线方法（6 种，随机抽样式）**：
1. Uniform Random —— 无先验随机抽
2. Repo-Strat —— 按仓库分层，按比例抽样
3. Diff-Strat —— 按历史"多数通过/多数失败"二分难度分层
4. **Consist-Strat** —— 按历史精确通过次数分组（如 3 次历史运行则 0/1/2/3 次通过四组）
5. Repo × Diff、6. Repo × Consist —— 仓库与结果维度交叉分层

所有分层方法保持各组在全量中的占比。

**几何选择方法（5 种，确定性）——即提出的 Embedding-Within-Strata**：
1. **Centroid（质心）**：计算组内嵌入均值，选取距离均值最近的实例（**论文最优方法**）
2. **Facility Location**：贪心选取使"已选集合与剩余实例的总相似度"增益最大的实例
3. **Medoid（PAM Build）**：选取总距离最小的真实数据点，再逐步添加最能缩短剩余距离的点（保证选真实实例）
4. **Kennard-Stone**：每次选取距已选集合最远的实例，最大化多样性
5. **Core/Edge**：90% 用 Centroid（典型）+ 10% 用 Kennard-Stone（异常），兼顾代表性与覆盖度

**核心组合**：保留按历史通过次数（或单次历史时的 pass/fail）的分组以锁定难度构成，组内用几何选择替代随机抽样。给定相同历史运行、嵌入与子集规模，几何方法**每次产出完全相同的子集，无随机性**。
