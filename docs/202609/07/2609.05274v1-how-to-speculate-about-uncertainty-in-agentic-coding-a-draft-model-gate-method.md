## 摘要
用于软件工程的LLM智能体失败代价高昂：它们会自信地犯错，而糟糕的行为往往只有在昂贵的执行和重试之后才被发现。我们提出了一种推测不确定性（SU）方法，该方法仅从黑盒智能体的输出标记中恢复预测性失败信号，无需访问logits、权重、激活或重复采样。通过反转推测解码，一个小的开放权重草稿模型在单次前向传播中对智能体已生成的轨迹进行评分。从这些推测性的交叉似然中，我们通过分离推理和动作跨度来提取相位感知特征，并将它们与可验证的目标进行校准。SU产生一个失败可能性得分，任何下游策略（如路由、人工干预或额外的测试时计算）都可以直接使用。为了证明该信号是可操作的，我们在软件工程智能体Qwen3-Coder-480B和闭源的Claude 3.5 Sonnet上实例化了一种这样的策略——一个执行前否决门控，在部署中将执行错误率降低了6-8个百分点，令牌成本降低了14-19%，无需重新训练即可迁移到分布外基准，并跨智能体模型进行泛化。

## Abstract
LLM agents deployed for software engineering fail expensively: they act confidently wrong, and bad actions are recognized only after costly execution and retry. We present Speculative Uncertainty (SU), a method that recovers a predictive failure signal for a black-box agent from its output tokens alone, with no access to logits, weights, activations, or repeated sampling. Inverting speculative decoding, a small open-weight draft model scores the agent's already-generated trajectory in a single forward pass. From these speculative cross-likelihoods we extract phase-aware features by separating the reasoning and action spans, and calibrate them against a verifiable objective. SU produces a failure-likelihood score that any downstream policy, such as routing, human intervention, or extra test-time compute, can consume directly. To show the signal is actionable, we instantiate one such policy, a pre-execution veto gate, on software engineering agents Qwen3-Coder-480B and closed-source Claude 3.5 Sonnet, cutting execution error rate by 6-8 percentage points and token cost by 14-19% in deployment, transferring to out-of-distribution benchmarks without retraining, and generalizing across agent models.

## 论文详细总结

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：大语言模型（LLM）智能体在软件工程任务中部署时，存在一种代价高昂的失败模式：它们经常**自信地犯错**。糟糕的行动只有在执行、报错并重试之后才被发现，这个过程消耗了大量的API成本和延迟。现有的不确定性量化工具（如白盒探针、重复采样）在现实部署中不可行，因为最强大的智能体通常是**仅提供API服务的闭源模型**，不暴露内部信号，且重复采样成本过高。
- **研究动机**：需要在行动计划被执行之前，仅从黑盒智能体输出的文本标记中，恢复一个**可操作的预测性失败信号**，从而避免昂贵的“执行-失败-重试”循环。
- **整体含义**：本研究挑战了“要获得不确定性信号就必须访问模型内部”的隐含假设。通过反转推测解码的思路，利用一个小型的、开放的“草稿”模型来评估大型黑盒智能体的输出，实现了一种无需内部访问、单次前向传播的失败预测机制。这不仅为闭源模型提供了一种通用的失败预警方案，还通过一个“预执行否决门”证明了这个信号可以直接用于节约成本、减少错误，标志着从“观察不确定性”到“主动干预智能体行为”的转变。

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

**方法论核心思想**：**Speculative Uncertainty (SU)**。将推测解码机制反转：不是让小型草稿模型生成token来加速大模型，而是让草稿模型对黑盒智能体已经生成的轨迹进行**教师强制（teacher-forcing）评分**。草稿模型只需单次前向传播，即可从交叉似然中提取出黑盒智能体的不确定性信号。

**关键技术细节**：

- **问题设置**：将智能体的轨迹 `T` 视为交替出现的推理片段和动作片段。目标是在第 `i` 步的 `action ai` 执行前，预测一个可验证的二元目标（如代码是否无异常执行）。
- **步长窗口**：为避免轨迹过长带来的噪声，模型只考虑最近的 `k=3` 个步骤作为一个窗口 `Wi`。
- **推测性交叉似然**：草稿模型对被评估的token `yt` 产生的三个关键信号：
  - **推测性惊异度（`st`）**：`st = -log q(yt | x, y<t)`，草稿模型对该token的困惑度。
  - **推测性差距（`gt`）**：草稿模型对最优token `ŷt` 的对数概率与对实际token `yt` 的对数概率之差。
  - **推测性熵（`Ht`）**：草稿模型在 `yt` 位置的输出分布熵。
  - 这些信号的有效性基于概率接受率的逻辑：如果草稿模型能较好地模拟智能体，高的推测性惊异度就暗示智能体本身在那个token上也存在高度不确定性。
- **相位感知特征提取**：这是核心设计。论文观察到推理阶段的熵很高（探索性），而动作阶段的熵极低（受语法和工具调用结构约束）。将信号 `{s, g, H}` 与 `{reason, action}` 两种相位解耦，并分别在进行特征提取，防止推理阶段的噪声掩盖了动作阶段中微小但关键的失败信号。
  - 对每个相位-信号组合，提取8个统计量：**均值、方差、最大、最小、偏度、趋势（首尾均值差）、前10%均值、后10%均值**。加上两个相位的长度，共产生50维特征。
- **校准器与下游策略**：
  - 训练一个 **L1正则化的逻辑回归**（校准器）将50维特征映射为成功概率。使用训练集上的交叉验证来选择L1正则化系数 `λ`。
  - **预执行否决门 (Veto-Gate)**：作为SU框架的一个示例性下游策略。若校准器输出的成功概率低于阈值 `τ`，则阻止当前行动，触发一个预先定义的、低成本的“重规划”动作，而非执行后重试。

### 6. 论文的主要结论与发现

- **核心结论**：**黑盒智能体的失败信号是可以被恢复的**。SU方法仅通过草稿模型对输出轨迹的评分，就能接近访问模型内部的白盒方法（HTC）的表现，且完全不需要依赖模型内部状态或大量采样。
- **相位分离有效**：将推理和行动阶段的特征分开处理是关键。

- **草稿模型对齐至关重要**：未训练的草稿模型（SU, no train）性能接近瞎猜；经过SFT或TF蒸馏后，AUROC从`.61`提升到`.77`，显著优于语言化置信度和逐token logprob基线。
- **可落地带来实际收益**：在Qwen3-Coder和Claude 3.5 Sonnet上部署SU否决门，将SWE-Bench Verified执行错误率**降低6个百分点（21%→15%）**，DA-Code错误率**降低8个百分点（14%→6%）**，并分别节省 **14%** 和 **19%** 的token成本。
- **跨模型迁移性**：在Qwen3上蒸馏的草稿转移到Claude 3.5 Sonnet时，AUROC（.69）远高于未训练的基线（.60），并与混合语料训练的草稿性能（.75）竞争，表明可以**用开放的代理模型作为代理来对齐闭源模型**。
- **成本收益**：SU提供的成本降低主要在于节省了失败重试的开销，而非提升最终任务成功率（成功率几乎不变，甚至略有下降），其定位是“失败预警与降本”而非“任务增强”。

### 7. 优点：方法或实验设计上的亮点

- **问题定位精准**：针对闭源模型和单次执行场景，提出了用户实际需要的方案（成本，可靠性）。
- **概念巧妙优雅**：反转推测解码的构思不仅新颖，而且有效地绕开了黑盒访问的限制。技术上，利用教师强制对轨迹进行单次前向评分，而非生成token。

### 8. 不足与局限

- **过拟合风险与统计稳健性缺失**：论文自身指出，实验结果是单次运行，没有报告方差或置信区间。在多个基准和消融上，几点的AUROC差异可能存在统计不确定性。主要结论（如任务成功率）的差异可能过高估计了模型的稳定性。
- **对“草稿质量”的依赖**：性能高度依赖草稿模型对智能体的对齐质量。如果更换一个与现有智能体差异极大的目标模型，草稿模型可能需要重新训练才能维持信号质量。
- **单一目标与领域**：验证目标仅限于代码执行是否成功。结论中提到的方法可以适用于更广泛的领域（如SQL或Web智能体），但没有提供实验证据。方法的通用性尚未得到验证。
- **部署假设的局限性**：结论认为4B草稿模型的开销是“可忽略的”，但这取决于草稿模型需要在每步都运行一次，并且其延迟是主要瓶颈。如果智能体本身延迟很低或草稿模型需要更大的规模时，成本平衡可能需要重新估算（论文也承认了这一点）。
- **任务成功率的代价**：错误率降低和成本节约是以**牺牲少量任务成功率为代价**的（SWE-Bench Verified从49%降至44%，DA-Code从64%降至63%），虽然有部分是重规划策略本身的效果，但这说明在特定场景中，为避免执行失败而保守地阻止成功行动可能削弱最终性能。
