## 摘要
当正确性依赖于执行时耦合时，基于LLM的代码生成会失败：一个例程的含义由另一个例程的运行时行为定义，这种关系无法仅从文本描述中解析。我们将这种局限性称为静态绑定，它并不局限于显式耦合的问题；每当正确性依赖于跨组件的联合执行行为时，从显式交叉耦合优化器到打包、路由和符号搜索中更细微的联合约束，它都会以不同程度出现。本文提出动态上下文适配，一种针对这种场景设计的样本高效验证-生成循环。验证代理从执行轨迹中提取结构化诊断信息，为生成代理提供类梯度引导，后者每轮提出多个候选。源自问题描述的知识图向生成代理提供语义约束。模拟退火在候选中进行选择以避免贪婪崩溃。在300次和600次评估中，我们的方法在八个问题中的七个上优于零样本、Reflexion和OpenEvolve（p < 0.01），而在此评估次数区间，基于种群的搜索尚未积累足够的多样性来竞争。值得注意的是，在主要激励问题（交叉耦合优化）上，我们的方法在1000次评估时也取得了最佳分数，这与结构化执行反馈在正确性依赖于运行时耦合时最有益这一假设一致。消融结果确认结构化执行反馈是主要驱动因素。

## Abstract
LLM-based code generation fails when correctness depends on execution-dependent coupling: the meaning of one routine is defined by the runtime behavior of another, a relationship that cannot be resolved from textual descriptions alone. This limitation, which we call static binding, is not confined to explicitly coupled problems; it appears to varying degrees whenever correctness depends on joint execution behavior across components, from explicit cross-coupled optimizers to subtler joint constraints in packing, routing, and symbolic search. This paper proposes dynamic context adaptation, a sample-efficient validation-generation loop designed for this setting. A validation agent extracts structured diagnostic information from execution traces, providing gradient-like guidance to a generation agent that proposes multiple candidates per iteration. A knowledge graph derived from the problem description supplies semantic constraints to the generation agent. Simulated annealing selects among candidates to avoid greedy collapse. Our method outperforms zero-shot, Reflexion, and OpenEvolve on seven of eight problems at both 300 and 600 evaluations (p < 0.01), a regime where population-based search has not yet accumulated sufficient diversity to compete. Notably, on the primary motivating problem (cross-coupled optimization), our method also achieves the best score at 1000 evaluations, consistent with the hypothesis that structured execution feedback is most beneficial when correctness depends on runtime coupling. Ablation results confirm that structured execution feedback is the primary driver.

### 1. 核心问题与研究动机（论文的整体含义）

论文聚焦于**LLM（大语言模型）代码生成的一个深层缺陷**：当一段代码的正确性依赖于**组件之间的运行时耦合语义**（即一个函数/例程的含义由另一个例程在执行时的行为决定）时，LLM 无法直接依据文本描述推断出正确实现。作者将此现象命名为 **静态绑定**（static binding）——LLM 在生成时按已训练好的注意力模式做“概念链接”，无法动态地解释执行语义。

- **典型场景**：跨组件交叉优化的资源调度问题、迷宫导航中的动作-后端逻辑耦合问题，以及圆打包、TSP、符号搜索等存在隐含联合约束的问题。
- **类比**：这种缺陷类似于编译时的参数静态绑定，与运行时的动态值解析相对应——代码生成缺少了“执行反馈→语义修正”的闭环。

### 2. 方法论：动态上下文适应（Dynamic Context Adaptation）

核心是一个**两代理（验证-生成）循环 + 知识图谱 + 模拟退火选择**的架构：

- **验证代理（Validation Agent）**：
  - 执行当前候选程序，读取输出日志与量化结果。
  - 分析执行轨迹，识别失败的耦合关系、错过的机会和约束违背。
  - 输出**结构化诊断反馈**（如“圆1与圆12重叠”“指令X不在ISA中”），作为**类梯度引导**。
- **生成代理（Generation Agent）**：
  - 输入五项提示组件：任务摘要、来自知识图谱的语义约束、当前最优候选、执行轨迹日志、结构化建议。
  - 每轮并行提出 **k 个新候选**（实验取 k=3）。
- **知识图谱（KG）中间层**：
  - 从问题描述中提取领域节点与类型化边（“依赖”“实现”“约束”等）。
  - 标记硬/软强度，追踪依赖子图，嵌入 JSON 结构化上下文，实现 Mtext → MKG → Mcode 的语义转换链路。
- **模拟退火（SA）选择器**：
  - 若新候选得分 s2 大于当前最优 s1 则无条件接受；否则以概率 P=exp((s2−s1)/T) 接受劣质解，防止“贪婪崩塌”。
  - 温度几何冷却：T0=2.5，α=0.85，Tmin=0.01。

在实现层面，该过程将“独立语义”的初始实现逐步转化为满足发送者-接收者耦合关系的正确实现。

### 8. 不足与局限

- **验证器的浅层诊断能力有限**：只能观察表面症状；不具备反事实推理的能力（无法提前推断“如果改这一处会如何”）。因此观察不到位于测试套件之外的隐藏缺陷（只在可见日志中覆盖）。
- **单驻留候选（incumbent）机制抑制多样性的潜力**：没有维护多个候选，面对多峰/多盆地的误解在较晚阶段会出现较大的相对结构性局限；论文自己也承认这点。
- **对“执行轨迹可获得性”的依赖**：该方法适用于能够廉价执行、具有确定性输出日志的任务，对需要真实外部世界交互的生成（机器人控制、物理仿真需要时间步、网页交互技术栈）等许多新场景中仍是不小的应用障碍。
- **消融覆盖不够系统化**：消融仅针对 4 个任务和 300 次评估预算执行，高预算下的组件是否会转移到其他任务还需要更多测试数据；此外，也未报告给 OpenEvolve 与本文方法同样的候选数量 k 的敏感性分析。
- **关于模型/算力透明度的限制**：作者没有报告使用了什么 GPU 型号或集群规模——只是“本地提供”，这让“样本高效性”和端到端实际时间收益的直接比较变得困难。
- **基准窗口跨度有限**：8个问题是系统性的起点，但在更接近真实软件开发的多模块 / 长期依赖的项目规模（比如数千行多文件代码库）上的可行性仍未验证。
