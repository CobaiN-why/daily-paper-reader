## 摘要
自主编程智能体现在正以两年前难以想象的规模在公共代码仓库中提交拉取请求，然而对于这些代码合入之后会发生什么，人们却知之甚少。本文研究了来自五个商业智能体（OpenAI Codex、Devin、GitHub Copilot、Cursor 和 Claude Code）以及一个匹配的人类基线的 37,623 个带有来源标注的拉取请求（PR），这些数据取自 2024 年 12 月至 2025 年 7 月期间的 2,807 个 GitHub 代码仓库。我们将 AIDev 数据集与 58,792 条缓存的 GitHub API 响应相结合，以衡量新增代码中的安全性异味、结构可维护性、合并后改动量、回滚率以及人工评审行为。有三项结果尤为突出。第一，质量差异因厂商而异，而非整齐划一：由 Codex 编写的 PR 被回滚的频率约为人类 PR 的一半（6.1% 对 11.5%，优势比 0.50），而 Devin 的 PR 被回滚的频率更高（14.5%，优势比 1.31）。第二，跨厂商汇总的智能体代码比人类代码更不容易包含安全性异味（优势比 0.63），这主要归因于硬编码凭证和 eval 式构造的减少。第三，评审投入的分布并不均衡：Copilot 的 PR 引来最多的人工评审和变更请求，而 Claude Code 的 PR 等待首次人工评审的时间最长（中位数为 12.6 小时）。所有流水线代码、统计报告和图表均已公开，以供复现。

## Abstract
Autonomous coding agents now open pull requests in public repositories at a scale that was out of reach two years ago, yet little is known about what happens to that code after it lands. This paper studies 37,623 provenance-labeled pull requests (PRs) from five commercial agents (OpenAI Codex, Devin, GitHub Copilot, Cursor, and Claude Code) and a matched human baseline, drawn from 2,807 GitHub repositories between December 2024 and July 2025. We combine the AIDev dataset with 58,792 cached GitHub API responses to measure security smells in added code, structural maintainability, post-merge churn, revert rates, and human review behavior. Three results stand out. First, quality differences are vendor-specific rather than uniform: Codex-authored PRs were reverted about half as often as human PRs (6.1% vs. 11.5%, odds ratio 0.50), while Devin PRs were reverted more often (14.5%, odds ratio 1.31). Second, agent code pooled across vendors was less likely than human code to contain a security smell (odds ratio 0.63), driven by fewer hardcoded credentials and eval-style constructs. Third, review effort concentrates unevenly: Copilot PRs drew the most human reviews and change requests, and Claude Code PRs waited the longest for a first human review (median 12.6 hours). All pipeline code, statistical reports, and figures are released for replication.

## 1. 核心问题与整体含义（研究动机与背景）

- **现实背景**：基于大语言模型的编程智能体已从"代码补全"转向"任务委托"——它们能读取 issue、修改仓库、运行测试，并以自己的名义提交 PR。仅 AIDev 数据集在不到一年内就记录了近百万条此类智能体 PR，覆盖十万余个仓库。
- **核心问题**：当这些代码真正合入项目之后，**维护它的代价是什么**？即：智能体代码在真实项目中的缺陷倾向、结构可维护性、合并后改动量（churn）、回滚率与人工评审负担究竟如何。
- **现有证据的缺口**：
  - 主流证据来自**受控环境**：HumanEval/SWE-bench 等基准测"模型能产出什么"，agent 框架在精选 issue 集上比较，安全研究多在实验室提示模型并检查输出。
  - 田野证据稀薄，且多局限于**单一助手（Copilot）的自动补全形态**。
  - 受控设计回答不了"代码要过评审、要与既有设计共存、要在合入后数月存活"这类问题。
- **本文的整体含义**：把智能体代码放回它**真正生存的地方**（公开仓库）来测量，并把"智能体整体"与"具体厂商产品"明确区分开。作者发现**厂商身份才是关键变量**——把"AI 生成代码"当作单一类别会抹掉维护者真正关心的差异。

## 2. 方法论

### 2.1 核心思想
构建一条可复现的四阶段流水线：**语料构建 → GitHub 富化 → 多维测量 → 验证与统计分析**，对每个 PR 追踪至合并后 90 天。

### 2.2 语料构建
- 起点为 AIDev 数据集的规范化切片（>100 star 仓库的智能体 PR），含 33,596 条智能体 PR，按厂商标注为 Codex / Devin / Copilot / Cursor / Claude Code。
- **匹配人类基线**：仅保留同时含智能体 PR 的仓库（810 个），限制在智能体活动窗口内（2024-12-24 至 2025-07-30），按仓库设上限并使用固定随机种子，避免单一项目主导，最终得到 4,027 条人类 PR。

### 2.3 GitHub 富化
- 通过 GitHub REST API 获取：变更文件列表与 PR diff、仓库与 PR 元数据、合并后提交历史。
- **90 天跟踪窗口**：对合并 PR，查询其"最常改动文件"在合并后 90 天内被提交触及的情况，并按 commit message 标记回滚式提交。
- 全部 58,792 条 API 响应**落盘缓存**，使采集可断点续传，后续阶段直接复读原始 payload。

### 2.4 补丁级静态分析
- 只分析 **diff 的新增行**（added lines），覆盖语料中最常见的三种语言：Python、JavaScript、TypeScript，得到 8,933 个 PR、1,348,822 行新增代码；超过 5,000 新增行的 diff 作为自动生成排除。
- **可维护性计数**：TODO/FIXME 标记、超过 120 字符的长行、注释行、分支关键字、最大嵌套深度。
- **安全气味**：用正则目录匹配 8 个 CWE 类别——硬编码凭证（CWE-798）、SQL 字符串拼接（CWE-89）、shell 命令注入（CWE-78）、eval/exec（CWE-95）、不安全反序列化（CWE-502）、弱哈希/密码（CWE-327）、DOM 型 XSS（CWE-79）、文件打开中的路径拼接（CWE-22）。
- **关键公式（密度归一化）**：对第 i 个 PR，设 L_i 为分析的新增行数、S_i 为安全命中数、M_i 为可维护性命中数：
  - 安全气味密度 `s_i = 100 · S_i / L_i`
  - 可维护性气味密度 `m_i = 100 · M_i / L_i`
- **Churn 公式**：对合并 PR，C_i 为变更行数、F_i 为 90 天内其最常改动文件上的后续提交数：
  - `c_i = 100 · F_i / C_i`

### 2.5 评审测量
- 使用 AIDev 提供的评审、评论与时间线表，按平台账号类型区分人工评审与机器人评审；延迟与深度仅基于**人工评审者**计算。
- 评审延迟定义为 PR 创建到首次人工评审的时间。因这些表不覆盖人类样本，RQ5 只在智能体之间比较，并逐组报告覆盖率。

### 2.6 统计设计
- 软件度量重尾且零膨胀，因此全程采用**非参数方法**。
- 组间差异：Mann–Whitney U 检验 + Cliff's δ 效应量 `δ = 2U/(n₁n₂) − 1`，按惯例分档（|δ|<0.147 可忽略，<0.33 小，<0.474 中，否则大）。
- 六组整体差异：Kruskal–Wallis H 检验，效应量 `ε² = (H − k + 1)/(n − k)`，随后用 Dunn 检验做事后两两比较。
- 二值结局（回滚、某 CWE 类是否存在）：χ² 或 Fisher 精确检验 + 优势比 OR 与 95% 置信区间。
- 每族相关比较均用 **Benjamini–Hochberg 程序在 FDR = 0.05 下校正**，报告校正后 p 值；δ 的置信区间来自 **5,000 次固定种子 bootstrap**。
- 分析前设**验证门**检查 schema、取值范围与组覆盖，并生成记录全部 **63 个变量**的 codebook。
