## 摘要
大语言模型（LLMs）越来越多地用于软件工程流水线中的代码生成，其中生产环境中的提示通常组合多个约束。本文对输出格式、角色分配和紧迫性框架如何联合影响LLM代码生成的可靠性进行了全因子实证研究。我们在受控的3x3x3设计中评估了全部27种组合，并将每种复合条件分解为加性预测和残差交互项，以捕捉超加性退化。该研究使用了来自GPT-4o系列、GPT-4.1系列和o3-mini的五个OpenAI模型上的全部164个HumanEval+问题，产生了22,140次贪婪解码评估。一个格式感知的提取流水线将格式失败与推理失败分开，并使用McNemar检验、优势比和95%置信区间评估显著性。结果表明，复合约束可能产生无法从单因素实验预测的架构相关退化。GPT-4o系列表现出一致的超加性效应，pass@1降低比加性预测高出3-12个百分点；最大的交互作用是在GPT-4o-mini上JSON+专家角色+中等紧迫性的-12.2个百分点。JSON组合通常比XML产生更大的交互作用。相比之下，GPT-4.1系列基本不受影响，而o3-mini则表现出质的不同模式，其中结构化输出约束可以提高性能。这些发现表明，脆弱性是架构相关的而非规模相关的，单独中性或有益的约束组合起来可能导致实质性退化，并且复合提示测试应成为LLM辅助工程流水线可靠性评估的标准。

## Abstract
Large language models (LLMs) are increasingly used in software engineering pipelines for code generation, where production prompts often combine multiple constraints. This paper presents a full-factorial empirical study of how output formatting, persona assignment, and urgency framing jointly affect LLM code-generation reliability. We evaluate all 27 combinations in a controlled 3x3x3 design and decompose each compound condition into an additive prediction and a residual interaction term that captures super-additive degradation. The study uses all 164 HumanEval+ problems across five OpenAI models from the GPT-4o family, GPT-4.1 family, and o3-mini, yielding 22,140 greedy-decoding evaluations. A format-aware extraction pipeline separates formatting failures from reasoning failures, and significance is assessed with McNemar's test, odds ratios, and 95% confidence intervals.   Results show that compound constraints can produce architecture-dependent degradation not predictable from single-factor experiments. The GPT-4o family exhibits consistent super-additive effects, with pass@1 reductions 3-12 percentage points beyond additive predictions; the largest interaction is -12.2 pp on GPT-4o-mini for JSON + expert persona + moderate urgency. JSON combinations generally produce larger interactions than XML. In contrast, the GPT-4.1 family is largely resistant, while o3-mini shows a qualitatively different pattern in which structured output constraints can improve performance. These findings show that vulnerability is architecture-dependent rather than size-dependent, that individually neutral or beneficial constraints can combine to cause substantial degradation, and that compound-prompt testing should be standard in reliability assessment for LLM-assisted engineering pipelines.

### 二、论文提出的方法论

**核心思想：**
- 采用**3×3×3 全因子（full-factorial）实验设计**，同时操纵三类独立的提示约束因素，而非逐一评估。
- 将每个三因素组合的条件分解为**加性预测**（各单因素主效应之和加上基线）与**残差交互项**，从而量化**复合效应**超出"单因素效应之和"的程度。

**三因素设置：**
| 因素 | 水平 1（无） | 水平 2（中） | 水平 3（高） |
|---|---|---|---|
| **格式约束** | 自由形式 | JSON格式 | XML格式 |
| **角色设定** | 无系统消息 | 普通开发人员角色 | 资深 Python 专家角色 |
| **紧迫性框架** | 无框架 | 中等重要性描述 | 极端紧急场景（生产故障、失业压力） |

**统计模型与交互项公式：**
- 对每个三因素组合 (f, p, u)，实际结果与加性预测（基线+各主效应之和）的残差定义为：

$$I_{f,p,u} = Y_{\text{actual}} - (Y_{\text{base}} + \Delta_f + \Delta_p + \Delta_u)$$

- **负数 I 值**表示超加性退化（复合约束造成的性能损失比各部分叠加预测的更严重）；论文以此作为检测复合提示失败模式的核心度量指标。

**格式感知代码提取流水线：**
- 针对结构化输出中的代码提取问题，论文设计了多策略回退提取流程：
  - JSON：依次尝试直接解析 → 正则表达式键匹配 → 自动修复畸形 JSON → 纯文本提取回退；其中关键细节是处理字符串中的双重转义换行符。
  - XML：按标签提取 → HTML 实体解码 → 纯文本回退。
  - 自由格式：代码栅栏检测 → 按缩进结构识别函数定义。
- 每次提取均记录方法，实现后验区分"格式失败"和"推理失败"。

**统计显著性检验：**
- 因为 164 个问题在每个条件下均出现，采用的是同一批问题上的配对二元结果，因此使用 **McNemar 配对检验**（非独立样本检验）。
- 报告优势比（odds ratio）及 95% 置信区间，并结合 p 值评估退化是否显著。

### 六、主要结论与发现

1. **GPT-4o 家族存在显著超加性退化**：
   - GPT-4o-mini：平均交互效应 𝐼̄ = −7.6 pp，8/8 的组合均呈超加性退化；最大交互效应为 −12.2 pp（JSON + 专家角色 + 中等紧迫性组合）。
   - GPT-4o：平均交互效应 𝐼̄ = −4.2 pp，8 个组合中 5 个超加性；但其退化程度弱于同族的更小模型。

2. **GPT-4.1 家族基本免疫**：
   - GPT-4.1-mini（𝐼̄ = +1.7 pp，0/8 超加性）和 GPT-4.1（𝐼̄ = +1.3 pp，2/8 超加性）均无系统性超加性退化。
   - 论文认为这与 GPT-4.1 被显式优化指令跟随能力有关；该优化附带带来了对多约束干扰的鲁棒性。

3. **o3-mini 呈现定性不同模式**：
   - 其无约束基线异常低（59.8%），但任何结构化输出约束都能大幅提升其表现（JSON：88.6%，XML：88.1%，提高约 11 pp）。
   - 由于该模型主效应高达 20–30 pp，天花板效应使三因素交互模型不适用。该结果可能与其内部思维链机制解耦了推理与输出格式有关。

4. **脆弱性是架构相关的，而非规模相关**：
   - GPT-4o 系列（新旧、大小两型号均受影响）和 GPT-4.1 系列（同样涵盖两种尺寸，皆抵抗）的内部差异远超单一家族在两种规模之间的差异，说明架构/训练过程而非参数量决定了该脆弱性。

5. **单因素评估不足以预测复合提示行为**：
   - 例如 GPT-4o-mini 的紧迫性框架或 XML 格式在单独条件下均有正效果（76.6%→80.2%，78.1%→82.0%），但与其他约束组合后出现 −12.2 pp 的交互退化。
   - 单独中性甚至有益的约束在组合时会产生大规模退化，此类故障模式在单因素测试中完全不可见。

6. **JSON 比 XML 诱导更大的交互效应**：
   - 在 GPT-4o-mini 上，JSON 组合的平均交互效应（−10.7 pp）远大于 XML 组合（−4.6 pp），这为实践提供了潜在的缓解方向——当需要与角色设定及紧迫性配合时，XML 包裹的低复合开销优于 JSON 字符串编码。

7. **统计显著性**：
   - GPT-4o-mini：单约束最佳条件（紧迫性仅，82.9%）vs 最差三重组合（JSON+专家+中等紧迫性，73.2%）对比得到的 OR=3.67（95% CI: [1.49, 9.04]，p=0.004），统计显著。
   - GPT-4o：紧迫性(仅) 87.8% vs JSON+generic+无紧迫性 75.0%，OR=6.25（95% CI: [2.18, 17.96]，p<0.001），高度显著。
   - GPT-4.1-mini：所有配对比较均未达显著水平，与其近似零的交互效应一致。

### 七、优点

- **实验设计严谨**：采用全因子实验设计（3×3×3），避免了常见单因素或多因素"部分组合"设计的盲区，是探索复合提示交互效应的恰当方法；交互分解公式（加性预测 + 残差交互项）逻辑清晰、直接可操作。
- **统计方法与基准选择得当**：使用配对 McNemar 检验而非独立样本检验，契合"同一批问题跨条件出现"的数据结构；使用 HumanEval+（增强后约 764 个测试用例）而非原版 HumanEval，有效降低假阳性率，更利于检测由提示引起的细微退化。
- **格式与推理失败的解耦**：多策略回退提取流水线记录提取路径，能够区分"格式失败"与"推理失败"，避免将提示格式因素引入的解析问题错误归因于模型推理能力——这对结构化输出指令的研究有方法论借鉴意义。
- **覆盖面广，架构对比明确**：同一实验框架横跨 5 个模型、两个架构家族和一个推理模型，可以区分"规模效应"与"架构效应"。
- **实践相关性高**：发现和部署场景直接挂钩——人员识别"单个约束可加性测试的失效边界"、说明"JSON 与 XML 不对称性可作缓解抓手"，并提出"应以生产完整提示而非其组件来评估可靠性"这一原则性建议；同时将复合提示评估定位为补充系统安全实践的环节，而非简单替代。
- **对模型差异处理的透明度**：明确说明 o3-mini 因 API 限制与标准模型的差异（不支持 system 角色、temperature 固定等），便于读者对结果的边界进行判断。
