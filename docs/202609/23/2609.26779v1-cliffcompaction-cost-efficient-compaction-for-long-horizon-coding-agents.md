## 摘要
智能体常需处理需要数百万 token 上下文的复杂问题，而受限于上下文窗口，必须在跨会话间进行压缩。我们开发了 CliffCompaction，一种自动压缩技术，在有界上下文下可将成本降低最多 50%，同时在 Terminal-Bench 上保持或提升性能，并实现测试时扩展效率的新高度，在 KernelBench 上取得当前最优结果。CliffCompaction 在每次 rollout 上的节省使测试时扩展的性能—成本权衡更高效，在 Terminal-Bench 上以低于两次全上下文运行的成本增加超过 10 个百分点。在并行测试时扩展下，CliffCompaction 使 Kimi K2.6 追平 Opus 4.7，并以更低成本超越 Opus 4.6 和 GPT-5.3 Codex。CliffCompaction 有效性的关键在于，它仅通过截断或丢弃内容来保持压缩后信息的忠实性，绝不重述或重写内容。我们从不压缩“压缩结果”——每一轮只对原始内容操作，并丢弃先前的压缩输出，从而防止上下文漂移累积。这些特性使跨超过百万 token 的会话能够持续学习：在 KernelBench 上，CliffCompaction 在 200 步后达到 2.23× 的 CUDA 内核加速比，在 400 步后达到 3.58×，尽管它只是一种通用压缩技术，仍超越了专用搜索算法和经训练的智能体。我们开源了一个与脚手架无关的 CliffCompaction API 代理实现，可用于 Claude Code、Codex 和其他 harness。

## Abstract
Agents often work on complex problems that require millions of tokens of context, which necessitates compacting across sessions due to limited context windows. We develop CliffCompaction, an autocompaction technique that reduces cost by up to 50% under a bounded context while maintaining or improving performance on Terminal-Bench and achieving new levels of efficiency for test-time scaling and state-of-the-art results on KernelBench. The per-rollout savings of CliffCompaction make the performance--cost trade-off of test-time scaling more efficient, adding over 10 percentage points on Terminal-Bench for less than the cost of two full-context runs. Under parallel test-time scaling, CliffCompaction lets Kimi K2.6 match Opus 4.7, and exceed Opus 4.6 and GPT-5.3 Codex at lower cost. The key to CliffCompaction's effectiveness is that it keeps compacted information faithful by only truncating or dropping content, never rephrasing or rewriting it. We never compact a compaction---each pass operates only on original content, and prior compacted output is discarded, preventing context drift from accumulating. These properties sustain continual learning over sessions exceeding a million tokens: on KernelBench, CliffCompaction reaches CUDA kernel speedups of $2.23\times$ after 200 steps and $3.58\times$ after 400 steps, surpassing specialized search algorithms and trained agents despite being a general-purpose compaction technique. We open-source a scaffold-agnostic API-proxy implementation of CliffCompaction usable with Claude Code, Codex and other harnesses.

# CliffCompaction 论文总结

## 1. 核心问题与研究动机

- **背景**：编码智能体（coding agents）在解决复杂任务时，需要与工具和环境反复交互，轨迹上下文常达数百万 token 量级，远超模型上下文窗口。跨会话压缩（compaction）成为必需。
- **两类核心挑战**：
  - **(a) 上下文容量管理**：会话耗尽窗口后如何管理上下文。现有方案包括滑动窗口（丢弃最旧轮次）、LLM 摘要、外部记忆/RAG、子智能体分解等，但各有代价。
  - **(b) 成本效率**：长上下文对应的 KV-cache 是主要内存与计算瓶颈，cache read 在 agent 场景中占总成本约 78%。任何上下文修改都会使 KV-cache 失效并触发昂贵的 re-prefill（未缓存输入约为缓存 token 的 5–6 倍价格）。
- **现有方法的具体缺陷**：
  - **滑动窗口**：窗口推进时前缀缓存失效，re-prefill 成本高。
  - **LLM 摘要**：摘要的摘要链式压缩会累积损失，导致“低压缩精度”（low compaction precision）与上下文漂移。
  - **学习型压缩**：需要额外训练，跨模型迁移性差。
  - **外部记忆/RAG**：需要检索基础设施，存在检索失败风险，非 drop-in。
  - **子智能体分解**：编排复杂，需专门提示或训练。
- **整体含义**：论文主张在**有界上下文 + 自动压缩**下，可以以更低成本匹配甚至超越全上下文性能，并让测试时扩展（test-time scaling）与持续学习（continual learning）变得经济可行。

## 2. 方法论：CliffCompaction

### 核心思想
- **规则驱动、免训练、即插即用、模型无关、缓存友好、无辅助 LLM 调用**的上下文管理方法。
- 三大设计选择：
  1. **阈值触发压缩**：上下文自然增长至预设 token 阈值时才压缩，段内不修改上下文以保持 KV-cache 有效。
  2. **保留逐字片段而非摘要**：只截断或丢弃内容，绝不重述或改写。
  3. **每次压缩丢弃旧压缩块**：只压缩最近一次压缩之后的“活跃会话”，不压缩“压缩结果”，避免摘要链式损失。

### 关键技术细节
- **压缩对象与规则**（基于 Terminal-Bench 2.0 的 token 归因：tool results 占 56.0%，tool calls 占 28.0%，二者合计 84%）：
  - **工具结果**：长度 > 500 字符的丢弃，短结果保留（如 grep 匹配、退出码、简洁脚本输出）。
  - **工具调用**：压缩为签名（tool name + 目标文件/路径 + 关键参数），保留前 150 字符；去除内联的长文件内容（如 file-write），因文件本身持久存在于代码库，可按需重读。
  - **思考（thoughts）**：截断至 300 字符。
  - **系统提示与首个用户消息（任务描述）**：完整保留。
  - **最近 K 轮**：完整保留（算法中为最近 2K 个 turn pair）。
- **算法流程**（Algorithm 1）：
  - 将 turns 切分为 `old` 与 `recent`；
  - 遍历 `old`：遇先前压缩块则跳过（丢弃）；遇 assistant 消息则加入截断后的 thinking（≤300）与 toolcall 签名（≤150）；遇短 tool result（≤500）则原样保留；
  - 返回 `JOIN(parts)` 与 `recent`；
  - `QUERY` 捕获 `CONTEXT WINDOW EXCEEDED` 异常后触发压缩，重建消息 `[system, first_user, C] ++ recent`。
- **精度—召回权衡（核心理论视角）**：
  - **高精度（precision）**：保留的片段逐字未改写，用户指令与模型生成在两个完整压缩窗口内完整保留。
  - **低召回（recall）**：两次压缩后的直接信息被丢弃。
  - **残差传播（residual propagation）**：虽然不直接传递旧信息，但 `C_t ← L_t ← C_{t-1} ← L_{t-1} ← …`，agent 的行为与推理隐含携带了被丢弃上下文的影响，缓解召回损失。
- **缓存机制**：两次压缩之间上下文不变，cache 全程有效；仅在压缩点失效并 re-prefill，但压缩后上下文显著变小且压缩频率低，re-prefill 开销被长期缓存复用摊销。

## 6. 主要结论与发现

- **性能保持/提升**：
  - SWE-bench Verified：Kimi K2.6 在 32K 下 73.27% vs 全上下文 73.87%；16K 内差距 <2 点；GLM 5.1/5 Turbo 在 16K 内差距约 2 点。
  - Terminal-Bench 2.0：Kimi K2.6 在 32K/16K 达 61.42%，超过全上下文 59.16%；GLM 5.1 从 49.83% 提升到 54.33%（16K）。
  - Terminal-Bench 2.1（Claude Code）：GLM 5.3 Flash 在 ~45K 下达 76.69%，超过 Claude Code auto-compaction（70.97%）与默认 200K（73.03%），方差更低。
- **成本大幅降低**：
  - 总成本最多降 50%；cache read 成本降 80%（$0.427 → $0.087/task）；Terminal-Bench 上降幅 25.0%–52.1%（Kimi）与 35.8%–64.6%（GLM）。
  - 缓存命中率下降仅带来有限 re-prefill 开销（+$0.06 vs 节省 $0.34）。
  - 真实 runtime 也下降 23%–34%（OpenHands SWE-bench）。
- **测试时扩展经济化**：
  - Terminal-Bench：3 次 Kimi K2.6 + CliffCompaction 达 69.7%，匹配 Opus 4.7（69.4%），超越 GPT-5.3 Codex（64.7%）与 Opus 4.6（62.9%），总成本 $58.01，低于单次 GPT-5.3 Codex。
  - 相比无压缩 3 次 rollout：+5.7 点且成本低 37%；+10.5 点仅 1.9× 成本。
  - GLM 5.1：+10.9 点仅 1.8× 成本，成本降 40%。
  - SWE-bench Verified：3 次压缩 Kimi 达 76.4%，接近 Opus 4.5（76.8%）的 70% 成本；5 次达 77.0% 超越之。
- **持续学习新 SOTA**：
  - KernelBench L3：200 步 2.23×、400 步 3.58×（L40S，Kimi K2.7）；RTX Pro 6000 上 400 步 2.48×。
  - 超越专用方法 AdaExplore（1.78× @200 步）与 CUDA-Agent（1.80×）。
  - >2× 比例从 50% 提升到 86%（L40S，400 步）。
  - 按 kernels 归一化后优势更明显（10 个 kernel 即达 1.47× vs AdaExplore 0.99×）。
- **压缩方法对比**：CliffCompaction 是唯一在三个 benchmark 上同时保持高质量且低成本的方案；滑动窗口虽质量略高但更贵（+9%/+7%）；摘要在质量上最弱；微压缩成本高（KernelBench $12.84 vs $8.32）。

## 7. 优点

- **方法简洁、部署友好**：免训练、drop-in、模型无关、scaffold 无关（对 Claude Code 这种闭源 scaffold 也能通过 API proxy 直接接入，且无需知道其工具 schema）。
- **缓存感知设计**：明确区分“压缩收益”与“re-prefill 代价”，通过段内不改上下文、低频压缩实现 cache 高复用，是少见的将 KV-cache 经济性纳入压缩算法设计的方案。
- **精度优先的清晰理论视角**：提出 compaction precision vs. recall 权衡，并用“residual propagation”解释了低召回下仍能长程有效的机制，且有 re-read 行为实验佐证（CliffCompaction 增加 +5.04 次重读，说明模型会主动回读源文件）。
- **实验覆盖面广**：3 benchmark × 4 scaffold × 10+ 模型 × 多阈值 × 多 k，且附录给出成本模型、token 价格、特征表、算法细节，可复现性较好。
- **公平性意识强**：
