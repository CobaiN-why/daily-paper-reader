## 摘要
近年来的代码生成研究已从孤立的函数补全转向在现有代码库中进行仓库级生成。为了正确实现目标函数，LLM 必须识别可复用的仓库依赖，例如现有函数、API 和跨文件定义。现有检索方法通过代码相似性搜索、持久化的全仓库图或 LLM 驱动的图探索来提供此类上下文，但往往带来高昂的图构建、推理和 token 成本。面向特征的方法提供了软件功能的自然视角，但它们主要支持需求分解、规划或特征编辑，而非代码依赖检索。本文提出了 FeatLens，一种用于仓库级代码生成的特征引导动态代码图构建与检索方法。FeatLens 构建一个特征索引，将自然语言特征描述链接到函数级代码实体。给定生成任务，它从特征索引中动态构建任务特定的种子图，并应用带有个性化 PageRank 的语义-结构图推理来选择紧凑的推理图。该设计以确定且轻量的依赖检索取代了持久化的全仓库图维护和 LLM 探索。在 DevEval 和 EvoCodeBench 上的实验表明，FeatLens 在稀疏、稠密和基于图的基线中取得了最佳的 DR@15（0.501 和 0.460）。在 DevEval 生成任务上，它取得了最高的 DIR@1，使用 DeepSeek-V3.2 时达到 52.91%，使用 GPT-5-mini 时达到 53.58%，同时保持有竞争力的 Pass@1 并生成更短的代码。与最强的基于图基线相比，FeatLens 将图节点减少 61.0%，边减少 86.2%，总 token 开销减少 45.9%，且检索过程中不使用 LLM token。

## Abstract
Recent code generation research has moved from isolated function completion toward repository-level generation in existing codebases. To implement a target function correctly, an LLM must identify reusable repository dependencies such as existing functions, APIs, and cross-file definitions. Existing retrieval methods provide such context through code similarity search, persistent whole-repository graphs, or LLM-driven graph exploration, but often incur high graph construction, reasoning, and token costs. Feature-oriented methods offer a natural view of software functionality, yet they mainly support requirement decomposition, planning, or feature editing rather than code dependency retrieval. This paper presents \textbf{FeatLens}, a feature-guided dynamic code graph construction and retrieval approach for repository-level code generation. FeatLens builds a feature index that links natural-language feature descriptions to function-level code entities. Given a generation task, it dynamically constructs a task-specific seed graph from the feature index and applies semantic-structural graph reasoning with personalized PageRank to select a compact reasoning graph. This design replaces persistent whole-repository graph maintenance and LLM exploration with deterministic and lightweight dependency retrieval. Experiments on DevEval and EvoCodeBench show that FeatLens achieves the best DR@15 among sparse, dense, and graph-based baselines (0.501 and 0.460). On DevEval generation, it obtains the highest DIR@1, reaching 52.91\% with DeepSeek-V3.2 and 53.58\% with GPT-5-mini, while maintaining competitive Pass@1 and producing shorter code. Compared with the strongest graph-based baseline, FeatLens reduces graph nodes by 61.0\%, edges by 86.2\%, and total token overhead by 45.9\%, with no LLM tokens used during retrieval.

- **研究背景**：代码生成研究已从孤立的函数补全转向**仓库级代码生成**。在现有代码库中实现目标函数时，LLM 必须识别可复用的仓库依赖，包括现有函数、API 和跨文件定义；否则容易重复已有逻辑、误用 API 或违反架构设计。
- **现有方法的两条路线及其问题**：
  - **直接检索代码**：基于代码相似性（稀疏/稠密检索）或结构化表示（代码图、调用链图）检索上下文。问题在于：结构上下文通常从仓库代码构建，而非由功能需求引导；且维护全仓库图开销大。
  - **Agent 驱动探索**：LLM 迭代检查代码、调用工具、利用执行/测试反馈。问题在于：成本转移到在线 LLM 交互，长推理链易累积错误，定位不可控。
- **功能视角方法的缺口**：已有功能导向工作（如 EvoDev、FeatX）主要支持需求分解、规划、设计空间探索或功能编辑，**未将功能级意图作为代码级依赖检索的操作性信号**。
- **核心问题**：如何利用功能级意图，按需构建任务相关的结构化上下文，将功能请求映射到实现时应复用的具体函数、API 和跨文件定义，同时避免全仓库图维护和 LLM 探索的高开销。
- **整体含义**：FeatLens 提出一种**特征引导的动态代码图构建与检索方法**，用确定性、轻量的依赖检索替代持久化全仓库图和 LLM 探索，在提升依赖检索和生成质量的同时显著降低图与 token 开销。

## 2. 方法论

### 2.1 核心思想

- 将**功能（feature）**作为连接自然语言任务意图与可复用仓库代码的**检索锚点**。
- 离线构建**特征索引**，在线针对具体任务动态构建**种子图**，再通过**语义-结构图推理**与**个性化 PageRank** 过滤出紧凑的**推理图**，作为代码生成上下文。
- 检索阶段不调用 LLM，仅使用静态分析和确定性评分，避免 token 成本和模型调用不稳定性。

### 2.2 关键技术细节与流程

**（1）特征导向仓库索引（离线）**

- **静态分析**：提取函数、类、文件等代码实体，记录轻量结构关系（调用、导入）。
- **语义分析**：为每个函数生成轻量描述和嵌入，表示其实现语义。
- **层次聚类**：基于实体相似度对函数级表示进行聚类，将可能支持同一功能函数的函数分组。
- **特征摘要**：将每个聚类总结为自然语言特征描述，并记录对应函数集合，形成特征索引：
  - \( R = \{f_i\}_{i=1}^M = \{(d_i, C^{\text{func}}_i)\}_{i=1}^M \)
  - 其中 \(f_i\) 为第 \(i\) 个特征，\(d_i\) 为自然语言描述，\(C^{\text{func}}_i\) 为该特征关联的函数级代码实体子集。

**（2）特征引导动态种子图构建（在线）**

- 给定任务描述和目标函数位置，检索与需求语义对齐的特征聚类，并利用目标位置上下文细化选择。
- 仅使用生成时可得的信息，不访问缺失的目标实现。
- 选中特征关联的函数构成**种子节点**，实例化这些节点间的仓库依赖关系，形成任务特定的局部图，无需为整个仓库物化细粒度图。

**（3）语义-结构图推理**

- 从种子图沿仓库依赖关系扩展，以恢复特征检索可能遗漏的相关实体。
- 扩展会引入弱相关候选，因此结合**任务相关性**与**结构上下文**对候选排序。
- 采用**个性化 PageRank** 在依赖连接上传播偏好，排名最高的实体及其关系在检索预算下形成紧凑推理图。
- 推理图与任务描述、目标函数位置一起提供给生成模型，用于生成代码补丁。

### 2.3 动机示例中的效果

- 在 Mrjob 的 `_stream_history_log_dirs` 任务上：
  - BM25：P=21.4%，DR=50.0%；UniXcoder：P=14.3%，DR=33.3%；RepoGraph：P=0.0%，DR=0.0%；CodexGraph：P=7.7%，DR=33.3%。
  - FeatLens 种子图：P=26.7%，DR=66.7%；扩展图：DR=100.0% 但 P 降至 17.1%；最终推理图：P=37.5%，DR=100.0%。
- 说明特征引导入口优于原始文本匹配或固定图查询，且需结合受控扩展与语义-结构过滤。

- **研究启示**：仓库级代码生成未必需要维护全仓库细粒度图，也未必需要让 LLM 在线反复探索。先以功能语义定位任务相关区域，再以结构关系做受控扩展和过滤，可能是兼顾效果与效率的可行路线。
