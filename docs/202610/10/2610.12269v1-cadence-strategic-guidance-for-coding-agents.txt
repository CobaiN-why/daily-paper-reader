# Cadence: Strategic Guidance for Coding Agents 

MINXING WANG, Singapore Management University, Singapore 

HE YE, University College London, United Kingdom 

EARL T. BARR, University College London, United Kingdom 

YINTONG HUO, Singapore Management University, Singapore Runtime monitors are increasingly used to improve the reliability of LLM-based coding agents by inspecting execution trajectories and delivering corrective guidance upon detecting misbehavior. However, their effective-ness remains limited by static guidance triggering schemes. Existing monitors rely either on fixed inspection intervals, missing timely guidance during severe misbehaviors while incurring unnecessary overhead during healthy execution, or on rigid heuristic rules, failing to detect complex reasoning errors. To address these limitations, we propose Cadence, a dynamic monitoring framework that adaptively schedules inspections and delivers guidance according to the agent’s real-time execution health. Cadence consists of two core modules: a two-tier intervention module and an inspection scheduler. The intervention module delivers advisory-level guidance for normal executions and minor lapses, while providing replacement-level guidance for severe misbehaviors. Driven by the intervention level, the scheduler adjusts the inspection frequency by tightening supervision after replacement-level guidance and relaxing it after advisory-level guidance. Evaluated on 300 SWE-bench Lite tasks across two distinct agents, mini-swe-agent and Moatless, Cadence achieves the highest resolve rate among all evaluated monitors. Specifically, Cadence outperforms vanilla agents by 25.33% (+76 resolved tasks) on mini-swe-agent and 15.67% (+47 resolved tasks) on Moatless, while maintaining competitive token efficiency compared to state-of-the-art baselines. Additional Key Words and Phrases: Coding Agents, Runtime Monitoring, Large Language Models, Self-Adaptive Scheduling 

1 Introduction 

LLM-based coding agents have been widely applied to automate software maintenance tasks, such as bug fixing and new feature implementation [1, 29, 34, 35, 41]. Despite their promise, agents still fail in complex coding tasks, especially long-horizon ones [3, 7, 9, 25, 40]. To improve coding agents, existing work examines step-by-step agent trajectories and provides guidance to prevent error actions. This work can be divided into two categories based on the stage of guidance: offline learning and online monitoring . Offline learning relies on historical execution records to post-train the agent’s backbone model [24, 33, 36, 38], or to construct a memory bank as a domain knowledge base [2, 12, 42]. However, these offline methods cannot intervene during test-time execution once an agent deviates. In contrast, runtime monitors inspect the agent’s intermediate execution trace on-the-fly and inject guidance to correct misbehavior [20, 22]. Recent studies show that early mistakes propagate into cascading failures, making dynamic intervention essential to catch errors before they become unrecoverable [14, 25, 39]. Runtime monitoring approaches deploy a dedicated monitor to supervise the execution trajectory of a coding agent. By inspecting ongoing execution steps, the monitor identifies misbehaviors (i.e., error steps), and injects corrective guidance into the coding agent’s context. A central challenge is deciding when the monitor should deliver this guidance . Existing approaches fall into two categories: 1) periodic guidance , which inspects progress at fixed step intervals, then prompts corrective instructions into the context [22]; and 2) rule-based guidance , which triggers on predefined heuristic

Our preliminary study shows that neither of these static trigger mechanisms delivers guidance properly. Rule-based guidance overlooks reasoning errors, which manifest in natural language and follow no fixed misbehavior patterns. Periodic guidance, in contrast, oscillates between over-guidance and under-guidance . When the coding agent only encounters minor lapses, frequent interventions add unnecessary overhead (over-guidance). Conversely, when the coding agent enters severe failure actions (e.g., repeating an invalid patch), sparse guidance fails to correct the misbehavior before it compounds irreversibly (under-guidance). To address this, we argue that monitors must move beyond rigid schedules and simple rules and instead provide strategic guidance : an LLM-based monitoring policy that decides both when to inspect and how to intervene based on the agent’s runtime execution health. Rather than treating inspection and intervention as separate decisions, strategic guidance unifies them, dynamically tuning the inspection frequency while delivering context-aware interventions tailored to the agent’s evolving health status. Guided by this principle, we propose Cadence, a holistic runtime monitoring framework for cod-ing agents that synergizes adaptive inspection scheduling with a two-tier intervention mechanism. The first module is a two-tier intervention module , which evaluates agent’s recent execution health and applies an intervention at the appropriate level: advisory or replacement . When the coding agent stays on track or exhibits minor lapses, an advisory-level intervention provides light-weight guidance while allowing the current step to proceed. When severe misbehaviors occur, a replacement-level intervention discards the erroneous step and prompts the agent to regenerate an alternative action. The second module is an inspection scheduler , which dynamically adjusts the inspection frequency based on the first module’s output. Using the resulting intervention level as a direct signal of execution health, it extends the inspection interval upon an advisory intervention to reduce monitoring overhead, but resets the interval to a base value upon a replacement inter-vention to enforce close oversight. Together, these modules allow Cadence to adaptively balance intervention effectiveness while limiting unnecessary monitoring burden. We instantiate Cadence for autonomous bug-fixing agents, though its strategic guidance mecha-nism generalizes to broader coding tasks because it does not rely on task-specific heuristics. We comprehensively evaluate Cadence on SWE-bench Lite [16] across different scaffolds and backbones. Our results show that Cadence consistently outperforms existing runtime monitors, improving the task resolve rate by 25.33% (+76 resolved tasks) over the unmonitored baselines in mini-swe-agent, and 15.67% (+47 tasks) in Moatless. Furthermore, Cadence demonstrates competitive token efficiency against existing monitors, reducing average total tokens per task to 0.48M on Moatless and 1.03M on mini-swe-agent, compared with 0.51M and 1.47M for state-of-the-art monitor. To sum up, the main contributions of this paper are threefold: 

• We conduct a preliminary study on existing runtime monitors and find that rule-based guidance misses reasoning errors that follow no fixed pattern, while periodic guidance oscillates between over-guidance and under-guidance. 

• To the best of our knowledge, we propose Cadence, the first runtime monitor that strategi-cally inspects and guides coding agents, by combining a two-tier intervention module and an inspection scheduler to adjust inspection frequency according to the agent’s execution health. 

• We comprehensively evaluate Cadence on SWE-bench Lite, showing that Cadence improves resolve rates by up to 25.33% over vanilla coding agents while achieving up to 29.93% token savings compared with state-of-the-art monitors. 2 Motivating Study 

Existing runtime monitors deliver guidance through static triggers, relying on either fixed inspection intervals or predefined heuristic rules. In this section, we empirically examine the limitations of both mechanisms on SWE-bench Lite. 

2.1 Periodic Guidance: Does One Interval Fit All? 

Existing monitors with periodic guidance focus on refining prompts to detect agent misbehaviors, while simply adopting a fixed inspection interval. To investigate the impact of such periodic guidance on agent performance, we implement a basic fixed-interval monitor over the mini-swe-agent framework. In this study, the underlying coding agent employs GPT-5-mini as its backbone, whereas the monitor utilizes GPT-5.2. At each inspection point, the monitor prompts an LLM to inspect the problem description and the agent’s recent execution trajectory, generating targeted guidance that is appended to the agent’s context for subsequent execution. To examine how inspection frequency interacts with agent runtime behavior, we partition SWE-bench Lite into two distinct groups based on the outcome of the vanilla (i.e., without monitoring) mini-swe-agent: 145 resolved tasks and 155 unresolved tasks. Manual inspection of all 300 vanilla trajectories by two experts reveals that two groups represent distinct execution health profiles. The resolved group represents scenarios where the agent stays on track or recovers from minor lapses autonomously. In contrast, the unresolved group reflects compromised execution health, where the agent suffers from severe misbehaviors that compound into irrecoverable failure. We evaluate four distinct inspection intervals, namely 3, 5, 9, and 15 steps, plotting the resolve rate against the interval for each group in Figure 1. As the inspection interval increases, the resolve rate exhibits opposing trends between the two groups. For the group with compromised execution health, a larger interval degrades performance, dropping the resolve rate from 23.87% at interval 3 to 14.19% at interval 15, representing a severe 9.68% decline. In contrast, for the group with favorable execution health, the resolve rate consistently remains high across all interval settings, staying at or above 88.28%. Meanwhile, increasing the interval from 3 to 15 monotonically reduces token consumption in both groups, moving from 0.45M to 0.30M tokens for the resolved group and from 0.70M to 0.49M tokens for the unresolved group. These findings demonstrate that no single fixed interval fits all executions. Healthy executions benefit from sparser checks that minimize 4 Minxing Wang, He Ye, Earl T. Barr, and Yintong Huo

Existing rule-based monitors rely on fixed patterns to trigger in-terventions. To evaluate whether such heuristics are sufficient for coding agents, we equip mini-swe-agent with LivePlan, a state-of-the-art monitor that matches action sequences against predefined rules and generates LLM-guided advice when a rule fires. On SWE-bench Lite, 152 out of 300 tasks failed. To understand why these failures were overlooked, two experts conducted an open coding [26] anal-ysis of these trajectories, identifying three distinct categories of undetected misbehaviors (Figure 2). A wrong repair target means the agent identifies an incorrect code region for modi-fication. 3 Methodology 

This section introduces our framework for real-time agent monitoring and strategic guidance. We begin by defining the core problem formulation, establishing our goal of tracking agent health to deliver timely interventions that keep agents aligned with their task objectives. We then present an overview of Cadence, our overall monitoring system, detailing its high-level architecture and its two principal components. Next, we delve into the two-tier intervention module, which determines the depth and nature of corrective guidance. Finally, we describe the inspection scheduler, which optimizes the frequency and timing of agent evaluations to balance monitoring precision with computational efficiency. 3.1 Problem Formulation 

We first formally define the runtime monitoring task for coding agents. This problem comprises abase coding agent tasked with resolving a software issue and an external monitor supervising its execution. The coding agent interacts with the development environment through sequential steps. At each step 𝑖 , the agent reasons over the current context ( 𝑡 𝑖 , thought), invokes tools ( 𝑎 𝑖 , action), and receives execution feedback ( 𝑜 𝑖 , observation) [28, 37]. The agent’s trajectory, which records 𝑛 

steps, can be denoted as 

𝜏 = ⟨( 𝑡 1, 𝑎 1, 𝑜 1), (𝑡 2, 𝑎 2, 𝑜 2), . . . , (𝑡 𝑛 , 𝑎 𝑛 , 𝑜 𝑛 )⟩ .

At run time, the monitor synchronously inspects the prefix trajectory (𝜏 ≤𝑘 ) up to the current step 𝑘 ,where step 𝑘 presents the proposed thought 𝑡 𝑘 and action 𝑎 𝑘 without executing the 𝑎 𝑘 . Upon each inspection, the monitor generates guidance 𝑔 𝑘 based on the observed execution and integrates it as a distinct message into the trajectory. For guidance appended after the current step, the resulting trajectory is represented as 

𝜏 ′ = ⟨( 𝑡 1, 𝑎 1, 𝑜 1), . . . , (𝑡 𝑘 , 𝑎 𝑘 , 𝑜 𝑘 ), 𝑔 𝑘 , (𝑡 𝑘 +1, 𝑎 𝑘 +1, 𝑜 𝑘 +1), . . . ⟩,

The coding agent then conditions on 𝜏 ′ in generating subsequent steps. The objective of runtime monitoring is to detect and mitigate misbehaviors, steering the agent toward successful task resolution. 

3.2 Cadence Overview 

Cadence consists of two modules: a two-tier intervention module and an inspection scheduler. The first module decides how to intervene, the second decides when to inspect, and together they provide strategic guidance. Specifically, the intervention module evaluates recent execution health and applies an appropriate intervention level, either advisory or replacement, to the current step. For normal execution or only minor lapses, an advisory-level intervention allows the step to execute while appending guidance to the trajectory for future steps. For severe misbehaviors, a replacement-level intervention discards the proposed step before execution and prompts the agent to regenerate it with the guidance. The inspection scheduler then uses this intervention level as an indicator of current execution health to adjust the inspection interval. This adaptive mechanism enables Cadence to back off during stable execution and intensify inspection during severe failures, preserving effectiveness while reducing monitoring overhead. As illustrated in Figure 3, the inspection scheduler initializes with a base inspection interval. Every time this threshold is reached, the scheduler triggers the intervention module to evaluate the trajectory since the last inspection. The intervention module then decides an intervention level and provides strategic guidance to the coding agent. The scheduling module then updates the inspection interval based on the level. This cycle continues until the coding agent completes the task. The following sections describe each module of Cadence in detail. 

3.3 Two-Tier Intervention Module 

The execution health of a coding agent manifests across distinct severity levels during task execution. A minor issue, such as an occasional tool misuse, often does not lead to task failure, since the agent can self-correct in the subsequent step based on environment feedback. In contrast, a severe mistake, such as repeatedly failing the same attempt, can significantly damage the execution workflow and lead to task failure. Therefore, a uniform intervention policy struggles to handle both. To address this trade-off, Cadence adaptively determines how to intervene according to execution health. Instead of relying on rigid, hard-coded rules, Cadence leverages LLM-based semantic reasoning to evaluate execution health and dynamically select intervention level, applying advisory guidance for satisfactory health and replacement actions for compromised health. At each inspection, the module first invokes LLMs to evaluate the trajectory segment since the last inspection point, assign an appropriate intervention level and generate corresponding guidance text. Figure 4 illustrates the prompt used for this. Rather than using rigid and specific error patterns, we characterize execution health at a high conceptual level. Specifically, satisfactory execution health indicates that the coding agent is making steady progress toward resolving the issue, despite possible minor lapses in localized steps; compromised execution health signifies that the agent has drifted from the task goal, manifested by a persistent lack of progress or repeated failure modes. We deliberately avoid defining health through specific error types because different agents possess varying capabilities to resolve identical errors. Adopting high-level conceptual definitions thus enables Cadence to generalize across different coding agents. Crucially, Cadence does not simply re-prompt a secondary LLM with the original failed problem. Instead, it uses task decomposition to reshape the problem representation [17, 32, 43]. Under a replacement intervention, Cadence discards the proposed step and injects the guidance into the context and prompts the agent to regenerate the step, preventing catastrophic failure modes from compounding. Finally, the chosen intervention level serves as an execution health signal, passed to the scheduling module. 

3.4 The Inspection Scheduler 

Cadence’s scheduler dynamically changes the inspection interval based on the intervention module’s feedback [15], as formalized in Algorithm 1. In the beginning, the module is configured with a base inspection interval 𝐼 𝑏𝑎𝑠𝑒 , a fixed growth step 𝛿 , and a maximum inspection interval 𝐼 𝑚𝑎𝑥 that prevents the interval from growing so large that inspections effectively stop. During execution, an inspection is triggered whenever the agent completes 𝐼 steps since the last check. The scheduler then updates the interval according to the observed intervention level. When the intervention level is advisory, it indicates that the agent’s execution health is stable and only requires light guidance. In this case, the module increases the inspection interval by the growth step, capped at the maximum interval (i.e., 𝐼 ← min (𝐼 + 𝛿, 𝐼 𝑚𝑎𝑥 )). When the intervention level is replacement, however, it indicates that the agent is misbehaving seriously during execution. The module then resets the inspection interval to the base value (i.e., 𝐼 ← 𝐼 𝑏𝑎𝑠𝑒 ), providing tighter supervision to guide the agent back on track. 4 Experimental Setup 

We evaluate Cadence by answering the following research questions (RQs): 

• RQ1: How effective and efficient is Cadence compared with existing runtime monitors? 

• RQ2: How robust is Cadence across different backbone models and scheduling parameters? 

• RQ3: How does each module contribute to the performance of Cadence? 

• RQ4: When does Cadence succeed, and when does it fall short? 

4.1 Datasets 

We conduct our experiments on SWE-bench Lite [16], a benchmark of 300 issues collected from popular open-source Python repositories on GitHub and widely used to evaluate coding agents. Each issue provides a task description, a base commit, and a set of tests. These tests fall into two groups. FAIL_TO_PASS tests fail on the base commit and should pass once the issue is resolved. PASS_TO_PASS tests already pass on the base commit and should remain passing afterwards. Given the task description, the coding agent runs on the repository at the base commit and produces a patch. An issue is resolved only if all tests in both groups pass after applying the patch, indicating it fixes the issue without introducing regressions [10, 27]. 

4.2 Evaluation Subjects 

4.2.1 Monitoring Baselines. We compare Cadence against three monitoring baselines covering both periodic guidance and rule-based guidance described in Section 1. 

Fixed-Interval ( 𝑘 ) represents periodic guidance. Every fixed 𝑘 steps, it pauses the coding agent, invokes an LLM to inspect the recent trajectory, and appends the resulting guidance into the coding agent’s context. This design is a synchronous version of Wink [22]. Original Wink [22] allows the coding agent to continue executing while it generates guidance in the background. Once finished, Wink appends the guidance to the current context. Because guidance generation speed and coding agent execution speed vary with LLM delays, this asynchronous design causes the guidance to be Cadence: Strategic Guidance for Coding Agents 9

injected at unpredictable execution steps. We adopt a synchronous design to eliminate LLM latency as a confounding variable, ensuring a fair evaluation of intervention timing. 

LivePlan [20] represents rule-based guidance. It maps coding agent actions into predefined workflow phases and tracks state transitions using an execution graph. When predefined rules detect state anomalies, such as phase stalling or action loops, an LLM is prompted to generate targeted guidance. Depending on anomaly severity, LivePlan either blocks the erroneous step to force a regeneration with guidance, or simply appends guidance to context for subsequent steps. 

Static Rule-Based represents another rule-based guidance. It uses the same heuristics as LivePlan but does not call an LLM. Instead, each rule has a fixed guidance message written in advance, which the monitor returns whenever that rule fires. This baseline shows how well the coding agent performs with general guidance that is not tailored to its current situation. Additionally, we include Vanilla , the standalone agent without monitoring, as a control baseline to quantify the net benefits brought by monitoring. 

4.2.2 Working Agents. To examine whether monitors generalize across coding agent scaffolds, we evaluate the monitors on two representative coding agents that manage actions differently. 

mini-swe-agent [35] exposes only the bash command to the model. Every operation, such as reading files and editing code, is written as a shell command. Each command runs in a new subshell, so changes to the working directory or to environment variables do not carry over to later steps. The agent submits its solution by producing a git diff of the files. 

Moatless [1] instead exposes a set of 11 structured tools that cover search, file reading, editing, test execution, and task completion. Before the run, Moatless builds a vector index of the repository with a code embedding model. The agent can then call SemanticSearch to locate relevant code with a natural language query, instead of relying on exact text matching. In the end, Moatless invokes either VerifiedFinish to submit the patch, or Reject to report that the issue cannot be resolved. 

4.3 Evaluation Metrics 

We evaluate Cadence and the baselines along two dimensions, effectiveness and efficiency. To evaluate effectiveness , we report Resolve Rate , which is the standard metric used by SWE-bench Lite. It is defined as the percentage of tasks resolved, elaborated in Section 4.1. To measure efficiency , we report two key metrics. Tokens per Task denotes the average token count per task consumed by both the working agent and the monitor. Token Leverage captures overall token-efficiency, defined as the number of resolved tasks per million total tokens consumed. Additionally, for monitors using LLMs, we report Invocations per Task as the average number of monitor LLM calls per task. 

4.4 Environment and Implementation 

We conduct all experiments in isolated Modal sandboxes based on SWE-bench’s official prebuilt task images, following the default step limits established in prior studies (150 for mini-swe-agent and 50 for Moatless) [1, 35]. Unless otherwise specified, Cadence uses a base interval of 5, a growth step of 2, and a maximum interval of 20 (i.e., reference setting). To run the baselines on both agents, we make two adaptations for Moatless. The existing heuristic rules target mini-swe-agent only, so we construct a corresponding set of rules for Moatless that follow the same scope. These new rules are used by both Static Rule-Based and LivePlan. 5.3.2 Ablation of the Two-Tier Intervention Module. To evaluate the contribution of the two-tier intervention module, we construct two ablation variants that enforce a fixed intervention strategy for all inspections, using either always advisory or always replacement level actions. The monitor’s original tier recommendation is retained solely by the scheduling module to update the inspection interval accordingly. As shown in Table 4, resolve rates drop for both the always-advisory and always-replacement variants (by 7.33% and 4.33%, respectively) compared to the full Cadence, demonstrating that a single intervention strategy cannot adequately handle all execution states. 6 Threats to Validity 

Internal Threat. Internal threats to validity mainly involve three aspects. First, to mitigate the randomness inherent in LLMs, we set the generation temperature to 0 whenever supported while leaving other settings at their defaults, and perform statistical significance testing on the main results. Second, to guarantee fair baseline comparisons, we utilize the official public implementations when available or re-implement the methods strictly following their original papers. Third, manual annotations during qualitative categorizations may introduce human subjectivity. To mitigate this threat, all trajectory misbehaviors and failure categories are determined by two annotators, with all discrepancies resolved through discussion. 

External Threat. External threats to validity mainly involve two aspects. First, our evaluation focuses on bug fixing and feature implementation tasks in Python, whereas coding agents can also handle other kinds of tasks, such as test generation, and tasks in other programming languages. In the future, we plan to evaluate CADENCE on additional benchmarks, such as SWT-bench [21] and SWE-bench Pro [6], to further assess its generalizability. Second, there is a potential threat regarding whether the underlying LLMs were exposed to the evaluation tasks during training. Since all evaluated monitors share the same LLM backbones, any data contamination affects them comparably, ensuring that the relative performance gaps remain valid. 

7 Related Work 

Existing methods for enhancing coding agents primarily fall into two categories: offline learning and online monitoring. In the following, we review related works under both categories. 

7.1 Offline Learning 

Offline learning relies on historical execution records to enhance coding agents, primarily through model post-training or prompt-based experience reuse. Wei et al. [33] pioneered the use of rein-forcement learning in coding agents by introducing SWE-RL, which fine-tunes the backbone model using rewards based on similarity to ground-truth patches. In addition, SWE-GYM [24] leverages powerful LLMs to perform coding tasks and uses the generated trajectories to train smaller models via imitation learning. For experience reuse in prompts, Wang et al. [31] proposed Agent Workflow Memory, which extracts common workflows from past trajectories and integrates them into system prompts. Chen et al. [2] introduced SWE-Exp, which distills experiences from both successful and failed trajectories into a knowledge base and retrieves those relevant to a new task. However, these offline methods cannot handle runtime misbehaviors interactively; online monitoring fills this gap by providing real-time guidance during execution. 18 Minxing Wang, He Ye, Earl T. Barr, and Yintong Huo 

7.2 Online Monitoring 

Online monitoring inspects runtime execution trajectories and delivers guidance upon detecting misbehaviors. Existing approaches fall into two categories based on their guidance triggering mechanisms: rule-based guidance and periodic guidance. 

7.2.1 Rule-based Guidance. Rule-based guidance predefines targeted misbehaviors and models spe-cific misbehavior patterns over the agent’s action space. A representative approach is LivePlan [20], which maps agent actions to predefined workflow phases to detect skipped or stalled execution phases. Additionally, LivePlan tracks execution trajectories using an action-graph representation to detect action loops. Upon matching patterns for severe misbehaviors, such as action loops or unauthorized phase skipping, LivePlan blocks the proposed action and invokes an LLM to generate guidance, prompting the agent to produce a new action. Conversely, for minor misbehaviors, it merely appends guidance to the trajectory upon the current step completion. Through heuristic-based inspection, LivePlan achieves fast and precise misbehavior detection via pattern matching. However, heuristic rules fail to detect complex reasoning errors that require natural language understanding. Moreover, because each agent possesses a distinct action space, LivePlan requires manual adjustments to its action-phase mappings when deployed on a new agent. 

7.2.2 Periodic Guidance. To detect broader categories of misbehaviors without requiring manual adaptation across different agents, recent approaches resort to LLM-based inspection. By exploiting the natural language understanding and domain knowledge of LLMs, such inspection can identify complex reasoning errors beyond the reach of heuristic rules. Furthermore, directly analyzing raw trajectory text independent of the agent’s action space provides better generalizability across diverse coding agents. To keep cost under control, such monitors typically invoke LLM-based inspection periodically. A representative approach is Wink [22]. It invokes an LLM to inspect the execution trajectory at fixed step intervals. To mitigate the latency associated with frequent LLM calls, it performs inspec-tions asynchronously, allowing the agent to continue execution without waiting for inspection results. Guidance is injected into the trajectory only when misbehavior is detected. Although this asynchronous design reduces runtime delays, a severe misbehavior may rapidly cascade into an unrecoverable failure while the agent continues executing before the inspection completes. More fundamentally, the inspection interval in Wink is statically predetermined and remains indiffer-ent to the agent’s real-time execution status. Consequently, a healthy agent and a misbehaving agent receive the same frequency of supervision, which represents a sub-optimal design choice as demonstrated by our motivating study (Section 2.1). 

8 Conclusion 

In this paper, we propose Cadence, a dynamic runtime monitor for coding agents that integrates a two-tier intervention module with an inspection scheduler. The intervention module provides advisory guidance when agent execution health remains satisfactory, while issuing replacement guidance when severe misbehaviors occur. Based on the resulting intervention level, the scheduler dynamically adjusts the inspection frequency, increasing supervision for replacement-level cases and reducing it for advisory-level ones. Evaluation on 300 SWE-bench Lite tasks across two coding agents shows that Cadence achieves the highest resolve rate among all evaluated monitors while maintaining competitive token efficiency.
