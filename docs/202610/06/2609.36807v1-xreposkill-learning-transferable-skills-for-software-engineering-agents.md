## 摘要
软件工程智能体日益利用从既往经验中提炼出的可复用技能来解决仓库级问题，但此类技能往往难以跨仓库迁移。一个核心挑战在于，出现在成功轨迹中的行为未必对成功结果负责：它可能确实有用，也可能只是偶然出现，或者仅仅是模型的一种反复出现的习惯。我们提出 XRepoSkill，一种基于轨迹的学习可迁移技能方法。我们将技能表示为一组规则，每条规则规定在解决问题期间应采取什么动作以及何时采取该动作。XRepoSkill 首先对比同一智能体在同一问题上的成功轨迹与失败轨迹，并从二者执行路径发生分歧之处推导候选规则。每条规则都配有一个可执行谓词，使其规定的行为能够在其他轨迹上被系统评估。规则根据其与成功解决问题的关联进行验证，仅当其规定的行为在多个仓库中反复出现时才被保留；随后，同一行为在不同仓库中的特定变体会被整合为可迁移规则。对于新问题，XRepoSkill 选择相关规则来指导智能体。我们从官方 SWE-bench Verified 排行榜上公开的轨迹中学习技能，并使用来自不同厂商的三个骨干 LLM，在 SWE-bench Pro 和 DeepSWE 上进行评估；评估仓库均未出现在技能学习轨迹池中。与近期三种技能学习方法相比，XRepoSkill 在所有六种基准—LLM 组合中均取得最高的问题解决率。特别是在具有挑战性的长时程 DeepSWE 基准上，XRepoSkill 相比没有学习技能的同一智能体将问题解决率提升了 10.3 个百分点，相比最强的技能学习基线提升了 5.0 个百分点。

## Abstract
Software engineering agents increasingly use reusable skills distilled from prior experience to resolve repository-level issues, yet such skills often fail to transfer across repositories. A central challenge is that a behavior appearing in a successful trajectory is not necessarily responsible for the successful outcome: it may be genuinely useful, merely incidental, or simply a recurring habit of the model. We introduce XRepoSkill, a trajectory-based approach for learning transferable skills. We represent a skill as a collection of rules, each specifying what action to take and when to take it during issue resolution. XRepoSkill first contrasts successful and failed trajectories of the same agent on the same issue and derives candidate rules from where their execution paths diverge. Each rule is paired with an executable predicate that enables its prescribed behavior to be evaluated systematically on other trajectories. A rule is verified based on its association with successful issue resolution and retained only when its prescribed behavior recurs across multiple repositories; repository-specific variants of the same behavior are then consolidated into transferable rules. For a new issue, XRepoSkill selects relevant rules to guide the agent. We learn skills from publicly released trajectories on the official SWE-bench Verified leaderboard and evaluate them on SWE-bench Pro and DeepSWE using three backbone LLMs from different vendors; none of the evaluation repositories appears in the skill-learning trajectory pool. Against three recent skill learning methods, XRepoSkill achieves the highest issue resolution rate in all six benchmark--LLM combinations. In particular, on the challenging long-horizon DeepSWE benchmark, XRepoSkill improves issue resolution by 10.3 percentage points over the same agent without learned skills and by 5.0 points over the strongest skill-learning baseline.

## 1. 核心问题与研究动机

- **背景**：软件工程智能体（如 SWE-agent、mini-SWE-agent）通过探索仓库、改代码、跑测试来生成补丁解决仓库级 issue。一种流行做法是在推理时加载"技能"（skill）——打包的任务知识，从而不重训练骨干 LLM 就赋予其可复用经验。
- **核心问题**：软件工程技能**未必能跨仓库迁移**。已有工作（Han et al., 2026）表明多数公开技能在真实仓库上几乎没有增益，甚至可能损害性能。
- **更深的难点**：从轨迹中学习技能时，"出现在成功轨迹中的行为"不等于"导致成功的行为"。该行为可能（a）确实有用，（b）只是偶然伴随，（c）仅仅是骨干 LLM 的固有习惯。此外，即便行为有用，也可能绑定于特定仓库的约定或工作流而无法迁移。
- **研究问题**：如何从历史轨迹中判定哪些行为构成**真正可复用**的软件工程知识，并在未见过的仓库上依然有效。

## 2. 方法论

### 2.1 核心思想

- 把技能表示为一组**规则**，每条规则同时规定"做什么动作"（what）与"何时做"（when）。
- 关键设计：**把"发现潜在有用行为"与"经验验证该行为"分离**——发现阶段只产生假设，验证阶段用独立轨迹证据决定是否保留。
- 学习目标：给定智能体 A 与轨迹池 T（含成功与失败轨迹），学出可迁移技能 S；对新 issue i⋆ 选择相关规则作为附加指导，且**不修改智能体本身**。

### 2.2 三阶段流程

**阶段一：分歧引导的规则发现（Divergence-Guided Rule Discovery）**

- **配对**：对同一 issue、同一智能体 A，配对"成功轨迹 vs 失败轨迹"（来自不同骨干 LLM，按 LLM 解决率差距排序取前 4 对）。由于 issue、仓库、智能体固定，两者共享的行为无法解释结果差异。
- **动作抽象**：不直接比较原始轨迹，而是把每次工具调用映射为"类型 + 目标"的抽象动作（read / search / edit / test run / script run / install / git / submission / other）。复合命令（`&&`、`;`）拆分，剥离 `cd`、环境变量、`timeout` 前缀。
- **分歧定位**：对齐两条动作序列，允许信息收集类动作顺序差异；遇到真正改变后续走向的不匹配动作（编辑、跑测试等）即终止共享前缀，其后第一个动作即**分歧点**。保留压缩后的共享前缀与两条后缀用于生成规则。
- **候选规则生成**：不逐步对齐后缀，而从三个互补参照点生成规则——① 结合成功补丁审视失败轨迹，找出失败方遗漏的信息；② 审视成功轨迹在首次编辑前做的信息收集与验证；③ 聚焦分歧点，问成功方做了什么而失败方没做。每对产出 3–5 条候选规则（JSON 格式：≤1000 字符段落、类别、引用的轨迹与命令位置、可执行谓词）。
- **拒收机制**：段落超长、含行号或过多罕见符号、谓词不可解析、谓词在轨迹池上真值率 <10% 或 >90% 的规则被拒（失败可重提示一次）。

**阶段二：规则验证与跨仓库泛化**

- **可执行谓词**：每条规则配一个定义在抽象动作上的可执行谓词（如 `before(run test, first edit)`），评估时**无需 LLM 调用**且确定性，把轨迹池划分为"满足/不满足"两组。
- **仓库内合并**：同仓库同类别的候选规则由 LLM 批量合并（每批合并为 3–10 条），并选出最能刻画共享行为的谓词。
- **仓库内验证（避免循环验证）**：比较满足与不满足谓词的轨迹的成功率，且**排除该规则来源的成功–失败配对**；比较在 **issue 内部进行**（而非跨 issue 汇总），以控制 issue 难度差异。
- **跨仓库泛化**：把每个谓词在全部轨迹上求值得到二值向量，用 **ϕ 相关**（而非原始一致率，以折扣"共同缺席"）度量相似性；用距离 `1−ϕ` + **complete linkage 凝聚聚类**分组，仅保留**至少两个仓库独立验证过**的簇；簇内规则由 LLM 改写为去仓库特定路径/符号的可迁移规则。单仓库支撑的簇被剔除。

**阶段三：问题自适应规则选择（Issue-Adaptive Rule Selection）**

- 用两次骨干 LLM 调用：① 输入截断至 6000 字符的 issue 描述 + 全部规则标题，输出 2–3 句 bug 摘要与所需指导类型；② 输入 issue、摘要、全部规则（含 id、标签、标题、正文，按 z 值排序），返回**至多 3 条**规则 id 及理由。
- 每条规则附带历史证据（gain 与 z 值）辅助选择；选择可为空。
- **技能引导求解**：把选中规则放在 mini-SWE-agent 首条用户消息中 issue 描述之前，并要求智能体对每一步都结合当前仓库代码进行核验；规则只作引导而非覆盖其推理。技能由 36 条可迁移规则组成，写成单个 Markdown 文件（按 z 值排序的 bullet，标签形如 `(gain +5.7pp, z +15.59)`）。

### 2.3 关键公式（文字说明）

- **解决增益（resolution gain）**：`gain = Σ_j w_j (a_j/n_1j − c_j/n_0j) / Σ_j w_j`，其中 `n_1j`/`n_0j` 为 issue j 中满足/不满足谓词的轨迹数，`a_j`/`c_j` 为对应成功数，权重 `w_j = n_1j·n_0j /(n_1j+n_0j)`。这是**Mantel–Haenszel 分层率差估计量**；只有当 issue 的两组都非空时才提供证据。
- **z 值**：`z = gain / 标准误`（标准误用 Sato et al. 1989 的估计量），兼顾增益大小与证据量。gain 与 z **不作保留阈值**，仅用于阶段三选择。
- **跨仓库合并**：按逆方差加权 `ḡ = Σ(g_k/s_k²)/Σ(1/s_k²)`，`s̄ = (Σ 1/s_k²)^(−1/2)`，更精确的仓库估计获得更大权重（Cochran, 1954）；可迁移规则的支撑度为其合并规则支撑度之和。

  - **去掉跨仓库泛化（保留单仓库规则）**：同样造成退化，说明多数单仓库规则携带仓库特定约定，直接迁移会带来噪声甚至负迁移；
  - **提供全部规则（不做 issue 自适应选择）**：性能下降，表明"给得越多越好"不成立，过量或无关指导会稀释注意力、干扰推理；
  - **去掉证据信息（gain / z 值）**：选择质量变差，说明让选择器看到"该规则在历史上带来了多大增益、证据多强"对挑选真正相关的少数规则有帮助。
- **附录 C 的规则选择分析**：在 939 个（issue × 骨干 LLM）组合的选择日志中，36 条可迁移规则里只有 **19 条**被实际选中过，选择率高度不均——少数规则被频繁调用且对应增益为正，另一些则几乎从未被选中，说明规则库内部存在明显的"效用长尾"，也为后续精简技能库提供了依据。

## 7. 局限与作者提示的注意事项

- **样本规模与统计功效**：部分语言子集极小（SWE-bench Pro 的 TS 仅 6 个、DeepSWE 的 JS 与 Rust 各 5 个），作者明确声明这些子集的结论需谨慎解读，不能作为强证据。
- **单次采样为主**：除 RQ3 外，主结果中每个 issue 只运行一次，未在主表中量化单次采样方差；因此小幅度差距（如 1–2pp）在统计上未必稳健。
- **稳定性与消融的外推范围有限**：RQ3、RQ4 只在 DeepSWE + DeepSeek 这一组合上完成，能否推广到其他骨干 LLM 与基准尚待验证。
- **技能学习依赖轨迹池质量与规模**：需要同一 issue 上同时存在成功与失败轨迹（且最好来自不同骨干 LLM）才能做分歧配对；对于缺少这类对照的领域，方法适用性受限。
- **谓词表达力**：规则以"抽象动作上的可执行谓词"承载，虽然保证了确定性、零 LLM 开销与可验证性，但也意味着只能刻画可用动作序列表达的规律，难以涵盖需要语义理解或跨文件推理的软性经验。
- **评测环境差异**：为防泄漏，SWE-bench Pro 容器被加固（删 `.git`、断网），因此其绝对数值与官方排行榜不可直接比较，只能在同一容器内做方法间比较。

## 8. 总体评价与启发

- **核心贡献定位**：这篇工作把"技能学习"重新表述为一个**因果识别 + 统计验证**问题，而不是单纯的"从成功轨迹中抽取经验"。其最有价值的设计是**发现与验证的解耦**——发现阶段允许 LLM 自由假设，验证阶段用确定性谓词 + 分层率差估计量 + 跨仓库聚类来把关，从而系统性压制"共现 ≠ 因果""有用 ≠ 可迁移"这两类典型错误。
- **工程上的可复用性**：整套流程只做推理与技能构建，不训练骨干模型，技能最终落为一个可读的 Markdown 文件，成本增量很小（SWE-bench Pro 上约 +$0.02/issue，DeepSWE 上约 +$0.03/issue），对实际部署友好。
- **实证上的亮点**：在全部 6 个基准–LLM 组合上取得最佳解决率，且**越难的基准增益越大**（DeepSWE +10.3pp vs SWE-bench Pro +6.0pp）；从纯 Python 轨迹学到的技能在 Go/JS/TS/Rust 上优势更明显，是对"可迁移知识确实被学到"的有力证据。
- **值得进一步追问的方向**：(1) 19/36 的规则使用率提示技能库可以进一步压缩，是否存在更优的"最小充分技能集"；(2) 谓词语言若能引入更丰富的时序/语义条件，是否可覆盖当前遗漏的软性经验；(3) 在缺少失败轨迹对照的场景下，如何获得等价的分歧信号；(4) 稳定性增益（方差下降）的机制值得单独研究——是规则减少了无效探索步数，还是仅仅提供了更一致的先验。
