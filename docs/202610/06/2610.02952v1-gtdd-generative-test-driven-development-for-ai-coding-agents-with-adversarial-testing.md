## 摘要
测试驱动开发为 AI 编码智能体提供了用于实现软件的可执行需求。由于这些智能体能够根据其观察到的示例调整实现，通过一组预先确定的测试可能仍会使预期行为的很大部分未被实现。我们提出生成式测试驱动开发（GTDD），这是测试驱动开发的一种形式：其中单独的测试智能体在每次候选实现固定之后生成新输入，并利用人工指定的行为契约以及前几轮的反馈。可信评估器会检查这些输入，将化简后的反例返回给编码智能体，并将其保存用于回归测试，从而使开发过程持续面对初始示例之外的失败。我们通过自适应候选选择下错误接受的有限总体分析，刻画了这一过程所提供的证据。由此得到的界限量化了测试可见性和重复反馈如何影响接受，并表明在候选方案确定后进行的全新随机审计能够控制跨开发轮次的错误接受。在一项针对有状态键值存储的配对实验中，两种在开发过程中重新生成测试的策略最终的平均失败率均低于由同一语言模型一次性生成测试的策略，而将候选实现的源代码提供给测试器并未产生可检测的额外改进。进一步要求测试数量相等的条件，也未能将策略的任何单一特征分离为该差异的来源。GTDD 将这种自适应开发反馈与既有的回归测试以及独立的接受规则相结合。

## Abstract
Test-driven development gives AI coding agents executable requirements for implementing software. Because these agents can adapt their implementations to the examples they observe, passing a predetermined collection of tests can leave substantial parts of the intended behavior unimplemented. We propose Generative Test-Driven Development (GTDD), a formulation of test-driven development in which a separate testing agent generates new inputs after each candidate implementation is fixed, using a human-specified behavioral contract and the feedback from earlier rounds. A trusted evaluator checks these inputs, returns reduced counterexamples to the coding agent, and saves them for regression testing, so development continually confronts failures beyond the initial examples. We characterize the evidence that this process provides through a finite-population analysis of false acceptance under adaptive candidate selection. The resulting bounds quantify how test visibility and repeated feedback affect acceptance, and show that fresh random audits after candidate commitment control false acceptance across development rounds. In a paired experiment on a stateful key-value store, both policies that regenerated tests during development ended with lower mean failure rates than the policy whose tests were generated once by the same language model, and giving the tester the candidate's source produced no detectable additional improvement. Further conditions requesting equal numbers of tests did not isolate any single feature of the policies as the source of this difference. GTDD combines this adaptive development feedback with established regression tests and an independent acceptance rule.

## 1. 核心问题与整体含义（研究动机与背景）

- **根本矛盾**：测试驱动开发（TDD）为 AI 编码智能体提供可执行需求（Beck, 2002），但 LLM 编码智能体能够根据观察到的示例调整实现。一组预先确定（固定）的测试集被"适应"后，可能仍有大量预期行为未被实现。
- **反馈的双刃性**：指导开发的同一反馈，也让智能体可以只实现被测试到的样例、对输入做特判，甚至在更宽权限下尝试篡改测试（test subversion，Baker et al., 2025）。这是"优化观察目标 ≠ 满足真实意图"的一般性问题（Amodei et al., 2016; Skalse et al., 2022）。
- **现有工作的定位**：
  - CodeT（用生成测试选候选）、AlphaCodium（迭代修复）、AgentCoder（分离编程/测试设计/测试执行）、Claude Code 的双会话工作流、Krawczyk（2023）基于历史输入–输出对的生成式 TDD，都把测试纳入了开发过程本身。
  - 但这些工作大多没有明确区分：**开发反馈的证据** 与 **验收决策的证据**。
- **GTDD 的整体含义**：把"候选提交（commitment）、测试信息、反例反馈、验收规则"组织进同一个开发流程。增加测试数量与"开发中重新生成测试"解决的是问题的不同侧面；框架必须同时规定（i）新失败如何到达编码器，（ii）什么证据足以接受最终实现。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想

- 人类指定：**行为契约、输入 schema、测试预算**。
- **独立的测试智能体**：在编码智能体提交（commit）每个候选实现之后，才生成新的具体测试输入；使用契约与之前轮次的反馈（反例历史）。
- **可信评估器**：从可信参考实现获取期望响应，校验提案，返回受控数量的**缩减反例（reduced counterexamples）** 给编码智能体，并把生成用例与缩减结果保存为回归测试。
- **独立随机审计（fresh audit）**：在候选提交后采样，用于验收决策；审计用例与结果对编码/测试智能体均不可见。
- 关键区分：**对抗性测试只塑造开发反馈，不构成验收证据**；验收证据来自候选固定后的独立采样。

### 2.2 轮协议（Round Protocol）

单轮事件顺序（论文式 (24)）：

```
编码结束 < 候选提交 < 测试开始 < 测试结束
< 审计采样 < 审计结束 < 验收记录 < 总体评估结束
```

- 编码会话编辑仓库 → 恢复被修改的保护文件 → 对候选及执行配置（依赖版本、执行镜像、资源策略）做规范化清单哈希，得到承诺 $C_t$。
- 测试策略分：
  - **source-informed**：可读已提交候选的只读副本；
  - **source-blind**：不读源码。
  - 两者都看不到审计用例、family 审计结果、总体评估结果。
- 评估器对参考实现与候选同时执行每条有效非重复提案；失败时先找**最短失败前缀**，再逐操作删除，同时保持有效性与"指定差异"；最多返回 $k$ 个缩减失败；通过的生成输入进入回归测试集。
- 反馈历史 $\tau_{t-1}=(E_1,\dots,E_{t-1})$；回归测试累积 $G_t = G_{t-1}\cup V_t\cup E_t$，$G_0=\varnothing$。
- 开发条件（策略）：public-only / 固定测试 / 每轮重新生成；可见或隐藏；测试器是否读源码；反馈选择规则分 **standard**（优先 family 与失败机制多样性）与 **compact-failure**（优先短 trace、少操作种类）。

### 2.3 理论分析（核心公式与结论）

固定一个 issue 的一个 requirement family，总体 $U=\{z_1,\dots,z_N\}$，容差 $\rho$，候选损失 $\ell(f;z)\in\{0,1\}$，family 风险 $R(f)=\frac1N\sum_i \ell(f;z_i)$。

- **命题 4.1（精确接受概率）**：固定候选、无放回均匀样本 $S$（大小 $n$）：
  $$\Pr(f\text{ passes }S)=\frac{\binom{N-K(f)}{n}}{\binom{N}{n}}\le\left(1-\frac{K(f)}{N}\right)^n$$
  定义 $K_\rho=\lfloor\rho N\rfloor+1$，则 $R(f)>\rho$ 时接受概率 $\le q_{N,\rho}(n)\le(1-\rho)^n$。
- **命题 4.2**：允许样本中至多 $c$ 个失败时，用超几何下尾给出接受概率，且对 $K(f)$ 单调不增。
- **命题 4.3–4.4（已知测试的适应）**：在 unrestricted casewise 类中，已知测试大小 $n$ 时最大可接受风险为 $1-n/N$；一致保证需 $n\ge N-\lfloor\rho N\rfloor$（$N=500,\rho=0.05$ → **475** 条）。
- **定理 4.5（重复反馈的充分界）**：对隐藏固定测试集，按 Dwork et al. (2015a) 描述长度论证计数反馈历史：
  $$\Pr(\exists t: f_t\text{ passes }S, R(f_t)>\rho)\le\min\left\{1,\;q_{N,\rho}(n)\,\mathbb{E}\!\left[\sum_t|\mathcal{T}_{t-1}(\xi)|\right]\right\}$$
  指数充分条件给出式 (14)（例：$N=500,k=6,T=4,\rho=\alpha=0.05$ → 2,308 条）。
- **定理 4.6 + 推论 4.7（自适应探测下界）**：用 $r=T-1$ 个不相交区域，构造显式策略使最终候选以高于 $\rho$ 的风险被接受；给出阈值 $n^*$（$N=500,k=6,T=4,\rho=0.05$ → $n^*\approx104.65$）。
- **命题 4.8（均匀生成）**：每轮提交后均匀采样 $m$ 条，若要求累积回归测试通过，则 $\Pr(\text{假接受})\le T\,q_{N,\rho}(m)$。
- **命题 4.9（候选相关测试选择）**：若无分布关系，$\mathbb{E}_{Z\sim Q_f}[\ell(f;Z)]$ 不能识别 $R(f)$；需要覆盖条件（如 $Q_f(z)\ge\kappa/N$）才能推出 $\kappa R(f)$。
- **定理 4.10 / 4.12 / 4.14**：
  - family 同时结论：$\Pr(\bigcup B_{a,t,j})\le\mathbb{E}[\sum q_{N_{a,j},\rho_{a,t,j}}(n_{a,t,j})]$；
  - **完整仓库接受**（所有 family 审计都通过）把求和换成 $\max_j$，样本量更小；
  - **无界时域**：选择可和错误分配 $\sum_{a,t}\varepsilon_{a,t}\le\alpha$，则任意自适应候选选择与停止下假接受概率 $\le\alpha$。
- **定理 4.15**：跨不同候选的 e-process $Z_t=\prod_s A_s/q_{N,\rho}(n_s)$，在"每个候选都坏"的零假设下是非负超鞅；但拒绝该假设的证据可能来自序列中更早的候选，不能转移到当前候选。GTDD 因此把证据分配给**当前被接受的候选**（定理 4.14）。
- **表 1 比较**（共同时域 $T$、单 family，$Q(n)=q_{N,\rho}(n)$）：
  | 测试选择 | 充分规模条件 | 每轮新用例 |
