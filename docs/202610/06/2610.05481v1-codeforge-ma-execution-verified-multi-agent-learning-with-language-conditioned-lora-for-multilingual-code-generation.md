## 摘要
用于代码生成的大语言模型常常在执行、多语言覆盖和污染控制方面表现不佳，尤其是在冻结主干网络的约束下。我们提出 CodeForge-MA，一个统一框架，通过多智能体数据锻造、执行验证的强化指令微调以及语言条件化的 LoRA 适配器混合来改进代码合成。四个专用智能体——Composer、Reviewer、Executor 和 Curator——迭代地精炼指令-代码对，用测试验证它们，并过滤重复项和基准泄漏。在训练期间，我们将掩码监督微调与测试驱动的强化目标相结合，以使生成结果与可执行正确性对齐。对于更大的模型，我们在低秩适配器上使用稀疏专家路由，以改善跨语言迁移，同时在推理时保持基础模型不变。实验表明，联合的数据、目标和适配器设计在多种编程语言上带来了稳健的增益。

## Abstract
Large language models for code generation often fail on execution, multilingual coverage, and contamination control, especially under frozen backbone constraints. We present CodeForge-MA, a unified framework that improves code synthesis through a multi-agent data forge, execution verified reinforced instruction tuning, and a language conditioned mixture of LoRA adapters. Four specialized agents, Composer, Reviewer, Executor, and Curator, iteratively refine instruction code pairs, validate them with tests, and filter duplicates and benchmark leakage. During training, we combine masked supervised fine tuning with a test driven reinforcement objective to align generations with executable correctness. For the larger model, we use sparse expert routing over low rank adapters to improve cross language transfer while keeping the base model unchanged at inference. Experiments show that joint data, objective, and adapter design yields robust gains across programming languages.

## 2. 方法论
### 2.1 总体思想
- 在冻结的 Qwen-1.8B / Qwen-72B 上，从三方面改进：
  1. **数据侧**：多智能体闭环生成、评审、执行验证、去重去污染。
  2. **目标侧**：掩码监督微调 + 基于单元测试通过率的 PPO 式强化学习。
  3. **适配器侧**：语言条件化的 LoRA 稀疏专家混合，减少跨语言干扰。

### 2.2 多智能体数据锻造
- 四个智能体：
  - **Composer**：根据种子生成指令-代码对。
  - **Reviewer**：评估风格、正确性、教学价值。
  - **Executor**：在沙箱中编译并运行代码。
  - **Curator**：全局去重与基准污染过滤。
- 采用 Reflexion 式闭环：状态记为 `(X, Y, r, q, π)`，其中 `π` 表示执行是否通过；样本接受条件为：执行通过 `π=1`、质量分 `q ≥ 0.75`、修订次数 `k ≤ 3`。
- Reviewer 使用自一致性：采样 `M=5` 次取平均分，以降低单个 LLM 评审噪声。
- 语言平衡：按温度 `α=0.3` 对六种语言采样，缓解 Python 过度占比，覆盖 Python、JavaScript、Java、Go、C++、Rust。
- 去重去污染：用 MinHash LSH 近似 Jaccard 相似度，阈值 `J > 0.8` 时丢弃，并对 HumanEval、HumanEvalFix、MBPP 做泄漏过滤。

### 2.3 执行验证强化指令微调（EV-RIT）
- **监督损失**：只在 assistant 回复段计算掩码交叉熵，避免模型只复述 docstring 或用户提示。
- **强化目标**：对采样代码 `Y_hat`，奖励 `R` 为单元测试通过比例；用 PPO 式裁剪代理目标优化，并加入 KL 惩罚 `β_KL=0.02` 防止奖励攻击。
- **训练调度**：先进行监督微调，在 `T0=500` 步后才激活 RL，并在 `TW=1000` 步内将权重 `λ_t` 提升到 `λ_max=0.3`。
- 总损失为 `L_SFT + λ_t L_RL`，并按语言逆频率加权，缓解语言不均衡。

### 2.4 语言条件 LoRA 专家混合（LC-MoLoRA）
- 针对 72B 规模，在注意力投影 `W_Q, W_K, W_V, W_O` 上加入 `E=6` 个低秩专家，秩 `r=32`、缩放 `α=64`。
- 路由器基于 prompt 的均值池化表示，采用 **top-2 稀疏门控**，每个 prompt 只激活两个专家。
- 加入 Switch 风格负载均衡损失，防止专家坍塌；加入软语言身份先验，鼓励专家与语言相关
