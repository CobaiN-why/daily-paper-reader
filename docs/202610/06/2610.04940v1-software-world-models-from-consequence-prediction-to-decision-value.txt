## ABSTRACT 

A coding agent may safely modify one repository while silently breaking down-stream services, libraries, or datastores that depend on it. Exhaustively running integration tests after every agent action is impractical, so the agent must pre-dict these failures before executing them. Existing software world models predict the agent’s own observations, while static change-impact analysis only identifies where a change may propagate. We instead introduce the Software World Model 

(SWM), which models the broader system affected by a code change and pre-dicts its blast set : the components that the change will break. SWM follows three stages: explore, learn, and act. Explore executes candidate changes from restored system states, prioritizing regions where observed failures contradict the dependency graph. Learn fine-tunes a language model on these execution out-comes to predict downstream breakage. Act converts sampled predictions into per-consumer break probabilities for change ranking, proactive migration, and de-ciding when another execution is worth its cost. On held-out synthetic systems, SWM improves blast-set F1 from 0.431 for static reachability to 0.571 ± 0.037 ,more than halves ranking regret, and improves migration return at all nine evalu-ation checkpoints. The two methods are complementary: reachability is stronger on dependencies represented in the graph, while SWM recovers failures caused by couplings the graph misses. Experiments on held-out real libraries further show that predicting structured failure outcomes, rather than only scalar risk, is impor-tant for downstream decision quality. 

## 1 INTRODUCTION 

A real software system comprises interdependent repositories, services, libraries, and datastores. These components are coupled through APIs, schemas, shared data, and configuration. A coding agent, however, typically works inside one repository and verifies its changes with that repository’s tests (Jimenez et al., 2024; Yang et al., 2024; Wang et al., 2025). A change can therefore be locally correct while silently breaking a downstream consumer , a component that depends on the changed interface. Every local check can pass while that consumer fails when the system runs. Before landing a change, the agent needs to anticipate its blast set , the components that the change breaks. Executing every potentially affected component would reveal the blast set, but does not scale (Memon et al., 2017; Machalica et al., 2019). Classical change-impact analysis instead identi-fies what a change may affect from an extracted dependency graph (Bohner & Arnold, 1996; Rother-mel & Harrold, 1997), but not whether a particular consumer actually breaks. Our static baseline, typed reachability (reachability below), marks consumers connected to the changed interface by de-pendency paths. It cannot distinguish a consumer that tolerates a change from one that does not, and misses failures through couplings the extractor did not recover. We call couplings missing from the extracted graph hidden channels . A silent break is a downstream failure missed by repository tests. More fundamentally, any predictor computed from the extracted graph and change alone carries an error floor given by variation in outcomes among systems sharing that observation (Remark 1).

Existing software world models address the complementary problem: they learn what the agent it-self will observe. CWM learns from execution traces and agent interactions (Copet et al., 2025), SWE-World predicts execution and test feedback (Sun et al., 2026), and Qwen-AgentWorld predicts tool-call observations across agent domains (Zuo et al., 2026). Their state is the agent-visible envi-ronment, their action is a tool invocation, and their target is the returned observation. For a locally consistent change, however, that observation can be correct while a downstream service outside the workspace breaks. We instead model the software system the agent changes , rather than only the environment it observes. This shift raises three coupled challenges. Experience : downstream consequences are revealed only by executing affected components, and ordinary agent trajectories observe only one change from each state. Representation : consequences depend on both what the change does and how other components use the changed interface, under incomplete structural observability. Decision use :the learned knowledge must improve the agent’s decision before the costly execution that would otherwise reveal the failure. We introduce the Software World Model (SWM), a learned consequence predictor, and an Explore, Learn, Act framework to build and use it (Figure 1). Explore executes counterfactual changes from restored software states to collect their downstream consequences, concentrating limited execution on informative interventions. Learn trains the coding model on these executed consequences, using the proposed change and typed software relations to learn change-conditioned system dynamics. 

Act returns this learned world knowledge to the same coding agent before future changes, allowing it to anticipate affected consumers rather than discover them only after execution. The learned consequences are reused for later decisions (Section 3). Different exploration policies produce different training experience, with targeted exploration most useful at small budgets. Training on executed consequences improves the same coding agent under a fixed inference interface: it identifies more affected consumers and ships fewer downstream failures on held-out software worlds. Further analysis shows that explicit structure and learned dynamics are complementary. Reachability is strongest on recorded dependency channels, while learned experi-ence helps where structure is incomplete. Downstream decision value also depends on which errors a world model makes, not forecast accuracy alone (Section 4). Our contributions are: • Software world modeling. We formulate system-level consequence prediction for coding agents and characterize why partial software structure alone cannot determine downstream behavior (Re-mark 1). • Explore, Learn, Act. We introduce a framework that actively collects counterfactual software experience, trains SWM on change-conditioned consequences, and uses the learned dynamics to improve the agent’s decisions before execution (Section 3). 2Preprint • Agent improvement. We show that learning from executed consequences improves the same coding agent on held-out software worlds, and analyze how exploration, observability, and model errors determine downstream decision value (Section 4). 

## 2 PROBLEM FORMULATION 

2.1 THE SOFTWARE WORLD 

A software world is an executable system with checks and available actions. Its environment E

evolves a true state st = ( G⋆t , x t). Here G⋆t is the true System-Surface Graph, a typed, directed multigraph G = ( V, E, ρ, ω ) with nodes V , edges E, and two layers. The system layer holds com-ponents and shared resources; the surface layer holds their interfaces, such as endpoints, symbols, and schemas. The map ω assigns each surface node its owner, and ρ : E → R labels each edge with its dependency channel, the kind of coupling it represents (Appendix D.3). ## 3 EXPLORE , L EARN , A CT : T HE SWM F RAMEWORK 

To address these challenges, we propose an Explore, Learn, Act framework that builds and uses SWM (Figure 1; Algorithm 1). For the experience challenge, Explore executes counterfactual changes from restored training states, concentrating limited execution on informative downstream consequences (Section 3.1). For the representation challenge, Learn trains a consequence predictor that combines each change with typed dependencies and observed health to anticipate system-wide effects (Section 3.2). For decision use, Act brings these learned consequences back to the coding agent to guide candidate selection, preventive migration, and additional checking before a change is committed (Section 3.3). Explore and Learn run offline; their executed experience supports later agent decisions. The primary study uses the trained weights directly as the agent (Section 4.1); the decision rules below separately test how sampled predictions guide action. 3.1 EXPLORE : BRANCH FROM RESTORED STATES WHERE REACHABILITY FAILS

## 4 EXPERIMENTS 

4.1 EXPERIMENTAL SETUP 

Models and comparisons. All backbones in the main agent comparison have 3B parameters. We compare the base Qwen2.5-Coder-Instruct agent, its consequence-trained SWM counterpart, and our CWM and Qwen-AgentWorld implementations on synthetic worlds and held-out real libraries. Baseline adaptation is described in Appendix D.6. The synthetic ablations hold the base checkpoint, training recipe, and acting interface fixed while varying the training corpus. Random samples eli-gible targets; Coverage cycles through change types; Expert uses true-graph consumer information; Decision-aware combines uncertainty, disagreement with reachability, and novelty. 

Matched synthetic evaluation. A training record pairs one executed change with its conse-quences. Each 360-record corpus has three training seeds. Random and decision-aware exploration also use 100- and 200-record budgets. These 24 trained arms and the base checkpoint run on the same 40 tasks from seven held-out worlds, yielding 1,000 episodes. Each agent first lists candidate consumers for a fixed change, then selects consumers to migrate. Decoding is greedy, and execu-tion accounting is identical. The trained checkpoint acts directly, without external predictions or additional policy fine-tuning. 

Metrics and uncertainty. Return is J = 1 − 0.25 nbroken − 0.05( nfixes + 1) : the counts are services left broken and preventive migrations, and the extra action ships the change. Candidate recall is the fraction of truly affected consumers in the first call’s list. The main table reports means; standard deviations are retained in Table 5. Synthetic ablations average three seeds within each task and bootstrap paired return differences by world, using 10,000 resamples. These intervals apply to the synthetic ablations, not the real-library comparison. Full task accounting and seeds appear in Appendix A.2; implementation and metrics are in Appendix D.7. Structure and learned experience resolve complementary uncertainty. Reachability has higher F1 on direct propagation, while learned predictions recover more hidden-channel failures in both evaluated hidden-channel populations. This contrast supports combining explicit dependencies with executed experience to predict failures the graph misses (Appendix C.1). 

Prediction accuracy alone does not determine decision value. At matched blast-set F1, learned beliefs produce better migration plans than a noise-perturbed oracle, but incur higher ranking regret. Pairwise ranking accuracy also correlates more strongly with regret than aggregate set F1. The rever-sal shows why decision evaluation must account for where prediction errors occur (Appendix C.2). 

The value of prediction depends on the alternatives to execution. The main agent comparison favors SWM, but companion studies expose its boundaries. A supervised risk scorer has higher in-distribution forecast F1 and belief-plan return. Cheap checks of every consumer can also outperform the learned belief plan. These comparisons use different interfaces from the main agent evaluation. Their mixed outcomes bound the benefit by the available structure, execution cost, and decision rule (Appendix C.3). 

## 5 RELATED WORK 

Agent World Models. Learned world models let agents train inside or consult imagined fu-tures (Richens et al., 2025; Ha & Schmidhuber, 2018; LeCun et al., 2022; Hafner et al., 2025a;b; Gu et al., 2024; Chae et al., 2025). Software world models predict execution or tool feedback (Copet et al., 2025; Sun et al., 2026; Zuo et al., 2026; Guo et al., 2025; Zhang et al., 2026), while executable environments supply experience for agent training (Jimenez et al., 2024; Yang et al., 2025; Pan et al., 2025; Badertdinov et al., 2025). Our target is the downstream system affected by a change, including failures outside the agent’s workspace. We learn these consequences from execution and evaluate their value for subsequent decisions. 

Software Change Modeling. Change-impact analysis and regression-test selection use depen-dencies to identify potentially affected components (Bohner & Arnold, 1996; Rothermel & Harrold, 1997; Memon et al., 2017; Salis et al., 2021; Reyes et al., 2024). Graph-conditioned language mod-els provide structural context through graph representations (Perozzi et al., 2024; He et al., 2024; Hu et al., 2025; Chen et al., 2024; Li et al., 2023). SWM uses this structure to predict whether a par-ticular change actually breaks a consumer. Its evaluation connects to decision-focused prediction, where quality depends on the decisions a forecast induces (Elmachtoub & Grigas, 2022). 

## 6 CONCLUSION 

Coding agents should reason beyond the repository they edit. They should also anticipate how their changes affect the broader software system. We introduced Software World Models and an 

Explore–Learn–Act framework for this goal. Our experiments show that learning executed con-sequences improves the same coding agent under a fixed inference interface. The trained agent identifies more affected consumers and leaves fewer downstream services broken. We also find that structure and experience provide complementary information. Explicit dependencies are reliable when the relevant structure is observed, while learned dynamics help when that structure is incom-plete. Finally, forecast accuracy alone does not determine decision value. The location and type of prediction errors also matter. These results point toward coding agents that do more than react to failures. By exploring and learning their software worlds, agents can anticipate the consequences of future changes before acting. 9Preprint

All generated code was reviewed by the authors and validated through the project’s test and execution pipelines. AI tools were not used to generate experimental labels or reported results: software-world consequences were obtained from executed environments, and all reported numbers were computed from saved experimental outputs. The authors take full responsi-bility for the methodology, analysis, claims, and manuscript. 

## ETHICS STATEMENT 

This work studies coding agents that predict the downstream consequences of software changes. Our experiments use procedurally generated systems and permissively licensed open-source software; they involve no human subjects, personal data, or user-generated content. The proposed techniques may help identify cross-component failures before software changes are deployed, but similar capa-bilities could also reveal structural weaknesses in software systems. Our experiments are restricted to systems and environments under the experimenter’s control. We encourage deployment only with appropriate authorization, access controls, and human oversight for consequential software changes. 

## REPRODUCIBILITY STATEMENT 

Training and evaluation worlds are disjoint, corpus generation is seeded, and each reported train-ing condition retains its data split, configuration, random seeds, and model checkpoint. Executed transitions—rather than model-generated judgments—serve as supervision for downstream conse-quences. For the main agent experiments, we retain per-task outputs and report results across train-ing seeds with world-clustered uncertainty estimates. The appendices document the software worlds and graph schema, exploration and evaluation protocols, model training details, decision accounting, and complete experimental results.

C.4 STRUCTURAL LIMITS OF CONSEQUENCE PREDICTION 

The typed-reachability baseline follows consumer-dependency paths backwards from the nodes modified by the change, tgt( at):

R(Gt, a t) = {u ∈ V : u has a consumer-dependency path to tgt( at)}, (15) It is a deterministic function of the extracted graph and the change; Appendix D.3 defines the de-pendency relations it follows. 21 Preprint To locate where accuracy beyond reachability must come from, we call a predictor structural if it uses only the extracted graph and the action, that is, measurable with respect to (Gt, a t); reachability is one, and so is any learned model restricted to these inputs. 

Remark 1 (Structural predictors carry irreducible error) . Let f be any predictor with values in

where Var sums the per-component variances. The right-hand side is nonzero for two reasons, both properties of the environment rather than of the estimator. Consumers differ in whether they tolerate a change on a dependency they share, and the extractor drops channels that carry 34 .8% of the broken consumers at our forecast steps (Appendix D.4). 

The bound applies to learned models too: the expected loss is the floor plus the expected squared distance between f and the conditional mean of 1B given (Gt, a t). No predictor restricted to these inputs can remove the floor; it can only represent it, as a graded break probability per consumer. A predictor can narrow the distance, and reachability leaves it wide by marking every reachable consumer as broken, tolerant or not, and every consumer reached only through a hidden channel as safe. Narrowing it requires executed supervision where reachability is wrong; going below the floor requires information outside the graph, such as executed outcomes in ht. The evaluated SWM also reads the observed health ηt, the component health that earlier checks revealed (Section 3.2). When 

ηt carries no further information about B, SWM’s floor equals the structural one, and SWM can only narrow the distance and represent the floor.

D.7 EVALUATION PROTOCOL AND PRE -REGISTRATION 

Exploration yields. A yield is the fraction of executed records satisfying the stated condition: breaking yield counts changes that break at least one consumer, and hidden-channel yield counts breaking records missed by reachability. Static-prediction error counts any mismatch between the reachability set and the executed blast set. Real-library yields use records whose upstream checks pass; corpus size and denominators accompany each table. 

Blast-set F1. Each evaluation record carries the change, the recovered graph, and the blast set observed when the change was executed in the true system. Blast-set F1 compares the predicted and executed blast set, computed per record and averaged over records (record-mean); the companion forecast population is the 90 step-0 forecast steps of the held-out evaluation systems. The direct-channel group contains failures on recovered dependency paths; the hidden-channel group contains at least one missing dependency channel. Behavioral/latency records have no hidden channel but depend on response behavior or timing; no-break records contain no downstream failure. These groups concern graph coverage, whereas silent/visible labels concern detection by repository tests. 25 Preprint 

Decision accounting. A migration episode scores return = 1 − 0.25 nbroken − 0.05 ( nfixes + 1) −

feedback. Here nbroken counts services broken when the change ships, and nfixes counts consumers migrated before shipping. Feedback is the total cost of paid checks at the stated price (e.g. 0.02 for a consumer check). Belief plans (Figure 9) threshold sampled break probabilities at the cost ratio and execute the result; hard-selector rows execute a fixed prediction as the plan. 

Ranking. Each of the 90 choice sets presents the executed branches of one counterfactual as candi-dates. Top-1 is the fraction of sets whose safest executed candidate is ranked first; pairwise accuracy is the fraction of candidate pairs ordered correctly; regret is the expected number of broken services above the best candidate under uniform tie-averaging. 

Agent exploration. The action catalog and split are frozen before the first request. At each step the tool-using agent may inspect only eligible training candidates, selects one action, and receives only that action’s executed downstream observations. Acquisition is measured by verified transitions, repository test suites executed, breaking yield, hidden-channel yield, and the utility of the resulting training corpus. Validation and test outcomes are never returned to the explorer. 

Training from acquired experience. Agent-selected and matched control corpora use the same optimizer, update count, model initialization, and evaluation actions. Training seeds measure opti-mization variation; exploration seeds measure acquisition variation and are not conflated. A check-point is evaluated only after its training receipt, configuration, corpus hash, and output parser have been archived. 

Companion decision protocols. Besides the direct agent evaluation in Appendix A, we distin-guish three protocols. Ranking chooses among candidates whose outcomes are later executed. Be-lief planning converts sampled consequence frequencies into migrations and paid checks. The real-world agent protocol freezes forecasts before returning them to the coding agent, records whether the response consulted them, saves the selected patch before execution, and then verifies patch iden-tity, restoration, and downstream outcomes. The companion real-world coding-agent protocol tests end-to-end feasibility. It is distinct from the comparative agent results in Table 1. 

Prediction-noise diagnostic. We perturb true blast sets to compare error patterns at matched blast-set F1. Each prediction-noise axis is swept over eleven noise levels (Figure 9c). The induced blast-set F1 is not evenly spaced, so a comparison “at matched blast-set F1” interpolates the noise-perturbed oracle’s curve at the learned model’s own mean F1 rather than reading the two curves at the same noise level. The same nine checkpoints have mean blast-set F1 0.587 on the 90 forecast steps, 

0.525 on the 340 executed ranking candidates and 0.546 on the 40 planning tasks.
