## 摘要
随着编码智能体从有边界的软件工程任务迈向长时程开发，动态并发为扩展复杂开发任务提供了一种有前景的方式。在该策略下，智能体在执行过程中决定是否以及如何生成并发的子智能体。模型能力在很大程度上决定较短任务的结果，而长时程开发使编排成为任务完成的核心。现有工作主要关注编码智能体在较短任务上的失败，或预定义多智能体工作流中的协作，难以揭示前沿智能体在不同任务复杂度下动态并发的情况。我们通过受控比较启用或禁用该策略的匹配 Codex、Claude Code 和 Kimi Code 执行，将动态并发作为一种执行策略进行研究。跨越 354 个任务和 2,124 次执行，涵盖一系列任务复杂度和执行时程，我们评估其端到端效应与调度行为，并分析匹配轨迹，以刻画 13 种并发特有的失败模式、28 种可观察模式，以及其提供优势的条件。

## Abstract
As coding agents advance from bounded software engineering tasks toward long horizon development, dynamic concurrency offers a promising way to scale complex development tasks. Under this policy, agents decide during execution whether and how to spawn concurrent sub-agents. Model capability largely determines outcomes on shorter tasks, whereas long horizon development makes orchestration central to task completion. Existing work, focused on coding agent failures on shorter tasks or collaboration in predefined multiagent workflows, offers little insight into dynamic concurrency in frontier agents across task complexity. We study dynamic concurrency as an execution policy through controlled comparisons of matched Codex, Claude Code, and Kimi Code executions with the policy enabled or disabled. Across 354 tasks and 2,124 executions spanning a range of task complexities and execution horizons, we evaluate its end to end effects and scheduling behavior, and analyze matched trajectories to characterize 13 concurrency specific failure modes, 28 observable patterns, and the conditions under which it provides an advantage.

## 1. 核心问题与整体含义

- **研究动机**：LLM 编码智能体正从有界任务（如 SWE-bench 中几十行补丁）走向长时程、开放式软件开发（如从零重建代码仓库、持续演进软件），单智能体在上下文、推理与执行容量上存在瓶颈，多智能体协作成为扩展执行能力的重要路径。
- **范式转变**：早期编码智能体（TRAE、OpenHands）采用**静态并发**，依赖预定义角色、任务图与编排框架；前沿智能体转向**动态并发（dynamic concurrency）**——主智能体在执行过程中动态决定是否、何时、如何派生子智能体。
- **核心问题**：动态并发的有效性、效率与失败特性尚不清楚，尤其针对长时程编码任务；现有评估多集中于单智能体或预定义多智能体协议，且主要面向有界任务。
- **整体含义**：本文首次系统研究三种前沿智能体（Codex Multiagent v2、Claude Code Dynamic Workflow、Kimi Code AgentSwarm）的原生动态并发机制，揭示其"承诺"（长时程任务能力扩展）与"陷阱"（资源消耗激增、并发特有失败模式）。

## 2. 方法论

- **核心思想**：将动态并发视为一种**执行策略**，通过在同一智能体、同一任务上启用/禁用并发进行匹配对照，分离并发机制本身的影响。
- **关键技术细节**：
  - 每个任务对三个智能体分别执行两种模式：**Concurrent**（启用动态并发）与 **Sequential**（禁用，保证不创建任何子智能体）。
  - 控制变量：骨干模型、提示词、环境、时间预算保持一致。
  - 各智能体的启用方式：Codex 通过 `multi_agent`/`multi_agent_v2`；Claude Code 通过 `ultracode` 激活 Dynamic Workflow（禁用 Workflow/Task/Agent 工具）；Kimi Code 通过 `swarm_mode=true`。
  - 收集主智能体与全部子智能体的完整轨迹、提交产物、官方测试结果。
- **分析流程**：
  - **定量分析**：任务通过率、测试通过率、shell 调用数、时间、token 消耗；使用精确 McNemar 检验 + Holm 校正进行显著性比较；用 Spearman 置换检验分析任务难度与委派规模的关系。
  - **重叠分析**：比较并发/顺序模式下成功任务的交集，识别"唯一成功"任务。
  - **定性标注**：对 1,062 条并发轨迹人工标注，两位标注者独立编码，Cohen's κ = 0.77，三级分类法（主类别→子类别→具体模式）。
- **调度行为度量**：定义**重叠比例（overlap fraction）**为归一化轨迹中至少两个子智能体同时活跃的时间占比；统计首个子智能体启动时刻、最后端点、创建数、峰值并发数等。

## 6. 主要结论与发现

- **Finding 1（有效性）**：动态并发能扩展能力，尤其长时程任务收益更明显；实现规模越大，平均测试通过率增益越高（RepoZero −8.29pp → LoopsBench +4.31pp）。在 LoopsBench 上 Codex/Claude Code 任务通过率提升最高达 14.3pp；但在 SWE-bench Verified 上无增益，Claude Code 甚至下降 24.0pp（p = 5.08×10⁻⁷，显著）。
- **Finding 2（效率）**：并发显著增加资源消耗（token 1.41–3.31×，shell 调用数倍增长）与运行时（15 个 agent-benchmark 组合中 14 个变慢）；但双模式均成功的 366 个任务中，27.9% 并发更快，12.6% 显著更快（≥20% 时间节省），说明选择性并发有提速潜力。
- **Finding 3（委派规模）**：难度越高委派越多（平均创建数 6.69 → 7.53 → 15.84；峰值 3.66 → 4.61 → 6.70）；不同智能体偏好不同——Codex 倾向小规模（峰值 1.21–3.00），Claude Code 在 LoopsBench 硬任务平均创建 133.69 个，Kimi Code 创建较少但峰值更高（37.46）。
- **Finding 4（时间动态）**：Codex 委派最早（中位 4.0% 轨迹处）但重叠有限（中位重叠比例 23.9%）；Claude Code 委派较晚但并发最持续（52.7%）；Kimi Code 重叠比例最低（15.6%）。
- **Finding 5（失败分类法）**：4 大类、13 子类、**28 种具体失败模式**：
  - **A. 任务编排问题（28.5%）**：缺失负责人、伪并发、负载失衡（20.6%，最常见子类之一）。
  - **B. 执行治理问题（29.0%）**：错误的启动/汇合/结果时机（20.6%）、失败传播、缺乏主智能体主动监控。
  - **C. 全局上下文管理问题（9.3%）**：任务需求缺失、接口契约缺失、交接过载、无依据的全局完成声明、无变化重试。
  - **D. 共享状态与合并问题（33.2%，最大类）**：并发写入（26.5%）、共享环境污染。
- **Finding 6（收益条件）**：并发产生收益的三种机制——**互补工作**（子智能体并行完成不同模块，主智能体整合）、**替代方案探索与选择**（并行实现不同版本后择优/融合）、**独立验证**（子智能体提供纠正性证据）。

## 7. 优点

- **首创性**：首次针对前沿编码智能体的**原生动态并发机制**进行系统实证研究，填补静态多智能体与单智能体研究之间的空白。
- **规模化受控实验**：2,124 次执行、跨 5 个 benchmark 与 3 个难度层级，成本超 $20K，匹配对照设计有效隔离并发策略影响。
- **定量+定性结合**：不仅报告通过率与成本，还通过重叠比例、时间动态刻画调度行为；人工标注构建细粒度失败分类法（κ = 0.77）。
- **实践指导价值**：明确指出并发应"选择性启用"而非默认开启，并给出适用条件（可分解、可多解探索、可独立验证）。
- **可复现性**：公开 2,124 条轨迹、标注、分析脚本与代码手册，支持后续研究。

## 8. 不足与局限

- **外部效度**：仅覆盖 3 个智能体（Codex、Claude Code、Kimi Code）与 5 个 benchmark，结论受限于特定 agent-model 配对；替换模型可能因 RL 后训练适配而失效。
- **内部效度**：智能体执行具有随机性，但长时程评估成本过高，未能大规模重复运行；作者以与原始报告趋势一致作为间接证据，说服力有限。
- **标注主观性**：失败模式分类依赖人工判断，虽有一致性与仲裁机制，仍存在主观偏差风险。
- **样本与功效**：部分 benchmark 样本量小（NL2Repo 26、LoopsBench 28），统计显著性检验的功效受限。
- **应用限制**：动态并发成本高昂（token 1.41–3.31×、时间普遍增加），而聚合效果增益不稳定甚至为负；ProgramBench 上所有智能体任务通过率均为 0%，仅测试通过率有部分改善，说明对极难任务收益有限。
- **未涉及**：未报告 GPU 等硬件算力信息；未探讨如何自动决定"何时启用并发"的机制，仅给出经验性指导。
