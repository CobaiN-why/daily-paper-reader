# SWE-C RITIX : Post-Training Generalist Verifiers for Assessing Coding-Agent Trajectories 

Jiajun Hu

Hong Kong SAR, China hu.jiajun@huawei.com

Abstract —Coding agents are increasingly deployed for end-to-end software engineering tasks, where a readily available oracle evaluator that defines the success criteria is often absent. This motivates verifications for coding agents that can reliably judge and explain their behavior. However, verification is non-trivial as coding agents are increasingly capable of solving long-horizon software engineering tasks. Their execution trajectories can be extremely long, containing hundreds of iterative interactions with code repositories and external tools. Existing verifiers either rely on general-purpose LLMs without specialized training or train dedicated critics that predominantly focus on producing scalar rewards, highlighting the relatively limited exploration of training-based generalist verification. We introduce SWE-CRITIX , a post-training pipeline for training generalist verifiers of coding-agent trajectories. Given a task and its execution trajectory, the learned verifier predicts the completion label and generates a natural-language analysis that explains its judgment. Our pipeline combines supervised fine-tuning (SFT) with reinforcement learning (RL) and trains a series of 30B models on trajectories from CodeForge-Preview. On a held-out test set, SWE-C RITIX improves classification accuracy from 57% for the base Qwen3-30B-A3B reasoning model to 66% after SFT and 78% after RL. We release our models, datasets, and training code to facilitate further research. 

I. I NTRODUCTION 

Recent advances in large language models (LLMs) have enabled a shift from code generation toward autonomous coding agents that can interact with environments to solve complex software engineering tasks. Rather than producing one-shot code snippets, coding agents can inspect repositories, edit files, execute commands, run tests, interpret feedback, and iteratively refine their solutions through interactions with external tools [1]–[3]. This agentic paradigm has substantially expanded the scope of automated programming from isolated function synthesis to repository-level issue resolution [4] and long-horizon software development tasks [5], [6]. As coding agents become more capable and autonomous, reliably verifying their execution trajectories (i.e., step-by-step record of an agent solving a task) becomes increasingly important. In realistic end-to-end tasks, the criteria for success-ful completion are often not explicitly specified by a readily available ground-truth oracle. A verifier is therefore needed to determine whether an agent has accomplished the task and, when it fails, identify the causes of failure. Compared with the two existing approaches in this category, SWE-C RITIX differs from them in terms of verification target (planning phase [30] vs. whole trajectory), annotation strategy (per-step dense labeling [31] vs. differential analysis), scale (2–8K training samples and 4– 8B models [30], [31] vs. 119K and 30B), learning algorithms (DPO [30] vs. GRPO), and reward design (process reward [31] vs. outcome reward). Using this pipeline, we train a Qwen3-30B MoE verifier on a distributed cluster equipped with Huawei Ascend NPUs, using coding-agent trajectories from CodeForge-Preview [32]. Our preliminary evaluation shows that the proposed post-training substantially improves the model’s ability to discrim-inate between successful and failed trajectories, increasing classification accuracy from 57% for the base model to 78% after reinforcement learning on the held-out test set. We open-source SWE-C RITIX on GitHub [33] and Hugging Face [34]. II. SWE-C RITIX 

Figure 1 shows the post-training pipeline of SWE-C RITIX ,which learns an LLM (i.e., a generalist verifier) for evaluating coding-agent trajectories. The verifier takes an issue-solving trajectory as input and determines whether the issue has been successfully resolved. Before making the binary judgment, the verifier produces a chain-of-thought (CoT) rationale that casually infers its decision (Figure 1-Application). To train the verifier, SWE-C RITIX first applies a more capable teacher LLM to review a pair of successful and failed trajectories that address the same issue. Through differential analysis, the teacher summarizes the respective procedures, mistake patterns, and key factors leading to the success or failure of each trajectory (Figure 1-CoT Annotation). These summaries are then incorporated into a small amount of SFT training samples, providing supervision for the base model to learn the reasoning process underlying trajectory evaluation (Figure 1-SFT). Finally, RL is applied to a substantial number of samples without CoT annotations, where unit-testing results are used as ground truth for computing the reward signal (Figure 1-RL). 

A. Data Collection 

We collect test-verified trajectories from CoderForge-Preview [32], a large open dataset containing 258K trajec-tories (155K pass vs. 103K fail) spanning 51K issues across 1,655 repositories. These trajectories were generated using the OpenHands scaffold [35] with Qwen3-Coder-480B [36] as the underlying model, on three downstream task sources [20], [37], [38] that provide executable gym environments. We further prune the dataset by discarding any trajectory that exceeds 64K tokens or does not contain a submitted patch (e.g., the task is incomplete). After filtering out 16% of the data, we split the remaining trajectories into SFT, RL, and test sets as follows: 1. We randomly choose 20% of the issues and use all associ-ated trajectories as the test set. 2. Among the remaining issues, we randomly select one successful and one failed trajectory from each issue that contains both types, and assign them to the SFT set. 3. From the remaining trajectories, we include all failed trajec-tories in the RL set and then sample successful trajectories in a round-robin fashion across issues until the two classes are balanced. This maximizes the coverage of distinct issues. The resulting data is released on Hugging Face [34] and its statistics is summarized in Figure 1-Data Splits. 

B. Chain-of-Thought (CoT) Annotation 

It has been widely acknowledged that generating a CoT before providing the final answer significantly improves the performance of LLMs to resolve complex tasks [39]–[41]. To bootstrap the reasoning capabilities of our target verifier, SWE-C RITIX leverages a teacher LLM (GPT-5.5) to generate a structured CoT trace by comparatively analyzing each pair of successful and failed trajectories in the SFT set. We adopt this pairwise comparison approach based on prior findings that LLMs perform better in pairwise evaluations than in individual judgments [42], [43]. We then post-process the generated CoTs to adapt them for pointwise judgment, which is the intended evaluation setting for the trained verifier. The prompt templates and more details are released on GitHub [33]. The resulting CoT trace of a trajectory includes a concise summary of its issue-resolving procedure, a characterization of mistake patterns based on a predefined taxonomy, and a causal summary of the factors contributing to the success or failure of the trajectory. We apply CoT annotation only to the SFT set, which contains 10,390 trajectories and accounts for 8.7% of the training set.

The reward curve during training is shown in Figure 2. We refer to the resulting checkpoint as πRL and release its weights on Hugging Face [34]. III. P RELIMINARY EVALUATION 

As a preliminary evaluation, we focus on the model’s ability to distinguish between successful and failed trajectories. We evaluate πRL , πSFT , and the base Qwen3 MoE model on the test split created in Section II-A. We serve these models using vLLM Ascend [49] on one node containing 16 Huawei Ascend 910C-64GB NPUs. Given the large scale of the test set (over 43K long-trajectory samples), we evaluate each model on each sample only once. We report accuracy , as well as precision , recall , and F1 scores for both the positive (successful trajectory) and negative (failed trajectory) classes. We present the results in Table II. The results reveal a clear progression from general-purpose language modeling to specialized trajectory verification. The base Qwen3 MoE model exhibits a strong bias toward predicting trajectories as correct, as its negative recall is nearly zero across all subsets. It also has limited instruction following capability on this task. We observed that 9.6% of its responses do not adhere to the required output format, preventing reliable extraction of the predicted judgments. SFT substantially alleviates both issues. All responses produced by πSFT strictly follow the instructions required by the prompt, and the model becomes considerably less biased toward positive predictions. Further RL training yields another significant improvement, increasing accuracy from 66% after SFT to 78% on the overall test set. These results suggest that SFT primarily addresses the base model’s strong positive bias, while subsequent RL further strengthens its discriminative capability by recovering positive recall from 67% to 85% without substantially sacrificing negative recall. Despite these gains, two limitations remain. First, perfor-mance on R2E-Gym is notably lower than those on SWE-Rebench and SWE-Smith. One possible explanation is its relatively smaller data volume. Second, πRL remains less effective at recognizing failed trajectories as the negative recall reaches only 64% overall. This suggests that failed trajectories remain more challenging to distinguish from successful ones, potentially due to the greater diversity of failure patterns and the subtle failure signals that are difficult to identify. IV. F UTURE WORK 

Our current evaluation focuses on the discriminative ability of SWE-C RITIX . In future, we plan to conduct more com-prehensive evaluations along the following five dimensions. 

1. Training Data : All samples in CodeForge-Preview [32] are generated using OpenHands [35] with Qwen3-Coder-480B [36]. To investigate the impact of data mixtures, we plan to incorporate trajectories from other sources, such as Open-SWE-Traces [50], and synthesize trajectories using different combinations of LLMs and harnesses. Furthermore, beyond the balanced positive-to-negative ratio, we plan to investigate the effects of different class ratios, such as 2:1, 1:2, and 4:1. 

2. Training Methods : It remains an open question whether RL alone is sufficient to train an effective verifier. We therefore plan to establish a cold-start RL baseline by removing the CoT annotation and SFT stages from our pipeline. In addition, we plan to conduct reward ablations in the RL stage by incorporating signals not only from the final test results but also from the intermediate reasoning process. 

3. Downstream Applications : We plan to explore down-stream scenarios that can benefit from the trained verifier. For example, can the verifier help recover a correct solution by identifying and rectifying errors in a failed trajectory? Can the verifier serve as a proxy reward for RL training when ground-truth test results are unavailable? 4. Baselines : We plan to compare SWE-C RITIX with fron-tier open/closed-source models [51]–[53] and representative methods from the categories summarized in Table I. 

5. Qualitative Analysis : Beyond the quantitative evalua-tions described above, we plan to conduct a qualitative analysis of the model’s reasoning traces to assess whether its analyses are logically coherent and grounded in evidence. We will also investigate cases in which the verifier makes incorrect judgments to better understand the sources of its errors. V. R ELATED WORK 

Prior work proposing verifiers for reviewing coding-agent executions can be classified into two major categories depend-ing on whether a specialized verification model is trained. One is training-free verification, where an evaluator agent uses general-purpose LLMs to assess coding agent executions through test generation [7], [9], rubric-based grading [10]– [12], verification scaling [8], metamorphic relations [16], fail-ure attribution [13], or anti-pattern detection [14], [15], [17], [18]. Another major category is training-based verification, where a specialized critic is trained to evaluate trajectories using different learning paradigms such as TD learning [25], [26], autoregressive next-token prediction [10], [19]–[23], [28]–[31], multi-label classification [27], DPO [30], Bradley-Terry [24], and policy gradient [28], [31]. VI. C ONCLUSION 

In this paper, we proposed a post-training pipeline SWE-CRITIX that integrates SFT with RL to learn a process-level generalist verifier for assessing coding-agent trajectories. Preliminary experiments on coding-agent trajectories from CodeForge-Preview demonstrate a substantial improvement in the model’s discriminative ability.
