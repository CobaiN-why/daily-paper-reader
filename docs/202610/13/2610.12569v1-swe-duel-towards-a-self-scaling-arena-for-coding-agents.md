## 摘要
静态编码基准在发布时即已固定。随着时间推移，其任务会泄漏进训练数据，而更强的智能体最终会使其饱和。我们认为，基准应转而追求自扩展：其任务与判定标准在评估时创建，因此事先不存在可供泄漏的内容，其难度由参与其中的智能体决定，而非在发布时固定。我们提出 SWE-Duel，一个让两个编码智能体通过镜像的红蓝回合相互评估的竞技场。在每个回合中，红方智能体在三个上下文隔离的会话中处理一个真实代码仓库。它提出并实现一个新功能及其功能测试，然后在该功能中嵌入一个隐蔽缺陷以及封存的缺陷触发测试。由此产生的拉取请求只有在满足以下条件时才被接纳：(1) 它通过功能测试和仓库的现有测试，同时恰好使缺陷测试失败；(2) 同一智能体的一个全新会话能够盲修该缺陷，从而排除无解任务。随后蓝方智能体在未被告知存在缺陷的情况下审查该拉取请求。只有当其修订通过全部三套测试时，它才获胜，之后两个智能体交换角色。我们在 5 种语言的 15 个仓库上，对 11 个模型-框架参赛者进行了 1500 个回合的锦标赛。领先者以不同方式取胜。使用 Codex CLI 的 GPT-5.5 作为最强解题者排名第一，修复了其审查的 98.3% 的缺陷。使用 mini-swe-agent 的 Claude Opus 4.8 作为最强任务出题者排名第二，红方胜率为 27.3%。最后，在同一模型家族内，由最新版本编写的任务击败固定参考解题者的频率远高于旧版本（42.9% 对 4.0%），初步表明任务难度会随任务编写能力而扩展。

## Abstract
Static coding benchmarks are fixed at release. Over time their tasks leak into training data, and stronger agents eventually saturate them. We argue that a benchmark should instead aim to be self-scaling: its tasks and oracles are created at evaluation time, so no content exists in advance to leak, and its difficulty is set by the participating agents rather than fixed at release. We introduce SWE-Duel, an arena in which two coding agents evaluate each other over mirrored Red-Blue turns. In each turn, the Red agent works on a real repository across three context-isolated sessions. It proposes and implements a new feature with feature tests, then embeds a subtle bug in that feature along with sealed bug-triggering tests. The resulting pull request is admitted only if (1) it passes the feature tests and the repository's existing tests while failing exactly the bug tests, and (2) a fresh session of the same agent can repair the bug blind, which rules out unsolvable tasks. The Blue agent then reviews the pull request without being told a bug exists. It wins only if its revision passes all three test suites, and then the two agents swap roles. We run a tournament among 11 model-harness participants on 15 repositories in five languages for 1,500 turns. The leaders win in different ways. GPT-5.5 with Codex CLI ranks first as the strongest solver, repairing 98.3% of the defects it reviews. Claude Opus 4.8 with mini-swe-agent ranks second as the strongest task author, with a 27.3% Red win rate. Finally, within one model family, tasks written by the newest version defeat a fixed-reference solver far more often than those of older versions (42.9% vs. 4.0%), giving preliminary evidence that task difficulty scales with task authoring capability.

# SWE-Duel 论文总结

## 1. 核心问题与研究动机

- **背景痛点**：现有编码基准（如 SWE-bench）在发布时即固定，任务来源公开，会逐渐泄漏进被评测模型的训练数据；同时固定任务集终将被更强的智能体饱和。OpenAI 已因发现前沿模型能复现 SWE-bench Verified 的黄金补丁而停止报告结果。
- **现有缓解手段的不足**：
  - 持续更新型基准（SWE-bench-Live、SWE-rebench）虽缓解泄漏，但难度仍受限于人类开发者日常 issue 的难度上限，任务只是"更新"而非"更难"。
  - 自动生成 bug 方向（SWE-smith、BugPilot、Self-play SWE-RL）多用于造训练数据，且 BugPilot 的 bug 因会破坏现有测试而可被测试套件暴露；CDBench 的变异是局部编辑且向防守方展示 diff。
  - 竞技场方向（Chatbot Arena、SwingArena）依赖人类投票或人工任务池/黄金补丁，仍有人类锚点。
- **核心命题**：基准应追求**自扩展（self-scaling）**——任务与判定标准在评测时创建（事先无内容可泄漏），难度由参与智能体自身能力决定（随参与者变强而上升）。由此提出中心问题："能否为编码智能体创建一个自扩展的基准？"

## 2. 方法论

- **核心思想**：两个编码智能体在真实仓库上通过**镜像的红蓝回合**互相评测。每回合后双方交换角色，形成对抗循环。
- **任务形式化定义**：任务为元组 \( C = (R, s, d, T_f, T_b) \)，其中 \( R \) 为仓库、\( s \) 为功能规格、\( d \) 为同时含功能与缺陷的 PR diff、\( T_f \) 为功能测试、\( T_b \) 为封存的缺陷触发测试。
- **红方（出题者）三会话流程**（每会话独立上下文，各配一个可执行验证门）：
  - **Session A 功能实现**：探索仓库、自选目标模块、实现新功能并写规格与功能测试 \( T_f \)；验证门 A 要求现有测试 \( T_e \) 与 \( T_f \) 在功能 diff 上通过，且满足最小尺寸阈值（确保功能正确，后续失败可归因于 bug）。同一仓库内须选不同模块以保证多样性。
  - **Session B 缺陷植入**：新会话基于规格与功能 diff 植入隐蔽缺陷，写出缺陷测试 \( T_b \)；验证门 B 要求 (i) diff 可应用且通过 lint/编译；(ii) 构建、\( T_e \)、\( T_f \) 仍通过（缺陷无可见失败信号）；(iii) \( T_b \) 在功能版本通过、在含缺陷版本失败。
  - **Session C 盲自修**：同参与者的全新实例仅接收公开包 `pub(C) = (R, s, d, T_f)`（与蓝方所见完全相同），须盲修缺陷；只有 \( T_e, T_f, T_b \) 全通过任务才被接纳（排除无解任务，同时意味着任务难度上限受作者自身解题能力约束）。
- **槽位与尝试机制**：每个（参与者，仓库）请求 N 个任务，每槽最多 5 次尝试；成功即存入任务库并跨比赛复用，5 次全失败则该槽耗尽且不再替换（任务创建能力本身是被测能力），耗尽槽在比赛中记为缺任务。
- **蓝方（解题者）**：仅收到 `pub(C)`，缺陷测试与元数据保密，提示中不告知存在缺陷。蓝方可编辑代码甚至重写功能。评分采用硬合取：
  - \( S_{Blue} = S_e S_f S_b \)，\( S_{Red} = 1 - S_{Blue} \)，无部分分。
  - 蓝方失败三类：缺陷漏出（\( S_b=0 \)）、功能被破坏/删除（\( S_f=0 \)）、现有行为回归（\( S_e=0 \)）。若蓝方原样提交，由门 B 保证 \( T_b \) 失败，红方胜。
- **防作弊设计**：因缺陷内嵌于新功能，蓝方无法通过回滚 PR 去除缺陷（否则 \( T_f \) 失败）。
- **锦标赛与排名**：
  - 配对赛每仓库每槽产生两个回合（双方各做一次蓝方），一场比赛共 \( 2N|R| \) 回合；缺任务自动判蓝方胜（避免幸存者偏差，且计入红方任务创建能力）。
  - 采用**循环赛（round-robin）**；排名用 **Bradley–Terry 模型**：\( \Pr(p \text{ beats } q) = \sigma(\beta_p - \beta_q) \)，平局计半胜，用 1000 次匹配 bootstrap 重采样给出 95% 置信区间与排名概率分布。
  - **新参赛者接入**：只需与 \( \lceil \log_2 M \rceil + 1 \) 个在位者（按 Chatbot Arena 主动采样规则选取）比赛，复用已有任务库与历史结果，新增比赛数随 M 对数增长。

## 6. 主要结论与发现

- **总排名**：GPT-5.5 + Codex CLI 以 BT 评分 +2.82 居首（最强解题者，蓝方修复率 98.3%/98.7%）；Claude Opus 4.8 + mini-swe-agent 以 +2.46 居次（最强出题者，红方胜率 27.3%）；MiniMax-M3 与迟入的 Gemini 3.1 Pro 垫底。
- **两种能力路径分离**：领先者靠不同方式取胜——GPT-5.5 是解题强，Opus 4.8 是出题强（其红方胜率是 GPT-5.5 两个组合的 2 倍以上）。多数模型解题能力明显强于出题能力。
- **整体解题率**：全部 1,500 回合蓝方成功率 87.9%；1,219 个"有争议回合"为 85.1%（1,037 次干净修复、158 次缺陷漏出、24 次功能/回归崩塌）。
- **按语言**：Java 89.2% > Go 85.7% > C/C++ 83.9% > Python 83.5% > Node 82.9%。
- **按缺陷类型**：逻辑错误最难修（81.9%），其后为安全漏洞（84.9%）、off-by-one（88.9%）、类型混淆（90.6%）、输入校验（95.5%）。
- **自扩展性初步证据**：同族 GLM-5.1→5.2→5.3 阶梯中，固定解题者失败率 8.3% / 0% / 42.9%（趋势检验 p=.015；最新版 vs 旧版合并 6/14 vs 1/25，Fisher p=.005），且同族内循环赛中 GLM-5.3 的任务击败兄弟版本 11/28 而旧版本合计仅 3/50。说明**任务难度随出题者能力提升**。
- **固定参考验证**：GLM-5.2 参考解题者失败 15/134（11.2%），与内生红方胜率秩相关 ρ=0.66，说明难度排序主要是任务固有属性而非对手场效应；Kimi-K2.7-Code 从内生 17.9% 掉到对参考 0/13，说明其胜率来自对手弱而非任务难。
- **可扩展接入**：迟入者用 5 场比赛即获得一致排名，且不改变已有 45 场拟合的排名顺序（Kendall τ=1.0）。
- **可靠性**：Session-C 接纳噪声研究显示 79.5% 任务 3/3 稳定可解，池化自修率 91.7%；缺陷测试假阴性率 6.0%（3/50，全部来自两个 Go JWT 任务）。
- **框架效应**：框架消融中 mini-swe-agent (+0.73) > Codex CLI (−0.25) > Claude Code (−0.49)，但置信区间大幅重叠，无法确立显著排序。

## 7. 优点

- **概念创新性强**：提出"自扩展基准"这一清晰目标，并通过让被测智能体互相出题从根本上消除训练数据泄漏（任务在评测时创建）与难度固定问题。
- **防退化解设计精巧**：缺陷内嵌于新功能，堵死"回滚 PR"的作弊路径；三重测试（现有/功能/缺陷）以硬合取评分，无部分分，判定客观可执行。
- **公平性保障扎实**：Session-C 盲自修门槛既保证任务可解、又天然限制难度不超过作者能力；双方同容器同预算、角色等频交换；缺任务自动判负以遏制幸存者偏差。
- **评测维度丰富**：单个 duel 覆盖需求规格、功能实现、测试生成、代码审查、故障定位、程序修复等完整软件工程生命周期。
- **工程与实证完备**：开源工具包与数据集；50 场/1,500 回合的大规模锦标赛；配合角色分解、固定参考、能力阶梯、人工审计、入场稳定性等多角度验证；并做了成本与 token 的敏感性分析。
- **可扩展的接入机制**：主动采样使新智能体以 O(log N) 场次接入，实证证明不扰动既有排名，利于长期维护排行榜。
