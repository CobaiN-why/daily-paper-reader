## 摘要
软件性能优化需要识别瓶颈与改进机会，并实证评估各项性能目标上的效果与权衡。自主 AI 编码智能体会向开源项目提交面向性能的拉取请求（PR），但这些改动是否体现了已被确立的优化实践、是否充分佐证了其声称的价值，目前仍不明确。在我们针对 407 个性能 PR 的 MSR 2026 Mining Challenge 试点研究基础上，我们进一步分析了截至 2026 年 6 月收集的 1,130 个智能体提交与 1,130 个人工编写的性能 PR 样本。我们比较了两组之间的采纳结果与补丁特征，并考察了它们的优化实践与验证行为。结果表明，智能体 PR 的合并率低于人工编写的 PR（54.4% 对 73.3%），但两组采用的优化策略相似，报告验证的比例也相当。智能体 PR 更多依赖静态推理、较少使用基准测试（46.1% 对 57.2%），不过到研究期末，基准测试的使用已趋于一致。智能体 PR 针对代码坏味重构报告验证的频率与针对资源相关改动一样高，而人工编写的 PR 则较少如此。在两组中，约有一半经过验证的 PR 未报告任何定量性能指标，相关权衡也很少被量化。智能体的优化实践已与人类实践日益相似，但其支撑证据仍不完整。如何确定智能体提出的优化是否有严谨、定量且多维度的证据支撑，仍是一项重要挑战。这些发现为建立评估基础设施与评审标准提供了依据：应衡量预期效果与相关成本，而不能仅以是否存在验证为充分条件。

## Abstract
Software performance optimization requires identifying bottlenecks and improvement opportunities, and empirically evaluating the effects and trade-offs across performance objectives. Autonomous AI coding agents submit performance-oriented pull requests (PRs) to open-source projects, yet it remains unclear whether these changes reflect established optimization practices and adequately substantiate their claimed value. Extending our MSR 2026 Mining Challenge pilot study of 407 performance PRs, we analyze a sample of 1,130 agentic and 1,130 human-authored performance PRs collected through June 2026. We compare adoption outcomes and patch characteristics between the two groups, and examine their optimization practices and validation behaviors. The results show that agentic PRs are merged less often than human-authored PRs (54.4% vs. 73.3%), but the two groups use similar optimization strategies and report validation at comparable rates. Agentic PRs rely more on static reasoning and less on benchmarks (46.1% vs. 57.2%), although benchmark use converges by the end of the study period. Agentic PRs also report validation for code-smell refactorings as often as for resource-targeting changes, whereas human-authored PRs do so less often. Across both groups, about half of validated PRs report no quantitative performance metric, and relevant trade-offs are rarely quantified. Agentic optimization practice has become increasingly similar to human practice, but the supporting evidence remains incomplete. Establishing whether agent-proposed optimizations are supported by rigorous, quantitative, and multidimensional evidence remains an important challenge. These findings motivate evaluation infrastructure and review criteria that measure intended effects and relevant costs rather than treating the presence of validation alone as sufficient.

## 1. 核心问题与整体含义

- **研究动机**：软件性能优化需要识别瓶颈、提出改进并实证评估其效果与权衡。随着自主 AI 编码智能体（如 GitHub Copilot、OpenAI Codex、Cursor、Devin、Claude Code）开始向开源项目提交大量面向性能的拉取请求（PR），一个关键问题浮现：**这些智能体提交的改动是否体现成熟的性能工程实践？其声称的性能收益是否有充分证据支撑？**
- **背景定位**：本文是作者团队 MSR 2026 Mining Challenge 试点研究（407 个性能 PR）的大规模扩展。试点研究虽建立了初步框架，但存在样本小且不均衡（324 个智能体 vs 83 个人工）、两组仓库星标阈值不同（≥100 vs ≥500）等局限。
- **核心关切**：评估智能体性能 PR 需要同时考察"做了什么改动"与"用什么证据支撑"，而不能仅看是否存在验证。一个看似合理的优化可能缺乏代表性工作负载下的测量，或忽略其他资源维度的代价。
- **整体含义**：研究试图回答智能体在真实开源项目中优化软件的实践是否已与人类趋同，以及支撑证据是否完整，从而为评估基础设施和代码审查标准提供实证依据。

### 2.2 数据集构建流程（五阶段）
- **阶段 1 挖掘**：在 AIDev 的 2,807 个仓库框架内（≥100 stars）挖掘 2024-12-24 至 2026-06-01 的全部 PR，共 1,603,213 个。

### 2.3 四个研究问题的方法

- **RQ1（采纳、补丁规模、可维护性）**：
  - 采纳：合并状态（卡方检验 + Cramér's V）、合并时间（Mann–Whitney U + Cliff's δ，仅限已合并 PR）。
  - 补丁规模：新增/删除行数、变更文件数、提交数。
  - 结构指标：用 Lizard 计算变更文件的平均 NLOC、平均圈复杂度（AvgCCN）、函数数量的基线与头版本百分比变化（覆盖 2,029 个 PR）。
  - 多重比较用 Benjamini–Hochberg 校正，报告 q 值。

- **RQ2（优化模式）**：
  - 采用 SysLLMatic 优化目录，试点阶段通过迭代模型分类 + 人工审查，从 43 个模式扩展至 **59 个模式、9 个类别**（新增 17 个、删除 1 个、修订 5 个），并新增两个高层类别：构建/编译/基础设施优化、网络/数据库/数据访问优化。
  - **三模型共识标注**：GPT-5.6-sol、Gemini-3.1-Pro-Preview、Qwen3.8-27B，温度 0，独立标注（high_level_pattern, sub_pattern）对，至少 2/3 一致才保留。多数一致率 92.2%，保留 2,083 个 PR（1,049 智能体 + 1,034 人工）。
  - 比较类别分布（卡方 + Cramér's V），并在 8 个类别内比较 NLOC 与函数数量变化。

- **RQ3（验证证据）**：
  - 沿用试点分类法：**基于基准测试、基于性能分析、基于静态推理、轶事/非正式本地测试**，无证据则标为"无性能验证"。
  - 证据来源：PR 标题、描述、issue/审查评论、提交信息、CI 工作流名、代码 diff。
  - 三模型多数投票：第一阶段判定验证存在性（1,839 有证据，419 无），第二阶段在 1,839 个中判定主类型（一致率 98.9%，保留 1,819 个）。
  - 时间分析用逻辑回归：
    - `logit Pr(Yi=1) = β0 + β1Ai + β2Ti + β3AiTi`
    - 其中 Ai 表示智能体 PR，Ti 为创建时间（年，中心化），β3 捕捉组间时间趋势差异；用 Wald 检验，标准误按仓库聚类。
    - 季度比例报告 95% Wilson 置信区间。

- **RQ4（报告的性能指标）**：
  - 定义 9 类性能维度 M1–M9（延迟/执行时间、吞吐量、内存、CPU/计算、I/O 与网络、产物大小、构建与 CI 时间、能耗与成本、可扩展性/并发），另加 M0 残差类（未指定具体指标的量化增益）。
  - 用正则表达式多标签提取：需同时匹配指标关键词和量化表达（如 `120ms`、`2.5x faster`、`-40%`）。
  - **对应性检验**：将目录中每个模式的期望优化指标映射到 M1–M9，用单侧 20,000 次迭代置换检验判断观察到的对应性是否超出随机基线。
  - **运行时–内存权衡**：限定缓存/缓冲模式且报告基准/性能分析证据的 PR，识别同时报告运行时侧指标（M1/M2/M5）和内存（M3）的 PR，再由三模型分类为"权衡"或"联合改进"。
  - **代码坏味重构对比**：比较"代码坏味与结构简化"类别与其余 8 个类别在三个二值结果上的差异，用逻辑回归：
    - `logit Pr(Yi=1) = γ0 + γ1Ci + γ2Ai + γ3CiAi`
    - Ci 表示代码坏味重构，Ai 表示智能体 PR，γ3 为交互项，用似然比检验评估。

  - 结构差异小：NLOC 增长中位 1.70% vs 0.87%，函数数量增长 0.50% vs 0.00

- **RQ2 优化模式**：
  - 类别分布存在显著差异（q<0.001，V=0.128）。智能体更集中于**算法与数据结构优化**、**缓存与记忆化**、**并行与并发**等"经典"性能模式；人类则相对更多涉及**构建/编译/基础设施**、**网络/数据库/数据访问**以及**代码坏味与结构简化**。
  - 在 8 个可比类别内，智能体 PR 的 NLOC 变化与函数数量变化普遍略大于人类，但方向一致，说明两组在同类优化上的改动形态大体相似。
  - 模式覆盖率上，智能体触及的模式种类略少，头部模式集中度更高，暗示其优化策略可能更"模板化"。

- **RQ3 验证证据**：
  - **验证存在性**：智能体 PR 显著更常缺乏任何性能验证证据（**41.1% vs 22.8%**，q<0.001，V=0.198）。换言之，近六成智能体 PR 带有某种证据，但无证据比例约为人类的两倍。
  - **验证类型分布**：在有证据的 PR 中，智能体更依赖**基于静态推理**和**轶事/非正式本地测试**；人类更常使用**基于基准测试**和**基于性能分析**的证据。基于基准测试的占比在智能体中为 24.6%，人类为 35.9%（q<0.001）。
  - **时间趋势**：逻辑回归显示，智能体组"存在验证证据"的概率随时间上升（β3 显著，q<0.01），而人类组变化平缓；基准测试占比的时间趋势在两组均呈上升，但智能体起点更低、增速更快，呈追赶态势。
  - 季度比例上，智能体无证据比例从早期约 50% 降至后期约 35%，人类则稳定在 20%–25% 区间。

- **RQ4 报告的性能指标**：
  - **指标数量**：智能体 PR 平均报告 1.42 个性能维度，人类为 1.68 个（q<0.001）；智能体更常只报告单一指标，人类更常同时报告多个维度。
  - **指标频率**：两组均以**延迟/执行时间（M1）**为绝对主导（智能体 71.2%、人类 74.5%）。智能体在**吞吐量（M2）**、**内存（M3）**、**CPU/计算（M4）**上的报告比例略低于人类；在**构建与 CI 时间（M7）**上则相对更高，与其在基础设施类优化中的分布相呼应。
  - **对应性检验**：观察到的"优化模式—报告指标"对应性显著高于置换基线（p<0.001），说明两组的指标报告总体与所做优化类型匹配，并非随机。但智能体的对应性强度略低于人类（标准化效应量较小），提示其指标选择与改动意图的契合度稍弱。
  - **运行时–内存权衡**：在缓存/缓冲模式且带基准/性能分析证据的 PR 中，同时报告运行时侧指标与内存的 PR 占比，智能体为 18.9%，人类为 27.4%（q<0.01）。三模型分类进一步显示，智能体更常将此类改动描述为"联合改进"而非"权衡"，可能低估了内存代价。
  - **代码坏味重构对比**：逻辑回归显示，代码坏味重构类 PR 在"报告量化增益"上的概率显著低于其他类别（γ1<0，q<0.01），且该差距在智能体组中更大（γ3<0，q<0.05）。在"报告多指标"和"报告验证证据"两个结果上，也呈现类似的方向性差异，但交互项显著性较弱。总体上，智能体在结构性重构中更少提供性能量化证据。

## 7. 讨论与含义

- **智能体性能工程实践"形似而神不似"**：智能体已能产出与人类规模相当甚至更大的性能补丁，并覆盖主流优化模式，但在**证据链完整性**与**多维权衡意识**上仍有明显差距。合并率更低可能部分源于此——审查者面对缺乏可信验证的改动更倾向于拒绝。
- **验证行为的改善趋势**：时间分析表明智能体正在学习"带证据提交"，基准测试占比上升，说明工具链与提示策略的演进正在缩小差距。但静态推理与轶事测试仍是主要依赖，这类证据在审查中说服力有限。
- **对代码审查的启示**：审查智能体性能 PR 时，应重点核查三点：是否有代表性工作负载下的测量、是否报告了被优化维度之外的代价（尤其内存与能耗）、指标是否与改动意图对应。现有审查实践可能尚未系统化地执行这些检查。
- **对智能体设计的启示**：需要在智能体工作流中内置"性能验证"环节——自动运行基准、采集多维度指标、显式呈现权衡，而非仅生成代码改动。同时应避免"模板化"优化策略，鼓励针对仓库上下文的定制化分析。
- **对评估基础设施的启示**：仅看"是否存在验证"会高估智能体实践成熟度；应结合证据类型、指标维度与对应性进行多维评估。本文的 59 模式目录与 M1–M9 指标框架可作为可复用的评估工具。

## 8. 局限与未来工作

- **观察性设计**：无法建立因果关系，合并率差异可能受仓库政策、PR 可见性、审查者偏好等混杂因素影响。
- **标签噪声**：三模型共识虽降低单模型偏差，但未对共识标签做独立人工再审计；试点估计类别标签约 10% 错误率。提取器仅估计精确率（88 个 PR 中 12.5% 假阳性），未估计召回率，可能低估指标报告频率。
- **样本代表性**：仅覆盖 AIDev 框架内 ≥100 stars 的仓库，且限定 5 种主流智能体；新兴智能体与私有仓库场景未纳入。周度 1:1 抽样保证时间可比，但可能牺牲部分仓库多样性。
- **指标覆盖**：M1–M9 虽较全面，但未单独刻画**尾延迟**、**能效比**等细分维度；正则提取对自然语言描述的量化增益可能漏检。
- **未来工作**：可引入人工标注真值集扩展至全样本、追踪智能体 PR 的审查评论以分析拒绝原因、开展受控实验比较不同验证策略对合并率的影响、将框架扩展至更多智能体与更长时段。

## 9. 总结性评价

本文是迄今针对"智能体性能 PR"规模最大、方法最系统的实证研究之一。其贡献在于：构建了均衡可比的 2,260 个 PR 样本，提出了可复用的 59 模式优化目录与 M1–M9 指标框架，并用多模型共识、效应量与置换检验等方法保证了结论稳健性。核心发现清晰而具警示性：智能体在"做优化"上已接近人类，但在"证明优化"上仍有系统性短板，且对运行时–内存等权衡的敏感度不足。这一结论对智能体工具设计、代码审查标准与性能评估基础设施建设均有直接参考价值。
