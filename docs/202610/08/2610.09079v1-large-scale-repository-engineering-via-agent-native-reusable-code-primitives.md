## 摘要
配备开发环境的大型语言模型已将代码生成推进到仓库级构建，但构建完整仓库仍然困难，因为相互作用的模块、接口、配置、测试和依赖必须协同工作。我们提出代码原语（Code Primitives），这是一种智能体原生的可复用可执行组件，具有接口契约、依赖闭包、验证测试和来源溯源。每个原语使用一个常驻 LLM 来评估相关性，并使其实现、接口和依赖适配目标仓库；我们在 CodeFace 中组织了 1,424 个经过验证的原语，这是一个用于仓库构建的可搜索库。我们提出 LEGO（Large-scale repository Engineering via aGent-native reusable cOde primitives，基于智能体原生可复用代码原语的大规模仓库工程），它激活与任务相关的原语，将其适配后的实现与任务特定代码集成，同时解决跨组件约束，并根据已执行的测试修订结果。为了端到端地衡量构建，我们构建了 LEGO-REPO，一个包含 522 个可执行重构任务的基准，涵盖七个软件领域、22 个能力赛道和五个难度级别，并依据原生测试套件在空包下限和原始源码上限之间评分。在 13 个被评估的主干模型中，最强者的交付得分为 0.318，并在 41.0% 的任务上得分为零；LEGO 使全部 13 个模型平均提升 0.1474，并将 GPT-5.6-terra 从 0.3180 提升到 0.5134（+61.4%）。在受控比较中，经适配的原语优于作为上下文提供的检索代码或未经修改直接引入的代码。该效果在面对独立的仓库智能体、跨越三个外部基准以及使用不重叠重新挖掘的 CodeFace 时依然存在；用于适配和诊断的 GPT-OSS-20B 以低 24.0% 的成本保留了 95.1% 的同质得分。

## Abstract
Large language models equipped with development environments have moved code generation toward repository-scale construction, yet building complete repositories remains difficult because interacting modules, interfaces, configurations, tests, and dependencies must work together. We introduce Code Primitives, agent-native reusable executable components with interface contracts, dependency closures, validation tests, and provenance. Each primitive uses a resident LLM to assess relevance and adapt its implementation, interfaces, and dependencies to the target repository, and we organize 1,424 validated primitives in CodeFace, a searchable library for repository construction. We introduce LEGO (Large-scale repository Engineering via aGent-native reusable cOde primitives), which activates task-relevant primitives, integrates their adapted implementations with task-specific code while resolving cross-component constraints, and revises the result against executed tests. To measure construction end to end, we build LEGO-REPO, a benchmark of 522 executable reconstruction tasks spanning seven software domains, 22 capability tracks, and five difficulty levels, scored against native test suites between an empty-package floor and original-source ceiling. The strongest of 13 evaluated backbones reaches a delivery score of 0.318 and scores zero on 41.0% of tasks; LEGO improves all 13 by 0.1474 on average and raises GPT-5.6-terra from 0.3180 to 0.5134 (+61.4%). In controlled comparisons, adapted primitives outperform retrieved code supplied as context or vendored unchanged. The effect persists against independent repository agents, across three external benchmarks, and with a disjointly re-mined CodeFace; GPT-OSS-20B for adaptation and diagnosis retains 95.1% of the homogeneous score at 24.0% lower cost.

## 2. 方法论

### 2.1 核心思想：Code Primitives（代码原语）

- **定义**：`Pi = (Ci, Ii, Di, Vi, Xi, Mi)`，即实现、接口与行为契约、依赖闭包、验证测试、上下文与溯源、常驻 LLM。
- 每个原语以**自然语言接口**评估自身相关性并适配到目标仓库；适配由拥有该实现的组件自己完成。
- **粒度由挖掘诱导**而非人工调参：中位数 214 行、跨 2 个文件、导出 4 个符号、携带 9 个验证测试。
- **两个核心算子**：
  - 相关性评估：`(si, ui) = M_assess_i(Pi, r, C)`
  - 适配改写：`(P̃i, μi) = M_adapt_i(Pi, r, C)`，其中 `μi = {μi→j}` 为对其他组件施加的需求（本地封闭改动时为空）。
- 适配仅作用于自身状态与**有界上下文**（目标位置、所需导出、待绑定接口），**不接触**无关实现、目标原生测试套件、全局仓库计划；随后更新接口/依赖记录并对适配后组件重跑 Vi。

### 2.2 CodeFace 库

- 1,424 个验证原语 = **871 挖掘 + 343 从验证过的构建运行中收集 + 210 网络定向采集**。
- **挖掘六步**：解析程序实体与关系 → 构建依赖图 → 图分割为组件（边界对照邻近代码/文档/测试精化）→ 从导出符号与使用推断接口 → 收集可达测试/配置/文档入 Vi 与 Xi（本地辅助内化，外部需求记入 Di）→ 合成原语并在隔离环境中做 build/import/runtime/test 验证，失败引导边界精化直至准入或排除。

### 2.3 LEGO 框架（五阶段流程）

1. **检索与激活**：`Πt = (r1,…,rK) = DECOMPOSE(q, Ct)`；每个需求检索 top-m 候选（m=2），收集 `(si, ui)`，按能力覆盖与互相兼容性选择激活集 `At`；无合适匹配的需求交给任务特定代码 `gt`。
2. **原语适配与协作**：若某原语的改写改变了导出签名、数据表示或配置键，则向消费者发出自然语言需求 `μi→j`；同一轮内沿依赖边传递：`(P̃i, μi) = M_adapt_i(Pi, r_k(i), Ct ∪ μ→i)`。
3. **仓库编辑**：`St = INTEGRATE({P̃i}, gt)`，在仓库层解决跨组件边界约束（API 绑定、共享数据类型、包依赖、配置）。
4. **执行反馈**：`ot = EXECUTE(St)`，产出构建状态、测试结果、失败用例、运行时错误与调用栈；补充从需求与接口合成的单元/集成测试。
5. **验证与诊断**：`(vt, φt) = DIAGNOSE(q, Πt, St, ot)`，`φt = (et, ct, ut)`；失败时 `Ct+1 = Ct ∪ {φt}`，**只重新激活 ct 中被牵连的原语**；每模块预算 b=5 轮；诊断可分离（禁用后直接以 ot 重入循环）。
- **提示契约**：三个 LLM 位置（检索与激活 / 原语交互 / 验证与诊断）均使用固定四段输入与固定输出 schema；返回不可解析、缺字段或保留测试失败则拒绝并重试最多 3 次，仍失败则交回仓库层处理（记为不成功适配）。
