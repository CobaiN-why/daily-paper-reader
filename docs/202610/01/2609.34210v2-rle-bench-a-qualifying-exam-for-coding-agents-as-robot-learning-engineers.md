## 摘要
编码智能体正开始超越纯数字任务，去应对物理世界中的挑战，尤其是在机器人领域。然而，现有的机器人基准主要关注单个产物（如策略或控制器）的性能，对编码智能体更广泛的工程能力的覆盖有限。现实世界的机器人技术不止于控制：智能体必须在资源约束下构建、集成、诊断和改进异构产物，并基于多模态反馈进行推理。为评估这些更广泛的能力，我们提出了 RLE-Bench，这是一个机器人学习任务基准，涵盖四类代表性的机器人开发工作流：交互控制、策略学习、感知与估计以及机械设计。我们使用多样化的任务特定指标来评估编码智能体提交的产物，从智能体取得的成功率，到训练出的策略智能体、构建的测试框架，以及智能体设计的机械结构。我们将这些指标汇总为总体 RLE 指数，并报告特定工作流的能力画像，从而能够在多个能力维度上系统比较编码智能体的能力。除性能排名之外，我们还开展深入的案例研究，考察智能体在代表性任务上的行为，既突出其当前能力与局限，也指出机器人任务为未来智能体训练带来的机遇。

## Abstract
Coding agents are beginning to move beyond purely digital tasks to tackle physical-world challenges, particularly in robotics. Existing robotics benchmarks, however, primarily focus on the performance of individual artifacts, such as policies or controllers, offering limited coverage of coding agents' broader engineering capabilities. Real-world robotics extends beyond control: agents must build, integrate, diagnose, and improve heterogeneous artifacts under resource constraints and reason from multimodal feedback. To evaluate these broader capabilities, we introduce RLE-Bench, a benchmark of robot-learning tasks spanning four representative robotics development workflows: interactive control, policy learning, perception and estimation, and mechanical design. We use diverse task-specific metrics to evaluate the artifacts submitted by the coding agents, from the success rate the agents achieved to the policy agents trained, the harness agent built, and the mechanical structures the agent designed. We aggregate these metrics into an overall RLE Index and report workflow-specific capability profiles, enabling systematic comparison of coding agents' capabilities across multiple capability dimensions. Beyond performance ranks, we also conduct in-depth case studies examining agent behavior on representative tasks, highlighting both current capabilities and limitations, and pointing to the opportunities robotics tasks have to offer for future agent training.

## 1. 核心问题与研究动机

- **背景**：编码智能体已从代码补全走向长程工程任务——能浏览陌生仓库、编写并执行程序、解读测试失败并迭代修改产物。SWE-bench、Terminal-Bench、MLE-bench、MLE-Dojo 等基准使这一转变可被度量。
- **缺口**：机器人领域是 LLM 智能体迈向物理世界的"大挑战"，需要理解时空关系、推理决策的物理后果、依据多模态反馈调整行为。但现有机器人基准（LIBERO、RoboTwin、RoboDojo、IsaacLab、ManiSkill 等）主要评估**单个产物**（策略、控制器、VLA/WAM 模型）的性能，无法覆盖编码智能体在机器人开发全流程中的工程能力。
- **最接近的工作**：CaP-X 系统评测了"代码即策略"的控制器生成能力，但仍局限于把代码写成策略，未覆盖整体机器人学习工作流。
- **核心研究问题**：*通用编码智能体能否胜任机器人学习工程师那种多样、迭代、物理接地的工作？*
- **论文定位**：提出 RLE-Bench，把机器人学习任务当作编码智能体的"资格考试"，覆盖 4 类工作流、9 个任务族、共 51 个任务。

## 2. 方法论

### 2.1 核心思想
- 不再孤立评估策略/控制器，而是评估智能体能否**构建、集成、诊断并改进异构产物**（控制代码、训练策略、感知系统、机械结构），且必须在资源预算约束下、依据物理仿真器的多模态反馈迭代完成。
- 每个任务分为**开发阶段**（在公开环境 `E_dev` 中交互并提交产物 `a`）与**评估阶段**（验证方在私有环境 `E_eval` 中评测）。

### 2.2 任务形式化
任务定义为一个元组：**τ = (I, E_dev, B, A, E_eval, M)**
- `I`：纯文本任务指令
- `E_dev`：公开开发环境（如带 RoboCasa 模拟器连接的临时工作区）
- `B`：预算（挂钟时间、交互步数、算力等）
- `A`：可执行产物契约
- `E_eval`：验证方控制的评估环境（隐藏场景、动力学、本体、随机种子、留出任务）
- `M`：验证器，唯一权威评分来源

### 2.4 编排与评估协议
- 所有任务以 **Harbor 环境**形式发布，智能体获得指令、产物契约、公开资产、工具与受资源约束的开发会话。
- 开发结束后产物**跨入验证方镜像**，隐藏种子、特权状态、参考资产全部对智能体不可见，防止信息泄漏。
- 验证器在沙箱/受限子进程中加载产物，执行物理 rollout，产生唯一权威奖励报告。

### 2.5 评分聚合
三层聚合（公式 2）：
- 族内子任务平均 → 族分 `S_j,k`
- 工作流内族分平均 → 工作流分 `S_k`
- 四个工作流等权平均 → **RLE Index** `S_RLE = (1/4) Σ_{k=1..4} S_k`

即每个工作流族权重相同，因此 RLE Index 不等于 9 个族列的简单平均。

- **规模**：51 个任务 × 11 个模型–框架组合 ≈ **561 次完整评测运行**，成本覆盖 51/51（除 Grok 与 Gemini 外）。

- **消融/机制分析充分**：
  - F01 的三级脚手架消融（L1/L2/L3）直接量化"外部模块收益随模型变强而衰减"。
  - F05 记录了 36 个开发会话的完整进度曲线，并对比开发期评分与官方评分的差距（开放设计 vs. 鲁棒性赛道）。

  - F08 拆解为 14 项检查点的子分数，暴露"通过可见目标但违反耦合物理约束"的模式。

## 6. 主要结论与发现

论文以 7 条 Finding 组织结论：

1. **视觉接地是关键区分因素**：GPT-6 Astra 与 Claude Fable 5.1 显著领先，优势集中在交互控制与感知估计这两个需要解读多模态观测、反复响应环境反馈的工作流。
2. **策略开发上模型

- **策略开发上模型能力呈明显分层**：需要训练并提交 checkpoint 的工作流（F04 全身运动跟踪、F05 nanoVLA 配方工程）区分度显著——头部模型能产出可被评估器加载并稳定跟踪的 ONNX 策略，而中后段模型常出现训练不收敛、动作抖动或提交物与契约不符（如缺少元数据、接口不匹配）的问题。该工作流对"配方工程"（数据/超参/课程设计）而非单纯写代码的依赖，使模型差距被进一步放大。
- **感知估计任务暴露"会用深度"与"能写出鲁棒估计器"之间的鸿沟**：F06 显示多数模型在 RGB-D 赛道上能借助深度图快速降低误差，但一旦切换为方法无关赛道或引入遮挡/缺失深度，误差回升明显；只有少数模型稳定实现表面滤波 + XY 深度 + 遮挡掩码 + NN 回退的组合策略。即深度线索是"易得分点"，而鲁棒估计器设计才是"真区分点"。
- **机械设计任务的核心失败模式是"违反耦合物理约束"**：F08/F09 表明模型能做出在可见目标上"看起来可用"的 MJCF 设计，但在静态/动态稳定性、载荷承受、结构有效性等隐藏检查点上频繁失分。模型倾向于优化显式任务指标，而忽视刚体耦合、重心、关节限位等隐性约束——这与"通过可见目标但违反耦合物理约束"的诊断结论一致。
- **外部模块/脚手架的边际收益随模型变强而衰减**：F01 的 L1→L2→L3 消融显示，加入分割与抓取建议（L2）、特权位姿（L3）对弱模型的提升远大于对强模型的提升；强模型在 L1 基础 API 上已能自行完成大部分感知与规划，脚手架反而可能引入噪声或限制其探索空间。这提示"给工具"与"给能力"存在替代关系。
- **开发期反馈存在乐观偏差风险**：F05 的开发期评分普遍高于官方评分，说明在可查询评估服务的环境下，智能体易对开发分布过拟合；开放设计赛道与鲁棒性赛道之间的落差，进一步印证了"能拿分"不等于"能泛化"。
- **成本–性能呈现明显分层与错配**：在性能–成本权衡中，头部闭源模型（GPT-6 Astra、Claude Fable 5.1）以较高 API 成本换取领先 RLE Index；部分开源/低价模型（DeepSeek-V4.1-Flash、GPT-5.6 Luna）以极低成本达到中位水平，性价比突出；而个别高价模型（Claude Opus 4.8）得分反而偏低，说明成本并不直接决定工程能力。同时，失败状态（超时未提交）与低分需要区分对待——前者是可靠性问题，后者是能力问题。

## 7. 结论与启示

- **核心结论**：通用编码智能体已具备一定机器人学习工程能力，但远未达到"机器人学习工程师"的可靠性水平。最强模型在部分工作流上接近可用，而在机械设计、鲁棒感知与策略泛化上仍存在系统性短板。
- **能力画像**：模型优势集中在"可交互、可反馈、可局部迭代"的任务（交互控制、感知估计）；劣势集中在"隐性约束多、反馈稀疏、需物理直觉"的任务（机械设计、训练策略）。
- **对基准设计的启示**：RLE-Bench 的价值在于把"机器人学习"从单产物评测扩展为**全流程工程能力评测**——开发/评估分离、隐藏环境、预算约束、可执行产物契约，共同构成一个可复现、可防止信息泄漏的评测框架。
- **对智能体开发的启示**：外部模块与脚手架应"按需提供"，过度辅助可能抑制强模型的自主能力；同时需警惕开发期反馈带来的过拟合，评测应保留留出任务与隐藏动力学。

## 8. 局限与未来工作

- **方差与重复性**：每个任务族仅报告选定单次运行，未给出多种子重复下的方差，难以区分"能力差距"与"随机波动"。
- **成本数据不完整**：Grok 4.6 与 Gemini 3.7 Flash 因框架与 Harbor 不兼容而缺失 token/成本统计，影响成本–性能分析的完整性。
- **阈值暂定**：F04 除舞蹈外的四个动作跟踪阈值仍为 provisional，可能影响该族的绝对分数可比性。
- **任务覆盖**：虽覆盖 4 类工作流 9 个族，但每族实例数有限（部分仅 1 个任务、多实例变体），对真实机器人工程的长尾场景覆盖仍不足。
- **未来方向**：引入多轮重复与统计显著性检验、补齐缺失成本核算、将任务扩展至更真实的硬件闭环（sim-to-real）与更长程项目级工程流程。
