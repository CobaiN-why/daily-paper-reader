## 摘要
语言模型智能体越来越多地处理长时程任务，这些任务的交互历史超出模型的活跃上下文。近期工作已开始使用强化学习将记忆控制纳入策略，通常依赖相对短时程的领域特定训练环境中的预定义记忆工具。这种设置将学到的记忆行为绑定到环境特定的接口上，这些接口位于基座模型预训练之外，必须从头学习，因此即使在后训练之后，智能体仍难以在长时程任务中使用记忆。为解决这些限制，我们提出 Coding Agent Memory Gym (CAMG)，一套涵盖 Shop、Coding、DeepResearch 和 AutoResearch 的长时程智能体强化学习环境。除每个环境原生的任务接口外，CAMG 还提供可执行的 shell 访问和回合持久工作区，使智能体能够在整个回合中创建、修改、搜索并复用文件作为记忆。我们还提出 CAMG-RL，它使用完全异步 PPO 在全部四个环境中联合训练单一策略，直接从下游任务奖励中学习这种基于文件的记忆行为；我们基于规模匹配的 Qwen3.5 模型训练了 CAMG-RL-4B 和 CAMG-RL-9B。在 SWE-bench Verified 和 MLE-bench Lite 上，CAMG-RL-4B 和 CAMG-RL-9B 分别与 Qwen3.5-35B-A3B 和 Qwen3.5-122B-A10B 具有竞争力。

## Abstract
Language-model agents increasingly tackle long-horizon tasks whose interaction histories exceed the model's active context. Recent work has begun to use reinforcement learning to make memory control part of the policy, often relying on predefined memory tools within domain-specific training environments of relatively short horizons. This setup ties learned memory behavior to environment-specific interfaces that lie outside the base model's pre-training and must be learned from scratch, so even after post-training, agents struggle to use memory in long-horizon tasks. To address these limitations, we introduce Coding Agent Memory Gym (CAMG), a suite of long-horizon agentic-RL environments spanning Shop, Coding, DeepResearch, and AutoResearch. Alongside each environment's native task interface, CAMG provides executable shell access and an episode-persistent workspace, enabling agents to create, revise, search, and reuse files as memory throughout an episode. We also introduce CAMG-RL, which trains a single policy jointly across all four environments with fully asynchronous PPO, learning this file-based memory behavior directly from downstream task reward, and we train CAMG-RL-4B and CAMG-RL-9B from Qwen3.5 models of matching size. On SWE-bench Verified and MLE-bench Lite, CAMG-RL-4B and CAMG-RL-9B are competitive with Qwen3.5-35B-A3B and Qwen3.5-122B-A10B, respectively.

## 2. 方法论

### 2.1 核心思想
- 用**普通编码智能体文件操作**作为记忆机制，而非专门的记忆工具。
- 一个任务执行策略（task-acting policy）在**回合持久工作区**（episode-persistent workspace）中通过 shell 命令维护记忆文件；记忆文件的创建与复用由**下游任务奖励**塑造。

### 2.2 CAMG 环境套件
- 四个长时程环境，均要求跨上下文边界保留信息：
  - **Shop**：6 个依赖式购物会话（720 个 WebShop 验证商品；会话间清空会话记录，后续购买依赖策略自己保留的信息）。
  - **Coding**：SWE-smith 软件修复（从 59,136 个实例中筛选出 11,218 个可执行任务，来自 93 个仓库）。
  - **DeepResearch**：LiteResearcher 的 Search–Visit–Answer 流程（合并两个版本，26,597 个任务，冻结语义判官评分）。
  - **AutoResearch**：公开 OpenMLE 任务包（931 个任务、804 个任务族，原生指标评分）。
- **统一接口**：每个环境在原生任务接口之外，提供单一 `shell_command` 文件系统动作 + 回合私有持久工作区。动作空间为并集：
  - `A_d = A_d^task ∪ A^fs`，一个 `shell_command` 可同时产生任务效果与文件效果。

### 2.3 上下文替换与记忆文件协议
- 环境在上下文压力或子回合边界触发替换，并提示策略用一次普通文件动作写 `.agent_memory/CONTINUATION.md`（8,192 字节上限）。
- 是否合规由策略自行决定；环境不代为写入或清空。
- 只有验证该文件被写成非空常规文件后，环境才替换活跃消息历史；替换后**不插入文件内容**，策略需通过后续文件读取自行恢复状态。
- 只有 `.agent_memory/` 下的常规文件算作"策略记忆"；仓库编辑、模型文件、缓存不算。

### 2.4 CAMG-RL 训练算法
- **联合目标**：单一策略在四个环境上均匀采样，目标为各环境目标的等权平均：
  - `J_CAMG-RL(θ) = (1/|D|) Σ_{d∈D} J_d(θ)`，`|D| = 4`。
- **轨迹构造**：每个完整响应视为一个 RL 步（action-level）；响应可先输出自由推理，再以可执行动作结束；任务动作与文件系统动作在同一条轨迹上。
- **双粒度 PPO（Dual-granularity PPO）**
  - 响应级估计一个优势（稳定，因每个响应只收到一个奖励）；
  - token 级对每个采样 token 裁剪一个概率比（更新细粒度）；
  - 兼顾 Turn-PPO（太粗）与 SAO（太细、高方差）的优缺点。
- **信用分配**
  - 用响应轴上的 GAE（γ = λ = 1）计算优势，赋给该响应内所有采样 token；
  - 按环境 token 数做逆权重加权与掩码标准化；
  - 策略生成的文件内容 token 同样被 PPO 优化。
- **完全异步 PPO**
  - rollout 与 learner 独立运行：rollout worker 把完成的回合放入持久队列，learner 取最早的 N=64 个完整回合组成优化批次，更新共享 actor/critic 并把新权重提供给后续回合。
  - 队列吸收不等长回合的完成时间，避免 worker 等待最慢的回合。
- **奖励设计（稀疏、基于成功）**
  - Shop：正确购买 `r̃=1`（第 1–5 次）/`r̃=2`（第 6 次），错误/非法动作 `-0.01`；
  - Coding：仅隐藏测试通过 `r_T=1`，检查点写入失败 `-0.1`；
  - DeepResearch：仅语义判官接受 `r_T=1`，非法动作 `-0.02`；
  - AutoResearch：`r_T = min(1, max(0, s_T)+0.1)`，并有首次成功执行 `+0.05`、首次验证指标 `+0.10` 两个一次性里程碑。

## 6. 主要结论与发现

- **主结果**：CAMG-RL 在四个测试环境上的等权平均成功率达 **54.4%**，高于最强基线 CompactionRL（48.0%）与 AgeMem（25.3%）；在 Coding 与 AutoResearch 上优势显著（配对区间不含零）。
- **外部迁移**：
  - CAMG-RL-4B 在 SWE-bench Verified 达 15.8%、MLE-bench Lite 4.5%，与 Qwen3.5-35B-A3B 相当；
  - CAMG-RL-9B 达 27.6% 与 9.1%，与冻结的 Qwen3.5-122B-A10B 相当（SWE-bench 上甚至略高）。
- **预训练先验是关键**
  - 冻结基座对文件系统记忆动作的 surprisal 为 **0.076–1.193 nats/token**，AgeMem 的六种专用工具在每种意图上都更"惊讶"；
  - 改名为未见过的工具名仅改变 ≤0.013 nats/token，说明先验来自文件系统动作本身而非工具名。
- **RL 将先验转化为完整记忆链**
  - CAMG-RL 的完整 store–retrieve–use 链从第一季度的 8.0% 升到最后一季度的 **20.9%**；
  - AgeMem 在 261,941 个响应中仅尝试 53 次且从未完成一条链；
  - 两者权重移动都很小（相对权重变化 0.22% vs 0.19%），但只有 CAMG-RL 把这点移动转化为完整记忆链。
- **记忆内容有因果作用**：清空记忆内容平均降低 **14.1 个百分点**，替换为异任务内容降低 **11.5 个百分点**，四环境均下降。
- **Coding 剩余瓶颈**：94 个失败中 61.7% 是"修复错误"、37.2% 是"预算耗尽未提交"；94 个跨边界回合中每一个都在边界写入并读回检查点，说明记忆机制本身已在运行，瓶颈在修复质量与动作预算。
- **组件归因**：移除记忆动作梯度使平均分降至 21.1

% 以下（相对完整模型下降约 33 个百分点），说明记忆行为的习得确实依赖针对记忆 token 的梯度信号，而非仅靠任务奖励的间接传导；
  - 移除通用记忆文件（仅保留 continuation 文件）后性能同样大幅回落，表明"可自由命名的持久文件工作区"这一通用接口比单一续写文件更关键；
  - 用逐 token GAE 替换响应级优势估计后训练不稳定、最终分数下降，验证了双粒度 PPO 在"每个响应只有一个奖励"这一设定下的必要性；
  - 将原生 shell 文件编辑替换为单个 Codex 风格 `apply_patch` 工具后表现变差，说明收益来自预训练中已经充分覆盖的通用文件系统动作，而非某种特定工具形态。

## 7. 局限与不足

- **环境仍是受控的合成长时程设定**
  - CAMG 的上下文替换由环境在压力阈值或子回合边界处**显式触发**，并配有统一的 `.agent_memory/CONTINUATION.md` 协议提示。真实部署中"何时该压缩、压缩成什么"需要智能体自主判断，论文并未验证策略能否自行决定压缩时机与粒度。
  - 8,192 字节的记忆上限、单一持久工作区等约束是人为设定的，其对更长时程、多智能体协作场景的可扩展性未做讨论。
- **记忆形态被限定为文件**
  - 论文的核心主张是"释放预训练已有的文件操作先验"，因此有意排除了向量库检索、结构化数据库、embedding 记忆等机制。这不构成缺陷，但意味着结论的适用范围被限定在"文件即记忆"这一范式内；当任务需要语义相似度检索而非精确路径访问时，该方案的相对优势可能减弱。

  - 论文未披露 GPU 型号与生成侧的具体规格，也未给出超参数（学习率、KL 系数、PPO 裁剪范围）的完整清单，对第三方复现构成一定障碍。
  - 完全异步 PPO 的队列策略（取最早 64 个完成回合）会引入离线程度随负载变化的隐式偏差，论文未量化其对收敛的影响。

## 8. 批判性评价与启示

- **概念贡献大于算法贡献**
  - 双粒度 PPO、异步 PPO、GAE 信用分配都是已有技术的组合与工程化适配，真正的新意在于**问题重述**：把"记忆机制设计"问题转化为"如何用 RL 释放基座已有的文件操作先验"。这一视角使得记忆接口不再需要从零学习，从而绕开了 AgeMem 类方法最致命的冷启动问题。
- **界面先验探针是全文最有说服力的证据**
  - 通过 surprisal 对比直接证明：冻结基座对 `shell_command` 类文件动作的困惑度远低于对专用记忆工具的困惑度，且改名几乎无影响。这为"用熟悉接口而非新接口"的设计原则提供了可测量的实证支撑，其方法论价值超出本文任务本身，可迁移到其他需要引入新工具/新动作空间的智能体训练工作中。
- **"权重移动小、行为变化大"的解释需谨慎**
  - CAMG-RL 与 AgeMem 的相对权重变化量级相近（0.22% vs 0.19%），但只有前者形成了完整记忆链。论文据此论证"关键在于先验而非更新幅度"，逻辑自洽，但两者训练数据、奖励与优化目标不同，权重变化量并非受控比较量，这一论据更宜视为**辅助观察**而非因果证明。
- **对工程实践的启示**
  - 在构建长时程智能体时，优先复用基座已见的动作语义（文件读写、shell），把新能力放在**策略如何使用**而非**接口长什么样**上；
  - 记忆内容的因果干预（blank/shuffled 均显著掉分）提示：即便记忆机制"被调用"，内容的正确性与任务相关性仍是性能瓶颈，单纯统计"是否调用记忆"会高估系统能力；
  - Coding 的失败分析（61.7% 修复错误、37.2% 预算耗尽）说明记忆机制解决的是"信息可得性"，而非"推理质量"，后续提升应回到代码修复能力与动作预算管理本身。

## 9. 一句话结论

论文证明了：在代码预训练基座上，通过端到端 RL 让智能体用**普通文件系统动作**充当长时程记忆，其效果显著优于引入专用记忆工具的方案——记忆能力的瓶颈不在接口新颖度，而在能否激活基座已有的动作先验，以及策略能否把这一先验转化为完整的"存储—检索—使用"闭环。
