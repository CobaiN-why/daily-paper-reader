## 摘要
围绕语言模型的运行框架是智能体性能的核心决定因素。近期方法通过在完整程序上进行搜索来优化运行框架，其中单个机制难以被分离和复用。我们提出 PluginRSI，它将运行框架表示为原子化插件的组合，并围绕这些插件组织运行框架的演化。单个插件被独立改进并累积到共享库中，然后在每次迭代中重新组合成新的运行框架。PluginRSI 在软件工程、命令行交互和问答任务上优于现有的运行框架优化方法。所得运行框架在迁移到其他求解器模型时无需进一步优化即可保持其优势。演化后的插件库可从初始运行框架加速后续优化，有助于在未见任务上更快、更高地收敛。这些结果表明，累积可复用机制为持续改进运行框架提供了有效基础。

## Abstract
The harness surrounding a language model is a central determinant of agent performance. Recent methods optimize harnesses by searching over complete programs, where individual mechanisms are difficult to isolate and reuse. We introduce PluginRSI, which represents a harness as a composition of atomized plugins and organizes harness evolution around these plugins. Individual plugins are improved independently and accumulated in a shared library, then recombined into new harnesses at each iteration. PluginRSI improves over existing harness optimization methods across software engineering, command-line interaction, and question-answering tasks. The resulting harnesses retain their advantage when transferred to other solver models without further optimization. The evolved plugin library accelerates subsequent optimization from the initial harness, which helps faster and higher convergence on unseen tasks. These results show that accumulating reusable mechanisms provides an effective basis for continued harness improvement.

# PluginRSI 论文总结

## 1. 核心问题与整体含义

- **研究背景**：递归自我改进（Recursive Self-Improvement）是 LLM 智能体研究的重要方向。改进来源有二：更新模型参数，或改进组织智能体交互机制（工具、角色、技能）的 **harness（运行框架）**。harness 优化无需重新训练权重即可适配智能体行为，成本更低。
- **现有方法的局限**：近期工作通过"迭代重写完整 harness 实现"来做递归优化，但存在两个根本问题：
  - **探索受限**：多个机制耦合在同一个 harness 实现中，难以独立探索新机制并验证其贡献，优化容易反复收敛到相似设计。
  - **难以复用**：重写会覆盖有效的局部机制，改进无法沉淀为可跨迭代复用的经验。
- **核心主张**：harness 演化应以"发现新机制并在候选间复用"为中心，而非反复重写整体实现。
- **整体含义**：论文提出 **PluginRSI**，将 harness 表示为原子化插件的组合，围绕插件组织演化——独立改进单个插件、累积到共享插件库、每轮重新组合为新 harness，从而让机制可隔离评估、可累积、可复用。

## 2. 方法论

### 核心思想
- 将 harness 表示为 **插件参数化** 形式：`H = H(W, P)`，其中 `P` 为选定插件集合（实现角色、工具、技能、记忆机制），`W` 为协调插件执行的工作流（决定何时调用、输出如何用于后续交互）。
- 每个插件由两部分组成：(1) YAML 规格（接口、输入输出 schema、prompt、rubric、元数据）；(2) Python 可执行实现。插件通过标准化接口将"机制实现"与"调用它的工作流"解耦。
- 维护一个**共享插件库 L**，保留经验上有效的实现，跨迭代累积与复用。

### 优化目标
- 定义 harness 的期望回报：`J(H) = E_{x∼D, τ∼Φ(·|x,H,Θ)}[r(τ, x)]`，在策略模型 Θ 固定的前提下，寻找最大化该回报的 harness `H*`。
- 递归优化：proposer 智能体 Φ_proposer 基于上一轮最优 harness 及其执行轨迹生成新候选 `Ht ∼ Φ_proposer(· | Ĥt, T_Ĥt)`。

### 算法流程（Algorithm 1）
1. **初始化**：从初始 harness `H0 = H(W0, P0)` 与插件库 L（P0 ⊆ L）出发，在验证集 D_val 上评估。
2. **插件变异（Plugin Mutation）**：每轮并行生成 N 个变异候选，每个候选在单独采样的平衡 minibatch M（b 个任务，正确/错误各半）上评估。proposer 选择一个插件 `pi`，产出修改版 `p'i`，其余插件与工作流保持不变，重编译为 `Hi = H(W, (P\{pi}) ∪ {p'i})`。若 `SM[Hi] > SM[H]`，则将 `p'i` 加入插件库 L。
3. **Harness 重组（Harness Recomposition）**：proposer 审阅历史反馈与变异结果，从更新后的库中选择插件子集 `P' ⊆ L`，并将工作流由 `W` 修订为 `W'`（改善插件协调、调用时机、信息流），编译为 `H' = H(W', P')` 并在完整 D_val 上评估。
4. **接受准则**：若 `S[H'] > S[H]`，则更新当前最优；T 轮后返回最优 harness。
- 两个阶段互补：变异实现**局部机制探索**，重组实现**全局协调改进**。

## 6. 主要结论与发现

- **性能提升**：PluginRSI 在 SWE-bench Verified 上 held-out resolve rate 达 65.00%（GPT 优化）与 69.00%（Kimi 优化），比最佳基线 Meta-Harness 高 **10.00 / 6.00 个百分点**，且 held-out 增益大于 held-in，说明改进可泛化到选择集之外。
- **跨模型迁移**：优化后的 harness 无需再优化即可迁移到其他 solver，仍保持领先（如 GPT 优化的 harness 在 Kimi-K3 上 60.00%、GLM-5.2 上 52.00%）。
- **其他任务**：Terminal-Bench 上 held-out 73.3%（vs Meta-Harness 66.7%）；QA 整体准确率由 0.638 提升至 0.675（held-out 0.568→0.588，增益较小）。
- **优化效率**：以更少 solver rollout 即达到更高 held-in 与 held-out 表现，且 held-in 与 held-out 对齐更好。
- **消融结论**：插件变异与 harness 重组均有显著贡献（去掉后 held-out 由 69% 分别降至 57% / 59%）；**仅提供插件库本身收益有限**；去掉初始插件后性能仍基本保持。
- **累积与复用**：插件库从 75 增至 132，候选实现规模达约 1300 LoC，但工作流始终低于 300 LoC（"大插件 + 紧凑工作流"）；复用演化库可从初始 harness 在 2 步内达到 69%（无复用为 65%）。

## 7. 优点

- **问题切分巧妙**：将 harness 原子化为插件，使单个机制可隔离评估、可独立改进、可跨候选复用，直接针对现有重写范式的两大痛点。
- **累积式改进机制**：共享插件库使局部改进得以沉淀，形成可持续的递归自我改进基础，而非每轮从零重写。
- **两阶段互补设计**：变异（局部、并行、平衡 minibatch 提供多样反馈）与重组（全局、协调、工作流修订）结合，兼顾探索与整合。
- **实验较为扎实**：跨 3 类任务、多骨干、跨模型迁移、消融、动态曲线、插件累积统计与 token 成本分析，论证链条完整；并单独消融验证"库本身不等于增益"。
- **工程细节透明**：给出了插件 manifest 示例、接口定义、proposer prompt、文件操作协议、数据划分与子域分布，可复现性较好（附代码仓库）。

## 8. 不足与局限

- **任务分布固定**：仅在固定任务集、有限迭代轮数（T=15）上评估，未探索任务分布变化下的长期演化，以及插件库持续增长后的管理问题。
- **迁移依赖领域**：机制迁移受任务域与 solver 模型影响，跨不相似 QA 域（如数学→法律）增益明显偏小；跨域/跨模型联合优化有待研究。
- **变异评估的局部性**：插件变异在"其余 harness 固定"的假设下评估单个改动，可能漏掉需要多个插件或工作流协同变化才能生效的机制；未来需插件—工作流联合优化。
- **算力信息缺失**：未报告 GPU 型号、数量与时长；由于依赖闭源 API 模型（GPT-5.6、Kimi-K3、GLM-5.2），结果的可复现性与成本可控性受 API 可用性限制。
- **比较公平性细节**：基线运行 25 轮 vs 方法 15 轮，虽以 rollout 对齐解释，但轮数差异可能对某些基线不利或有利，需谨慎解读；个别 held-in 跨模型场景出现性能略降（如 58.00% vs 58.25%），论文以"可比"处理。
- **应用限制**：自动演化出的 harness 可能生成有误代码或非预期命令，部署到真实环境需人工代码审查与执行权限管控（作者在伦理声明中亦提及）。
