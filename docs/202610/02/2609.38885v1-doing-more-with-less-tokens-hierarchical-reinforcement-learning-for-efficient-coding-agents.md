## 摘要
近年来，编码智能体已成为真实世界软件工程（SWE）场景中的主流范式，其通过与开发环境进行多轮交互来解决复杂任务。然而，频繁与环境交互不可避免地会带来大量 token 开销，导致较高的使用成本和延迟。尽管近期研究已探索通过在推理阶段进行上下文操控和交互限制来减少 token 使用量，但这些方法侧重于提升 token 效率，却忽视了丢弃任务相关信息所带来的风险，因而难以在解决率与 token 效率之间取得平衡。在本文中，我们研究一种不受该局限影响的更通用范式，即训练兼具良好解决性能与 token 高效性的编码智能体，这是一个极具实践价值但尚少探索的问题。为此，我们揭示了 SWE 场景中的两个核心观察：i）效率差异：成功解决任务可以用更少的 token 实现；ii）熵相关性：非生产性行为与轮次级熵相关。受这些观察启发，我们提出了一种新颖的强化学习框架，称为 HERO。具体而言，HERO 在策略优化过程中优先考虑任务解决而非 token 效率，并在轨迹级和轮次级上鼓励高效的推理模式。在 SWE-bench Verified 和 SWE-bench Multilingual 上的大量实验表明，与最先进的编码智能体和强化学习方法相比，HERO 在解决率与 token 效率之间实现了良好的权衡。

## Abstract
Recently, coding agents have emerged as a dominant paradigm for real-world software engineering (SWE) scenarios, which solve complex tasks through multi-turn interactions with development environments. However, frequent interactions with environments would inevitably introduce substantial token overhead, leading to high usage costs and latency. Although recent studies have explored reducing token usage by context manipulation and interaction limits at inference time, these approaches focus on improving token efficiency while overlooking the risk of discarding task-relevant information, thus struggling to balance the trade-off between resolution rate and token efficiency. In this paper, we study a more general paradigm without suffering from the limitation, i.e., training token-efficient coding agents with promising resolution performance, which is a highly-practical yet less-explored problem. To this end, we reveal two core observations in SWE scenarios: i) Efficiency Variation: successful resolution could be achieved with fewer tokens; ii) Entropy Correlation: unproductive behaviors are associated with turn-level entropy. Motivated by observations, we propose a novel reinforcement learning framework, dubbed HERO. Specifically, HERO prioritizes task resolution over token efficiency during policy optimization and encourages efficient reasoning patterns at both trajectory and turn levels. Extensive experiments on SWE-bench Verified and SWE-bench Multilingual demonstrate that HERO achieves a favorable trade-off between resolution rate and token efficiency compared with state-of-the-art coding agents and reinforcement learning methods.

## 2. 方法论：HERO 框架

### 2.1 问题形式化

- 给定仓库级任务 $x_i=(r_i, s_i)$，编码智能体 $A$ 与环境交互 $n_i$ 轮后生成解决方案，由测试驱动协议判定解决结果 $y_i \in \{0,1\}$。
- 累计 token 用量 $c_i = \sum_{j=1}^{n_i} t_{i,j}$，其中 $t_{i,j}$ 为第 $j$ 轮的输入+输出 token。
- 优化目标为 **Token-efficient Resolution Score（TRS）**：$\text{TRS} = \dfrac{R}{\sqrt{1+C}}$，其中 $R$ 为平均解决率（%），$C$ 为平均累计 token 用量（百万），TRS 越高表示解决率与 token 效率的权衡越优。

### 2.2 核心思想

HERO（HiErarchical ReinfOrcement learning）通过**分层策略优化（HPO）**与**多粒度效率信用分配**，在策略优化中**始终优先保证任务解决**，待具备足够解题能力后再激活效率优化。

### 2.3 关键技术细节

**(1) 分层策略优化（HPO）**

- 总优势：$A_i = A_i^{\text{res}} + w \cdot A_i^{\text{eff}}$，其中 $A_i^{\text{res}}$ 为基于 GRPO 的组相对优势（以 0/1 解决结果为奖励），$A_i^{\text{eff}}$ 为效率优势，$w$ 为效率门控权重。
- **效率门控机制**：$w = \lambda \cdot \text{clip}\left(\dfrac{p-\tau}{1-\tau}, 0, 1\right)$，$p$ 为组内平均解决率，$\tau$ 为激活阈值。只有当组内解决率达到阈值后，才开启效率优化，实现"先解决、后效率"。
- **解决优先裁剪（Resolution-first Clipping）**：$\Gamma(A_i) = \max(A_i, 0)$ 若 $y_i=1$；$\Gamma(A_i) = \min(A_i, 0)$ 若 $y_i=0$。保证已解决轨迹的优势非负、未解决轨迹的优势非正，防止效率信号覆盖解决信号。

**(2) 多粒度效率信用分配**

- 效率优势分解：$A_{i,j}^{\text{eff}} = A_i^{\text{coarse}} + A_{i,j}^{\text{fine}}$。
- **粗粒度轨迹优势（解决校准）**：
  - $u_i = 1 - \tanh\left(\max\left(\dfrac{c_i}{B^{y_i}} - 1, 0\right)\right)$，其中 $B^{y_i}$ 为组内**相同解决结果**子集的中位 token 用量。
  - $A_i^{\text{coarse}} = \dfrac{u_i - \bar{u}}{\sigma_u}$（组内标准化）。
  - 关键点：在**同一解决结果的子集内**校准效率奖励，避免把 token 效率与解决率混为一谈。
- **细粒度轮次优势（熵感知）**：
  - $A_{i,j}^{\text{fine}} = -\tanh\left(\dfrac{1 - h_{i,j}}{q}\right)$ 若 $h_{i,j} < q$，否则为 0。
  - $q = \text{Percentile}_{0.2}(\{h_{i,j}\})$，即组内所有轮次熵的最低 20% 分位。
  - 惩罚低熵轮次（潜在非生产性行为），从而减少无效交互带来的 token 开销。
- 熵估计：基于 top-10 token 概率计算 token 级熵，再对轮次内 token 求平均得到轮次级熵。

## 6. 主要结论与发现

- HERO 在 SWE-bench Verified 与 Multilingual 上均实现了**解决率与 token 效率的更优权衡**，TRS 指标显著优于现有编码智能体和 RL 方法。
- 使用仅 640 个训练任务，HERO 将 Qwen3.5 变体的平均解决率从 37.4% 提升至 42.2%；相比 GRPO，在 token 用量减少 39.8% 的情况下取得更好的解决率提升。
- **训练动态**：HERO 先提升解题能力（token 用量在 step 40 前上升），随后在保持高解决率的同时降低 token 用量，体现"先解决、后效率"的分层优化效果。
- **非生产性行为抑制**：HERO 显著降低了重复工具调用、过度探索、工具错误的频率。
- **推理模式**：HERO 在后期轮次从"检查"转向"执行"，与 GRPO 的推理进程相似但 token 更少，说明高效推理模式被内化而非削弱必要步骤。
- **与推理时方法互补**：HERO 训练后的模型仍可受益于推理时方法，且保持较好的前缀缓存复用率与相对推理成本。
- **消融结论**：移除 HPO 会降低 token 但损害解决率；粗粒度与细粒度效率优势均对降低 token 有贡献；解决校准避免效率与解决率混淆。

## 7. 优点

- **问题定位精准**：指出推理时方法的根本局限（丢弃任务相关信息），转向训练阶段内化高效推理模式，视角新颖且实用。

- **效率门控的冷启动问题**：效率优势仅在组内解决率达到阈值 $\tau$ 后才激活，若某类任务初始解决率极低（如多语言中的小众语言），效率优化可能长期不激活，导致这些任务上的 token 效率改善有限，可能加剧不同任务类型间的性能不均衡。
- **组内相对优势的稳定性依赖采样规模**：粗粒度与细粒度优势均在组内做标准化（中位数、分位数），当组内样本数少或解决结果分布极不均衡（如全为失败轨迹）时，统计量估计噪声较大，可能影响信用分配的可靠性。

## 9. 可借鉴之处与启示

- **"先解决、后效率"的课程式优化思路**：把能力门槛作为效率优化的前置条件，是一种可迁移到其他智能体任务（如网页导航、工具调用、多轮检索）的通用训练范式，避免过早引入效率约束导致策略退化。
- **解决结果校准的效率奖励**：在相同解决结果的子集内比较 token 用量，是解决"效率—性能混淆"的简洁而有效的做法，可推广至任何同时存在质量与成本目标的 RL 场景（如推理长度压缩、搜索深度控制）。
- **熵作为非生产性行为的代理信号**：为细粒度信用分配提供了低成本、无需额外标注的监督来源，启发了"用模型自身不确定性定位低效行为"的研究方向。
- **多粒度信用分配的组合设计**：轨迹级解决全局效率、轮次级解决局部浪费，两者分工明确，为长程任务中的稀疏奖励分解提供了可参考的架构。
- **TRS 指标的实用价值**：$R/\sqrt{1+C}$ 用单一标量刻画解决率与 token 成本的权衡，便于工程实践中快速比较不同方案，其形式也可按需替换（如引入成本权重或延迟项）。
- **轻量训练数据的高效利用**：仅 640 个任务即可取得稳定提升，说明在强基座模型 + 精心设计的 RL 目标下，数据规模并非唯一瓶颈，对资源受限的研究团队具有参考意义。

## 10. 总体评价

本文针对编码智能体中"高 token 开销"这一真实且高价值的痛点，提出训练阶段的 HERO 分层强化学习框架。其核心贡献在于：**将"先保证解决、再优化效率"的原则显式编码进策略优化流程**（效率门控 + 解决优先裁剪），并通过**轨迹级解决校准与轮次级熵感知**的多粒度信用分配，在避免效率信号污染解决能力的前提下精准抑制非生产性交互。

从证据强度看，论文在 2 个 benchmark、3 个模型规模上验证了 TRS 的稳定提升，并配有较完整的消融、参数敏感性与多角度分析（训练动态、工具使用模式、前缀缓存、跨脚手架泛化），方法有效性的内部证据较为扎实。主要短板集中在**外部有效性**：模型家族单一（仅 Qwen3.5）、训练任务规模偏小、部分基线未统一调参、算力信息缺失，使其结论的可迁移性与可复现成本仍待第三方验证。

总体而言，这是一篇**问题意识清晰、方法设计精巧、实验分析充分**的工作，其"能力门槛 + 多粒度效率信用分配"的框架具有较好的通用性与工程落地潜力；若能在多模型家族、更大规模数据与统一基线调参上进一步补强，将显著提升其结论的说服力与影响力。
