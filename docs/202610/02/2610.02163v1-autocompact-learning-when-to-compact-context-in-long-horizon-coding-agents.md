## 摘要
编码智能体通过代码检查、搜索、编辑和测试的长轨迹来解决仓库级软件工程任务。随着任务推进，早期的探索会变得过时，因此管理上下文不仅仅是避免溢出：智能体必须决定何时压缩、保留哪些工作状态，以及如何从中继续。我们提出 AutoCompact，它训练编码智能体将这些决策作为其策略的一部分。为了收集训练数据，我们在编码任务上运行基础智能体，并使用评判器审查其压缩决策、摘要以及压缩后的动作。有缺陷的输出会在环境中执行之前被替换为修正后的输出，因此每条轨迹都从修正后的决策继续。我们使用这些轨迹进行监督微调，然后通过以任务成功为奖励的强化学习联合优化编码和压缩。在 SWE-bench Verified 和 SWE-PolyBench Verified 上的实验表明，AutoCompact 相较于基础模型将通过率分别绝对提升 9.2% 和 5.0%。这些改进在所有评估的推理预算下均成立，无论是使用从不溢出的 256K 上下文窗口，还是使用溢出会触发回退压缩的 16K 窗口。

## Abstract
Coding agents solve repository-level software engineering tasks through long trajectories of code inspection, search, editing, and testing. As a task progresses, earlier exploration becomes stale, so managing context is more than avoiding overflow: an agent must decide when to compact, what working state to preserve, and how to continue from it. We introduce AutoCompact, which trains a coding agent to make these decisions as part of its policy. To collect training data, we run the base agent on coding tasks and use a judge to review its compaction decisions, summaries, and actions after compaction. Flawed outputs are replaced with corrected ones before being executed in the environment, so each trajectory continues from the corrected decisions. We use these trajectories for supervised fine-tuning, then jointly optimize coding and compaction through reinforcement learning with task-success rewards. Experiments on SWE-bench Verified and SWE-PolyBench Verified show that AutoCompact improves pass rates over the base model by an absolute 9.2\% and 5.0\%, respectively. The improvements hold across all evaluated inference budgets, with a 256K context window that never overflows and with a 16K window whose overflow triggers fallback compaction.

# AutoCompact 论文总结

## 1. 核心问题与研究动机

- **背景**：仓库级软件工程任务（SWE）中，编码智能体需要经过代码检查、仓库搜索、编辑、测试等长轨迹。随着任务推进，早期探索（假设、失败尝试、冗长工具输出）逐渐过时，继续保留全部历史会把上下文填满陈旧信息。
- **问题本质**：上下文管理不只是"避免溢出"，而是一个策略问题，包含三个子决策：
  1. **何时压缩（when）**：应在当前阶段充分解决后压缩，而非等到长度阈值；
  2. **保留什么（what）**：需要压缩出可用的工作状态（已得结论、相关代码与工作区状态、剩余动作）；
  3. **如何续接（how）**：压缩后需可靠地沿用摘要继续执行，而非重访已完成的探索。
- **现有方法不足**：
  - 长度触发式（如 CompactionRL）把压缩绑定到上下文长度而非任务进度，陈旧探索持续累积，且可能在未解决阶段中途压缩，丢掉仍需要的证据；
  - 主动式方法（SelfCompact 的推理期规则、SWE-Compressor 的离线插入压缩调用）只解决"何时压缩"，不解决工作状态可能遗漏/错误、以及压缩后智能体不遵循摘要的问题；规则法无训练信号，离线插入则保留了原有后续动作。
- **整体含义**：论文把压缩决策（何时、保留什么、如何续接）直接纳入智能体策略，实现模型–框架协同设计（model-harness co-design）。

## 2. 方法论

### 2.1 核心思想
- 为智能体增加一个可主动调用的 `compact()` 动作；调用后，早前交互历史被模型生成的**工作状态摘要**（以 `# Auto Context Summary` 开头）替换，原始任务保持不变，智能体从该上下文继续执行。
- 使压缩成为模型决策，而非单纯应对上下文窗口压力；其有效性依赖上述三种行为。

### 2.2 裁判引导的在线数据采集（Judge-Guided Data Collection）
- 在基座策略上 rollout 编码任务，由裁判（GPT-5.5-Codex）**仅依据当前步可得的历史**逐步审查提议动作，按预定义标注协议判定是否合格。
- 三类修正对应三种主要失效模式：
  - **触发修正（Trigger）**：检查当前是否适合压缩（阶段已解决则压缩，仍需要中间证据则继续探索）；
  - **工作状态修正（Working-state）**：检查摘要是否准确保留后续所需信息（结论、代码与工作区状态、剩余动作）；
  - **续接修正（Continuation）**：检查压缩后的首批动作是否遵循摘要，而非重做已完成探索或忽略既定下一步。
- **关键点**：修正在执行**之前**进行，环境执行的是修正后的输出而非原始输出，因此每次修正都会塑造后续轨迹；这与事后标注（修正不影响后续状态）本质不同。
- 裁判仅用于数据采集，推理阶段被移除。

### 2.3 两阶段训练
- **SFT**：在修正轨迹上用标准下一 token 预测目标微调基座策略，得到 AutoCompact-SFT，同时学到普通编码行为与三类压缩行为。
- **RL**：从 SFT 检查点出发，在 SWE-Gym 上用 GRPO + 全异步 RL 系统做端到端多轮训练。
  - 奖励：仅用二值结果奖励（最终 patch 是否通过任务测试），组内相对优势在轨迹内所有模型生成 token 间共享，**覆盖编码动作、`compact()` 决策、摘要生成与压缩后续接**；
  - 无压缩专用辅助目标、无压缩特定奖励塑形、无 KL 惩罚、无熵奖励；
  - **序列切分**：由于 `compact()` 会重写上下文，轨迹不再满足"每轮在增长前缀上条件化"的单一序列假设；论文在上下文前缀被重写处将轨迹切分为若干段，段内前缀单调增长，全轨迹共享同一优势，策略损失在 batch 内对所有段的 token 做平均。

## 6. 主要结论与发现

- **主结果**：AutoCompact 在 SWE-bench Verified 达 39.6%、SWE-PolyBench Verified 达 24.5%，相对 Base（30.4%、19.5%）绝对提升 **9.2%** 与 **5.0%**。
- 长度触发式压缩收益有限：Fixed Compaction 甚至低于 Base（−1.6%、−0.9%）；CompactionRL 有提升但明显落后 AutoCompact。
- **主动压缩在全历史可容纳时仍有益**：256K 下所有主动式方法均优于 Base，说明保留完整历史并非最优，陈旧信息会造成干扰。
- **SFT 与 RL 均带来增益**：AutoCompact-SFT 超过 SWE-Compressor 1.2%/1.6%（提示在线裁判修正优于离线插入）；RL 在 SFT 基础上再提升 7.4%/2.8%，且在低预算区间增益最大，说明 RL 提升的是成本效率而非单纯拉长轨迹。
- **RL 在无压缩专用奖励下改善压缩行为**：主动压缩率从 SFT 的 44.3% 升至 58.5%（Base 约 0%），同时关键状态遗漏率由 3.1% 降至 0.2%，下一步动作遗漏率由 8.2% 降至 2.2%。
- **主动压缩可与长度触发回退互补**：16K 共享回退设定下仍全面优于 Base（如 $0.10 处 +55 个/500 任务）。
- **执行压缩本身有贡献**：同一检查点忽略摘要时 pass rate 下降，$0.10 预算处优势达 19.9%，$4.00 处仍为 1.9%。
- **摘要自洽性（self-consistency）**：SFT 摘要可能"记录了未解决的语法错误却建议直接收尾"，最终因 SyntaxError 失败；RL 摘要的状态与下一步动作一致，任务通过——说明摘要质量不止于信息覆盖，还在于状态能否约束后续动作。

## 7. 优点

- **数据采集机制有针对性**：在线裁判修正在执行前生效，使修正真实影响后续轨迹，直接监督"压缩后如何行动"这一前人未监督的环节，优于离线插入与纯规则引导。
- **显式建模三类失效模式**，并为每类给出修正示例，问题分解清晰。
- **训练信号极简而统一**：仅用任务成功的二值奖励同时优化编码与压缩，无需压缩专用奖励塑形或辅助目标，避免人工设计奖励带来的偏差。
- **工程细节扎实**：针对 `compact()` 重写上下文导致的训练序列不连续，提出分段 + 共享优势的处理方式；完全异步 RL 与 GRPO 结合。
- **消融设计有说服力**：用同一检查点"遵循 vs 忽略摘要"分离参数收益与执行收益，回应了"提升是否只是训练得更强"的质疑。
- **多维度评估**：覆盖 256K/16K 两种上下文制度与 6 档成本预算，兼顾性能与成本效率；行为指标与定性案例互相印证。
- **模型–框架协同设计的定位明确**，对现有工业 harness（Codex、Claude Code 的长度触发自动压缩）有直接可借鉴意义。

## 9. 总体评价与启示

- **定位准确**：论文抓住了长轨迹编码智能体中的一个真实且被低估的问题——上下文管理的本质是"何时压缩、保留什么、如何续接"的策略问题，而非单纯的窗口溢出问题，并将其形式化为可学习的智能体动作。
- **方法简洁有效**：以"新增一个可调用动作 + 裁判在线修正采数据 + 二值结果奖励端到端 RL"的最小设计，同时解决了触发时机、工作状态质量与压缩后续接三个环节，避免了为压缩单独设计奖励或辅助目标，方法可迁移性强。
- **对工业实践的直接价值**：现有主流 harness（Codex、Claude Code 等）多采用长度触发式自动压缩，本文结果（Fixed Compaction 低于 Base）提示这类默认策略可能并非最优；把压缩决策交给模型、并以任务进度而非长度作为触发依据，是更具性价比的替代方案。
- **可复现性中等**：核心训练流程与超参有描述，但裁判模型闭源、算力未披露、行为指标测量依赖启发式筛选，独立复现并严格对齐结论的难度较高。
