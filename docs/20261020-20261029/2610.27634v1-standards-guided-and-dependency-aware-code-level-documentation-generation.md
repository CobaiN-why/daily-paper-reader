## 摘要
为软件仓库自动生成高质量文档仍然具有挑战性：现有方法大多将文档生成视为不受约束的文本生成，缺乏明确的质量规范，过度依赖基于原始代码的长上下文提示，并且对可复现评估的支持有限。我们认为，代码级文档生成应被视为一项标准引导的软件工程任务，其中文档应依据源自权威标准的明确、可复用的质量要求来生成和评估。我们将代码文档定义为对仓库函数和类的自然语言描述，并按源代码路径组织。我们提出 CODEDOC，一个标准引导且依赖感知的框架，它通过静态调用图和 AST 分析识别代码实体之间的依赖关系，并构建依赖感知的结构化提示，融合局部代码上下文、仓库路径以及源自权威标准和风格指南的文档准则。我们进一步引入一种交互式 LLM-as-a-judge 协议，提供与准则对齐的反馈，以依据正式标准和实践导向标准中的细粒度维度来改进生成的文档。在十个开源 Python 仓库上的实验表明，在与标准对齐的评估下，CODEDOC 生成的文档质量高于 RepoAgent 和长上下文基线，相对提升分别为 11.6%-17.0% 和 21.4%-29.6%，同时每个文档实体消耗的 token 数大约比长上下文基线少一个数量级。一项人工研究证实，基于 LLM 的判断与人工判断之间具有较高一致性（Spearman's rho = 0.72），并且相对结论在不同评判 LLM 上均成立。代码见 https://github.com/ControllableModel/CodeDoc。

## Abstract
Automatically generating high-quality documentation for software repositories remains challenging: existing approaches largely treat documentation as unconstrained text generation, lacking explicit quality specifications, depending heavily on long-context prompts over raw code, and offering limited support for reproducible evaluation. We argue that code-level documentation generation should instead be a standards-guided software engineering task, in which documentation is generated and assessed against explicit, reusable quality requirements derived from authoritative standards. We define code documentation as natural-language descriptions of repository functions and classes, organized by source-code path. We present CODEDOC, a standards-guided and dependency-aware framework that identifies dependencies between code entities via static call-graph and AST analysis and constructs dependency-aware structured prompts combining local code context, repository paths, and documentation criteria drawn from authoritative standards and style guides. We further introduce an interactive LLM-as-a-judge protocol that supplies criterion-aligned feedback to refine generated documentation along fine-grained dimensions from formal and practice-oriented standards. Experiments on ten open-source Python repositories show that CODEDOC produces higher-quality documentation than RepoAgent and a long-context baseline under standards-aligned evaluation, with relative improvements of 11.6%-17.0% and 21.4%-29.6%, respectively, while consuming roughly an order of magnitude fewer tokens per documentation entity than the long-context baseline. A human study confirms substantial alignment between LLM-based and human judgments (Spearman's rho = 0.72), and the relative findings hold across different judge LLMs. Code is available at https://github.com/ControllableModel/CodeDoc.

## 2. 方法论：CODEDOC 框架

### 2.1 核心思想

- 将仓库表示为 \(C=(E,R)\)，其中 \(E\) 为代码实体集合，\(R\) 为调用、导入、模块层级等结构关系。
- 为每个实体 \(e\) 生成文档 \(d_e\)，形成文档集合 \(D=\{d_e\mid e\in E\}\)。
- 文档质量由准则集合 \(Q=\{q_1,\dots,q_n\}\) 约束，每个准则 \(q_i\) 对应可评估要求，如核心功能、模块依赖、使用假设等。
- 每个准则配有 1–5 分评分函数 \(s_i(d_e,C)\)，生成目标为：
  \[
  D^*=\arg\max_D \frac{1}{|E||Q|}\sum_{e\in E}\sum_{q_i\in Q}s_i(d_e,C)
  \]
- 该目标作为概念框架，实际通过“提示生成—评审反馈—单次重生成”的迭代流程近似，而非形式优化。

### 2.2 Phase (a)：离线准则提取

- **来源**：ISO/IEC/IEEE 26514 软件文档标准 + GitHub 文档风格指南。
- **流程**：
  1. 用 GPT-5-mini 从标准文档中抽取候选质量维度，形式为“类别、维度、描述、评分指南”；
  2. 两位作者人工检查、去重、规范化，形成固定 schema 评分 rubric。
- **结果**：
  - ISO rubric：7 类、14 维；
  - GitHub rubric：5 类、12 维；
  - 每个维度含短名称、单句定义、1–5 分评分锚点。
- **双重用途**：同一 \(Q\) 既作为生成提示的第一块内容，也作为文档评审器和外部评估的评分 rubric。

### 2.3 Phase (b) Stage 1：源代码静态分析

- 以函数和类为粒度抽取实体，记录仓库路径和源码体。
- **Pyan3 调用图分析**：解析导入和调用点，生成仓库级有向调用图，caller–callee 边构成依赖结构主干。
- **AST 解析**：提取函数签名、参数列表、类属性、主要控制流结构及精确行号范围。
- 两者结合形成精化表示 \(C'=(E,R')\)，使后续只检索依赖相关上下文，降低冗余输入和 token 消耗。

### 2.4 Phase (b) Stage 2：标准引导的文档生成与评审

- 对每个目标实体，仅检索直接调用者和被调用者等少量依赖实体，而非整个仓库。
- 构造固定顺序的四块结构化提示：
  1. 来自 \(Q\) 的文档准则定义；
  2. 目标实体源码及仓库路径；
  3. 依赖相关实体源码，带 `uses` / `used_by` 标注；
  4. 指定输出格式的生成指令。
- 生成文档按源码路径组织，保持可追溯性。
- **LLM-as-a-judge 闭环**：同一准则集 \(Q\) 下逐维评分并给出文本反馈；反馈追加到原提示，进行**一次**重生成。所有生成、精炼和默认评判使用 GPT-5-mini，默认温度设置。
