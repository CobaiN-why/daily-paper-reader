## 摘要
仓库级编码基准大多假设任务和环境在整个执行过程中保持不变。在软件开发中，代码、依赖、运行时状态和需求可能在智能体仍在工作时发生变化。我们提出 SWE-Shift，一个用于评估编码智能体在执行中途发生此类变化时表现的基准。从相同的已保存历史和工作空间出发，Clean 续跑不进行干预地继续执行，而匹配的 Shifted 续跑会接收与任务相关的更新。成功需要完成当前任务、保留仍然有效的工作，并满足适用的状态与证据检查。该基准包含 12 类变化中的 120 个场景，每个场景在九个预定的干预位置进行评估。我们评估了 17 个编码智能体系统，所有系统的 Shifted 成功率均低于 Clean 成功率。GPT-6 Astra 从 67.35% 降至 24.79%，配对成功率为 20.34%。工具/会话变化和过期证据在所有系统中均导致配对成功率为零。较晚位置的配对成功率在某些系统中较低，在另一些系统中较高。这些结果表明，在未变化任务上取得成功，可能与更新后无法保留工作、恢复状态或刷新证据的情况并存。

## Abstract
Repository-level coding benchmarks largely assume that tasks and environments remain unchanged throughout execution. In software development, code, dependencies, runtime state, and requirements can change while an agent is still working. We introduce SWE-Shift, a benchmark for evaluating coding agents under such mid-execution changes. From the same saved history and workspace, a Clean continuation proceeds without intervention, while a matched Shifted continuation receives a task-relevant update. Success requires completing the current task, preserving still-valid work, and satisfying the applicable state and evidence checks. The benchmark contains 120 scenarios across 12 change families, each evaluated at nine scheduled intervention positions. We evaluate 17 coding-agent systems, all of which have lower Shifted than Clean success. GPT-6 Astra drops from 67.35% to 24.79%, with 20.34% paired success. Tool/session changes and stale evidence yield zero paired success across all systems. Late-position paired success is lower for some systems and higher for others. These results show that success on the unchanged task can coexist with failures to preserve work, recover state, or refresh evidence after an update.

## 1. 核心问题与研究动机

- **背景缺口**：以 SWE-bench 为代表的仓库级编码基准，普遍假设任务与环境在执行过程中保持不变；智能体只需理解 issue、导航仓库、修改代码并通过测试。
- **现实矛盾**：真实软件开发是动态的——代码可能被他人编辑、依赖可能升级、运行时/会话状态会变化、需求与可用信息可能在执行中途被修订。
- **关键研究问题**：当任务相关的变化发生在执行中途时，编码智能体是否还能继续成功？
- **评估方法论难点**：仅在“变化后的任务”上评测无法归因失败——无法区分“本来就不会做”与“变化打断了本可成功的执行”。因此需要**匹配对照（matched continuation）**来分离这两类失败来源。
- **整体含义**：论文主张把“对执行中变化的鲁棒性”确立为独立于静态任务成功率的评估目标，并指出“原任务测试通过”可能掩盖工作丢失、状态未恢复、证据过期等问题。

## 2. 方法论

### 2.1 核心思想：匹配续作（Matched Continuation）

- 智能体先在任务上正常执行一段**共享前缀**；在预定检查点保存完整执行状态（agent 可见历史、工作区、控制器状态、可用工具、系统设置、执行计数器）。
- 从同一保存状态恢复两次，形成配对：
  - **Clean 续作**：不施加干预，继续原任务与环境。
  - **Shifted 续作**：在分叉点施加一个任务相关更新。
- 分叉前两条轨迹的历史与工作区完全一致，仅分叉后观测与动作可分化；Clean 提供“从该中间状态能否成功”的基线，Shifted 检验“该成功能否在变化后存活”。

### 2.2 变化设计原则：相关性 + 可恢复性

- **Relevance（相关性）**：忽略该变化会使原本可成功的续作失效。
- **Recoverability（可恢复性）**：变化后仍存在至少一条经由 agent 可访问工具完成任务的合法路径。
- 每个场景需明确四要素：初始仓库任务、被授权的执行中变化、agent 发现该变化的途径、对正确续作的可执行检查。

### 2.3 12 类变化家族（三大组）

- **World Shift（F01–F07，可执行状态/依赖）**：F01 用户实现（编辑区内加入有效代码）、F02 用户契约（公共 API/数据契约变更）、F03 直接协作者（目标代码或直接依赖变更）、F04 间接协作者（传递依赖变更）、F05 运行时与资源（进程/端口/锁/缓存变化）、F06 工具与会话（工具、授权、schema、协议失效）、F07 外部副作用（工具响应与真实效果不一致）。
- **Goal Interaction（F08–F10，需求/权威/反馈）**：F08 披露（目标不变但暴露新约束）、F09 纠正性反馈（新证据推翻旧信念）、F10 目标修订（授权方修改目标与验证器）。
- **Observation Shift（F11–F12，证据有效性/来源）**：F11 过期证据（证据对应旧状态）、F12 错绑证据（证据绑定到错误请求/分支/会话）。

### 2.4 干预时机 T10–T90

- 基于参考解的**合格前缀**（eligible prefix，截止于第一个正确性依赖该更新的动作之前）构造 9 个锚点。
- 对 N 个合格动作，检查点规则：`k_j = floor(jN/10)`，j = 1..9，保证 9 个互异检查点覆盖 10%–90% 的参考进度。
- 若前缀动作不足 9 个，则拆分最长的合格文件读取为不重叠行区间；无法产生 9 个真实动作的前缀被拒绝（不添加空读或 no-op）。
- 注意：T10–T90 是**计划位置**而非语义进度；不同系统在同一名义位置可能处于不同工作区状态；提前终止或不适用情形按结果协议处理，不重新调度。

### 2.5 成功判定（合取式）

- 对系统 m、场景 i、位置 t，续作 a ∈ {Clean, Shifted} 的严格成功为所有适用二元检查的连乘：`Y = Π_j v_j(ρ)`。
- 检查类别：task、preservation、recovery、authority、effect、evidence、budget、terminal-integrity；任一适用检查失败即整体失败。
- Shifted 额外要求 recovery 与 fresh-observation 检查（更新后、首次修改前必须发生一次允许的观测）；Clean 要求任务、保留、无禁止副作用、披露有效、目标/验证器版本正确、预算合规。

### 2.6 指标与聚合

- 令 C、S ∈ {0,1} 为 Clean/Shifted 验证成功，联合成功 `R = C·S`；提前完成信用 `P`（在干预前已通过回放验证完成任务）；单元得分 `K = max{R, P}`（P 与 R 互斥，故 K = R + P）。
- **PSR（Paired Success Rate，主指标）**：9 个位置上 K 的加权平均。
- **CRR（Conditional Retention Rate）**：`CRR = Σw·R / Σw·C`（分母非零），衡量 Clean 成功中被保留的比例，不含提前完成信用。
- **分层加权**：12 个变化家族等权 → 家族内 cluster 等权 → cluster 内场景等权。
- 同时报告 Clean、Shifted 绝对值。

## 6. 主要结论与发现

- **普遍性下降**：17 个系统 Shifted 成功率**全部低于** Clean。GPT-6 Astra 从 67.35% 降至 24.79%，PSR 20.34%，CRR 30.20%（不足三分之一 Clean 成功被保留）。
- **高 Clean 不等于高保留**：Kimi-K3 Clean 31.41%、PSR 8.20%、CRR 25.12%；DeepSeek V4-Pro Clean 更低（29.37%）但 PSR（8.83%）与 CRR

CRR 则并未随 Clean 同步走低，说明“基础任务能力”与“变化后的成功保留能力”并不是同一个维度，单看静态成功率会误判系统的动态鲁棒性。

- **家族间差异显著**：论文的家族级热图显示，不同变化家族对系统的杀伤程度并不均匀。总体而言，涉及**目标与权威**（F08 披露、F09 纠正性反馈、F10 目标修订）以及**证据有效性**（F11 过期证据、F12 错绑证据）的家族更容易造成续作失败，因为智能体往往沿用分叉前的旧信念、旧计划或旧观测，而未能重新确认“当前应做什么、依据是否仍然有效”。涉及**直接/间接协作者**（F03、F04）与**用户实现/契约**（F01、F02）的家族则更多暴露“工作区被外部改动后未重新读取、未合并、未适配”的问题；**运行时与资源**（F05）、**工具与会话**（F06）、**外部副作用**（F07）则集中检验状态恢复与效果核验能力。没有任何系统在所有家族上表现均衡，家族级弱点具有明显的系统性而非偶发性。
- **位置效应**：9 个干预位置的 PSR 曲线整体呈“越晚越脆弱”的趋势，T70–T90 通常低于 T10–T30。早期变化尚可通过后续正常执行被吸收；越接近完成，智能体越倾向于“收尾”，对重新观测、重新验证的投入越少，已积累的工作与结论也越难被推翻重做。这提示“临门一脚”阶段的变化是当前智能体的共同薄弱区。
- **“原任务测试通过”会掩盖失败**：RQ4 的 24 例定性审计发现，部分续作在最终任务测试上通过，但仍因 preservation（覆盖或丢弃他人有效改动）、recovery（未走允许路径恢复）、evidence（未在更新后首次修改前进行有效观测）、authority（未遵循修订后的目标/验证器）等检查而整体判负。也就是说，静态基准中“通过”的结果，在动态条件下可能对应工作丢失、状态未复原或证据过期，任务成功率本身不足以刻画执行质量。
- **诊断控制的启示**：状态访问累积干预（逐步加入变化通知、只读状态刷新、移除变更前对话历史）表明，失败并非单纯源于“不知道变化”，信息披露只是必要条件之一；智能体还需具备主动刷新状态、重估计划与丢弃过期上下文的习惯。分叉后 token 预算扫描显示，增加预算能在一定程度上缓解但无法消除差距，说明瓶颈更多在策略与验证行为，而非单纯算力或步数不足。
- **总体判断**：SWE-Shift 揭示的是一种**结构性、跨系统普遍存在**的鲁棒性缺口——当前编码智能体擅长“沿既定计划推进”，却不擅长“在执行中察觉变化、重建世界模型并重新验证结论”。

## 7. 贡献、启示与局限

### 7.1 主要贡献

- **问题重构**：把“执行中变化的鲁棒性”从工程轶事提升为可度量、可归因的独立评估目标，明确指出静态任务成功率无法代表动态可靠性。
- **方法创新**：提出匹配续作（Matched Continuation）范式，用同一分叉状态下的 Clean/Shifted 配对分离“本来就不会”与“变化打断了本可成功的执行”，并通过 PSR、CRR 等指标把“保留率”与“绝对成功率”区分开。
- **系统化变化分类**：给出 12 类变化家族与相关性、可恢复性两条设计原则，以及“初始任务—授权变化—发现途径—可执行检查”的四要素场景规范，为后续基准扩展提供可复用的构造模板。
- **细粒度评测**：以 T10–T90 的 9 个干预位置刻画“变化发生时点”的影响，配合合取式成功判定（task/preservation/recovery/authority/effect/evidence/budget/terminal-integrity），把“通过”拆解为多维可审计条件。

### 7.2 实践启示

- **对智能体设计**：应在执行循环中显式加入“状态复核”环节——在关键修改前重新读取工作区与依赖、校验观测是否对应当前版本、在收到新信息后主动重估目标与计划，而不是把早期上下文当作长期有效的前提。
- **对评测实践**：仅报告任务通过率会系统性高估系统可靠性；建议同时报告保留率与失败归因（工作丢失、状态未恢复、证据过期、权威错配等）。
- **对工程部署**：在人机协作、长会话、多代理共享仓库的真实场景中，“变化”是常态而非例外，鲁棒性缺口会直接转化为返工、覆盖他人修改与错误结论。

### 7.3 局限与改进方向

- **统计功效**：每家族 10 个场景、23 个 root 快照，且以点值报告、未给置信区间或方差；结论宜作趋势性解读，家族间细微排序不宜过度解读。
- **随机性未控制**：配对固定了历史与工作区，但未固定采样，Clean/Shifted 差异中仍含采样噪声；可通过多 seed 重复与方差报告改进。
- **单次变化**：每次运行仅施加一次更新，未覆盖连续变化、相互冲突的变化或“变化后又回滚”的情形。
- **位置语义**：T10–T90 是计划位置而非语义进度，跨系统在同一名义位置的实际上下文可能不同，位置曲线的跨系统可比性有限。
- **系统可比性**：托管系统与本地服务系统在上下文长度、单次输出上限等条件上不完全对等，部分未暴露项以“–”标注，跨系统绝对值的比较需谨慎。
- **构造者偏差**：初始 24 例由单一强模型在特定配置下构造与审计，虽经准入检查与正负对照，仍可能存在构造风格上的系统性偏好；扩展集的构造质量控制细节披露有限。
- **诊断控制覆盖有限**：仅 5 个系统参与控制实验，相关机理解释的外推需谨慎。

## 8. 总体评价

SWE-Shift 的价值主要不在于“又一个新的编码基准”，而在于它提出了一种**可归因的评估逻辑**：通过同一分叉状态的配对续作，把“能力不足”与“变化冲击”分开，并用保留率指标揭示静态成功率所掩盖的脆弱性。其实验规模（17 个系统、120 个场景、9 个位置、约 1.8 万个配对单元）与分层加权、定性审计、诊断控制的组合，使结论具有较好的内部一致性与解释力；12 类变化家族与四要素场景规范也具备较强的可扩展性。主要不足在于统计报告的严谨性（无置信区间、未控制采样随机性）、单次变化的覆盖限制，以及跨系统条件不完全对等。总体而言，论文的核心论断——“高静态成功率不等于高动态可靠性，执行中变化的鲁棒性应作为独立评估目标”——得到了较充分的证据支持，对编码智能体的评测与设计均具有明确的参考价值。
