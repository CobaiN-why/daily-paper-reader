## Abstract 

Code review is essential for maintaining software repositories by identifying defects, improving code quality, and supporting reli-able software evolution. With the growing adoption of LLM-based coding agents, an increasing number of code contributions and repository changes are generated by these agents. Consequently, LLM-based code review agents are becoming increasingly preva-lent to evaluate these contributions and maintain software quality. However, LLM reviewers often generate lengthy reviews containing numerous potential issues, many of which are false positives or lack sufficient evidence. These unreliable reviews can mislead developers and downstream coding agents, motivating the need to distinguish actionable findings from unsupported claims. We propose CIVER, a causal intervention-based framework that identifies the core is-sues underlying code-review findings and distinguishes genuine defects from false positives. CIVER integrates three modules: a review module assesses findings, an intervention module generates repair-oriented perturbations, and a verifier module scores review reliability. Through joint optimization via expert iteration, the three modules identify genuine defects by responding to targeted repairs while remaining stable under unrelated changes. Extensive experi-ments on SWE-Review-Bench demonstrate that CIVER correctly identifies 77% of genuine defects through targeted repairs. Cross-project and downstream repair evaluations further demonstrate that CIVER generalizes across repositories and improves coding agents’ task success rates, highlighting its effectiveness for reliable automated code review.

## 1 Introduction 

Code review is a fundamental component of collaborative soft-ware development [4, 33], enabling developers to discuss proposed changes, identify defects, and maintain software quality through pull requests (PRs) on Web-based platforms such as GitHub. Re-cent advances in large language model (LLM)-based coding agents, including SWE-agent [41], OpenHands [39], Claude Code [3], and Codex [28], have enabled increasingly autonomous software de-velopment, from implementing features and fixing bugs to main-taining entire repositories. As these agents become widely adopted, they generate a growing volume of code contributions, including commits, PRs, tests, and documentation updates. Recent empiri-cal studies [34, 40] report increasing adoption of coding agents across GitHub repositories and their participation in real-world software contributions. For example, GitHub’s Octoverse 2025 re-port [14] documents over one million PRs created by its Copilot coding agent within five months of its introduction. This growing volume of agent-generated contributions creates an increasing de-mand for scalable code review, driving the adoption of LLM-based review agents such as OpenCodeReview [22], GitHub Copilot Code Review [13], and CodeRabbit [7] to evaluate code changes and support reliable repository maintenance. Recent benchmarks, in-cluding SWE-Review-Bench [38], AACR-Bench [42], and CodeRe-viewBench [19], further highlight the importance of evaluating automated code review in realistic software engineering work-flows [18]. Despite their growing capabilities, LLM-based reviewers [8] fre-quently generate lengthy reviews containing numerous potential issues, many of which are false positives [17, 25], redundant ob-servations, or claims unsupported by the actual program behavior. Unlike traditional code analysis, where findings can often be asso-ciated with explicit program constraints, LLM-generated critiques are expressed in natural language and may appear convincing even when the underlying defect does not exist. Recent empirical studies on LLM-assisted code review [1] and noisy review comments [23] further highlight the prevalence of non-actionable feedback and concerns about review reliability. This creates a critical challenge for automated code review: generating more critiques does not necessarily improve review quality. Instead, excessive unreliable findings increase the burden of distinguishing genuine defects from unsupported concerns. More importantly, when these critiques are passed to downstream coding agents, false positives [6, 17] may trigger unnecessary modifications, introduce new defects, or dis-rupt previously correct functionality. code review requires not only identifying potential issues but also verifying which critiques correspond to genuine defects and should guide subsequent code modifications. Existing approaches have explored several directions for improv-ing code review reliability. LLM-based review systems, such as CodeReviewer [21], SGCR [37], and OpenCodeReview [22], lever-age code representations and repository context to generate more informative critiques. Self-Refine [24] improves model outputs through iterative feedback, while Refute-or-Promote [2] and ad-versarial review [32] employ independent or adversarial verifi-cation to assess candidate findings. Other approaches, including LLM4PFA [11], execution-path-based false-positive reduction [10], and fix-guided verification [17], investigate program feasibility and proposed repairs to filter unreliable findings. Counterfactual code analysis [12] and ComPass [43] further explore program-state com-parisons and semantic consistency for vulnerability detection and patch assessment. However, these methods do not explicitly estab-lish whether a critique is causally connected to its claimed defect. High reviewer confidence or agreement among verification agents may reinforce incorrect assumptions, while changes in critique scores after code modifications may reflect superficial differences rather than the removal of the underlying defect. To address this limitation, we investigate code-review reliability from a causal intervention perspective. A reliable critique should respond to repairs targeting its claimed defect while remaining stable under unrelated changes. For example, if a critique identifies a missing null check, introducing the necessary guard should inval-idate the original finding, whereas modifying an unrelated function should not affect its validity. Conversely, if the guard already exists, the critique should be rejected rather than accepted simply because the described bug is plausible. This shifts review verification from judging the plausibility of explanations to examining their causal relationship with program behavior. Comparing targeted repairs with unrelated perturbations helps distinguish genuine defects from false positives. We propose CIVER, a causal intervention-based framework for identifying the core issues underlying code-review findings and verifying their reliability. As illustrated in Figure 1, CIVER inte-grates three coupled modules. The review module transforms LLM-generated code reviews into structured candidate critiques. The 

intervention module generates repair-oriented perturbations and ranks candidate edits according to their relevance to the claimed defect. The verifier module assigns reliability scores to candidate critiques based on their responses to targeted repairs and unrelated perturbations. These modules are jointly optimized through an ex-pert iteration framework, allowing review assessment, intervention selection, and verification feedback to improve one another. In par-ticular, the learning objective distinguishes genuine defects from unsupported critiques by penalizing score changes under unrelated modifications while encouraging larger changes under targeted repairs. The LLM reviewer, embedding model, and intervention generator remain fixed, allowing CIVER to improve review verifi-cation without retraining these components. Extensive experiments on SWE-Review-Bench [38] demonstrate that CIVER achieves 77% accuracy in distinguishing defective code from its repaired counterpart in matched pairs. Cross-project eval-uations demonstrate that CIVER generalizes to unseen repositories, achieving a transfer AUROC of 0 .760. Downstream experiments fur-ther show that our accurate critiques improve coding agents’ repair success, highlighting the importance of reliable review verification for automated and collaborative software maintenance. Our contributions are summarized as follows: 

• We introduce a causal intervention-based approach to code-review verification that distinguishes genuine defects from false positives by examining how critiques respond to targeted repairs and unrelated modifications.

## 2 Related Work 

Code Review Evaluation. Recent benchmarks have advanced code-review evaluation toward realistic software development workflows. The CodeFuse code review benchmark [15] incorpo-rates issue, pull-request, and repository context for end-to-end review, while AACR-Bench [42] provides multilingual, cross-file scenarios with expert-verified defects. SWE-PRBench [20] evalu-ates agreement with human pull-request feedback under different context configurations. CodeReviewBench [19] uses frozen repos-itory replay and human-authored reference findings, whereas c-CRAB [45] constructs executable tests from human review comments. SWE-Review [38] further evaluates whether review feedback helps coding agents improve issue-resolution patches. These benchmarks provide complementary measures of review quality and downstream utility. In contrast, CIVER focuses on verifying individual critiques by examining whether their validity changes in response to targeted repairs. 

LLM-Based Review Verification. Existing approaches improve re-view reliability through reflection, adversarial verification, and spec-ification grounding. OpenCodeReview [22] combines repository-grounded review with independent reflection to identify unsup-ported findings. Refute-or-Promote [2] employs adversarial veri-fication, cross-model criticism, and empirical confirmation, while Adversarial Review [32] coordinates reviewer and critic agents through structured disagreement. SGCR [37] grounds code review in human-authored specifications, combining explicit rule checking with implicit issue discovery. Although these approaches strengthen the verification of candidate findings, CIVER introduces a com-plementary learning signal that compares critique responses to targeted repairs and unrelated modifications. This comparison ex-plicitly encourages reliability scores to reflect the claimed defect rather than unrelated code changes. 

False Positive Reduction. Fix-guided Verification Filter [17] pro-vides a closely related approach by executing original and repaired implementations against tests to identify unnecessary fixes, intro-duced defects, and successful corrections. Unlike this execution-based filtering approach, CIVER learns a critique-conditioned ver-ifier and intervention ranker, using targeted repairs to measure defect sensitivity and unrelated modifications to enforce specificity. Semantics-preserving transformations further encourage consis-tent verification across equivalent program representations. Related static-analysis approaches, including LLM4PFA [11] and execution-path-based false-positive reduction [10], assess the feasibility of re-ported program errors. In contrast, CIVER verifies natural-language code-review findings through their responses to program modifica-tions. Prior observations that false accusations can induce harmful code changes [25] further motivate reliable review verification be-fore downstream repair. 

Counterfactual Code Analysis. Counterfactual and contrastive learning have also been explored for code analysis. VISION [12] gen-erates minimally modified code pairs with contrasting vulnerability labels to improve vulnerability detection. ComPass [43] combines semantics-preserving transformations with contrastive learning for patch correctness assessment, while earlier code-representation learning [5] uses program transformations to capture semantic invariance. CRScore [26] evaluates code-review quality by compar-ing generated comments with code-grounded claims and potential issues. Unlike these approaches, CIVER jointly models review reli-ability and intervention relevance, explicitly distinguishing score changes caused by targeted repairs from those caused by unrelated modifications.

## 4 CIVER: Causal Intervention Verification 

Framework Overview. Building on the causal verification for-mulation in Section 3, CIVER distinguishes genuine defects from unsupported critiques by examining their responses to program in-terventions. Targeted interventions 𝐼 𝑐 should reduce review finding validity, whereas unrelated interventions 𝐼 𝑐 ′ should preserve it, as defined in Eqs. (2) and (3). To achieve this, CIVER jointly optimizes three modules: a review module 𝐹 𝜃 , an intervention module 𝑅 𝜙 , and a verifier module 𝐺 𝜓 . The review module extracts claim-conditioned representations and supporting evidence, the intervention module ranks candidate program modifications, and the verifier module integrates intervention responses to estimate the validity proba-bility 𝑝 𝜓 (𝑥, 𝑐 ). All pretrained models remain frozen, while only lightweight module parameters are optimized. Figure 1 illustrates the overall framework.

Semantics-preserving transformations

## 5 Experiments 5.1 Experimental Setup 

Benchmarks. We use six benchmarks to evaluate review verifica-tion, intervention-based code review, and review quality. AACR-Bench [42] serves as the primary benchmark for review finding validity classification and finding filtering, while CRScore [26] provides human-rated comments for review-quality classification. 

SWE-Review-Bench [38] provides executable pull requests for constructing targeted and unrelated interventions, evaluating causal intervention effects, cross-project generalization, interven-tion retrieval, and downstream repair. CodeReviewBench [19] and SWE-PRBench [20] provide additional real-world code re-view data, while Review4Repair [16] supplies aligned review comments and code edits for intervention construction. 

Metrics. We evaluate review finding validity on AACR-Bench [42] and review quality on CRScore [26] using AUROC, precision, recall, and F1. We additionally measure false positives per PR (FP/PR) and per positive finding (FP/pos) on AACR-Bench, and accuracy and average precision (AP) on CRScore. On SWE-Review-Bench [38],

we assess score discrimination using PairAcc, rejection rate, and AUROC. Following Eq. (2), we measure causal intervention effects using three metrics: Flip, the defect-removal success rate measured by the fraction of targeted repairs that reduce review finding validity scores; score reduction (SR), the mean logit difference before and after repair; and Pair AUROC, the AUROC of these dif-ferences against a zero-effect reference. We assess transformation consistency using verdict agreement and target-effect correlation (EqvValid). Cross-project and cross-language generalization are evaluated using Pair AUROC and AUROC, respectively. Interven-tion retrieval is measured using Top-1, Recall@5, and MRR, while downstream repair is evaluated using resolution rate and observed harm. 

Baselines. We compare CIVER against a frozen LLM reviewer, self-reflection [24], independent verification [22], and fix-guided verification [17], as well as LLM-as-a-judge [26, 46], BERTScore [44], and chrF++ [31] for review-quality evaluation. The reviewer-based baselines are controlled implementations inspired by the cited meth-ods rather than exact reproductions. We additionally include MLP and bilinear classifiers using the same frozen text-embedding-3-small representations from OpenAI [27], along with an always-negative control for review-quality evaluation. We use gpt-5.6 [29, 30] as the frozen reviewer. We use repository-level separation with a default 70%/10%/20% project split, except for CRScore, which uses disjoint code-diff splits. The main configuration contains approx-imately 9.04M trainable parameters, while all pretrained models remain frozen.

Table 6 evaluates downstream code repair on 121 issues from SWE-Review-Bench [38], using a fixed base mini agent from SWE-bench Pro [9]. Table 7 evaluates the contribution of different training objectives. CIVER achieves the highest Pair AUROC of 0.83 and maintains strong pairwise accuracy and targeted repair sensitivity. Removing individual objectives generally degrades discrimination or inter-vention effectiveness, highlighting the complementary roles of the proposed training objectives. 

## 6 Discussion 

CIVER reduces false positives by measuring how critiques respond to targeted defect repairs: Δ𝑐 = 𝑝 𝜃 (𝑥, 𝑐 ) − 𝑝 𝜃 (𝐼 𝑐 (𝑥 ), 𝑐 ), where 𝐼 𝑐 

denotes a targeted repair. Genuine defects should yield Δ𝑐 > 0, while false positives should yield Δ𝑐 ≈ 0. Since interventions may introduce unrelated changes, CIVER uses negative controls and semantics-preserving transformations to assess causal specificity and invariance. Its reliability depends on how well interventions isolate the claimed defect.

## 7 Conclusion 

We propose CIVER, a causal intervention framework for reliable code review verification. By evaluating critique responses to tar-geted repairs, unrelated edits, and semantics-preserving transforma-tions, CIVER moves beyond correlation-based assessment toward causal verification of code review findings. Extensive experiments demonstrate improved review reliability, stronger causal sensitivity, and robust generalization across repositories and programming lan-guages. Our results further highlight the practical value of causal verification for intervention retrieval and downstream code repair.
