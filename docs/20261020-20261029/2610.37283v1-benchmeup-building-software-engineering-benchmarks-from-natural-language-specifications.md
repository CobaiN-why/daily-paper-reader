## 摘要
软件工程研究依赖于基准，用以在一组问题实例上评估新技术。不幸的是，手动构建基准是劳动密集型的，因为研究人员必须寻找合适的实例、准备执行环境、确定预期结果并验证正确性。本文提出 BenchMeUp，一种从自然语言规范自动创建软件工程基准的方法。给定一个定义所需实例、数据源和评估过程的规范，BenchMeUp 生成搜索规则和构建计划，调用并行 LLM 智能体来识别候选实例并构建可执行实例，在全新的执行环境中验证结果，并将这些实例封装在统一的命令行界面之后。我们在四个任务上评估该方法：程序修复、问题复现、编译器自动调优和修复静态分析警告。以每个任务 50 个实例（共 200 个）为目标，BenchMeUp 构建了 198 个实例，其中 196 个（99%）成功打包。搜索和构建平均每个实例耗时 36 分钟，花费 0.79 美元。在生成的基准上评估八种现有技术时，我们发现 196 个已打包实例中有 189 个（96%）支持端到端评估，使用户能够研究这些技术的有效性。对照每个已构建实例的来源、规范及其预期结果进行检查，我们发现 198 个实例中有 180 个（91%）满足所有标准，而 Codex（通用编码智能体）交付的 200 个实例中仅有 10 个满足。总体而言，我们表明基于 LLM 的智能体能够在多样化的软件工程任务中自动构建基准，并生成现有技术可使用的可执行实例，但执行之外的有效性仍需检查。

## Abstract
Software-engineering research relies on benchmarks that evaluate new techniques on a set of problem instances. Unfortunately, manually constructing benchmarks is labor-intensive, as researchers must find suitable instances, prepare execution environments, establish expected outcomes, and validate correctness.   This paper presents BenchMeUp, an approach for automatically creating software-engineering benchmarks from natural-language specifications. Given a specification defining the desired instances, data sources, and evaluation procedures, BenchMeUp generates search rules and a construction plan, invokes parallel LLM agents that identify candidate instances and construct executable instances, validates the results in fresh execution environments, and packages the instances behind a unified command-line interface. We evaluate the approach on four tasks: program repair, issue reproduction, compiler autotuning, and fixing static-analysis warnings. Targeting 50 instances per task (200 in total), BenchMeUp constructs 198 instances, of which 196 (99\%) are successfully packaged. Search and construction take 36 minutes and \$0.79 per instance, on average. Evaluating eight existing techniques on the generated benchmarks, we find that 189 of 196 packaged instances (96\%) support end-to-end evaluation, allowing users to study the effectiveness of the techniques. Checking every constructed instance against its source, the specification, and its expected outcome, we find that 180 of 198 (91\%) meet all criteria, compared with 10 of 200 instances delivered by Codex (general-purpose coding agent).   Overall, we show that LLM-based agents can automate benchmark construction across diverse software-engineering tasks and produce executable instances that existing techniques can use, while validity beyond execution still needs to be checked.
