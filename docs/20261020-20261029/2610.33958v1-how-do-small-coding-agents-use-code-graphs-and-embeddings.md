## 摘要
编程智能体被赋予嵌入搜索与代码图工具，其前提是仓库结构是模型所缺乏的、而工具可以提供的。我们在 SWE-bench Verified 上，用小型开放权重模型检验这一前提，并按一个确定性跳数深度对任务分层（该深度指从问题提到的代码到金标准补丁所改代码的最短代码图路径），该深度由一篇配套论文定义并验证。首先，我们在一个深度均衡的 160 任务划分上，以及在全部 500 个任务上，对十个模型（六个 Qwen3 规模，从 0.6B 到 32B，每种五个解码设置，一个 FP8 对照，三个 Gemma 4 规模；79k 个回合）消融定位智能体的工具集（仅 grep；+嵌入搜索；+图工具；全部）。结构化工具使 Qwen3-8B 和 Gemma 4 E4B 的仅用 grep 准确率翻倍；其增益在 1.7-4B 达到 17-21 个百分点的峰值，并在 32B 降至 4-5 个百分点（参数每翻一倍，优势比为 0.77-0.82）。从 8B 起，该增益中约有一半来自提交形式而非找到目标；从 14B 到 32B 的下降，是在仅用 grep 准确率相同的情况下工具采用率的下降；而同样是 4B 规模，是否会从某个工具中获益取决于检查点。每增加一跳，正确局部化的优势比在所有规模上都乘以 0.50-0.67，且没有任何工具集能抹平这一梯度：轨迹显示，图工具的增益在跳 0 是名称查找，在跳 1 是一次扩展，而智能体仅在 12-14% 的回合中串联扩展。一个固定的修复模型基于这些局部化结果解决了 160 个任务中的 6-13 个（oracle 为 26）。其次，线性探针发现，直接调用边可在锚点内、按度数分层的协议下被解码（AUC 0.74；在智能体对话内部为 0.61-0.66），但低于词法基线（0.99），两跳边为 0.57。小型智能体在权重中以及在使用中，都对其仓库持有一幅一跳的、很大程度上是词法的图景。我们发布智能体、探针、日志与轨迹。

## Abstract
Coding agents are given embedding search and code-graph tools on the premise that a repository's structure is something the model lacks and the tool supplies. We test that premise on SWE-bench Verified with small open-weight models, stratifying tasks by a deterministic hop depth (the shortest code-graph path from code the issue mentions to code the gold patch changes) that a companion paper defines and validates. First, we ablate a localization agent's tool set (grep only; +embedding search; +graph tools; all) on a depth-balanced 160-task split and on all 500 tasks for ten models (six Qwen3 sizes from 0.6B to 32B with five decodings each, an FP8 control, three Gemma 4 sizes; 79k episodes). Structured tools double grep-only accuracy for Qwen3-8B and Gemma 4 E4B; their gain peaks at 17-21 points at 1.7-4B and falls to 4-5 points at 32B (odds ratio 0.77-0.82 per doubling of parameters). From 8B up, about half of that gain is the form of the submission rather than finding the target; the fall from 14B to 32B is a fall in tool uptake at equal grep-only accuracy; and the same 4B size gains or does not gain from a tool depending on the checkpoint. Each extra hop multiplies the odds of correct localization by 0.50-0.67 at every size, and no tool set flattens that gradient: traces show the graph tools' gain is name lookup at hop 0 and one expansion at hop 1, and agents chain expansions in only 12-14% of episodes. A fixed repair model resolves 6-13 of 160 tasks from these localizations (oracle 26). Second, linear probes find direct call edges decodable under a within-anchor, degree-stratified protocol (AUC 0.74; 0.61-0.66 inside agent conversations), but below a lexical baseline (0.99), with two-hop edges at 0.57. Small agents carry a one-hop, largely lexical picture of their repository, in weights and in use. We release the agent, probes, logs and traces.

## 1. 核心问题与研究动机

- **背景前提**：当前编码智能体普遍被赋予两类“结构化工具”——对函数体做稠密检索的嵌入搜索，以及对静态代码图（文件/类/函数节点，包含 contain/import/invoke/inherit 边）的查询接口。其隐含假设是：**仓库结构是模型本身所缺乏的，工具负责补足它**；问题文本点名某处代码，修复位置沿依赖结构在若干跳之外，纯文本 grep 无法跨越这段距离，因此需要语义索引（直接跳到语义相近处）或代码图（沿边走）。
- **文献缺口**：LocAgent 曾用 GPT-4o 抽取提及、按跳距打分，报告图引导智能体随深度增长退化最小；CodeAnchor 指出 SWE-bench Lite/Verified 多为 1–2 跳故障，并呼吁“按结构深度排序的基准”。但既有工作未系统回答三个问题：
  1. 结构深度是否是**可用且可控**的难度轴？
  2. grep、嵌入搜索、图工具各自贡献多少，机制是什么？
  3. 模型**内部**是否表征了仓库的调用/继承图？
- **研究定位**：作者刻意选择**小型开放权重模型（0.6B–32B）**，因为其行为可低成本重复测量，且工具支持最可能在此规模上起作用；核心论点是检验“工具补结构”这一前提是否成立。

## 2. 方法论

### 2.1 第一部分：Hop Depth 作为难度轴

- **代码图构建**：对每个 SWE-bench Verified 实例，在 `base_commit` 检出仓库，用 Python `ast` 解析全部 `.py` 文件，构建无向类型多重图 \(G_i=(V_i,E_i)\)，节点为文件/类/函数（以 `path:QualifiedName` 标识，含行号跨度），边为 CONTAIN、IMPORT、INVOKE、INHERIT 四类；名称解析采用固定优先级（同类方法→同文件→from-import 模块→全仓库同名且数量 ≤ \(K_{res}=5\)）。
- **目标与提及**：
  - **目标 \(T_i\)**：金标准补丁修改行所在的**最内层定义**（模块级则为文件节点）。
  - **提及 \(M_i\)**：用六条正则（反引号跨度、`name(`、traceback 帧、点分名、snake_case、CamelCase）从 issue 文本抽取 token，再映射到节点集合；过于通用的名字（> \(K_{men}=20\) 个定义共享）被丢弃。
- **Hop depth 定义**：从 \(T_i\) 出发做 BFS，取提及节点到目标节点的**无向最短路径长度**，分桶 hop0/hop1/hop2/hop3+，另有 no_mention 与 unreachable。
- **统计模型（Depth GEE）**：对智能体回合拟合总体平均 logistic 模型
  \[
  \text{logit}\,\Pr(y_e=1)=\beta_0+\beta_{hop}\cdot \text{hop}_i+\beta_{arm}^\top \mathbf{1}[a_e]+\beta_{repo}^\top \mathbf{1}[r_i]+\beta_g n^{gold}_i+\beta_p\log(1+L_i)
  \]
  用 GEE（binomial、exchangeable 工作相关、按任务聚类）估计，报告每跳优势比 \(OR_{hop}\)，并做有/无控制块对比。
- **标签稳健性（LABEL VAR）**：三种变体——`strict_resolve`（\(K_{res}=1\)）、`loose_resolve`（\(K_{res}=20\)）、`strict_mentions`（仅反引号与 traceback，\(K_{men}=5\)），重算标签并重拟合。

### 2.2 第二部分：工具消融

- **任务形式**：智能体只做**定位**——读 issue，调用一次 `submit` 提交最多 10 个排序位置（`path.py:QualifiedName` 或 `path.py`），不写补丁。
- **四个工具臂**：
  - **G** = `grep` + `read_file` + `list_dir`
  - **E** = G + `semantic_search`（Qwen3-Embedding-0.6B，节点 id + 前 40 行定义，带检索指令前缀）
  - **T** = G + `find_entity`（按名查找）+ `graph_neighbors`（1–2 跳 BFS 扩展，每行一条边，截断 50 行）
  - **ET** = 全部工具
- **关键 harness 规则**：① 无工具调用的回合后强制要求下一回合调用工具（否则贪心解码会重复空消息至步数上限）；② 工具输出截断 4,000 字符，只有模型实际收到的行才算“揭示”节点。
- **指标**：主指标 `function Acc@10`（所有金标准函数都进入前 10）、`recall@10`、`file Acc@5`、`gold revealed`、提交率、步数、token 数；匹配允许限定名前缀匹配。
- **实验族**：SEEDS（方差）、TRACES（轨迹级机制分析）、WEAK EMB（弱嵌入器）、FORCE TOOL（强制调用）、BUDGET（50 步/40k 上下文）、REPAIR（下游修复）、SCALE CURVE（规模曲线）。
- **规范重打分（canonical rescoring）**：把提交字符串无歧义地修复为节点 id（行号→最内层定义、`::`→`.`、去掉参数表、唯一短名可接受），用于**分离“发现目标”与“提交形式”**。

### 2.3 第三部分：线性探针

- **关系与标签**：CALL（a 直接调用 b）、CALL2（a 经两跳到达 b，且 b 的短名不出现在 a 的源码中，以去除词法线索）、INHERIT（a 的类继承 b）；负例为无 ≤2 跳调用/继承路径的对，排除包含关系。
- **表示**：定义 \(v\) 取**最后一个 token 的残差流** \(h_v^{(\ell)}\)；对 (a,b) 的探针输入为 \(x_{ab}=[h_a;h_b;h_a\odot h_b]\)，另有单侧（只看 \(h_a\) 或 \(h_b\)）与仅交互（\(h_a\odot h_b\)）对照；线性 logistic 探针（Adam，300 步全批，类加权交叉熵）。
- **关键协议设计——within-anchor + 度数分层**：
  - 全局对探针 AUC 可达 0.75–0.80，但**单侧探针、b 的文件内入度、词法基线**也能达到同等水平，说明存在节点级捷径。
  - 因此改为**锚点内排序**：每个锚点 a 的候选集为其正例 + 最多 15 个同上下文负例，度量池化 within-group AUC；**严格分组 = 锚点 × b 的入度分箱**（0/1/2/3–4/5+），使入度基线被压到 0.50–0.53。
  - 对照：b-only 探针、仅交互探针、组内置换标签、入度基线、词法基线 \(\mathbf{1}[\text{name}(b)\in\text{text}(a)]\)、token 距离、同类成员；锚点 bootstrap 置信区间。
- **对话内探针（CONV PROBE）**：把真实智能体对话按原样渲染（chat template + 工具 schema）过一遍模型，在对话中出现的定义上重复同一协议，并区分“工具打印过的边（stated）”与“未打印的边（unstated）”。

## 3. 实验设计

- **数据集/基准**：SWE-bench Verified 全部 500 个任务（Python），按 hop depth 分层；主实验用**深度均衡的 160 任务子集**（每桶 40 个，156 个有函数级金标准，覆盖 11 个仓库，Django 占 80），预算实验用 80 任务，规模曲线用全部 500 任务（485 个有函数级金标准）。
- **模型**：Qwen3-0.6B/1.7B/4B(hybrid)/8B/14B/32B-FP8（每种贪心 + 4 个 \(T=0.7\) 种子），Qwen3-14B-FP8（精度对照），Gemma 4 E2B/E4B（贪心 + 2 种子）、Gemma 4 12B（仅贪心、307 任务、退化）；主实验另有 Qwen3-4B-Instruct-2507、Qwen3-8B、Gemma 4 E4B、Qwen3-32B。
- **对比方法**：四个工具
