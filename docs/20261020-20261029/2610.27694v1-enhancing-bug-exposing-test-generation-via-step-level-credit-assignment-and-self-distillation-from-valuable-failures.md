## 摘要
大语言模型已展现出强大的代码生成能力，但其输出往往包含细微缺陷。自动修复此类代码需要信息丰富的测试：能够暴露错误行为的输入，并配有正确的预期输出。近期基于强化学习的测试生成方法将所有推理步骤赋予相同的结果奖励，这可能抑制有用的推理并强化有缺陷的步骤。它们也无法有效从找到触发缺陷输入但预测输出错误的轨迹中学习，导致其已验证的触发缺陷进展未被充分利用。为解决这些局限，我们提出 SCALF，一种过程监督的强化学习方法，将步骤级信用分配与从有价值失败轨迹中进行针对性学习相结合。SCALF 从过程奖励中推导步骤特定的优势，使每个推理阶段获得各自的学习信号。它进一步将暴露缺陷但预测输出错误的轨迹路由至同策略自蒸馏，利用执行反馈从其有价值的触发缺陷进展中学习。在三个基准上，SCALF 在联合成功率、输出正确率和触发缺陷率上分别较强提示与后训练基线最高提升 2.97、5.26 和 3.53 个百分点。我们的代码和数据集可在 https://anonymous.4open.science/r/SCALF-F4D1 获取。

## Abstract
Large Language Models have shown strong code generation capabilities, yet their outputs often contain subtle bugs. Automatically repairing such code requires informative tests: inputs that expose faulty behavior, paired with correct expected outputs. Recent RL-based test generation methods apply the same outcome reward to all reasoning steps, which can discourage useful reasoning and reinforce flawed steps. They also fail to effectively learn from trajectories that find bug-triggering inputs but predict incorrect outputs, leaving their verified bug-triggering progress insufficiently exploited. To address these limitations, we propose SCALF, a process-supervised RL approach that combines Step-level Credit Assignment with targeted Learning from valuable Failed trajectories. SCALF derives step-specific advantages from process rewards, allowing each reasoning stage to receive its own learning signal. It further routes trajectories that expose bugs but predict incorrect outputs to on-policy self-distillation, using execution feedback to learn from their valuable bug-triggering progress. Across three benchmarks, SCALF outperforms strong prompting and post-training baselines by up to 2.97, 5.26, and 3.53 percentage points in joint success rate, output correctness rate, and bug-triggering rate, respectively. Our code and datasets are available at https://anonymous.4open.science/r/SCALF-F4D1.

## 1. 核心问题与研究动机

- **背景**：LLM 代码生成能力强，但输出常含细微逻辑缺陷。自动程序修复需要“信息丰富的测试”，即同时满足两个条件：输入能触发错误行为（Bug Triggering, BT），且给出正确预期输出（Prediction Correctness, PC）。
- **现有方法局限**：
  - 基于提示（prompting）的方法仅靠零样本/少样本，缺乏任务特定优化。
  - 后训练方法（如 UTGen 用扰动数据微调、ATGen 用对抗 RL + 结果奖励）存在两个关键缺陷：
    1. **结果奖励均摊**：同一轨迹内所有推理步骤共享相同结果奖励，可能抑制有效推理、强化错误步骤；而测试生成涉及“缺陷分析→测试设计→输出预测”等相互依赖的推理阶段。
    2. **失败轨迹利用不足**：对于“触发缺陷但输出错误”（BT=1, PC=0）的轨迹，其已验证的触发输入极具价值（只需修正输出即可成为有效测试），但标准 GRPO 不区分不同部分成功的价值，未加利用。
- **整体含义**：论文主张对缺陷暴露测试生成引入**过程级监督 + 步骤级信用分配**，并针对性地从“高价值失败轨迹”中学习，从而同时提升输出正确率与缺陷触发率。

## 2. 方法论（SCALF）

### 2.1 核心思想
将测试生成建模为 MDP（状态为前缀上下文，动作为结构化推理步骤），在 GRPO 框架上叠加两个组件：**Step-level GRPO**（步骤级信用分配）与 **Failure-routed OPSD**（有价值失败轨迹的同策略自蒸馏），通过损失级路由联合训练。

### 2.2 关键技术细节

- **任务特定 PRM 的构建（数据三阶段流水线）**：
  - *Stage 1 难度过滤*：基于 CodeContests+，用 Qwen2.5-Coder-32B-Instruct 对每个（问题，错误解）采样 8 条响应，丢弃全成功或全失败者；得到 2,000 题用于 PRM 数据、1,843 题/15,695 任务用于生成器训练。
  - *Stage 2 蒙特卡洛步骤标注*：对中间步骤采样 K=8 条续写，计算 MC 分数（完成轨迹的执行成功率的均值）；按相对进度准则打硬标签：若 MC(s_t,a_t)/MC(s_t) ≥ ε（ε=0.9）则标为正，否则为负。
  - *Stage 3 LLM 一致性过滤*：用 DeepSeek-V3.2 独立判断每步有效性，仅保留 MC 标签与 LLM 判断**逐步完全一致**的轨迹（最终 23.1K 轨迹、69.4K 步骤标签，正例 53.9%）。
  - PRM 以 Qwen2.5-Coder-7B-Instruct 初始化，作为二分类步骤验证器训练（预测奖励 token r⁺/r⁻），人工验证集上准确率 77.11%、F1 79.68%。

- **Step-level GRPO**：
  - 结果奖励：`R_out = BT + PC + R_fmt`（格式非法记 -1）。
  - **全成功门控**：仅当 BT=1 且 PC=1 时叠加 PRM 步骤分数 `p_i,t`，即 `R̃_i,t = R_out + I[BT∧PC]·p_i,t`，以缓解 PRM 在分布外轨迹上的 reward hacking。
  - 对每个步骤 t 在 G 条轨迹间做组归一化得到步骤级优势 `A_i,t = (R̃_i,t − μ_t)/(σ_t + δ)`，且该优势**只作用于对应步骤的 token 区间**，从而避免跨阶段信用干扰。

- **Failure-routed OPSD**：
  - 路由指示 `z_i = I[BT=1 ∧ PC=0]`。
  - 对被路由轨迹，保留其触发缺陷的输入 x_i，用参考解执行得到正确输出 y*_i，连同执行反馈构成特权信息 f_i。
  - 学生分布仅条件于（问题、错误解、前缀），教师分布额外条件于 f_i，二者共享参数；最小化逐 token KL 散度，实现“保留触发输入、纠正输出预测”的定向学习。

- **联合目标**：
  `L = (1/G) Σ_i [ (1−z_i)·L_step-GRPO,i + λ_OPSD·z_i·L_OPSD,i ]`
  即先对全部 G 条轨迹计算步骤级优势（保留组内相对比较），再按轨迹路由选择损失；λ_OPSD=0.1。

## 6. 主要结论与发现

- **主结果**：SCALF-7B 在三个 benchmark 上同时取得最佳 PCR、BTR 与 PCR∩BTR。CodeContests+ 上达 87.41% / 41.19% / 28.83%，较最强基线 ATGen-7B 分别提升 5.26 / 2.75 / 2.97 个百分点；TestCase-Eval 联合成功率 9.22%→11.37%；MBPP+Fix (Hard) 28.82%→31.18%。
- **参数效率**：SCALF-3B 以约 1/10 参数量在多项指标上超过 Qwen3-32B，说明增益并非仅来自更大骨干。
- **消融结论**：Step-GRPO 与 Routed OPSD 各自有效且互补，组合最佳；步骤级信用分配优于所有轨迹级 PRM 聚合方式（联合成功率 27.69% vs. 最高 26.77%）。
- **路由机制验证**：GRPO 下 BT1PC0 的案例有 30.2% 在加入 routed OPSD 后转为完全成功，而仅 13.2% 退化为未触发，印证“保留触发输入、修正输出”的设计意图；路由比例仅约 8–12%。
- **门控必要性**：无门控 PRM 会诱发 reward hacking（输出空泛推理模板），全成功门控比无门控/子目标门控分别高 4.35/3.66 个百分点。
- **下游价值**：K1=7、K2=3 时修复成功率达 44.16%，优于所有基线；K2=1 与 K2=5 设置下同样领先。
- **泛化性**：跨模型家族（DSC-6.7B 上联合成功率 18.76%→20.37%）与真实缺陷（BugsInPy 上 20.00%→26.67%）均有效。

## 7. 优点

- **问题切分精准**：将“触发缺陷”与“预测正确输出”作为两个可执行验证的子目标，并识别出 BT=1/PC=0 这一被忽视的高价值失败类型，动机清晰、针对性强。
- **方法设计巧妙**：
  - 步骤级优势仅作用于对应 token 区间，避免跨阶段信用干扰；
  - 全成功门控把过程监督锚定在执行验证的成功轨迹上，有效抑制 PRM reward hacking；
  - 失败轨迹路由采用“共享参数、不同上下文”的自蒸馏，无需额外教师模型，且保留组内相对比较。
- **数据构造严谨**：MC 估计 + LLM 判官双重一致性过滤，并附标签统计与人工校验的 PRM 质量评估。
- **实验体系完整**：主实验、消融、机制分析（聚合方式、门控时机、阈值敏感性、结果转移矩阵）、跨模型/跨域泛化、下游修复多设置，形成较完整的证据链。

## 8. 不足与局限

- **过程监督覆盖有限**：为避免 reward hacking，PRM 分数仅用于完全成功轨迹，失败轨迹缺乏直接过程监督；作者亦承认这是权衡。
- **训练开销增加**：PRM 逐步打分与自教师前向带来额外计算成本，论文未量化其相对 outcome-only GRPO 的具体开销比例。
- **数据与标注依赖**：PRM 标签源自特定模型（Qwen2.5-Coder-32B）的 rollout，存在模型相关偏差；LLM 判官过滤可能引入判官偏好，人工校验集仅 150 例。
- **统计严谨性不足**：未报告多次运行的方差、置信区间或显著性检验，随机种子固定为 42。
- **泛化验证规模偏小**：BugsInPy 仅 30 个实例，结论的统计力度有限；训练数据集中于竞赛编程风格，跨语言（非 Python）与仓库级真实工程场景未验证。
- **应用前提较强**：OPSD 依赖可执行的参考解 C_ref 来获得正确输出，在缺少可靠参考实现的现实场景中适用性受限；作者也提示生成测试若期望输出错误可能误导下游修复，需配合执行验证或人工审查。
- **指标解读需谨慎**：TestCase-Eval 上各方法绝对联合成功率普遍偏低（约 9%–11%），整体任务难度仍构成挑战。
