## 摘要
随着编码智能体能力不断增强，开发者越来越多地通过多轮交互使用它们修复缺陷。现有基准未能充分覆盖这一场景。多数基准在单轮中给出完整的问题报告，且不涉及交互。其评估既可能产生假阳性也可能产生假阴性，即接受错误的补丁或拒绝正确的补丁。我们提出 UserSWE，用于评估编码智能体通过与动态用户进行多轮交互修复仓库级缺陷的能力，并在每一轮给出基于执行的判定。其构建流程将仓库历史与现有单轮基准转化为多轮任务。在每一轮中，信息池约束模拟用户可透露的信息，而从基于 20,859 个开发会话校准的转移模型中采样得到的人设链则决定其说话方式。每一轮后都会运行测试，由来自不同模型家族的一对智能体撰写并把关每项判定，以测试结果作为主要证据，仅在测试无法解决的方面才使用模型判断。我们在来自 42 个仓库的 72 个任务上评估了 11 个智能体，发现智能体的排名会随交互预算而变化。Claude Fable 5.1 在单轮内解决的任务最多，GPT-6-Astra 在第八轮时解决的任务最多，而 Claude Opus 5 在大多数中间预算下领先。这些结果表明，单轮性能不足以刻画交互式编码能力。

## Abstract
As coding agents become more capable, developers increasingly use them to fix bugs through multi-turn interactions. Existing benchmarks do not adequately cover this scenario. Most present a complete issue report in a single turn without interaction. Their evaluation can produce both false positives and false negatives, accepting incorrect patches or rejecting correct ones. We introduce UserSWE for evaluating coding agents' ability to fix repository-level bugs through multi-turn interactions with dynamic users and execution-grounded verdicts at every turn. Its construction pipeline turns repository history and existing single-turn benchmarks into multi-turn tasks. At each turn, information pools constrain what the simulated user can reveal, while a persona chain sampled from a transition model calibrated on 20,859 development sessions governs how it speaks. Tests run after every turn, and a pair of agents from different model families writes and gates each verdict, using test results as primary evidence and model judgment only for aspects the tests cannot resolve. We evaluate eleven agents on 72 tasks from 42 repositories and find that agent rankings change with the interaction budget. Claude Fable 5.1 resolves the most tasks in one turn, GPT-6-Astra resolves the most by the eighth turn, and Claude Opus 5 leads at most intermediate budgets. These results indicate that single-turn performance is insufficient to characterize interactive coding ability.

# UserSWE 论文中文总结

## 1. 核心问题与研究动机

- **背景**：编码智能体已从自动补全、上下文对话演进到能自主浏览仓库、编辑文件、运行测试的"vibe coding"形态。真实开发中，开发者往往先给出不完整请求，再根据中间输出逐步追问、澄清，调试尤是如此。
- **现有基准的两大缺陷**：
  - **单轮设定**：多数基准一次性给出完整 issue，要求一次返回补丁，智能体从未真正处于"对话工作流"中；少数多轮基准（如 SWE-Interact、SWE-Together）用户是静态的——按固定顺序释放信息或用固定口吻说话，本质是"无响应的机制"而非"开发者的模拟"。
  - **多轮判定不可靠**：每轮都需独立评估，但标准测试只能提供事实性执行证据；不受约束的 LLM 评审容易做出超出测试证据的推断。测试过松会接受无效补丁（假阳性），过紧会拒绝功能等价实现（假阴性）。
- **整体含义**：论文主张单轮性能不足以刻画交互式编码能力，需要一个同时解决"任务从哪来、轮次从哪来、每轮如何判"的多轮基准，即 **UserSWE**。

## 2. 方法论

### 2.1 核心思想
UserSWE 由三根支柱构成：**任务构建管线**（仓库历史 + 单轮基准 → 多轮任务）、**动态人格用户模拟**（基于真实开发会话校准）、**执行锚定的双智能体评估框架**（每轮跑测试，跨家族 Judge/Reviewer 把关）。

### 2.2 数据构建（两条路线 + 信息池）
- **级联路线**：在仓库历史中挖掘由维护者显式关联的两个 issue——"揭示信号"（后一 issue 自述在排查前一 issue 时暴露）或"依赖信号"（PR 声明叠加/依赖前一改动）；要求两者均有合并修复，且后一记录指向先前工作。22 个级联中 6 个来自揭示信号、16 个来自依赖信号。
- **转化路线**：取已发布单轮任务，保留仓库状态、gold patch、测试与容器镜像，仅改变信息在多轮中的释放方式。
- **信息池**：每任务一个冻结文件，字段包括 clear symptom（可复现的用户可见观察）、vague symptom（模糊印象）、correct idea（低置信正确方向，非修复步骤）、wrong idea（貌似合理但非因果的方向）、follow-up set（第二 issue 的同四字段）、phase map（各阶段验收点）。
- **防泄漏**：禁止 gold patch 引入的标识符；级联中两 issue 标题共享的 scope 若未被第一补丁交付则移除；检查不通过则拒收任务。

### 2.3 多轮交互（内容选择 + 人格表达）
- **内容释放策略**（固定优先级）：① 智能体直接提问→直接回答；② 最严重的用户可见阻塞性失败；③ 未覆盖的核心业务边界；④ 次要边缘情况。任务解决后不再释放信息。
- **八种人格**：两轴交叉——**clarity**（clear / vague）× **veracity**（none / correct / off-target / wrong）。off-target 与 wrong 开场相同，仅在面对反驳时分化：off-target 在合理论证后放弃，wrong 只屈服于已执行测试、复现或代码事实证据。
- **人格链校准**：从内部部署商业编码助手的 **20,859 个开发会话**中标注，剔除无代码变更后剩 **13,530 个**；八格覆盖 98.65%，其中 52.98% 以 clear-none 开场、19.03% 以 clear-correct 开场。构建 **8 个以开场人格为条件的转移矩阵**（而非单一全局矩阵）。
- **冻结机制**：每任务预先抽样整条人格链并写入 cohort manifest，同一任务的所有智能体面对完全相同的人格轨迹；内容选择动态、措辞动态，但"议程"冻结。
- **话语策略**：以软件用户而非代码评审者口吻说话，只陈述用户可见诉求/观察/期望，不暴露评测或实现细节；人格可被交互"削弱"（如 off-target 被反驳后变 none），但无 cause 的人格永不获得 cause，correct cause 永不变成实现指令。

### 2.4 评估框架
- **每轮后执行测试**：fail-to-pass 与 pass-to-pass 全绿才算解决。
- **Judge/Reviewer 双家族门控**：Judge 写出判定与下一轮用户消息，Reviewer 来自不同模型家族，可 KEEP / REWRITE / UNAVAILABLE；等价请求另有 APPROVE / REJECT。两者在任务间互换角色，属**内联门控**而非事后审计。
- **Judge 状态机**：U（未改动，加权轮数 +0.5）、F（继续）、C（框架步骤）、D（完成）、R（等价重写请求）、E/T/X（判官错误/测试错误/策略违规）。
- **机械结算四规则**：规范测试通过覆盖模型写的 N；无有效认证的等价 Y 变 N；声称未编辑但 workspace 指纹变化则禁用 U 重问；验收项集合与任务契约不符则 fail-closed。
- **等价通过（Algorithm 2）**：改写测试须在候选 workspace 通过且不回归 P；须在 base workspace 失败（base discrimination）；再由 Reviewer 做行为保留审查；全部通过才更新 scorecard。
- **LDPR 指标**：`LDPR = (K+1−k)/K`（全部测试通过时），否则为 0；k 为加权轮数，无代码编辑的轮计 0.5 轮。K=5（单 issue）或 K=8（双 issue）。
- **准入检查**：base P2P 通过、base F2P 失败、gold P2P 通过、gold F2P 通过；级联还需中间态检查（第一修复后第一阶段通过、第二阶段仍开放、回归保持绿色）。另有只读的 agent 可解性人工复核。

## 3. 实验设计

- **Benchmark**：UserSWE 共 **72 个任务、42 个仓库**——22 个仓库历史挖掘的级联任务（双 issue，K=8）+ 50 个由已发布单轮基准转化的单 issue 任务（K=5）。
- **被评对象**：**11 个模型-脚手架组合**（Claude Opus 5 / Claude Code、Claude Fable 5.1 / Claude Code、Grok-4.6 / Claude Code、GPT-6-Astra / Codex、DeepSeek-v4.1-Flash / DSH、GPT-5.6-Sol / Codex、GLM-5.3 / Z.ai Code、Gemini-3.8-Flash / Claude Code、Hunyuan-4.0-preview / Claude Code、Doubao-Seed-2.1-Pro / Claude Code、Kimi-K3 / Kimi Code）。
- **评审配置**：Judge/Reviewer 在 Claude Code–Opus 5 与 Codex–GPT-5.6-Sol 之间轮换。
- **对比与分析组**：
  - 主表：各 agent 在前 1–8 轮内的解决率、平均轮数 k、LDPR。
  - 单轮对照：4 个领先 agent 在另取 **42 个单轮任务**（SWE-bench Pro + SWE-bench-Live）上的排名。
  - 人格消融：4 个 agent 在 50 个单 issue 任务上，比较"始终 clear-correct 的理想用户"与"动态人格链"。
  - 框架分析：Reviewer 改写率与四类异议分布（Evidence / Guidance / Equivalence / Persona）、等价通过批准率与拒绝门、按开场清晰度分组的 LDPR 差异。
  - 统计：任务为采样单位的 bootstrap 95% 置信区间；55 对 agent 比较的配对置换检验 + Benjamini-Hochberg 5% FDR 校正。
  - 成本：每任务 agent 侧与评审侧的请求数、token、费用、编辑规模。
