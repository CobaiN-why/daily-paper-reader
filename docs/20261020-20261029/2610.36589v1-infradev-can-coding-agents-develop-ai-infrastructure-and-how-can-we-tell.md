## 摘要
编码智能体正开始开发用于训练和 serving 大模型的生产级 AI 基础设施，但现有基准仅覆盖单个 kernel 或单 GPU 任务，并且使用会误判正确与错误补丁的测试和提示进行评分。我们提出 InfraDev，一个包含 36 个任务的基准，这些任务基于对 Megatron-LM、vLLM 和 verl 的真实 pull request 构建，涵盖训练、推理和强化学习的基础设施开发。每个任务要求智能体重新实现一个跨多个文件的真实改动，并且必须在多 GPU 上正确运行。为了评估此类改动，我们联合合成了隐藏探针（用于强制检查原始测试未覆盖的要求）和一个提示，该提示声明探针调用的每个接口而不泄露解决方案。我们还设计了一个共享执行环境，可跨任务复用依赖和产物，在 Megatron-LM 和 vLLM 上将存储减少 52-57%，构建时间减少 13-14%。在六个前沿模型中，最佳模型仅解决 38.9% 的任务；探针拒绝了 32% 通过所有官方测试的提交；并且以原始 pull request 描述作为提示时，没有任何模型能解决单个任务。失败分析表明，结构错误和状态错误占主导，且智能体自身的测试很少检查内存、时间或流量。将这些发现转化为一种智能体技能，可将某个前沿模型在 Megatron-LM 任务上的解决率提高 10.5%。

## Abstract
Coding agents are beginning to develop the production-grade AI infrastructure that trains and serves large models, yet existing benchmarks cover only single kernels or single-GPU tasks, and grade with tests and prompts that misjudge both correct and incorrect patches. We introduce InfraDev, a benchmark of 36 tasks built from real-world pull requests to Megatron-LM, vLLM, and verl, covering infrastructure development for training, inference, and reinforcement learning. Each task asks an agent to reimplement a real change that spans many files and must run correctly across many GPUs. To grade such changes, we jointly synthesize hidden probes, which enforce the requirements the original tests leave unchecked, and a prompt that states every interface the probes call without revealing the solution. We also design a shared execution environment that reuses dependencies and artifacts across tasks, cutting storage by 52-57% and build time by 13-14% on Megatron-LM and vLLM. Across six frontier models, the best resolves only 38.9% of the tasks; the probes reject 32% of the submissions that pass every official test, and with the original pull request descriptions as prompts, no model resolves a single task. Failure analysis shows that structural and state errors dominate and that agents' own tests rarely check memory, time, or traffic. Turning these findings into an agent skill raises the resolved rate of a frontier model on the Megatron-LM tasks by 10.5%.

# InfraDev 论文结构化总结

## 1. 核心问题与研究动机

- **核心问题**：编码智能体（coding agents）能否开发真实世界的 AI 基础设施（训练、推理、强化学习框架）？以及**如何可靠地判断**它们是否真的做到了？
- **背景**：vLLM 单月合并约 1,918 个 commit（约 64/天），基础设施代码库快速演化；真实改动往往跨多个文件、涉及并行/内存/通信子系统，且必须同时满足**数值正确**（分布式下激活、梯度、状态正确）与**行为正确**（新功能生效、优化真正降低内存/通信/时延）。
- **现有评测的三大局限**：
  - **任务范围窄**：多数基准只评单个 GPU kernel 或单 GPU 推理优化；Φ-Bench 虽到系统级，但仍是固定目标的优化题，而非开发者真正提交的改动。
  - **测试与提示双向误判**：直接复用 PR 自带测试和描述。36 个 PR 中 24 个没有数值断言，15 个性能优化中 13 个不检查承诺的节省；提示又缺少测试依赖的接口名与行为，导致正确实现也会失败。二者耦合：测试强制的每条要求都必须在提示中声明。
  - **评测成本高**：每任务独立依赖与大产物（模型权重），存储与构建时间开销大，限制基准规模与可复现性。

## 2. 方法论

### 2.1 总体框架
- 每个任务 = 让智能体基于 **pre-PR 快照** 重新实现一个真实合并 PR；用**官方测试 + 隐藏探针**评分；全部流程运行在**可复用执行环境**中。
- 流程：PR 筛选 → 隐藏探针合成 → 提示合成 → 智能体推理 → 评分。

### 2.2 PR 筛选（任务构建）
- 来源：Megatron-LM（训练）、verl（强化学习）、vLLM（推理），2025-01 至 2026-09 共 21,389 个 PR。
- 规则过滤：已合并未回滚、改动 ≥1,000 行、新增测试；再由领域专家人工挑选核心功能 PR，最终 **36 个**。
- 任务类型：新功能 19、性能优化 15、重构 1、Bug 修复 1；按仓库为 19/7/10。
- 规模：平均改动 **17.4 个文件、1,818 行**；**20/36 需多 GPU**。
- 记录 pre-PR 与 post-PR 快照，其差分为 **golden patch**（参考解）。

### 2.3 隐藏探针合成（Algorithm 1）
- 目标：补齐官方测试未覆盖的**数值正确性**与**行为正确性**要求。
- 流程：
  1. 总结 PR 承诺实现的内容 C；
  2. 构造**对抗补丁** Δ₁…Δₖ：能通过全部官方测试、但违反数值或行为要求的错误实现；
  3. 针对 C 编写探针 T_probe；
  4. 迭代修正探针与对抗补丁，直到通过验收检查；
  5. 输出探针。
- **验收检查（Algorithm 2）**，三个条件同时成立：
  - `ok1`：每个探针在 golden patch 上**连续三次运行**全部通过（且无 skip）；
  - `ok2`：每个探针在 pre-PR 快照、**hollow patch**（保留新接口但所有新函数抛异常）、以及每个对抗补丁上均失败；
  - `ok3`：每个对抗补丁在官方测试上得分**不低于** golden patch（证明其确实能骗过官方测试）。
- 探针类型：
  - 数值探针：与已有实现参考值比较、不变量（如 chunk size 改变不改变输出）、手算 float64 参考、恒成立性质（如分布对自身 KL 为 0）。
  - 行为探针：测量承诺效果（如激活 offload 搬运的字节数、各 rank 收到的元素数、权同步发送的条目数）。
- 固定轮数内未通过验收的 PR 将不带探针。

### 2.4 提示合成
- 核心原则：**充分（sufficient）**——正确实现不能因提示遗漏接口而失败；**无解（solution-free）**——不泄露算法、公式、数值常数与容差。
- 将 PR 信息拆为 **specification（做什么）** 与 **solution（怎么做）**，只把前者写入提示。
- 流程：探针合成方交付 handoff record（声称行为 + 所需符号及输入类型，不含探针代码）→ 静态分析器提取**接口契约**（golden patch 引入且被测试/探针引用的符号）→ 作者智能体依据 PR 描述、golden patch、官方测试、handoff、契约撰写提示。
- 双重校验：linter 拒绝遗漏契约符号的提示；checker agent 拒绝泄露解决方案的提示；循环修订至通过。
- 附录 B 给出统一模板：规格说明、全自主运行要求（禁止查询原 PR）、接口契约、执行与验证规则（import/collect 门禁、单进程 sanity、多 rank 分布式验证、回归测试）。

### 2.5 资源高效执行环境
- 打破 Docker 前缀缓存：为每个仓库维护轻量基础镜像（仅 CUDA、Python 等共享组件）。
- 每任务依赖装入由 `uv` 安装在**共享 volume** 上的虚拟环境；锁定依赖哈希相同的任务**共享同一环境**；新环境对缓存包做**硬链接**而非重装。
- 所有容器挂载同一个 Hugging Face 缓存，模型/数据集只下载一次。
- 推理与评分均使用该环境。

### 2.6 评分指标
- 每任务记录 golden patch 运行时的测试用例数 N_p；补丁通过率 s_p = passed_p / N_p；**% Passed** 为任务间等权平均。
- **% Resolved**：补丁通过的用例数不少于 golden patch 即视为解决（不要求通过 golden 本身失败的用例）。
- 缺失/空/不可应用补丁记 0/N_p（不丢弃，避免奖励放弃）；harness 故障单独计数，不计为模型失败；保留逐测试结果与完整轨迹供失败分析。

## 3. 实验设计

- **基准**：InfraDev 36 任务（Megatron-LM 19、verl 7、vLLM 10），覆盖训练、RL、推理。
- **评测模型（6 个）**：
  - 闭源：GPT-6 Sol、GPT-5.6 Sol（OpenAI Codex harness，v0.155.1）；
  - 开源：GLM 5.3、DeepSeek V4 Pro (0813)、Kimi K3、HY4 preview（OpenCode harness，v1.18.31）。
  - 推理强度统一设为 xhigh 或同等水平；每任务每模型运行一次。
- **运行设置**：每任务 2.5 小时时限（不含环境准备），带早期意外停止恢复机制；输出补丁应用到 pre-PR 快照的独立容器，测试目录替换为 post-PR 版本以防篡改测试。
- **消融/对照**：
  1. 官方测试单独（Set A）vs 官方 + 隐藏探针（Set B）；
  2. 合成提示 vs 原始 PR 描述（仅在 19 个 Megatron-LM 任务上）；
  3. 共享执行环境 vs 每任务一个 Docker 镜像（存储与构建时间）。
- **失败分析**：5 个模型（不含 GPT-6 Sol）× 36 任务 = 180 次提交，分析 1,754 个失败测试用例；对 94/103 条轨迹中的 5,532 条自写断言分类。
- **技能实验**：将失败分析提炼为智能体技能，在 Megatron-LM 19 任务上测试 GPT-5.6 Sol。

  - 主实验：6 模型 × 36 任务 = **216 次提交**；
  - 消融：探针消融（216 次双评分）、提示消融（2 模型 × 19 任务）、环境对比（Megatron-LM 2–19 任务、vLLM 若干任务的存储/构建时间曲线）；

  - 技能实验：19 任务。
- **充分性**：
  - 覆盖面较好：三大框架、三类任务（新功能/性能/重构/Bug 修复）、单/多 GPU、CUDA graph 等执行模式均有涉及；消融设计直接检验了论文两个核心主张（探针必要性、提示必要性）。

## 6. 主要结论与发现

- **能力仍不足**：最佳模型 GPT-6 Sol 仅解决 **38.9%** 任务；% Resolved 范围 25.0%–38.9%；% Passed 却高达 74.3%–83.3%，说明"大部分测试通过"不等于完成任务。
- **任务类别差异大**：推理（vLLM）最难，所有模型 10 个任务中仅解决 1 个；训练任务解决率 26.3%–52.6%，RL 任务 28.6%–57.1%；无单一模型全面领先。
- **隐藏探针必要**：加入探针后各模型解决率下降 11–19 个百分点；216 次提交中 102 次通过全部官方测试，但仅 69 次也通过探针，**探针拒绝 32%** 的"官方全过"提交。
- **合成提示必要**：改用原始 PR 描述后，即使加上探针，GPT-6 Sol 与 DeepSeek V4 Pro **无一任务解决**；合成提示下最高 52.6%，说明提示未泄露实现。
- **环境复用有效**：存储降低 57%（Megatron-LM，80.7→34.8 GB）与 52%（vLLM，206.0→98.8 GB）；构建时间降低 14% 与 13%；节省随任务数增长（2 任务时 17%/27%，全量时 57%/52%）。
- **失败模式**：
  - **结构错误主导**（48% 提交），其中执行/API 错误最多，其次是 state/lifecycle 错误；35 个状态错误提交中 **15 个仅被隐藏探针捕获**。
  - **数值错误全部源于算法错误**（24/24），**无一是纯精度问题**；误差量级远超舍入噪声（如 loss 应为 0 却得 19.95）。
  - **行为错误多与执行模式相关**：51 个行为错误提交中 35 个为条件特定；CUDA graph 任务上 60% 提交有此错误，其他任务仅 15%；智能体按 eager 模式写代码，忽视 CUDA graph 重放不重跑 Python 逻辑。
  - **自测盲区**：94/103 条轨迹写了自测，但 5,532 条断言中 **不足 2%** 检查资源（内存/时间/流量），56% 查功能、28% 查结构；11 条资源失败轨迹中仅 1 条写过资源断言。
- **技能可迁移**：围绕"检查调用者与状态、与朴素参考对比、测试资源与 CUDA graph"三条原则构建的技能，使 GPT-5.6 Sol 在 Megatron-LM 上从 42.1% 提升到 **52.6%（+10.5 个百分点）**。

## 7. 优点

- **测试与提示联合合成**：首次在同一闭环中同时修复"测试太弱"与"提示不全"两个耦合问题，并用对抗补丁 + hollow patch + 连续三次通过等严格验收，显著提升评分可信度。
- **任务真实性高**
