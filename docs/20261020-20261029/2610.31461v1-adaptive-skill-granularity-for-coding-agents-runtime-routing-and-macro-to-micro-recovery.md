## 摘要
可复用技能使大语言模型代理能够将任务特定流程、工具可供性和执行指导封装为模块化单元。已有工作大多研究代理在执行前如何检索、组合或合成技能。然而，在编码代理中，执行还带来了额外的运行时控制问题：同一任务既可以通过基础工具调用求解，也可以通过宏技能求解，或采用从宏开始并在失败时回退到微观级恢复的混合执行方式。我们提出自适应技能粒度（Adaptive Skill Granularity），该框架将技能粒度视为一种以任务结构、执行状态和宏技能失败为条件的动作抽象策略。系统结合了基于特征的粒度控制器和有限状态恢复执行器。我们采用确定性的编码代理协议评估该框架，使用验证器定义的成功、总成本以及宏采用率、失败恢复、路由匹配和转换正确性等过程指标。结果表明，固定宏执行在适用时高效，但在失配时较为脆弱；而运行时路由与显式宏到微恢复能够提升鲁棒性，并恢复固定粒度执行无法解决的受控宏失败。我们的发现表明，编码代理的技能库不仅应被视为可检索资源，还应被视为可控、可验证和可恢复的执行抽象。

## Abstract
Reusable skills allow large language model agents to package task-specific procedures, tool affordances, and execution guidance into modular units. Prior work has largely studied how agents retrieve, compose, or synthesize skills before execution. In coding agents, however, execution poses an additional runtime control problem: the same task may be solved through primitive tool calls, macro skills, or hybrid execution that starts with a macro and falls back to micro-level recovery. We introduce Adaptive Skill Granularity, a framework that treats skill granularity as an action-abstraction policy conditioned on task structure, execution state, and macro-skill failures. The system combines a feature-based granularity controller and a finite-state recovery executor. We evaluate the framework with a deterministic coding-agent protocol using verifier-defined success, total cost, and process metrics such as macro adoption, failure recovery, route match, and transition correctness. Results show that fixed macro execution is efficient when applicable but brittle under mismatch, while runtime routing and explicit macro-to-micro recovery improve robustness and recover controlled macro failures that fixed-granularity execution leaves unresolved. Our findings suggest that skill libraries for coding agents should be treated not only as retrievable resources, but also as controllable, verifiable, and recoverable execution abstractions.

## 1. 核心问题与整体含义

- **研究背景**：LLM 代理通过“技能”（skill）将可复用流程、工具可供性与执行指导封装为模块化单元。已有工作（如 SkillRouter、Graph-of-Skills、SkillCraft、轨迹挖掘等）主要关注**执行前**如何检索、组合或合成技能。
- **核心问题**：在编码代理中，技能被检索出来之后，**运行时仍存在一个额外的控制问题**——同一任务可以用基础工具（micro）求解、用宏技能（macro）求解，或采用“先宏、失败后回退到微观”的混合执行。技能抽象层级若与任务上下文不匹配，注入技能可能收益不均、增加成本，甚至降低软件工程表现（如 SWE-Skills-Bench 所示）。
- **整体含义**：论文主张把**技能粒度**从“检索问题”重新表述为**运行时动作抽象控制问题**，即代理不仅要决定“暴露哪个技能”，还要决定“以何种抽象层级执行下一步”，并在宏技能失败时进行受控的宏到微恢复。编码任务因仓库状态持久、工具副作用具体、测试可确定性验证，成为高可观测性的试验场。

## 2. 方法论

### 2.1 核心思想
- 将技能粒度建模为**以任务结构、执行状态和宏技能失败为条件的动作抽象策略**。
- 粒度模式集合 \(G=\{\mu, M, H\}\)：micro（仅原子工具）、macro（仅宏技能）、hybrid（先宏、可回退到微）。
- 与普通技能检索的本质区别：控制器改变的是**下游代理可用的动作集合**，而不仅是技能描述排序。

### 2.2 形式化流程
- **执行基底**：任务 \(\tau=(p, W_0, M, V)\)，轨迹 \(\pi=\langle a_1,\dots,a_T\rangle\)，动作 \(a_t\in S=S_\mu\cup S_M\)，每次动作变换工作区并产生观测 \(o_t\)（含工作区变化、验证失败、宏失败信号）。
- **动作包络**：\(A(g,h_t)\) 根据当前模式限制可选动作；hybrid 模式下，若历史中存在可恢复宏失败 \(F(h_t)\)，则包络切换为 \(S_\mu\)。
- **预执行控制器**：\(d_0=\rho(\phi(\tau))=(g_0,r_0,q_0)\)，其中 \(g_0\) 为初始策略，\(r_0\) 表示是否启用宏失败恢复，\(q_0\) 为可审计的解释/置信记录。
- **恢复转移函数**：\(g_{t+1}=\Delta(g_t,o_t,r_0)\)——当宏/混合模式出现可观测失败且恢复开启时降级为 micro；若恢复未开启则记为终止性宏失败 \(\perp\)；否则保持原模式。恢复被显式建模为**状态转移**，而非非正式的 retry 或重规划。
- **优化目标**：\(J(\rho,\pi_\psi)=\mathbb{E}[Succ-\lambda_T T-\lambda_C \hat C(\pi)-\lambda_F U(\pi,\tau)]\)，并以 G-score 作为效率的次要汇总指标（仅在成功率相近的策略间比较成本）。

### 2.3 关键技术细节
- **复杂度特征**（仅用执行前信息，防止验证结果泄漏）：路径数、Python/非 Python 文件数、实体串数、AST 节点数与最大深度、import 数、跨文件依赖数、文本任务标志、重构任务标志。
- **粒度控制器**：支持启发式规则与学习式路由；学习路由器为**最大深度 4 的浅层决策树**，离线训练后序列化为 JSON，运行时确定性遍历，保证可审计、无在线重训练、无黑箱神经检查点。
- **宏技能接口契约**：\(m=(name, args, pre, effect, V_m, F_m, fallback)\)，要求宏声明适用范围、允许的副作用、内部验证例程、可观测失败类别及微观回退路径。原型含三个手写宏：`inspect_python_module`、`replace_and_verify`、`move_module_and_update_imports`。
- **FSM 恢复执行器**：宏运行 → 失败分类器判定是否可恢复 → 若启用恢复则降级到 micro 并从当前工作区继续，否则终止为 `macro_failure_no_recovery`；成功必须通过验证器（语法+测试）。
- **失败分类法**：前置条件不匹配、部分副作用、验证失败、工具 schema 失败、执行器异常；只有降级后的微观轨迹产出通过验证的最终状态才计入恢复成功。
- **宏演化循环**（概念性扩展，未做端到端实验）：新宏须通过回放、副作用文档化、明确微观回退路径或声明不可恢复失败类的准入检查。

### 2.4 设计不变量
1. 预执行路由只使用预执行证据；
2. 恢复由事件驱动（可观测失败、验证失败、故障注入或恢复路由器决策）；
3. 成功由确定性验证器定义，而非模型自报完成。

## 6. 主要结论与发现

- **固定粒度的鲁棒性—效率权衡**：A-Micro 成功率 1.000 但成本最高（6.00 步、7217.75 token）；B-Macro 成本最低（2.71 步、3609 token）但成功率仅 0.583，失配时脆弱；C-Heuristic 仅取得 0.750 的折中。
- **恢复的价值取决于失败时机**：Before 故障下，无恢复完全失败（0.000），FSM 降级恢复全部任务（1.000）但成本升至 11293 token；After 故障下，宏已完成所需修改，无恢复即可通过（1.000、2440 token），无条件降级反而浪费成本（7566 token）。
- **学习式路由优于启发式**：D-Learned-ModeOnly 在 12 个任务上达到 1.000 成功率（启发式仅 0.750），说明基于经验结果标签的路由比静态结构规则更可靠。
- **端到端组合有效**：F-Learned-Full 在 Before/After 故障下均保持 1.000 成功率，同时将 Before 成本从 11293 降至 9764 token、After 成本从 7567 降至 3694 token，转换率从 1.000 降至 0.143，体现“选择性恢复”避免过度回退。
- **总体主张**：编码代理的技能库不应只被视为可检索资源，而应被视为**可控、可验证、可恢复的执行抽象**；自适应路由与失败感知恢复结合，比固定粒度或无条件回退都更稳健、更经济。

## 7. 优点

- **问题表述有新意**：明确区分“技能检索”与“运行时动作抽象控制”，把粒度选择提升为一等控制变量，并给出可审计的形式化（动作包络、恢复转移函数）。
- **恢复机制显式化**：用有限状态机把宏到微回退建模为状态转移，而非模糊的 retry 启发式；失败分类法（前置条件不匹配、部分副作用、验证失败等）便于归因分析。
- **可审计性与信息分离**：决策树路由器序列化为 JSON、深度受限；预执行路由严格不使用验证结果；成功由确定性验证器定义，减少自报偏差。
- **宏技能契约设计**：要求宏声明前置条件、副作用、内部验证与回退路径，为技能库准入提供了可操作的工程规范。
- **实验对照设计清晰**：固定粒度、启发式路由、学习路由、无条件恢复、选择性恢复逐层递进，故障注入区分 Before/After 时机，揭示了“恢复并非总是有益”的反直觉发现。

- **缺少与强基线的对照**：未与“统一使用 hybrid 但由 LLM 自行决定是否回退”（即把粒度决策交给底层模型而非外部控制器）这一最直接、最强的基线比较，因此无法判断外部控制器相对模型内隐自决的增量价值；也未与“始终 micro + 更强提示/更多步数预算”比较，成本优势的归因尚不完整。
- **理论刻画不足**：论文给出了优化目标 \(J\) 与转移函数 \(\Delta\)，但未分析该控制问题的可学习性、 regret 界或何时降级最优的判定条件；对 \(\lambda_T,\lambda_C,\lambda_F\) 的取值敏感性未做讨论，而结论（“恢复并非总是有益”）本质上依赖这些权重与失败时机分布。
- **写作与呈现层面的问题**：部分概念（宏演化循环、恢复路由器）在方法部分被完整形式化，但实验部分未落地验证，形成“设计强于实证”的失衡；图表未标注误差范围，正文对 12 与 7 两个任务子集的选择依据（为何是这些任务）交代不清。

## 9. 启示与可借鉴之处

- **把“抽象层级”作为一等控制变量**：对任何具备工具/技能两层动作空间的代理系统（不只是编码），都可借鉴“动作包络 \(A(g,h_t)\) + 事件驱动转移 \(\Delta\)”的建模方式，将“用哪个层级做下一步”从提示词中的软约束提升为可测试的硬控制。
- **恢复必须与失败可观测性绑定**：论文的核心洞见是“恢复的价值取决于失败发生在宏完成之前还是之后”。这提示工程实践中应先建立失败分类与验证器，再决定是否启用回退；否则无条件降级只会放大成本。
- **可审计的轻量路由**：深度受限、序列化为 JSON 的决策树是一个务实的折中——在保持确定性与可解释性的同时，显著优于静态启发式规则。对监管或生产环境要求“决策可追溯”的场景具有直接参考价值。
- **宏技能契约作为技能库治理规范**：前置条件、副作用声明、内部验证、可观测失败类别、回退路径这五项，可作为技能市场/技能库准入检查表，帮助抑制“宏技能静默产生部分副作用”这一最难排查的失败模式。
- **评测设计上的可借鉴点**：所有变体共享同一 LLM、工具实现与验证器，仅改变动作空间；预执行路由严格隔离验证结果。这一“单变量 + 信息分离”的对照思路，比追求任务数量更值得在类似研究中复用。

## 10. 总体评价

论文提出了一个清晰且有价值的问题重述：技能粒度不是检索排序问题，而是运行时的动作抽象控制问题；并以“动作包络—预执行路由—失败感知的宏到微恢复”三段式框架给出了可执行、可审计的答案。其最有说服力的部分是**故障注入实验揭示的反直觉结论**——恢复并非总是有益，其收益严格依赖于失败时机与宏的完成度；以及**学习式路由显著优于结构启发式**这一实证发现。宏技能契约与确定性验证器两项设计也具备独立于本文主张的工程价值。

但其证据强度与主张强度之间存在明显落差：实际评估仅覆盖 12 个混合任务与 7 个故障注入任务，缺少置信区间、消融、跨模型泛化与最强基线对照；宏演化循环停留在概念层面；算力与模型信息缺失使复现与成本归因受限。因此，本文更适合被视为**一个论证充分的问题框架与一套可复用的控制/评测设计**，而非对“自适应粒度普遍优于固定粒度”的确定性证明。后续工作若能在更大规模、多模型、真实失败分布上验证，并补上“外部控制器 vs 模型自决”的关键对照与权重敏感性分析，其主张的可信度将大幅提升。
